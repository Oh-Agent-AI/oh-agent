# 开车模式路灯"换引擎"：解析式街灯数组（治本）

## 结论确认

普通/飞行模式维持现状（圆片贴纸 + 全局亮度），**仅开车模式**（cameraOwner === "game"）启用解析式街灯：每帧取离相机最近的 16 盏灯写入 uniform 数组，在受光材质 shader 里按光度学分布（1/cos³ 蝙蝠翼 + 沿路压缩 + 截止 + 平方反比）求值，加进 `reflectedLight.directDiffuse`——与 three 自身光照管线同构（night-street 架构，MIT，可搬）。两条成本曲线互不侵犯：远景 4600 盏贴纸不动，近景 16 盏真求值。

关键机制：**互补交叉淡化**。40–70m 过渡带内，贴纸光斑淡出、解析光淡入（同一段 smoothstep 的互补权重），总亮度守恒，无双重照亮、无灯切换爆闪（被换出的灯在 70m 外权重已为 0）。

## 现状事实（已探明）

- 开车与普通模式**共用同一 CityEngine 场景/材质**，车挂进同一 scene（`CityEngine.ts:287`），因此解析光用 uniform 门控（count=0 时 shader 早退），不改材质结构。
- 地形（`terrainSystem.ts:100`）与路面（`roadSurfaceSystem.ts:162`，5 层 Lambert）都已有 onBeforeCompile 补丁且共享 uniform 对象；世界坐标 varying 已存在（`vCityWorld`/`vRoadWorld`）。
- Lambert 片段顺序（three 0.186.1）：`emissivemap_fragment`(L104) → `lights_fragment_end`(L110) → `outgoingLight` 求和(L115)，注入点成立，一条注入串同时适用于 Lambert 与 Standard（车漆）。
- 每帧咽喉点：`presentDrivingCamera`（`CityEngine.ts:1260-1289`），相机位姿可得；释放点 `onReleased`（`CityEngine.ts:293-298`）。
- 灯位数据目前写进 InstancedMesh 后即丢弃，但完全可由纯函数重算（`nightLighting.ts:141-210` 的确定性循环）。
- 夜量已存于 CityParts（`nightGlow`，setNightGlow 写入），开车时 `updateDaylight` 每帧刷新。

## 改动清单

### 1. `engine/cityLightBudget.ts` — 预算扩展（纯函数，无 three）
- `LIGHT_BUDGET.street` 增补：`analyticCd`（tier-1 天底坎德拉，场景单位，注释附 night-street 换算推导）、`warmStrike: [1, 0.30, 0.36]`、`warmWorking: [1, 0.47, 0.13]`（钠灯起辉/工作色度端点）、`warmthFloor: 0.35`。
- 新增纯函数：`lampWarmth(seed)`（哈希 → warmth ∈ [floor, 1]）、`lampWarmOutput(w) = w^0.55`、`lampWarmChroma(w)`（w^0.75 插值，颜色先于亮度稳定——夜街"灯与灯颜色不一致"的关键）。
- 扩展 `budgetProblems()` 自检（analyticCd 范围、色度端点峰值=1）。

### 2. `engine/render/nightLighting.ts` — 灯位表提取 + 贴纸淡化
- 抽出 `planStreetLamps(layout): StreetLampPlan[]`（纯函数，逐字搬现有四段循环：主干路 runs / 公园 / 尽端回车圈 / 高架；描述符含 x,z,nx,nz,base,yaw,tier,flat,poolReach,poolRadius）。`buildNightLights` 改为消费该表——**矩阵逐字节不变**（scene-baseline golden 会验证）。
- `pools` 材质加 onBeforeCompile：实例化世界坐标 varying（`#ifdef USE_INSTANCING` 守卫）+ `uPoolFadeCenter`/`uPoolFadeOn`，片元里 `diffuseColor.rgb *= smoothstep(FADE_NEAR, FADE_FAR, distToFrag)`（与解析光互补）。不改材质参数 → golden 安全。

### 3. 新文件 `engine/render/drivingStreetLights.ts` — 解析光引擎
- 模块级共享 uniform（沿用 night-street 单例模式）：`uCarLampP: Vector4[16]`（xyz + cd×night×fade）、`uCarLampD: Vector4[16]`（发射轴 + 横路压缩因子）、`uCarLampC: Vector3[16]`（色度）、`uCarLampCount`。
- GLSL：`lanternLobe`（1/cos³ 蝶翼，上限 LAMP_PEAK、8° 截止、立方先取下限防 NaN）+ 求值循环（200mm 平方反底下限、单比较距离剔除、几何法线 N·L）。强度/色度全部取 `LIGHT_BUDGET`（规避护栏禁用的 `night * <magic>` 字面模式）。
- 注入串 `carLampsAdd(worldPos, worldNormal)`：`reflectedLight.directDiffuse += artE * BRDF_Lambert(diffuseColor.rgb)`（Lambert/Standard 通吃）。
- `updateCarStreetLamps(plan, camX, camZ, night)`：按 d² 取最近 16 盏，warmth 用灯位哈希（每盏灯色温固定，不随帧变），fade 权重 CPU 算进 w；`clearCarStreetLamps()`。
- 导出 `FADE_NEAR=40, FADE_FAR=70` 供贴纸淡化 GLSL 对齐。仅 import three + cityLightBudget + type-only 引 nightLighting（保证 road-paint 守卫的 Node 可加载性）。

### 4. `engine/systems/terrainSystem.ts`
- 顶点补 `vCityWNormal`（objectNormal → 世界空间）；片元在 `<lights_fragment_end>` 后注入 `carLampsAdd(vCityWorld, normalize(vCityWNormal))`；onBeforeCompile 合入解析光 uniforms。

### 5. `engine/systems/roadSurfaceSystem.ts`
- 同样注入（`vRoadWorld` + 新增 `vRoadWNormal`），两个缓存键程序都覆盖；onBeforeCompile 直接合入模块单例 uniforms。

### 6. `game/CarVisuals.ts` — 车身受光
- `material()` 工厂里给每个 MeshStandardMaterial 挂同款注入（世界位姿 varying + uniforms + 求值）：车开过灯下，车顶/引擎盖接住暖光——低角度相机下可信度增益最大的一处。

### 7. `engine/cityParts.ts` + `engine/CityEngine.ts` — 接线
- CityParts：构建时存 `lampPlan`（随静态城缓存走）；新增 `updateDrivingStreetLamps(camX, camZ)`（nightFactor(this.nightGlow) → 更新 uniforms + 贴纸淡化中心）与 `clearDrivingStreetLamps()`。
- CityEngine：`presentDrivingCamera` 应用相机位姿后调用 update；`onReleased` 调 clear。普通/飞行/导片 worker 永不触发（count 恒 0，shader 早退，行为零变化）。

### 8. 规范与护栏
- `docs/CITY_NIGHT_LIGHTING_SPEC.md`：新增 N5 节（开车模式解析街灯：无 THREE.Light 对象、K=16、40–70m 互补交叉淡化、强度走预算），并在 N3 注记适用范围（N3 否决的是全城常驻点光，本方案是游戏相机周边的 shader 内解析求值）。
- `scripts/verify-city-night.mjs`：增补一条断言（源码含 `LIGHT_BUDGET.street.analyticCd`），与既有守卫角色一致。
