# City Repair 升级方案：让玩家自己修道路规划缺陷

状态：P0-A / P0-B / P0-C / P1-E / P1-D 已实施（2026-10-21，分支 `codex/city-repair-upgrade`，实施记录见 §6）；P2-F / P3-G 未做。前置：`189e5ae6`（整座擦桥 + 画桥桥头规则，见 `CITY_PLAN_MANUAL_REPAIR_SPEC.md` §18）。
原则（用户 2026-10-21）：「不追求完美，因为我们还有 city repair——玩家能不能用这个工具修复问题是关键」。
生成器只修便宜、普遍的缺陷；长尾缺陷交给玩家，但前提是玩家**找得到、改得动、知道改好了没有**。

## 1. 现状：三个环节，只通了中间一个

| 环节 | 现在有什么 | 缺什么 |
| --- | --- | --- |
| **发现**（哪里坏了） | 面板「体检」只有 4 条布局规则：楼压路 / 楼重叠 / 楼在陡坡 / 街区离路太远（+ 补丁失效） | 道路**能不能开**一条都没有。驾驶审计（`RoadPassabilityAudit`：挡住必有截面证据，通过必有同内核试跑）只在脚本里跑，玩家看不到 |
| **修改**（改得动） | 移楼、画路（五种路型、弧线、过河自动架桥）、擦路、改路型、拖路口、搬/拆设施，以及刚补上的整座擦桥 | 画地面路**不查坡度**，画得出车爬不上的路；桥台固定 3，岸坡陡就只能换地方；桥头路口拖不动 |
| **确认**（改好了没有） | 画路/拖路口的红绿预览：只判「合不合规」 | 没有「车能不能开过去」的回答，玩家改完只能自己进驾驶模式试 |

## 2. 已知规划缺陷能不能靠 repair 修（今天 / 升级后）

| 缺陷 | 规模（15 + 30 规划实测） | 今天 | 升级后 |
| --- | --- | --- | --- |
| 桥头斜接（桥端压在路口上，窄桥下桥车身越出桥面） | 431 个桥端里 43 个 | **能修**：擦桥 → 擦岸边残路 → 画直桥（7/2 悬索桥已端到端验证）；但要玩家自己找到它、自己试 | A 标出来、D 一键给方案、E 告诉你改好了 |
| **桥头过陡（车上不去）** | 5 个 | **部分能修**：擦掉后在附近找缓坡重画（规则已拦住再画出陡桥头）；附近没有缓坡就修不了 | C 桥台自动延伸到缓坡，原地重画即可 |
| 地面路过陡 | 未统计（生成器路沿地形，山区可能有） | 修不了：画路不查坡度，玩家甚至会画出新的 | B 画路拦/提示；A 体检标出既有陡路 |
| 通往水中设施、对岸无路的桥（7/2 第二座） | 少量 | 擦得掉，无处重画 | 不变：要么接受，要么移走该设施（设施工具已有） |
| 锐角路口、新断头、孤立路 | 已有 warning | 能修（擦/拖/画），面板只在编辑时提示 | A 体检常驻列出 |
| 大城碰撞预算耗尽（`budget-exhausted`） | 大城个别路线 | 不是道路缺陷，是审计算力 | 不归 repair；如实显示「未判定」，不当成坏路 |

**结论**：「5 个过陡」今天只在附近有缓坡岸时能修；做完 C 才能原地修。比 C 更要紧的是 A（玩家根本不知道是哪 5 个）。

## 3. 升级项（按「改动小、收益明显」排）

### P0-A 道路体检：把「哪里开不过去」放进面板
- 体检加一组**道路规则**（纯静态、毫秒级，和现在的布局规则同一面板、同样有「定位」）：
  - `bridgeheadApproach`：桥端到最近路口的直引道 < 喇叭口伸出量（复用 `bridgeApproachProblem`，与画桥同一判据）；
  - `bridgeheadSteep`：桥端外 8 内岸坡 > 0.31（车的爬坡上限 tan 0.3）；
  - `roadSteep`：地面路沿线坡比 > 0.31 的路段；
  - 既有提示升格为常驻条目：锐角路口、断头、与主网断开的路。
- 每条问题标 `origin: generated | edit`（已有机制），让玩家分清是生成器留下的，还是自己改出来的。
- **动态审计不进悬停**：截面证据 + 试跑一次几十毫秒到秒级，只在 E 里按需跑。
- 成本：小（规则层 + 面板复用）。验收：7/2 体检列出那座悬索桥；45 规划的统计与脚本口径一致（43 / 5）。

### P0-B 画路坡度校验
- `validateRoadAdd` / 弧线 / 拖路口 / 改路型：路段任一处坡比 > 0.31 → 阻断 `road-too-steep`（「车开不上去」，属于物理上做不到，符合 §15 放权口径）；0.2–0.31 只提示 `road-steep`。
- 成本：小。验收：合成坡地画路被拦；真实城市现有擦/画统计不回退。

### P0-C 桥台自动延伸到缓坡（原地修陡桥头）
- 画桥时桥面不再固定只伸上岸 3：从水线沿笔画往岸上走，直到岸坡 ≤ 0.31 且离路口够远，最多伸 20；伸不到就照旧报 `bridge-approach-steep`。
- 和生成器的桥同构（只是 deck 更长），渲染、驾驶面、桁架都不用改。
- 成本：小到中（`wetSpan` 输出桥面起止 + 校验/重放同一函数）。验收：那 5 个陡桥头擦掉后原地重画，`verify-plan-repair-bridgehead` 式同内核双向开过。

### P1-D 一键修复建议（体检条目 → 可预览的补丁）
- 体检里的桥头问题给一个「修复」按钮：生成候选补丁 = 擦整座桥 + 擦岸边残路 + 按画路规则搜一笔合法直桥。这就是 `verify-plan-repair-bridgehead.mjs` 的搜索，搬进 `session`。
- 候选只当**预览**（地图上画出将删/将建，推平与安置数照常），玩家点确认才写补丁，一步撤销；找不到候选就说明原因（「附近没有缓坡岸」「对岸无路」）。
- 不做「一键修全城」：每条建议都要玩家看过再收，补丁仍是玩家的修改记录。
- 成本：中。验收：7/2 悬索桥一键出方案，接受后 E 判通过。

### P1-E 试驾验证（改完告诉你通不通）
- 选中一条路或一座桥（或 D 的方案接受后自动）→ 在当前生效布局上跑一次 `RoadPassabilityAudit`（局部走廊、只载走廊内固体，`solidScope: "corridor"`），结果三态：**通过** / **挡住（带位置，地图上标截面）** / **未判定（带原因，如预算耗尽）**。
- 放进 worker 或延时执行，不卡交互（悬停不跑）。
- 成本：中（审计已是纯 CPU 模块，缺的是快照入口 + 面板展示）。验收：7/2 修前「挡住 @桥头」、修后「通过」；budget-exhausted 显示为「未判定」而非失败。

### P2-F 整桥平移/旋转（拖桥头）
- 路口工具拿起桥头 = 拿起整座桥：两端一起平移，或绕另一端旋转，实时按画桥规则判红绿。比「擦掉重画」少一步，也保留悬索桥这种地标。
- 成本：中（新补丁操作 `move-bridge`，扩档重定位要带上它）。等 A–E 上线后看玩家是否还需要。

### P3-G 地形平整（挖填）——暂不做
- 2026-10-22：系统方案见 [CITY_REPAIR_TERRAIN_GRADING_SPEC.md](CITY_REPAIR_TERRAIN_GRADING_SPEC.md)（玩家土方作为补丁层 `terrainOps`，与生成器土方分层），待拍板后分期实施。
- 真正把陡坡削平要引入地形补丁层（`terrainOps`）：地形是函数场，驾驶面、楼高、树、水线全读它，影响面大；此前生成器侧尝试过一次（桥头整平），全城渲染都变、收益不明显，已撤回。
- C + B 覆盖了「车上不去」的主要场景；只有 C 伸到 20 仍不够的桥头，才需要它。

## 4. 建议的实施顺序

1. **A + B**（一批，规模小）：玩家先看得到问题，画路也不会再造出陡路。
2. **C**（小到中）：5 个陡桥头可原地修；用 45 规划逐个回归。
3. **E**（中）：有了「改好了没有」的回答，A–C 的效果才可被玩家确认。
4. **D**（中）：在 E 之上做一键方案（方案接受后自动试驾）。
5. F / G 视反馈再排。

每一步的守卫：`verify-plan-*` 全绿 + `verify-plan-repair-bridgehead` 扩成「45 规划里每个体检到的桥头问题：可修 / 不可修原因」的报表，数字只许变好。生成器不动（不升版本、不重冻基线）。

## 5. 需要拍板的

1. 顺序是否按 §4（先 A+B），还是先做 C（直接回答「5 个过陡」）。
2. B 的阈值：> 0.31 阻断（车物理上爬不上）、0.2–0.31 提示——可否。
3. D 是否只给桥头问题做（最常见），其它问题只「定位 + 说明」。

## 6. 实施记录（2026-10-21）

按 §4 的顺序实施；§5 三个待拍板项按建议默认值执行（先 A+B；> 0.31 阻断、0.2–0.31 提示；一键方案只做桥头）。

| 项 | 落点 | 结果 |
| --- | --- | --- |
| P0-A 道路体检 | `planAudit.ts` 三条规则（`bridgeheadOblique` / `bridgeheadSteep` / `roadSteep`），几何在 `planGeometry.bridgeheadDefects` / `polylineMaxGrade` | 45 规划：斜接 43、过陡 5，与桥头统计逐个一致；另发现 **25 段地面路坡比 > 0.31**（最陡 1.27，多是通往山上地标的小路），以前没人知道 |
| P0-B 画路坡度 | `planRoadRules.gradeCheck`：直线、过河两端引道、弧线、拖路口 | 真实 380 楼城市拖路口 896 次里 3 次因 `road-too-steep` 被拦；拖本来就陡的路口不拦 |
| P0-C 桥台延伸 | `wetSpan`：岸坡陡时桥面往岸上伸，离水线最多 20；另查桥面本身的坡比 | 合成陡岸原地可画；陡坡长于 20、或高台让桥面本身过陡，仍然拦 |
| P1-E 试驾 | `planRepair/testDrive.ts` + 面板「试驾」工具（D） | 7/2：修前坏桥「挡住」并标位置，修后「通过」。只编译路线附近 40 内的局部驾驶面：4000 楼每次 ~160 ms（全城编译要 8.7 s）；380 / 4000 楼各抽 ~26 条路与桥，局部与全城结论 0 处不一致 |
| P1-D 一键方案 | `engine/planBridgeFix.ts` + 体检条目「修复方案」→ 预览 → 采用（一步写入）→ 自动试驾 | 7/2 悬索桥：擦桥 + 4 段残路 + 78 的直桥，双向开过。两岸分开找落笔点（两岸离路网的距离常不一样）；断头支路尽头可作落笔点；长于 60 的引道不擦（是路网的一部分） |
| 体检性能 | 路段坡度按路段对象缓存 | 新规则在 1600 楼冷体检上约 +50 ms、热体检近 0；桥头检测 4 ms |

**「5 个过陡」的实际情况**（`verify-plan-repair-bridgehead.mjs <seed> <tier> miami` 逐个跑）：它们在 3 个海滨规划的 4 座桥上，
都不是「两岸都有路网的过河桥」——是通往小岛设施的堤道跳板（两段桥面中间一小段岛上路，驼峰在岛上）和一条断头溪桥（引道本身坡比 1.13）。
对岸没有可接的路、或陡坡比桥台能伸的 20 还长，一键方案如实拒绝并给出拒因统计（`no-road-on-bank` / `bridge-approach-steep` / `road-in-water`），面板指向手动修法。体检列得出、试驾判得出「挡住」，
但要真正修好，需要「延长现有桥的桥台」或「整条堤道重建」这类新编辑操作——属于 §3 P2-F 的范围，未做。

### 6.1 玩家修的路能不能开（2026-10-21，`scripts/verify-plan-repair-drivability.mjs`）

在真实城市上随机做画路工具接受的编辑（直线 60、弧线 20、拖路口 20），逐条试驾每段新路：

| 迭代 | 380 楼 | 1600 楼 |
| --- | --- | --- |
| 起点 | 69% | 52% |
| 新路口 < 50° 拦下（`junction-too-sharp`；渲染层在 < 50° 的三岔口做渠化，岛尖伸进主路车道） | 94% | 93% |
| 试驾窄路走中线、导流岛从空侧绕（生成器自己的渠化口 13/27 → 27/27） | 98% | 97% |
| 试驾局部窗口带全路口（裁掉一条腿的路口扇面会解不出——是窗口假象，不是城市的洞） | **99%** | **100%** |

另两座城：800 楼（种子 42）95%（4 条「未判定」= 车没能起步，1 条拖路口碰到高度冲突），800 楼海滨 100%。
失败都过了几何截面检查（路面处处有车宽的空当）。生成器 15 个规划的驾驶面里没有一块解不出的路面片。

**驾驶面安全网**（`session.surfaceVerdict`）：停住后的确切预览与提交时，把这一笔套上、编译它附近的驾驶面，新出现解不出边界的
路面片就拦 `surface-unresolved`（规则层挡不住编译器自己的失败）；抽样里每百次编辑拦下 0–1 次。
守卫：默认城市上工具接受的编辑 ≥ 95% 试驾通过、挡住 ≤ 2 条。
