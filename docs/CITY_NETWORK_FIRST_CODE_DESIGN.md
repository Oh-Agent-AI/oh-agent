## 1. 结论与实际流程

采用“城市结构意图 → 粗地理 → 连通骨架路网 → 公共设施选址与入口 → 街网 → 地块 → 最终校验”。不要把所有建筑坐标固定后再生成地理：河流、港口、海滨设施仍需要真实空间条件。降低复杂度的关键是减少反复改动已确定的道路与用地，而不是取消地理约束。

实际代码顺序为：

1. `createCityPlan` 决定 shape/biome/tier，按地块容量最多重建五次。
2. `buildGeography` 生成岸线、河道、山脊与 height/buildable。
3. `chooseCore` 选核心；`snap/place` 先落公共用地及地标。
4. `buildSkeleton` 生成主干、桥与环线高架。
5. 多遍移动用地：避高架、临街、贴岸、海上地标等。
6. 生成海滨大道、沿海路、河岸路、扇区街网，再补入口与孤立分量连接。
7. 合并碎边、断头收尾、运行九个修复策略（最多三轮）。
8. 校验车流路径、终筛地块、组装 CityLayout；普通会话建筑由下游布局消费地块。

因此当前不是“路网 → 地理”，也不是“所有建筑 → 路网 → 地理”。规划器模块化已推进，但阶段之间仍共享可变 Network/sites/blocks。

## 2. 已确认问题

| 问题 | 代码证据 | 修改方向 |
| --- | --- | --- |
| 公共设施在道路前锁定坐标，随后多次移动 | `cityPlan.ts` 的 place、避高架、临街、贴岸等段 | 先生成 SiteIntent，最终落位在骨架路网之后 |

### 2.1 本次评审补充的设计缺口

| 缺口 | 为什么会出问题 | 本文修正 |
| --- | --- | --- |
| 只有连接请求，没有上游交通需求 | 生成器仍要等断头出现后才知道“该连谁” | 增加 `ConnectionDemand`，在生成道路前描述区域与设施关系 |
| 骨架后立即指派设施 | 设施只能贴主干/高架，容易形成所有入口都汇入干道的失真布局 | 在指派前生成 arterial/collector corridor 与入口锚点 |
| 主网定义含糊 | “接入最近分量”可能只是把两个孤岛接在一起 | 主网固定为含 civic/plaza 骨架的分量，提交后重算分量 |
| `EndpointRole` 缺少所有权 | 无法证明断头究竟服务哪个设施或需求，也无法审计合法尽端 | 角色携带 `ownerId`、`demandId` 或计划尽端原因 |
| `NetworkPatch` 仅是名称 | 缺版本、拆边映射和原子提交规则，仍可能留下半条路或过期索引 | 明确 baseVersion、草稿验证、一次替换和失败无副作用 |
| RoadEdge 只有 bridge 布尔值 | 无法正确区分地面交叉、高架跨越、桥面和匝道 | 内部边增加 layer/structure/纵断面，finalize 再做兼容投影 |
| 必要连接失败与公开返回值不兼容 | 设计要求“生成失败”，现有 API 只能返回 CityLayout | 内部 `PlanAttempt` 承载失败，外层有界重试后确定性报错 |
| “其它硬约束不恶化”过于笼统 | 可能错误接受安全问题，或拒绝必要的可达性修复 | 安全零容忍；需求约束使用固定字典序；最后才比较软分 |

## 3. 阶段边界

### 3.0 现阶段实现的结构性缺陷与优先级

本节结论基于本文开头记录的 HEAD 与调研时工作区，不代表此后其它分支的最新实现。模块抽取减少了重复代码，但尚未消除生成顺序依赖：道路与公共建筑反复变化，没有一个统一的收口阶段同时保证几何安全、网络连通和派生产物一致。

| 当前缺陷 | 触发与后果 | 处理优先级 |
| --- | --- | --- |
| 公共建筑先落位、道路后生成、建筑多遍挪动 | 解决压路后可能失去入口、临海位置或与其它设施冲突 | P1：骨架后指派，入口可行性一起验证 |
| 多套补路检查 | 一个阶段拒绝的路线可能被另一个阶段的兜底接受 | P1：统一连接器与硬约束 |
| 孤立分量直接加边兜底 | 图上连通不代表地面可行；可能越水、穿占地或产生非法交叉 | P1：删除绕过验证的兜底，返回可诊断失败 |
| 平地断头被高度阈值跳过 | 肉眼可见的问题未进入检测和修复 | P1：端点角色、度数及可达性检查 |
| 过水连接能力分散 | 普通补路遇河停止，只有部分入口路径能造桥 | P1：统一显式桥接候选 |
| 圆形稀疏占地采样 | 长条和旋转模型边角可能压路、落水、悬空 | P2：实际 footprint 与道路扫掠宽度终筛 |
| 求解封顶三轮且缺少单步回滚 | 后一步破坏前一步；轮次耗尽不等于满足约束 | P2：补丁接受检查与未收敛报告 |
| 扇区街网独立生成后补连接 | 方格片区割裂、长斜线扎堆，形成不自然城市结构 | P2：区域连接需求先行；后续再评估张量场 |

验收存在三个独立盲区：

- 普查通过的是已设置的残留上限，不是“没有问题”。此前调研运行的 120 岛普查仍有 4 个岛用地入水、3 个岛出现检测范围内的内陆断头；这些数量依赖当时版本与样本。
- 检查道路端点数量不能替代最终连通与设施可达检查；图连通也不能替代桥头、高架接驳和模型净空的几何验收。
- 规划基线匹配证明输出未发生未预期变化，不证明旧布局正确；静态截图也不能证明车流路径和动态渲染没有问题。

新增评分修正改善版本比较，但不能替代硬检查。MapGenerator 可改善街网方向和片区衔接，不自动解决桥接、建筑冲突或最终可达性。

实施顺序明确为：①修正检测并新增最终可达约束；②统一连接、删除不安全兜底、支持绕行与桥接；③骨架后选址并验证入口；④以最终道路生成地块/车流并实际占地终筛；⑤在前述守卫稳定后评估 MapGenerator 与地形调整。不要先通过更换街网算法掩盖现有安全问题。

建议新增内部类型，优先保留现有渲染接口；结构信息无法准确适配时，必须同步升级消费契约，不能以“零渲染改动”为硬条件。意图层必须先描述“哪些区域必须互通”，否则连接器只能追着生成后的断头修补：

```ts
type CityIntent = {
  seed: number; tier: number;
  districts: DistrictIntent[];
  sites: SiteIntent[]; // 区域、优先级、临水/临街条件，不是锁死坐标
  demands: ConnectionDemand[];
};
type ConnectionDemand = {
  id: string;
  from: DemandAnchor;
  to: DemandAnchor;
  class: "trunk" | "collector" | "district-access" | "site-access";
  required: boolean;
  redundancy: 1 | 2;
  redundancyPolicy: "required" | "preferred";
};
type EndpointRole =
  | { kind: "junction" }
  | { kind: "site-access"; ownerId: string }
  | { kind: "cul-de-sac"; reason: "terrain" | "coast" | "planned-local" }
  | { kind: "must-connect"; demandId: string };
type ConnectionRequest = {
  id: string;
  source: NodeRef | PointRef;
  target: ComponentRef | CorridorRef | SiteAccessRef;
  purpose: "district-access" | "site-access" | "coastal-link";
  allowBridge: boolean;
  maxLength: number;
  roadClass: "arterial" | "collector" | "local";
};
type ConnectionResult =
  | { ok: true; patch: NetworkPatch; cost: number }
  | { ok: false; reason: ConnectionFailure; attempted: number };
```

示意类型中的 DistrictIntent/SiteIntent/NetworkPatch/ConnectionFailure 在实现批定义；不要在运行时存储任何会话原文、路径或用户标识。规划只消费 seed/tier 和固定设计配置。

每阶段读只读上游产物、拥有自己的可变草稿。NetworkPatch 列出新增/删除边、共享节点、桥段及端点角色，提交前验证完整补丁。TypeScript Readonly 是接口约束，不等于深冻结；需通过所有权约定和测试防止修改上游对象。

市政核心、广场外环与候选桥位作为骨架保留区联合确定；其它公共设施不再先固定。骨架之后先生成 collector corridor 与设施接入锚点，再做设施指派；局部街网最后填充。这样车站、体育场等设施可以面对次干路，而不是被迫全部贴主干。海滨带先保留岸段与交通走廊，再选酒店/港口位置，避免“港口决定海滨带、海滨路又推动港口”的循环。

目标阶段顺序为：

```text
intent/demand → geography → skeleton + bridge candidates
→ arterial/collector corridors → site assignment + access trial
→ local streets → transactional repair → parcels/finalize
```

每个 `ConnectionDemand` 必须在最终图中有对应路径或显式失败。`redundancy=2` 表示需要两条边不重叠的出入口路径，不等同于简单统计两个度为 1 的出口。

### 3.1 完整规划图与实际展示图

代码复核发现 `cityLayout.ts::growWithBuildings` 在规划之后按活动街区裁路，保留桥、宽度 ≥12 的边和服务活动区的边，再尝试从已删边中 BFS 补回连接。它还用第一条宽主路选择主网，并通过端点对过滤车流。故规划图合格不代表最终展示图合格，断路也可能发生在这一步。

- `PlanNetwork` 是由 seed/tier/配置生成的完整规划，只读缓存；`VisibleNetwork` 是基于活动地块集合派生的子图，必须独立验收。规划区 id 与按真实数据显示的 harness 城区 id 分开，前者不依赖用户数据。
- 规划期记录 civic 环路上的稳定 `primaryAnchorNodeId`，不是广场中心的虚拟点，也不是第一条宽路。展示期保留该节点和服务活动街区/设施的必要路径；禁止通过把连接设施的边隐藏而破坏需求。
- 生长阶段仅恢复已验收规划边，首批不另造路、不挪设施。恢复失败明确报告 `visible-demand-unreachable`。同一活动集合产生同一展示图，不能依赖回放曾经过哪些时刻。
- 两层分别生成道路网格、路口标线、车流及空间索引。车辆路线须保存有序 edge id 和行进方向；拆边按映射重建，不能只比较旧端点对。显示变化后再做路线连续性检查。
- 性能允许时使用按实际长度的 Dijkstra 恢复路径；当前 BFS 仅保证最少边数，不保证最短距离。修改这项属于行为变更，需单独对照截图与基线。

最终交付链为 `PlanNetwork → layout/active parcels → VisibleNetwork → render/traffic`。§8 的连通验收必须覆盖这两层。

## 4. 统一连接器

### 4.1 有限搜索

按稳定顺序尝试：最近合法路段投影直连 → 利用已有道路连接 → 绕障碍的少量折线 → 有界网格 A*。网格搜索只用于前几级失败的必要连接，设置候选、搜索区域与扩展节点上限，避免每个断头全图搜索。

目标是已确认的主网分量；不能为了降低距离接到另一个孤立分量后就宣告成功。最终必须重新计算真实分量。

“主网”不能用“节点最多的分量”临时猜测。持久引用是 civic 环路上真实的 `primaryAnchorNodeId`；`primaryComponentId` 由当前图版本计算，仅在该版本内有效。若环路或锚点不存在，则本次规划失败。连接请求保存目标锚点，在执行时解析分量，不能跨补丁复用旧 component id。

长度、转弯、坡度和造桥构成软成本；建筑净空、禁止水域、不可接受坡度是硬约束，任何降级不得取消。成本权重须配置化、记录版本。首批只要求已有图路径复用、合法直连与有限折线；A* 在这些方法的拒绝原因和复现样本证明有必要后增补，不是 SiteSpec 的前置条件。后续 A* 使用位置、入射方向和显式桥接候选；仅在确实搜索多种结构模式时增加结构状态，不能让普通格点跨水后补一个 `bridge=true`。

### 4.2 桥梁与交叉

跨河允许返回 ground → bridge → ground 三段，检查桥头干地、跨距、桥下/桥上净空及入口坡道。河道用例优先；跨海长桥和高架立交单独处理，不从“遇水”自动推断可修桥。

与地面道路相交时，可在合法角度下创建路口并拆分原边，而不是全部拒绝。首批保留现有地面 RoadEdge、显式桥和独立 highwayRuns，连接器不得把高架投影当成可吸附道路；用完整走廊及高架包络检查净空，既有接驳保留专门的检查适配器。地面与高架视觉交叉不创建共享节点。

统一多层道路图、layer/structure 及完整纵断面消费契约后置另立设计，需覆盖渲染、桥梁与车流。§4.4 中分层节点规则适用于该后续阶段；首批通过分离图域防止误合并。未来若无法准确投影回旧 RoadEdge，必须同步升级消费契约；不能丢掉层级后输出看似相交的道路。后置完整立体拓扑不等于后置当前高架/桥头净空检查。

### 4.3 提交与失败

统一坐标规范化、吸附、边拆分和属性继承（宽度、道路等级、结构层级）。`NetworkPatch` 必须包含 `baseVersion`、新增/删除节点边、拆边映射与新增端点角色。提交过程为：在草稿副本应用 → 重建受影响空间索引与分量 → 跑硬约束 → 版本匹配后一次替换正式网络。任何一步失败都丢弃草稿；禁止部分提交。车流只从最终网络生成。

失败分类至少包含 water-span、slope、site-clearance、junction-angle、search-budget、no-target、stale-base、projection-loss。可选短支路允许移除；公共设施可换候选位置；必要主网连接失败则重选局部骨架。`createCityPlan` 实际返回推断类型的规划对象，下游 `layoutCity` 才组装 CityLayout；不得把两者误写成同一个契约。内部使用 `PlanAttempt = Success | Failure`，预算耗尽交由 UI 集成边界处理（§6.2），不能只新增一个未捕获的 throw。容量不足才触发半径校正；无目标、拓扑冲突和搜索预算耗尽不默认靠扩大岛屿解决。

### 4.4 数值、节点身份与交叉规范

统一 `GeometryPolicy`：坐标量化步长、吸附距离、交点容差、最短边长、最小路口夹角及最小转弯半径分别命名、版本化。当前量化步长为 0.01 世界单位；不能将量化精度直接当成道路吸附距离。其余值在合成测试中标定后固定，缺项阻止启用新连接器，不使用散落的默认数值。

节点键含量化后的 x/z 与拓扑连接层；同平面投影的桥上、桥下节点不能合并。`layer` 是连接层身份而非高度值：高度还须读取纵断面，跨层只允许显式接驳。节点可同时承担多个需求/设施角色，保存有序 role 集合；仅有角色标签不能免除端点检查，须验证所属设施入口或需求确实存在。

交点处理必须区分端点接触、T 接口、内部交叉、共线重叠和近似平行；按原边参数顺序一次拆分多个交点，量化后重新验证净空与角度。禁止零长边、自环、悬空引用和重复冲突边。共线重叠在层级、等级与结构兼容时规范化；不兼容则拒绝并记录原因，不沿用当前“相同 id 保留第一条”的隐式策略。

### 4.5 路面走廊与结构校验

安全检查对象为中心线扫掠出的完整道路包络（车道半宽 + 路缘/人行道 + 退界），包含拐角连接、端帽和匝道。建筑 footprint 与走廊用多边形相交/距离终筛；检查角点并不等于检查完整面积。曲线简化、平滑、吸附之后全部重验，渲染不得另做越出已验收包络的平滑。

水域和地形采用固定精度网格/自适应细分，并记录分辨率、误差余量、最大细分次数；无法证明安全的单元按不可通行处理。它是有误差界的工程检查，不能把若干采样点全干称为连续几何证明。纵坡使用路面高差/水平长度，横坡检查道路两侧；基础地形的梯度不能替代桥面或坡道纵坡。

桥梁必须记录两岸桥头、桥面厚度、纵断面、墩/桥台占地与所跨水域 id。按通航/非通航水域规则检查净空，保护已有船队航道；桥墩不得落入禁建航道。首批未支持的桥型或接驳返回 `unsupported-structure`，不得输出普通边冒充。桥头和地面路同时校验位置、高度及切向连续性。

### 4.6 入口预留与联合提交

设施 footprint、入口通道和必要连接必须在同一候选事务中接受。试算成功仅证明当前草稿可行，不代表之后仍可行；入口走廊成为带 ownerId 的预留区，后续街网/设施不得占用。所有权例外仅允许该设施的道路穿过明确的入口通道，不允许穿越整个建筑 footprint。

设施换位时同步撤销专属入口及预留，再试算新位置；已共享给其他需求的边不能随设施一起删除，按需求引用重验后保留。多设施联合换位可作为一个补丁，避免必须暂时破坏安全才能完成交换。

## 5. 选址与地形

SiteSpec 收拢模型 footprint、入口局部坐标、临水要求、道路等级、优先级和可选性。候选沿骨架道路或岸线生成：车站入口朝最近道路，体育场预留入口与服务道路，港口保留陆侧货运入口与水侧码头，海上地标必须同时找到可行堤道。

`footprint` 不能只存一个半径。首批至少支持圆、定向矩形与凸多边形；模型存在多个组成部分时使用若干凸多边形的并集。入口以模型局部坐标和朝向声明，转换到世界坐标后连同道路扫掠面一起校验。圆包围仅用于空间索引和候选粗筛。

候选接受前完成入口路线试算，避免“建筑合法但没有路”。生成期与修复期调用同一指派器。

第一批保留当前 height 函数，不引入地形重塑。后续若需要贴地打磨，可增加受限 TerrainPatch：只允许道路走廊小范围平整/桥头调整，保持河道连续、岸线与公共水域边界；规划、渲染和碰撞必须消费同一最终地形。不能只在渲染层加平台掩盖规划冲突。

普通建筑最后落位；道路定型后再切地块。若求解仍改变道路或设施，必须重切受影响地块并重算容量，而不是仅过滤掉冲突建筑后忽略容量损失。

### 5.1 自然环境调整边界

可以为交通基础设施适当调整环境，但分两批实现。首批道路适应现有地理：直连、绕行、桥接或换建筑候选；后续才允许受限的局部土木工程。禁止把地形重塑当成连接失败的无限兜底。

| 调整 | 首批 | 后续边界 |
| --- | --- | --- |
| 道路走廊小范围平整 | 不启用 | 限制挖填高度、影响宽度与过渡坡度 |
| 桥头整坡 | 使用现有合法桥头 | 允许局部整坡，不能堵塞河道或填掉水面 |
| 公共设施基座找平 | 检查实际 footprint，必要时换位置 | 有界调整，完整覆盖模型且与周围地面过渡 |
| 河流改道、填海、削山、全岛抬高 | 不启用 | 不属于本设计，另行设计与验收 |

后续 TerrainPatch 必须声明 `maxCut`、`maxFill`、`maxInfluenceWidth`、`maxTransitionSlope`、`maxTotalArea` 和 `maxIterations`。数值按现有世界单位、道路宽度和实测地形标定后固定成版本化配置；本设计不把未经验证的数值写成验收事实。任一参数缺失时禁用地形修改，超过预算时绕行或返回失败。

同时提交 NetworkPatch 与 TerrainPatch：先在草稿上验证两者，再原子接受；不得先改地形、后发现道路不可行而留下残余。多个地形补丁按稳定 id 顺序组合，重叠区域重新检查预算、坡度与水域边界。调整后重算受影响 height/slope/buildable、路段贴地、桥头和建筑基础；若尚无物理碰撞模块，不宣称已有物理保障，后续碰撞消费者也必须接入同一最终地形。

## 5A. 核心设计约束（实现不得放宽）

1. **安全优先于连通。** 不以降低建筑净空、水域保护、坡度和结构限制换取“连通率 100%”；失败有显式诊断。
2. **建筑坐标可重选。** 除核心与已确认基础设施保留区外，公共建筑先满足区域/临海/临街语义，最终坐标由可行候选决定。
3. **桥梁显式建模。** 普通地面边不得穿水；桥必须检查完整跨距、两岸接入和结构净空。
4. **几何交叉与拓扑连接分开。** 地面交叉建立共享节点；高架跨越不自动连接，匝道必须显式可行。
5. **局部地形调整有硬预算。** 超限不能不断扩大影响范围或提高预算，不能破坏河道连续性和保护水域。
6. **最终地形唯一。** 规划、渲染、建筑基础以及存在的碰撞消费者读取同一版本的最终 height；基础地形仅用于候选比较与回滚。
7. **确定性与无副作用失败。** 相同 seed/tier/配置/算法版本得到相同结果；搜索使用节点数预算而非墙钟超时；拒绝的候选不得修改正式网络或地形。
8. **派生产物最后生成。** 地块、普通建筑布局、植被与车流基于最终道路和设施；网络/地形版本改变时，相关缓存失效并重算。
9. **硬约束与软偏好分离。** 软评分不能允许非法方案，也不能阻止必要的安全修复；换位和连接必须先过同一套硬检查。

## 5B. 代码修改清单与完成条件

以下文件名为目标设计；新增文件必须在实际实现批创建。

| 文件 | 修改内容 | 完成条件 |
| --- | --- | --- |
| `planner/connect.ts`（新增） | 连接请求、有限候选搜索、桥接、失败原因、补丁试算 | 所有必要连接走统一入口；失败不改变正式数据 |
| `planner/intent.ts`（新增） | DistrictIntent、SiteIntent、ConnectionDemand 与稳定优先级 | 每个 required demand 有稳定 id、目标语义和最终满足记录 |

| `planner/network.ts` | 节点吸附、边拆分、属性继承、NetworkPatch 提交 | 拆边保持等级/宽度/结构属性；共享节点真实可达 |
| `planner/constraints.ts` | 语义端点、最终连通、设施可达检查 | 平地断头可被测量；合法尽端有显式角色 |
| `planner/networkRepairs.ts`、`repairs.ts` | 删除高度盲区，修复通过连接器执行 | 生成与修复共用安全规则；不另写过水兜底 |

| `planner/terrainPatch.ts`（后续新增） | 有预算的挖填、过渡、地形版本与回滚 | 首批不启用；补丁与道路共同接受，最终地形一致 |

连接器迁移时，需同步检查 `skeleton.ts` 高架出口的接驳线与角度/净空；不把它作为留在统一规则之外的特例。骨架/街网内部生成连续路段时可以调用低层 corridor validator，但任何跨分量、设施入口、桥梁和高架接驳都必须形成 `ConnectionRequest` 并走事务补丁。将 segmentDistance、节点 id 与容量规则等底层原语移入独立模块时，分批消除 planner 对 cityPlan 的反向运行时依赖，避免模块拆分后仍有循环依赖。

## 6. 求解与指标

先测量，再只触发相关策略。目标流水线的安全约束（落水、压建筑、非法坡度/桥梁/层级）必须始终为零；需求向量按 `[必要设施不可达数, 必要街区不可达数, 其它必要需求未满足数, 必选冗余不足数, 容量缺口]` 比较。三类“不可达”互斥归类，不重复计数。安全为零且需求向量严格改善时可以接受补丁；向量持平时仅接受软评分严格提高的补丁。每项已满足的 required demand 还须保持满足，防止以更高优先级改善换掉已有连接。前后状态哈希相同不计变化，上限结束明确标记未收敛。

迁移期旧草稿可能已不安全，直接套“安全始终零”会让所有修复无法启动：这类草稿只允许在隔离态执行减少旧违例且不新增/加重任何安全违例的修复，用稳定对象 id 与违例类型比较，不能仅比较总数。始终无法归零的草稿不得成为新规划成功结果。旧版兼容模式的残留普查另行保留，不能伪称通过新版零违例门禁。

指标分开记录：孤立可用路网分量、未满足 ConnectionDemand、合法尽端、公共设施可达性、桥头连续性、容量、耗时。街区只有在包含可用地块且最终保留时才进入可达验收。重要街区的双出口按到主网的两条边不重叠路径测量；地形受限街区允许一个带失败原因的单入口。无需对每个小街区强制双入口。

### 6.1 需求生命周期与容量诚实性

需求状态为 `pending / satisfied / waived / failed`。required 的最低连通要求不得 waived；可选第二出口仅在 `redundancyPolicy=preferred` 时允许带原因豁免。两个出口须有不同的街区边界接点，并在街区内部连通后分别到达预先指定的主网锚点集合；测试须拒绝“两条出口最后汇入同一条瓶颈边”的假冗余，不能用整个待测街区已并入的分量作为零长度目标。

合法尽端必须来自预先声明的局部街道用途或已证实的地形边界，并校验终点/回车空间。禁止把 failed must-connect 改名为 cul-de-sac 来通过验收。可选街区删除必须同步删除对应地块并报告容量损失；不能通过删光需求取得 100% 连通率。最终同时报告目标容量、可用容量、删除/省略数量及原因；不足时进入有界容量重试或显式失败。下游聚合展示不得伪称补齐了真实地块容量。

### 6.2 调用边界、取消与失败展示

内部成功结果携带规划与诊断；失败携带 code/stage/requestId/attempts/budgetUsed。不得将所有失败统一捕获成“种子保存失败”。实现批必须跟踪 `createCityPlan → layoutCity → CityEngine → CityExperience` 的错误传播，新增规划错误展示并保留原有持久化错误分类。

生产采用有界降级阶梯：局部换路线/设施候选 → 换骨架候选 → 仅容量原因进行半径校正 → 省略可选装饰设施或可选道路复杂度并重验 → 仍失败则保留旧成功场景或进入明确失败状态。不能承诺所有 seed 必然生成城市。

“缩小但完整”只允许减少可选场景内容，不能静默降低必需地块容量、隐藏会话或把 required demand 改成可选。若未来采用聚合建筑承载容量降级，须单独定义展示契约，保留全部会话映射与真实统计，并明确提示聚合数量。降级结果记录 `status=degraded`、省略内容及原因；仍需满足安全与其必需需求。生产和 guard 共享这些条件，不能只在 guard 中检查 required demand、生产却忽略。

- 有旧成功场景：构建新草稿时保留旧场景；新结果通过规划和展示图检查后整体替换。失败时展示明确错误，标识仍显示旧 seed/范围，避免旧画面冒充新数据。
- 首次构建失败：退出 loading，显示可重试/换种子的状态；不自动无界更换 seed。场景资源失败或取消时完整释放，成功替换后再释放旧场景资源。
- 每次构建携带递增 generationId；切换 seed/tier/范围、离开 City 或销毁引擎使旧请求失效。过期结果不得覆盖新场景。仅增加 AbortSignal 不能中断同步长循环，需在固定工作批次间让出执行权，或使用 worker。
- 是否采用 worker 由长任务测量决定；如采用，不能直接 structuredClone 带 height/buildable 闭包的 Geography。传可序列化 seed/config/几何结果，并用同版本公式在消费端重建查询。

### 6.3 搜索预算、缓存与确定性

必须同时配置每请求和每整图预算：候选数、A* 扩展状态数、开放队列大小、修复补丁数、骨架备选数、半径重建数及几何检查次数。整图预算跨全部重试累计，不能每次扩大半径就清零。`search-budget` 表示未完成搜索，不等于证明无路可走；诊断保留失败阶段和已尝试类型。

参数取值在迁移批 1 的实测后锁入版本化配置，未标定前只允许诊断模式。执行耗时和 UI 分块时间只用于性能报告/响应性，不影响候选排序和最终接受；固定 tie-break 为成本、长度、候选稳定 id，数值使用既有 DetMath 约定。

当前计划缓存键为 seed/tier/海滨参数。新版本须增加 plannerVersion、完整规范化配置指纹和模型占地目录版本；展示图键再包含活动地块集合与展示策略版本。失败/取消不缓存为成功；缓存有数量或内存上限。保持同 tier 内模型数据增量不重建完整规划；跨 tier 的布局重排属于显式行为，不能承诺所有建筑跨档位置不变。

### 6.4 残留问题的接受与产物修订（2026-10-10）

需求向量首项细分为必需设施未落位或不可达，互斥归类并保留独立诊断；未落位 obligation
也须触发生成期同一联合指派器。目录显式包含未接关系、入口、非主网分量与桥头，不仅登记软形态修复。
交叉/拥挤违例以参与对象 lineage、接触身份及显式 remap 比较，不能依赖 site/at 空值或只数总量。

候选可同时改道路、设施、入口、桥头及预留；只验收最终草稿。临时未发布的 parcels 可随区域
重整重建，但必须复核实际可用容量；已经发布的地址/会话映射须有确定性迁移合同并保持。
此规定不允许旧策略删除地块换分数，迁移须先完成新容量/地址回归。
合法 success 的完整/展示图都须满足 required 与安全；兼容残留、显式失败和生成失败率单独记账。
具体候选阶梯、生产调用与 R0–R5 退出条件采用关联的新 SPEC，本文其它模型物理与性能范围不缩减。

## 7. 迁移批次

### 7.1 首批范围与选址优先级

下列是交付依赖，不是要求实现完整蓝图后才能交付。SiteSpec 可以在最小连接器具备草稿验证、入口试算和原子提交后立即接入，不等待 A*、完整意图规划系统、多层路图或通用求解器。

| 交付 | 必须包含 | 明确不作为前置依赖 |
| --- | --- | --- |
| A：真实诊断 | 平地端点语义审计、完整图/展示图可达性、旧兜底触发证据 | 自动修复所有新暴露断头 |
| B：最小安全连接器 | Request/Result、复用路径、直连/有限绕行、拆边、草稿原子提交、失败传播 | A*、通用多层拓扑、全城市需求优化 |
| C：后置选址纵向切片 | 先迁车站/体育场的 SiteSpec、实际占地、入口预留及联合提交，再逐类迁移岸边设施 | 完整 collector 生成器；首批可复用已验收的地面走廊 |
| D：扩展与收口 | 合并既有桥接、其余设施、展示图和车流一致性、需求驱动求解 | TerrainPatch、张量场及统一立体路图 |

需求先以现有稳定街区/设施 id 描述最低可达要求，不先重写所有区域布局。占地先用实际模型可支持的圆/定向矩形/必要凸多边形组合，不为未出现的模型形态构建通用几何框架。工作量以每批出口条件与实际触及消费者估算；外部评审的“半天”“2–3 周”“3–5 倍”是经验判断，不作为已验证排期。

### 7.2 技术迁移清单（依赖优先于编号）

1. 固化当前行为与评分修正；记录残留 seed、重建次数和逐阶段耗时。独立修正端点高度盲区，保留新暴露缺陷的真实计数，不通过提高上限掩盖。
2. 先建立 `ConnectionDemand`、端点角色、主网定义和只读诊断；此批不自动补路，用固定 seed 证明检测完整。
3. 实现事务式 `NetworkPatch`、边拆分和版本检查；先迁移不跨水的现有连接，保持正常布局行为。
4. 删除不安全直接加边兜底，加入直连、少量折线与有界搜索；失败必须无副作用并进入诊断。
5. 合并桥接、入口连接与高架出口处理；新增最终连通、桥头连续和层级约束。在固定复现 seed 上解决必要连接失败。
6. SiteIntent/SiteSpec/assign/access 落地；先生成 collector corridor，再将公共设施最终坐标移到骨架后，逐类删除二次挪动遍。
7. 抽取局部街网与地块阶段；车流、容量和渲染产物基于最终网络统一 finalize；同步迁移 growWithBuildings，增加展示图验收和失败 UI。
8. 引入违例驱动补丁接受机制；测量后再决定半径校正和局部地形平整是否必要。

不同时改地形算法、道路算法和所有模型。纯抽取保持基线；行为变更逐批审查差异后更新基线。

新版诊断先以独立命令/实验配置运行，与旧守卫同时输出。开启新生产路径前必须满足最终安全零违例、required 需求全部满足、失败可恢复与性能预算；预算未锁定或失败传播未落地时，不得仅因基线已更新而默认启用。此处门禁优先于旧 v2 spec 中“软分下降一律撤销”和“CityLayout/渲染零改动”的历史要求；后续实现应同步更新上位文档对应条款。

### 7.3 影子门禁与不安全兜底退出

新约束依次为 `diagnostic-only → fixed-fixture gating → survey gating`。影子报告必须列出当前数量、复现 seed、对应迁移批次和剩余缺陷；旧门禁继续有效。修好的缺陷种子立即进入零违例 fixture 门禁，最后才切换整个普查，不为保持绿色而把新盲区数量直接加到旧容许上限。

去掉三处 height 门槛前，先区分设施入口、合法尽端与必需连接，检查当前语义证据是否足够；缺角色时记录 unknown endpoint，不以距设施近就一律豁免。体育场截图是否命中该盲区仍需同 seed 的规划图与展示图复现，不将“很可能”升级成已确认根因。

对 tolerance=0 路径先记录调用数、接受数和每条边的整段净空/水域/坡度结果。测量决定迁移范围，不决定是否容许非法边：合法候选经统一验证可保留，非法候选在新路径必须拒绝，随后走安全替代或显式降级。旧路径只在迁移对照中保留，不能成为新连接器失败后的隐式回退。

### 7.4 容量富余的新证据与归因边界

`CITY_PLANNER_V2_FINDINGS.md` 记录 tier1 约 1288 个地块，对目标 540 约为 2.4 倍。此为既有记录，本轮未复跑；未附 seed/每轮半径轨迹前，不能直接证明所有 tier1 都过量，亦不能唯一归因于 sqrt 重试。地块生成离散跳变、初始半径、预留区及终筛也可能影响结果。

补充每个样本的 `(seed, tier, attempt, radius, rawParcels, finalUsableParcels, target, retryReason)`；分别报告最终富余比和各轮容量跳变。饱和的 parcelYield 继续表示容量满足程度，另加 overProvisionRatio 作为诊断，暂不直接改软评分惩罚富余或缩岛。只有确定重试机制为主要原因且验证选址/路网不退化后，再改半径策略。

## 9. 论文与开源算法调研

本节区分来源实际提出的方法与本项目的工程适配。链接中的 master 是调研入口，不是版本锁；实现批必须记录采用的 commit 和文件许可。下面的伪代码为本项目设计示意，不是复制外部实现，也不代表已经落地。

### 9.1 全局目标与局部约束：近期采用

[Parish–Müller：Procedural Modeling of Cities（2001）](https://people.eecs.berkeley.edu/~sequin/CS285/PAPERS/Parish_Muller01.pdf) 将城市道路生成拆为全局目标与局部约束，并考虑环境输入。对 City 的适配是：城市区域与交通需求决定“需要连哪里”，统一连接器决定“怎么合法连接”。

当前问题是连接需求散在海滨、入口、街网、孤立分量的不同阶段，每处都有不同拒绝和兜底逻辑。把请求与几何执行分离，可以统一收集必要连接，按稳定优先级处理，并保留失败原因。不要照搬完整 L-system；已有骨架算法可继续使用。

```ts
// 本项目建议：先描述需求，再检查候选，不直接修改正式 Network。
for (const request of stableSort(requiredConnections)) {
  const result = proposeConnection(request, network, geography, reservations);
  if (!result.ok) diagnostics.record(request, result.reason);
  else if (validatePatch(result.patch)) commitPatch(result.patch);
}
```

修复的具体表现：平地断头进入请求队列；建筑挡路时尝试绕行；接入已有路段时拆边创建共享节点；无法接通的必要道路不会被未经检查的直线掩盖。

### 9.2 地形成本路径与土方：连接器采用简化版，地形修改后置

[Galin 等：Procedural Generation of Roads（2010）](https://perso.liris.cnrs.fr/egalin/Articles/2010-roads.pdf) 使用带权各向异性最短路径，考虑坡度及自然障碍，并研究桥隧与沿路径的地形处理。这支持“道路可局部改变环境”，但同时要求路线选择先考虑工程成本。

City 不实现论文完整优化器。建议有界搜索状态包括位置和入射方向，避免只按位置寻路产生锯齿急转；近期只支持地面和桥，不引入隧道。

```text
state = (cellX, cellZ, heading)
transitionCost = length + turnPenalty + slopePenalty + structurePenalty
illegal footprint / protected water / excessive grade => no transition
candidate route => continuous corridor validation => NetworkPatch
```

以上是适配设计：若用 A*，启发式只能采用可证明不高估的长度下界；若成本包含道路复用优惠，应同步降低下界或使用零启发式。格点路径还需简化并再次验证，不能认为格点合法就代表整个宽路面合法。桥接应使用明确的跨河候选边，检查完整跨度和两岸；不得让普通网格步穿过河后再补 bridge 标记。

解决的问题：长直线穿建筑改为短绕行；河岸断头在合适桥位汇入跨河连接；坡地路线先绕开高成本坡段。后续 TerrainPatch 对已选路线进行限额平整，解决贴地悬空，不通过挖填强行接受不可行路线。

### 9.3 张量场与方向连续性：后续街网升级

[Chen 等：Interactive Procedural Street Modeling（2008）](https://peterwonka.net/Publications/pdfs/2008.SG.Chen.InteractiveProceduralStreetModeling.pdf) 用张量场控制街道方向，并结合道路图编辑。对 City 可分别提供海滨切向、河岸切向、城区网格方向等引导，让区域之间的道路方向逐渐变化。

这主要解决俯视图中“独立方格街区 + 长放射斜线”的视觉割裂，不自动保证连通、桥梁合法或建筑净空。生成的流线仍必须进入统一连接器和硬校验。首批保留当前扇区街网，避免在安全修复中同时更换形态算法。

### 9.4 可检查的 TypeScript 代码参考

[ProbableTrain/MapGenerator](https://github.com/ProbableTrain/MapGenerator) 与当前技术栈接近，以下文件已作为源码调研入口查看：

## 10. 当前问题到算法及验收的对应

| 当前问题 | 应用算法/规则 | 修改落点 | 验收证据 |
| --- | --- | --- | --- |
| 普通平地断头漏检 | EndpointRole + 图度数/可达检查 | constraints、networkRepairs | 高度 1.2 的 must-connect 端点被报告并处理 |
| 断头不能直接接通 | 有限直连、方向候选与有界路径搜索 | connect | 建筑挡直线时绕行；无可行解返回原因 |
| 道路遇河消失 | 显式跨河候选与桥头校验 | connect、桥梁适配 | ground/bridge/ground 连续且拓扑可达 |
| 建筑压路、入口孤立 | 骨架后选址 + 实际占地 + 入口试算 | assign、access、footprint | 建筑安全且门前路线连通；必要时换位置 |
| 道路看似相交却不通 | 交点拆边、共享节点、层级区分 | network | 图路径能跨地面路口；高架跨越不误连 |
| 街区各自成网 | 区域连接需求先行、最终分量检查 | pipeline、connect、constraints | 每个保留街区接入主网，重要街区检查双出口 |
| 道路/基座悬空 | 共用最终 height + 有预算地形补丁 | 后续 terrainPatch、finalize | 近景贴地，预算超限拒绝，规划渲染高度一致 |
| 格网生硬、放射线扎堆 | 张量场方向引导，保留局部硬约束 | 后续街网模块 | 同 seed 俯视对照，连通/安全指标不退化 |

实施优先级仍为：语义检测与连接安全 → 桥接和后置选址 → 最终派生产物一致性 → 局部地形工程 → 街网形态升级。论文提供方法依据，项目的预算、确定性、诊断和事务式提交需要自行实现与验证。
