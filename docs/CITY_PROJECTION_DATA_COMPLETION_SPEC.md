# city_projection() 数据补全方案

版本：1.0 · 日期：2026-10-20 · 状态：首批数据与设施呈现已实现；完整完成定义尚待原生验收与存档集成

## 1. 目标与范围

让 City 的建筑身份、统计、模型、费用、活动与问题展示完整且可解释，为收租资产关联提供稳定数据身份。复用现有领域查询，City 投影负责权限、字段选择、范围声明与组合，不另建 Overview/Sessions/Findings/Skills 的计算逻辑。

“补全”不等于所有字段非空：源没有标题、没有定价或不支持 Skills 时，须返回原因与能力状态。游戏租金、金币、设施等级、道路工程、配件及装修不从真实统计推导，保存在独立 GameSave；数据读取不能触发发奖。

本方案仅覆盖官方同宿主内置 City。浏览器预览使用合成数据；不扩大 MCP/export 权限，不接入云端生成。

## 3. 发现的问题与修订决定

| 问题 | 现状/影响 | 决定 |
| --- | --- | --- |
| 时间口径 | UTC 滚动区间；窗口首末事件易被理解为会话完整生命周期 | 保留旧口径兼容，v3 明确窗口时间与生命周期时间 |
| 截断 | 最近活动优先选 4000，再按窗口内首事件排序 | 明示选择与排序规则；总览不从返回子集相加 |
| 未知时间 | `unknown_time` 统计有任意空时间 fact 的会话，可能与窗口会话重叠 | 新增互不混淆的分类，旧字段标为兼容字段 |
| 模型集合 | 由已返回会话的非 legacy 计费桶汇集 | 改用全窗口事实的共享分组查询；报告 unknown 和 legacy 覆盖 |
| 费用缺失 | 多提供方、无价格、legacy 不匹配可能为 null | 按币种/依据提供明细，不强行拼总价；继续复用计费策略 |
| 摘录 | 无时间过滤；先 LIMIT 2 再处理，劣质候选会占位 | 移到按需详情，扩大有界候选过滤后再取有效摘录，明确 session scope |
| Findings | 仅窗口内 opened 且当前 open/later；还有固定 Harness 列表过滤 | 区分当前积压和窗口新增，能力按注册判断，不忽略新 Harness |
| 查询成本 | 每会话计费桶与摘录查询，存在 N+1 | 公共聚合批量执行，详细文本/计费明细懒加载 |
| 类型不一致 | `title_source` 注释闭集与通用 Harness 扩展不相容；缺来源时当前可输出空串 | 开放受控来源标记或 unknown，缺失为 null；补运行时校验 |
| 状态解释不足 | empty 仅由会话数组决定，尚无逐模块 freshness | 分模块状态、能力、freshness 与 reason；不把 unsupported 当 empty |

另需评估 billing_tokens 求和溢出与 i64 → JavaScript number 精度。所有聚合失败要显式报错；不能截断、溢出或假装零。

## 4. 字段优先级与查询来源

### 4.1 P0：基础城市和经营身份

| 字段组 | 建议字段 | 来源与语义 |
| --- | --- | --- |
| 响应元信息 | protocol、query_semantics、data_revision、generated_at、source | 当前数据库事务与投影版本 |
| 时间窗口 | from/to、boundary、timezone、calendar_mode | 请求解析出的固定范围；范围选择与按日分桶分开 |
| 覆盖 | matched/returned/truncated、selection/order | 全窗口与返回子集分别统计 |
| 时间缺失 | unknown_time_only、mixed_time、excluded_no_usage | 各自明确统计范围；无时间不能猜测归属窗口 |
| 建筑身份 | id、asset_ref、harness_id、title、title_source、title_state | id 用于投影定位；asset_ref 为稳定 City 资产关联，详情见 §6 |
| 时间 | window_first/last_event_at、lifetime_first/last_event_at | 窗口/全会话独立命名；未知允许 null |
| 统计 | usage_event_count、token_buckets、models、coverage | event 是 usage fact 行，不是调用数、轮数或完成数 |
| 全窗概况 | session_count、tokens、models、daily_activity | 共享查询聚合全部匹配会话，不能依赖展示上限 |

P0 不要求读取摘录或生成剧情即可完成收租与升级。无 usage 的会话可在按需资产目录中支持，初始几何仍沿用有 usage 的建筑；避免投影升级突然改写全城规模。

### 4.2 P1：费用、详情与诊断展示

- 费用：`cost_status`、`has_unresolved`、reason codes、pricing versions、按 currency/basis 分组的 breakdown；unknown provider 保留不确定性。不跨币种直接相加，不把订阅判为实际零账单。
- 模型：实际模型 ID、未知模型计数/覆盖，不能仅从能成功计费的桶推导模型存在性。
- 活动：日界时区、按活跃会话/usage 行/token 三项分列；最忙日明确排序指标和并列规则，默认活跃会话、token、最近日期。
- Harness：通用注册身份、各字段的 supported/available 状态；不为 zcode 等单独加分叉 SQL。
- 详情：稳定楼号、受控来源说明、标题来源、有限摘录、字段可用性。原始文件路径和 native session id 留在宿主本地查看功能，不返回 City 插件。

### 4.3 P2：其他 Tab 的声明式模块

| 模块 | 补全内容 | 边界 |
| --- | --- | --- |
| Overview | 窗口总览、模型/提供方分布、覆盖与估价口径 | 复用领域聚合，不复制计价规则 |
| Findings | 当前未关闭积压、窗口新增、severity/category/count、受控详情句柄 | 不输出原始错误与参数，游戏动作不能关闭真实问题 |
| Skills | 有实际调用证据的使用次数、最近活动、定义清楚的结果 | 安装数不等于使用数，未记录不能猜测 |
| Workflow | 已记录工具开始/结束、结果与时长覆盖 | 独立于 token 时间线；配对和去重用现有领域口径 |

P2 在业务查询及投影授权逐项就绪后接入；不阻塞 P0/P1。每个模块都报告 unsupported/unavailable/empty/ready/stale，诊断原因另列。

## 5. 协议与加载方式

不把当前 `city_projection()` 扩成无限大响应。保留 `city:v2` 兼容入口，新增经注册的 `city:v3` 初始摘要，以及按需页面/详情操作；以下是拟定契约，不是现有可调用 API。

```text
city:v3 overview → 范围/覆盖/能力/总览 + 建筑轻量页
city:v3 sessions.page → 同一逻辑快照的后续页
city:v3 session.detail → 单栋有限统计与可选摘录
city:v3 module.read → findings / skills / workflow 等已授权模块
city:v3 assets.resolve → 游戏资产句柄的存在/删除/暂不可见状态
```

每个操作独立校验方法、参数、City 身份、活跃实例和数据范围；不是通过一个 name 参数获得任意宿主查询权限。读前及响应交付前检查实例仍有效。

页大小默认 200、上限 500，初始城市展示预算仍为 4000。分页不意味着渲染全部历史；统计总量与可见楼数量始终分开。4000 条完整兼容加载由 v2 承担，v3 渐进加载须验证城市布局稳定性，不让每页重排全城。

每次分页带 opaque cursor、固定 from/to、timezone、query_semantics 和 expected_revision。revision 变化返回 `revision_changed`，清理暂存页并重新开始；不得拼接两个 revision。v3 采用半开区间 [from,to)，v2 保持原闭区间，差异须写进契约和边界测试。

当前尚无长期保留的跨 IPC 数据库快照设施。初期使用 revision 检查的逻辑快照；缓存键包含固定窗口、revision、时区和契约版本。后续若 revision 不能覆盖标题、摘录、计价目录等变化，增加相关版本标识，不能假定一个数字覆盖所有来源。

v3 按日活动使用声明的 IANA 统计时区，处理 DST；`calendar_mode` 区分 rolling 与 calendar 请求，首版只开放 rolling。v2 日桶 UTC 保持兼容。不要在后台静默改变旧页的“今天”。

## 6. 稳定资产身份与游戏存档

当前 City ID 用盐和 `app:city:{session_key}` 生成，在相同 key/盐下稳定，但盐重建、库重建或会话键变化的持久性尚无充分保证。不能直接宣称它可支撑永久游戏资产。

建议宿主在独立 City 状态中维护稳定、随机、不含来源信息的 asset_ref，与内部规范会话身份映射；插件只见 City 范围句柄。迁移时仅凭可靠规范身份匹配，不按标题/时间相似度猜测。映射不可恢复时报告 orphaned，允许转通用物业，不产生重复启动金或租金。

`assets.resolve` 不受当前显示窗口限制，但仅解析当前 City 存档已引用且获准的有限集合。返回 present/outside_window/source_deleted/unavailable 等状态；批量请求有上限。源删除须清除私人派生文本与内部关联，保留通用游戏资产由用户数据生命周期契约定义。

金币、水位、收益槽、设施等级、配件和涂装属于 GameSave。投影不得输出“根据 token 应发金币”，也不得将估价作为租金。session.detail 与楼号复制只提供安全标识；原始来源打开走宿主控制的本地呈现，不伪装成插件数据字段。

## 7. 费用与内容质量规则

费用继续使用共享计费桶、路由证据、定价版本和降级策略。第三方端点/不明路由保留 metered_estimate 与 unresolved；subscription 只在官方订阅范围证据明确时成立。零 token、价格缺失、部分已定价、多提供方不可合计分别表达。

标题和摘录优先改善上游 Harness 的通用提取能力：过滤命令包装、系统消息、图片路径、重复和无意义应答。不能在 City 写 zcode 专用日志解析器。历史回填必须有增量版本与幂等策略，无法恢复的内容保持 unavailable。

有限摘录属于 session scope，可能早于当前统计窗口，必须标注；只有可靠时间证据才提供 excerpt_at，不能用 ordinal 猜日期。展示前按当前规则再次处理，保留 provenance/truncation。纯标题、用户要求、助手声称、验证结果不得混为同一种证据。

不返回原始 JSONL、路径、工作目录、调用参数、原始错误、凭证或金丝雀；新字段需版本化投影声明及测试。原有本地摘录权限不等于向云端模型发送的权限。

## 8. 性能与失败处理

- 汇总采用集合查询和共享查询模块；token/model/cost 明细尽可能按选定页批量分组。
- 定价目录、schema 检查在一次请求中复用；不要为每栋楼重复读取相同 overlay。
- 详情按需加载，摘录不进入初始规划关键路径；摘要与详情分别设置字节、行数与文本上限。
- 基于 EXPLAIN QUERY PLAN 检查现有索引再决定新增，不无依据堆索引。涉及 schema 变化单独迁移评审。
- 4000 会话下统计 SQL 次数与时间；不允许常规初始请求出现与会话数同阶的独立 SQL 调用。
- 公开阶段信息来自真实步骤：reading_summary / reading_sessions / ready；未知总量时不显示虚构百分比。
- 按模块失败保留已获得的可信模块；根授权/身份失效则停止交付。empty 只代表成功查询无数据。
- 错误输出 reason code，不携带 SQL、路径或原始文本。权限撤回清除相关缓存。

目标设备的延迟与内存门槛在基线测量后设定；必须记录 100/500/4000/超过 4000 会话、不同 facts 数与慢设备，不能只用会话数衡量规模。

## 10. 验收矩阵

| 场景 | 通过条件 |
| --- | --- |
| 窗口起止、跨时区/DST | v2/v3 各自边界明确；日桶与窗口一致 |
| 超过 4000 与相同时间并列 | 确定排序/分页，无重复遗漏；全窗汇总未被截断 |
| timed/untimed 混合、无 usage | 分类定义清楚，不误报未知为窗口内 |
| 模型未知/legacy/无法定价 | 模型和费用状态独立且诚实 |
| 多币种、多路由、部分价格、订阅 | 不伪总价、不默认为零或官方订阅 |
| 中途同步/标题更新/价格变化 | revision 或相关版本失效，禁止混页 |
| 盐/库重建、删除、窗口切换 | asset_ref 可迁移或显式 orphaned，无重发金币 |
| 新注册 Harness | 通用身份与能力处理，不新增专用 SQL |
| 命令/系统包装、路径、恶意指令 | 不进入展示文本、不执行；敏感 canary 不泄漏 |
| 无权/实例销毁/响应前撤权 | 不交付或重用缓存 |
| 初始响应/详情取消/模块失败 | 初始可加载、诚实降级、无无限等待 |
| 100/500/4000 会话 | 记录 SQL 次数、响应字节、延迟分位、内存与 UI 首次可用时间 |

验证复用现有 query/app-local 测试、data 计费测试、宿主投影权限测试、SDK typecheck 与 City build；补真实回归夹具，不将真实私有数据入库。原生 App 最后验证建筑标题、费用状态、总览范围、详情跳转与加载性能。文档完成不等于代码或验收完成。

## 11. 完成定义

基础数据补全完成：A–D 的已承诺字段均有来源、范围、缺失状态、SDK/运行时验证与测试；身份可安全关联经营存档；4000 规模性能有记录；原生入口验收通过。E 是可独立发布的增量，不能将“未支持 Skills”写成“零使用”。

不要求将所有 null 消除，不追求把所有 Tab 全量塞进一次调用。目标是可追溯、可加载、可安全用于城市展示的数据契约。


## 12. 实施状态（2026-10-20）

首批已实现共享统计、批量费用查询、v2 兼容补全、v3 快照分页、稳定资产注册表、按需详情及 SDK 校验。市政厅、观测站、医院和会话楼已有实际展示入口；Skills 已新增按需事件聚合投影；Workflow 仍明确 unsupported。空间映射与交互见 [数据设施方案](CITY_DATA_FACILITIES_PRESENTATION_SPEC.md)。

打包后的真实入口默认走 v3：总览加第一页即可渲染，后续页追加到按全窗规模规划的岛屿；`?cityData=v2` 仍可强制兼容投影。网站落地页宿主只回答 v2。v3 出错或快照重试耗尽时（插件 WebView 没有查询串可用）自动回退 v2。v3→UI 适配器补齐 findings / time_classification / model_coverage，并经过 `validateCityProjectionV2`。会话详情在后台写入后会重新取快照，而不是永远显示不可用。资产注册表提供受信宿主保存引用接口，真实 GameSave 尚未接线。原生 App 点击验收、慢设备首次可用时间与真实存档迁移未完成，不能宣布第 11 节全部完成。浏览器验收使用合成演示数据。

### 2026-10-21：缺少历史价格快照时的本地参考估价

City v2 默认入口与 v3 的按需 `session.detail` 显式启用参考估价：逐事件优先选取发生时间之前的快照；仅当没有历史快照时，使用本机最新保存的快照，复用领域计价器。已有历史快照但缺模型价卡时不改用未来整表覆盖。此选项不改变 MCP、导出和默认历史费用查询，不回写事实或补造历史快照，也不触发网络请求。

成功参考计价的桶标记 `pricing_source: current_card_reference`、`reference_captured_at_ms` 和实际 `pricing_version`；City `cost.reference_prices` 提供去重后的版本与采集时间，SDK 映射为 `cost_reference_prices`。参考金额始终是 `metered_estimate` 且 `has_unresolved: true`，界面展示采集日期（UTC）、“参考估价”和“非历史账单”，保留路由/价格的不确定性。采集日期不代表价格生效日或今天的实时价格。

订阅用量继续不产生按 token 账单；无卡、坏卡、无法计价模型保持明确缺失。部分可计价用量仅在分项展示金额，整单金额为空，参考来源在分项仍可见；不同币种不拼接总价。缺快照、历史汇总和多服务商等情况提供独立说明。v2 提供同样的可选来源字段；MCP 与现有严格查询保持兼容。
