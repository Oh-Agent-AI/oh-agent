# P0 结算顺序提示（2026-11-03）

## 本次变更

- 战斗顶栏“顺序”展开区使用有序阶段条：全队移动 → 我方行动 → 敌方行动 → 下一回合；始终说明我方按突击、射手、支援排序。
- “落空与即时结算”默认折叠，按需说明伤害、击退和损毁发生在行动中，以及目标位移或消失可能导致落空、落空不消耗冷却。战斗结束时跳过后续阶段；否则准备下一回合敌意。
- 敌方顺序仍明确是草稿试算，原敌人选择交互保留；中英文均提供可访问的阶段列表。小屏允许换行，不把完整解释长期铺在敌人列表上。

## 与权威规则的对应

`validateAndApplyPlan()` 先完成全部移动，随后按 `MECH_IDS` 依次执行行动，行动内立即产生伤害与击退等事件；`runTurn()` 在玩家行动后按需要运行敌方结算和下回合准备。胜负已定时不再进入后续敌方 / 准备阶段。这里不把用户计划中的“事件结算”画成虚构的独立阶段。

## 追加：旧综合交互回归及小屏修复（2026-11-03）

- 上述旧脚本失败是当时的历史结果；现已更新其城市入口、资源卡、风险详情和重置视角选择器，并按当前的模型与地面联合射线拾取寻找可见目标格，不再将被机体遮挡的格心误认为实际命中。原有棋盘、触屏、顺序、回放和日志断言保留。
- 发现 640×480 中展开“顺序”后，原滚动高度算法会根据当前可见文字动态缩放面板，使滚动区域上下跳动；现在阅读顺序时保持滚动区域稳定并遵循原生滚动。旧综合脚本验证滚动前后几何不变以及说明文字两端可到达。
- 远程状态强制展开摘要时，摘要按钮现在准确报告展开且不可操作，关联远程锁定状态，状态转换时保留原有焦点；远程结束恢复本地紧凑偏好。测试模拟切换前已有滚动和按钮焦点，核对警告可见、Enter 不会收起以及偏好恢复；并未连接真实远程服务。
- `scripts/verify-city-mecha-order-click.mjs` 在独立 Vite 端口以中英文合成 Chromium 通过：640×480 面板与顺序滚动、远程状态切换，1100×700 棋盘受威胁格鼠标/模拟触屏移动、敌人键盘/模拟触屏选择，及跳过动画后实际事件与血量记录核对、键盘访问和重开清理。
- `scripts/verify-city-mecha-turn-stages-browser.mjs` 中英文重新通过；`npm run typecheck`、`npm run verify:mecha`、`npm run build` 通过，构建仍提示大 chunk。
