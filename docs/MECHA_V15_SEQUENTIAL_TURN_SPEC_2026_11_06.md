# 机甲战棋 v1.5：逐台行动与即时结算规格

状态：待评审的实施规格；不表示已实现或已发布。
日期：2026-11-06
范围：本地 PvE 逐台移动、行动、撤销、回合重置、敌方阶段、表现与兼容。
参考：`MECHA_ARCHITECTURE_UPGRADE_PLAN_2026_11_02.md`、`MECHA_BATTLE_SYSTEM_SPEC.md`、`MECHA_PVE_PVP_SHARED_ARCHITECTURE.md`。

## 1. 目标与当前基线

玩家确认开局部署后，三台机甲保持所选部署格。玩家在己方回合自由选择机甲：移动立即生效且可按规则撤销；选择并确认攻击、维修或待机后立即结算，敌人、建筑、血量和攻击预告随结果更新。玩家可以交错操作不同机甲；结束回合后才执行敌方阶段。

本规格借鉴《陷阵之志》的即时摆位和逐个行动，不承诺逐项复刻原作。以下条款是本项目 v1.5 的明确设计，独立于原作数值。

当前工作区的 `mecha-v1.5` 仅有显式创建的建筑碰撞规则内核，产品、回放和远程仍使用 v1.4；不得视为已上线。当前 v1.4 的 `validateAndApplyPlan` 固定为整队移动、整队校验、按机甲规范顺序行动；`ArenaPlan` 是一次性提交包。控制器开场自动填充建议、整队重置草稿；当前机甲正式位置与草稿目标分离。旧版行为是兼容基线。

**版本决定：** v1.5 尚未发布，本规格把建筑碰撞与逐台行动一起纳入最终 v1.5 规则契约；不把当前试验内核当成已经冻结的 v1.5。实施前先冻结规则版本、命令和回放 schema，并为两个 v1.4 场景建立固定输入/输出基线。若已有外部分发的 v1.5 产物或存档，先停用该版本标签并另定新版本，不复用同一标识承载不同语义。

## 2. 术语与状态

- **权威状态**：规则权威维护的棋盘、生命、单位、冷却、宣告和胜负；本地亦有独立的权威边界。
- **临时目标预览**：悬停或选择目标时的只读试算，不改变权威状态和修正次数，不进入命令日志。
- **已执行移动**：规则成功后即改变权威位置并播放移动；满足撤销条件时可以通过一条新命令回退。
- **已执行行动**：攻击、维修或明确待机成功后立即产生结果和事件；普通撤销移动不能撤回行动。
- **回合起始检查点**：敌方准备完成、玩家尚未执行第一条命令时的完整权威状态，以及当时的确定性规则上下文。

每台存活机甲具有当前己方回合的 `moveAvailable`、`actionAvailable`，以及为撤销所需的来源格/命令标识；存活但未消耗的机会可被明确放弃。禁止依赖 UI 中的 `selected`、动画位置或草稿标记推导权利。机甲死亡后不得继续行动；目标死亡、碰撞、场地变化立即影响后续合法操作。

## 3. 操作规则

### 3.1 部署与首回合

1. 维持现有部署整包校验，确认后机甲正式位置等于各自部署格。不得自动执行 AI 移动或行动。
2. 敌人根据真实部署位置准备首回合意图，进入玩家回合。展示开场提示、当前敌意和合法操作。
3. AI 建议仅为只读建议；采纳建议不得隐式提交整队。第一版可在逐台模式禁用整队自动填充并明确提示，不能把旧 v1.4 计划伪装成已执行操作。

### 3.2 移动

- 选择一台有移动机会的存活机甲，再选择合法目标格；规则基于**命令执行时的当前权威棋盘**计算路径、占位和消耗。成功即移动权威实体，消耗该机甲本回合移动机会，并发出起点、终点和可复现路线。
- 不能结束在其他单位、障碍或不可进入地形中；路径与地形花费沿用 v1.5 所选基础规则。禁止使用 v1.4 的“假设队友同时离开”来穿越当前被占终点。是否可穿越友军沿用现有可达策略并通过专门用例锁定。
- 移动后可切换其他机甲。目标点击预览不得移动模型；成功命令后模型走到实际格，血槽、拾取、检查和后续攻击均使用新格。
- 第一版允许先移动再行动，也允许直接行动；**行动后该机甲的移动机会失效**。若特殊技能改变此规则，须使用明确声明和独立测试，不由 UI 推测。

### 3.3 移动撤销

- 支持回退**最近一条尚可撤销的移动**，可连续撤销形成后进先出的移动历史；目标机甲仍存活、尚未行动，且撤销后路径与目标格仍满足当前占位和依赖约束。
- 任何已提交行动（包括待机、维修、攻击、技能）立即清空普通移动撤销历史；此后不能用普通撤销改写行动前位置。目标悬停、切换选中、预览与镜头变化不清空历史。
- 若后续移动占据要回退的来源格，严格按 LIFO 先撤销后面的移动；不得覆盖其他实体。若其他状态变化让回退无法安全验证，则拒绝并展示原因，局面不变。
- 撤销是一条原子命令：恢复对应权威位置和该次移动机会，产生可回放事件并递增 revision；不能只回滚模型。暂停、动画播放、旧 revision、终局和非玩家回合拒绝命令。

### 3.4 行动与目标

- 已移动或尚未移动的机甲都可选择一种当前合法行动。先预览目标，再明确确认；鼠标、触屏、键盘和列表选择使用相同规则。
- 成功行动立即消耗行动与剩余移动机会，按已提交顺序结算伤害、护盾、推挤、建筑碰撞、状态与胜负，输出带因果顺序的事件。目标死亡或从范围消失时，以当前棋盘重新校验；非法或过期命令原子拒绝，不耗机会、不扣冷却、不输出假命中。
- 行动预览和正式执行调用同一规则核心；预览操作必须隔离输入状态、事件接收器和随机源，不提交、不泄漏副作用。证据不足时显示未知，不展示必然命中或碰撞。
- 受击及建筑碰撞采用 v1.5 建筑规则：伤害值 2；大怪 2×2 新进入范围内每栋活建筑最多受一次，多个建筑各计一次；受阻的被推单位留在原格。实际盾吸收、死亡与胜负顺序由权威事件证明。不存在连锁推挤或暗中修改其他伤害数值。
- 普通移动撤销不能撤销行动造成的状态、位移、死亡或冷却；如需回退，使用本局有限的回合重置。

### 3.5 结束回合、冷却与重置

- 结束回合允许有未使用的机甲机会；首次点击需明确列出仍可行动的存活机甲并确认放弃。全部行动或待机后可直接结束。不能因建议已经填充而把玩家未确认的行动自动执行。
- 敌方阶段执行一次：先处理现有环境/持续效果时机，再按当前规则执行敌方意图、死亡与胜负，再进行冷却、下一次敌方准备和玩家回合初始化。具体原有顺序以 v1.4 golden 和已发布特殊技能语义为基线；逐项写成事件顺序测试，禁止因重构静默变更。
- 每局一次「重置本回合」：仅在己方回合、终局前可用；清晰显示剩余次数和确认结果。将所有棋盘、状态、血量、技能冷却、敌意、建筑、生命周期、时间与确定性上下文恢复到本回合起始检查点，并保留已消耗的重置次数。重置本身产生新 revision 与可验证事件，不能重用旧 revision 或复制旧 commandId；不得将重置消耗回滚。第一版不支持敌方阶段或终局后重置。
- 重置后清空移动撤销栈、未确认目标、临时预览、动画残留和过期异步请求；展示恢复后的实际棋盘。若恢复检查失败，拒绝且不消耗次数。

## 4. 权威命令与一致性

采用版本化的显式命令，例如 `MoveUnit`、`UndoMove`、`ActUnit`、`EndPlayerTurn`、`ResetTurn`，每条携带 match identity、规则版本、base revision 和唯一 commandId。字段、数值边界和错误码以实施时冻结的 schema 为准；此处为语义而非现有 `mecha-net:v1` 的扩展许可。

- 所有命令在隔离状态上先校验再原子提交，失败不改状态、机会、日志或外部持久化。并发请求按会话串行处理；`baseRevision` 不匹配返回 stale，客户端重取状态后重新选择。
- 同一授权主体、同一 commandId 和相同内容返回原结果，不重复执行；同 ID 不同内容拒绝。状态、事件、历史和 commandId 结果必须在同一提交边界内一致；无法证明是否成功时显式显示待确认，不盲目生成新命令。
- 每个成功改变权威状态的命令 revision 恰好递增一次。攻击与其伤害、碰撞、状态、死亡和宣告更新属于同一次原子提交；顺序、因果关联和受影响对象必须在版本化事件中明确。
- 严格限制实体类型、棋盘坐标、事件数量和数据形状。技能效果继续经过规则权威，UI、AI、远端和渲染不得写入状态或决定结果。无完整证据时回放/预览明确不可用，不从状态差猜测因果。
- v1.4 `ArenaPlan` 依旧原子执行其历史语义；v1.5 不把多个即时命令拼成旧包，也不将旧包解释成逐台行动。失败、回滚、异常和跳过动画不能让状态和画面最终分叉。

## 5. 表现与交互

1. 部署和所有真实移动只从已确认的权威状态与移动事件驱动模型；移动有可跳过、可恢复的动画。动画中输入锁定或按稳定队列顺序处理，不能出现第二条命令作用于不可见的旧状态。
2. 草稿目标使用明确的路线、落点和“预览”文字；敌人当前意图与基于目标预览的预测用不同标识。攻击确认后播放真实结果，命中与被动推移同一因果阶段；受阻显示碰撞对象及双方血量变化。
3. 当屏幕模型尚在过渡时，点击识别不得按尚未显示或已失效的格子猜测；动画完成、跳过或窗口恢复后必须与最新权威快照收敛。同步血槽、地块检查、建筑、目标和终局。
4. 展示每台机甲的移动/行动剩余机会、当前选中、撤销可用性、回合重置次数、失败原因；无颜色视觉、键盘、触屏、减少动态效果均能理解并操作。
5. 3D 模型仅是表现。任何 UI 重建、掉帧或动画中断都不能改写状态、重复执行事件或改变命令顺序。

## 6. AI、回放与版本兼容

- 现有 AI 输出整队 `ArenaPlan`，不能直接当作 v1.5 的即时行动结果。第一阶段保留只读提示并默认禁用整队自动执行；后续 AI 必须输出有序命令，每次成功后基于最新权威状态重验，失败时停止并说明。不得静默把原 v1.4 计划换序提交。
- 新回放使用新 schema，保存规则版本、部署、回合内有序命令（含撤销/重置）、必要的确定性输入、revision/命令标识和最终摘要；重建时逐条执行并核对事件与最终摘要。不得只保存最终棋盘或把逐条行动压成 `ArenaPlan`，也不得保存 City 日志、提示词、路径或凭证。
- 保留 v1.4 回放的旧解释器和旧 collision 行为；v1.5 回放由 v1.5 实现重建。不可验证、缺版本、损坏或不兼容的记录明确提示，不伪造成功。挑战码需要新的 schema/规则实现版本；旧码继续由 v1.4 路径处理或明确提示不兼容。
- 涉及的桌面 Rust 回放存储验证器须先支持新 schema 和限定版本；旧验证不能仅放宽为任意字符串。v1.5 新对局不能依赖只接受 v1.4 的存储而假装保存成功。
- **首发范围：本地 PvE。** 暂不启用 v1.5 远程和 PvP；入口明确说明不可用，不能偷偷创建 v1.4 房间替代当前局。之后须为新命令建立显式协议/能力版本、权限、去重、状态投影和逐请求授权；新旧不兼容必须拒绝。现行 Rust 网关、host/client 固定 v1.4 的检查应保留，直到新版本完成端到端验证。不得扩大远程数据字段或绕过匹配范围与用户授权。

## 7. 实施步骤与验收门

### A. 基线与契约

冻结当前 v1.4 对局、事件、预览、回放、远程合同；确认 v1.5 尚未外发。定义 v1.5 状态机、命令/事件、collision 和可恢复检查点，确认旧 `matchFromSite`、`pveRules`、回放、怪物 catalog、挑战码和 Rust 网关各自的版本职责。新增跨版本拒绝和旧数据基线测试。

### B. 纯规则与会话

实现逐条命令及事件，以真实顺序即时结算、撤销和回合重置；复用现有移动、伤害、碰撞和怪物规则但不复制整套战斗逻辑。局面、事件和 checkpoint 必须可重放。新旧规则通过显式规则适配分流，不隐式变更 v1.4。

### C. 本地交互与表现

接入移动、目标确认、行动、撤销、重置及未行动确认；重构当前草稿投影和 `CityMechaWorld` 播放协调。开局不自动执行 AI 建议。浏览器与打包 `.app` 均检查模型、实际棋盘、选择、受击推移和伤害显示一致。

### D. 存档和安全发布

实现版本化本地回放、旧数据兼容和 Rust 存储验证；禁用或明确拒绝未支持的 v1.5 远程、PvP 和挑战码。完成全量机甲验证和真实桌面包冒烟，才将产品默认入口切至 v1.5；开发浏览器预览须显式显示版本。

## 8. 验收矩阵

| 场景 | 必须满足 |
| --- | --- |
| 部署 → 玩家移动 | 部署后模型在原格；点击合法格后权威与模型都到目标格，只消费移动机会 |
| 交错顺序 | A 移动、B 移动、A 攻击、B 攻击严格按玩家输入，后续合法性基于即时局面 |
| 撤销 | 多台移动按 LIFO 撤销；移动后切换选择不清空；任一已提交行动后普通撤销不可回退历史 |
| 占位与非法操作 | 当前目标已被占、地形不通、超范围、死亡、冷却、旧 revision 均原子拒绝，不消耗机会 |
| 因果与碰撞 | 推敌撞楼双方受伤，多格建筑一次、多栋分别、盾吸收、撞死/守楼失败均与事件、血槽及预览一致 |
| 行动与重置 | 攻击不可普通撤销；一次回合重置恢复完整状态且保留重置消耗；第二次和终局后拒绝 |
| 结束回合 | 未行动时确认放弃；敌方阶段恰好运行一次、状态和冷却顺序正确 |
| 特殊技能 | 位移、盾、蚀格、召唤、神经链接与无证据降级、目标失效、连带伤害均有序且可回放 |
| 可靠性 | 重复/冲突 commandId、乱序/迟到命令、断连、重试、动画跳过/中断不重复执行并最终收敛 |
| 版本与回放 | v1.4 既有回放逐字节/行为基线不变；v1.5 命令序列可重建；跨规则和旧客户端明确拒绝 |
| UI 与无障碍 | 中英文、鼠标/触屏/键盘、缩放与减少动态效果可完成操作；画面、拾取、状态、血槽一致 |
| 测试面 | `npm run typecheck`、`verify:mecha`、`verify:mecha-clarity`、怪物/特殊效果/远程测试，浏览器合成与真实 Tauri `.app` 走查 |

## 9. 待实施前确认的产品参数

本规格确定交互方向；不静默决定新增付费、联网或数值。实施前须记录：多台机甲移动是否允许穿过尚未移动的友军；回合重置的首次使用是否需要确认弹窗；v1.5 是否在首发启用现有救援/怪物练习；以及保留旧回放解释器还是对无法安全支持的旧记录明确降级。若尚无决定，默认沿用已有规则、保守拒绝不明确操作，并将未完成范围列为发布阻塞，不通过跳过测试掩盖。


## 10. 实施进度（2026-11-06）

已加入实验性逐台行动内核与本地控制器：支持显式部署、即时移动与行动、LIFO 撤销、每局一次重置、结束回合确认及敌方阶段；命令带 revision 和去重标识，预览在隔离的重建会话运行。城市战场转换器支持显式选择 v1.5，默认仍为 v1.4。

已接入开发环境测试界面：显式使用 `?mechaV15=1` 才进入 1.5 本地测试，可部署、逐台移动和行动、预览、撤销、重置及结束回合；界面明确提示远程和挑战码不可用。该入口不会启用怪物遭遇点或替换正式入口。演出健康证据不足时明确要求查看权威结果，不伪造演出。

已有版本化回放封装，保存部署、匿名命令和摘要，加载时重建部署并逐条校验；开发界面可在本机保存、读取、逐步播放和删除，也可从未结束的已保存记录恢复对局。恢复时重建撤销栈、行动机会、回合检查点和重置消耗，失败不替换当前对局。逐条结算现在采集权威演出阶段，播放前核对阶段边界、伤害和特殊事件；重置即时显示恢复棋盘，证据不足时显式降级。桌面宿主按版本隔离 SQLite 存储并对形状、坐标、目标、版本和大小做闭合校验；恢复时仍由规则解释器核验摘要。浏览器刷新恢复和宿主单元测试不等于真实桌面包验收。

开发测试入口已接入自动检查点：部署和每条命令先持久化并回读确认，再公布权威状态；存储确认不明时锁定并要求重新读取。浏览器 IndexedDB 与桌面 SQLite 使用独立槽位和递增版本比较，显式清除后版本不回退，避免旧窗口覆盖。重启后须由玩家选择恢复或删除检查点；已结束或不兼容的检查点不会静默覆盖。浏览器刷新测试不等于真实断电或桌面包验收。

撤销和重置已产生独立的 `mecha-sequential-event:v1` 因果事件，包含命令、版本和对应坐标或检查点版本；保存前重算并核对事件，回放则从已验证的有序命令重新生成，不改变旧战斗事件格式。界面支持棋盘目标高亮、目标切换、明确确认、跳过演出和系统减少动态效果设置；普通构建仍不会开放此入口。独立的 macOS 探针构建只对独立合成数据视图允许测试入口。

自动检查点的命令现使用与归档一致的规范 ID，并拒绝不符合该序列的写入；恢复后用同一 ID 重试会返回已提交结果，不再次写入。此前试验构建中已经丢失的原始内存 ID 无法追溯，不能对其确认丢失的请求声称跨重启幂等。
