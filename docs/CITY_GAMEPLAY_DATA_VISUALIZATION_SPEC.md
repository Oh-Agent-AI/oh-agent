# Agent City 游戏设计文档（GDD）

版本：4.1 · 日期：2026-10-20 · 状态：基础玩法原型开发基线；未完成实机与平衡验收

## 1. 本版决策与产品定位

**Session 建筑收租，收入用于升级市政建筑、道路工程、汽车和飞机。** 用户日常 Agent 活动成为个人城市的资产与记忆，玩家用经营所得建设城市并享受驾驶和飞行。

本文整体替代 v3.1 的角色/社会剧情优先方案。基础循环不依赖模型、Session 摘录、NPC、问答或生成剧本。角色、租户模拟、Findings 剧情与模型对白均为后续可选扩展，不再是首版任务或验收前提。“机师阿岚”仅是早期创意示例，不是标准内容产能承诺。

面向工作后希望轻松建设、探索和驾驶的 Agent 用户，每次约 15–30 分钟。体验承诺：**“我的工作积累变成了一座城市；我修得通道路，也开得上喜欢的车。”** 不将金币等同真实费用，不鼓励增加 token 消耗。

相关规格：[City 模块](CITY_MODULE.md)、[城市架构](CITY_ARCHITECTURE.md)、[共享游戏基础](CITY_SHARED_GAME_FOUNDATION_SPEC.md)、[驾驶参数](CITY_DRIVING_RACING_GAME_PARAMETERS.md)。本文提出的功能均需开发前核对现有能力。

## 2. 核心循环与选择

```text
Session 建筑 → 累积租金 → 一键收取金币
                               ↓
           市政升级 / 道路工程 / 载具升级 / 商店装修
                               ↓
        更多经营容量 / 可通行新路线 / 更好的操作体验
                               ↓
              体验成果，选择下一项建设目标
```

四类资金用途竞争同一个钱包：市政投资偏长期经营，道路工程提供新的空间与路线，载具升级提供即时操作乐趣，商店装修提供个人审美表达。首版不设计唯一最优投资顺序，不让市政复利压倒所有其他选择。

收租是基础收入；少量人工配置的驾驶/飞行挑战提供可选主动收入，避免只能等待。挑战不是进入经营的强制条件。没有新增 Session、没有模型、只有一种 Harness，都可以继续成长。已有基础车辆与自由驾驶/飞行保持可用。

## 3. Session 建筑与收入资格

事实身份和经营状态分离：标题、时间、token、费用来自真实数据；租金、等级和金币属于游戏。经营升级不改变事实楼高，不把高费用会话解释为更有价值。

首版采用经营容量控制，而非按全部历史楼数无限产币：市政厅 L1 提供 4 个收益槽，L2 提供 6 个。玩家选择建筑加入收益槽；同级建筑基础租金相同。全城所有建筑仍可浏览，不要求删掉超出容量的建筑。

- 新存档可自动推荐最多 4 栋真实楼，玩家可更换；不足部分由明确标注的公共游戏物业补足，收益相同。
- 新 Session 增加选择与个人记忆，不直接赠送金币或扩张收益槽。
- 更换经营楼先按原状态结算，再激活新楼；不转移历史收入或重置领取状态。
- 时间窗口变化不影响收益资格，离开当前视图的经营楼仍列在资产面板。
- 数据删除后清除个人关联，经营槽可转为通用物业，保持游戏进度且不重复赠送。
- 使用稳定的应用作用域资产身份，不以标题、可变地图坐标或临时投影句柄直接作为永久存档主键；需要宿主提供受控身份映射。

## 4. 收租与经济规则

### 4.1 首轮可调参数

以下为原型调参起点，不是已验证的平衡结果。

| 参数 | 初值 | 用途 |
| --- | --- | --- |
| 启动金币 | 300 | 首次即可作一次实际投资 |
| 单收益槽租金 | 10 金币/24 小时 | L1 的 4 槽共 40/日 |
| 未领取累积上限 | 72 小时产量 | 在线与离线同一规则 |
| 普通挑战基础奖 | 40 金币 | 约 3–5 分钟，首版可选补充收入 |
| 市政厅 L2 | 240 金币 | 收益槽 4 → 6 |
| 首个道路工程 | 160 金币 | 一条明确的新支路/捷径 |
| 车库或机库 L2 | 各 100 金币 | 开放对应 L2 配件目录 |
| 单项 L2 配件 | 80 金币 | 购买可实际使用的升级 |

市政厅容量升级不同时增加每槽倍率。首版没有利息、负债、维修罚款、燃油费用、付费货币或随机抽卡。长期消耗为更多工程、有限等级配件和装修，不靠无限指数升级制造内容。

金币用定点数计算并保存余数，避免频繁结算损失；显示可领取整数。累积入待收余额，一键领取才进入钱包。未领取余额不超过当前规则的上限；容量变化先按旧规则结算，再开始新时段，不追溯重算。

### 4.2 时间与防重复

首次激活从当前时刻开始，不追溯 Session 历史。UTC 墙钟负责租金，挑战计时用单调时钟。保存结算水位、余额、余数与规则版本；时间倒退不产出，异常前跳最多累积上限且不重复领取。单机不承诺完全防改时钟，不新增网络反作弊。

到达上限后推进结算水位，超额时间不留待下次补领。领取只移动余额，不重算已结算时段。市政升级、经营楼更换、重启与多窗口领取都不能制造重复收益。离线不扣费、不损坏建筑。

可选挑战以稳定 runId 结算；最近六次同任务模板的奖励比例为 100%/50%/25%/25%…，不同模板按各自出现次数计算，重启不清零。实际配置需检查重复刷取与无聊劳动，不按真实会话多少增加挑战收益。

### 4.3 数值例与取舍

4 槽离线 48 小时可领 80，上限 72 小时为 120。启动 300 可以选择：市政厅 L2 后剩 60；道路工程后剩 140；车库 L2 加一项配件后剩 120。

市政 L2 增加 20/日，纯租金回本为 12 日；这是待测试的长期投资基线，不是强迫玩家等待 12 日才能玩。短期建设依靠启动金和可选挑战。若测试发现市政不值得或主动任务完全淹没租金，调整成本与节奏，不直接无限叠加收益倍率。

## 5. 市政建筑升级

| 建筑 | 初始状态 | 首版 L2 效果 | 世界反馈 |
| --- | --- | --- | --- |
| 市政厅 | L1，4 收益槽 | 6 收益槽 | 建筑展示变化、经营资产栏扩展 |
| 车库 | L1，可用基础汽车 | 开放汽车 L2 配件购买 | 配件预览、试车入口、外观标识 |
| 机库 | L1，可用基础飞机 | 开放飞机 L2 配件购买 | 配件预览、试飞入口、外观标识 |

道路工程不要求先升级市政厅，避免只有一条投资顺序。升级目录已拥有项不可重复扣款，解锁配件和购买配件分开显示总成本。不增加无实际效果的公共服务占位建筑。市政厅 L3、其他市政服务及建筑经营等级在首轮验证后扩展。

## 6. 道路工程

首版只做 2 个预设工程点，不做任意画路和实时全城规划：一个陆地支路/捷径，一个通过预检的连接工程；桥梁仅在完整几何、碰撞和路面验证通过后才可列入工程目录，否则使用陆地连接方案。

工程点使用明确的游戏规划用地和施工标识，预览价格、路线变化与连接目标。首版道路提供空间价值，不另加租金倍率。现有基础路网应可用，不能为了收费故意封掉已有正常道路。

**程序 bug 必须免费修复。** 桥头高度错误、碰撞包围盒过宽、原有高架无法通行、规划不连通不能包装成收费修路。游戏中的待建工程必须是设计明确、可完成的额外建设内容。

流程：候选工程预检 → 预览 → 预留资金 → 安全时机应用世界变更 → 校验成功并确认扣费。应用失败回滚并释放预留资金。不得在车正经过的区域切换几何。验收包括路面连续性、双向驾驶、净空、碰撞、出生点、层间连接和相关审计；不以截图代替通行测试。

## 7. 汽车与飞机升级

升级使用现有车辆控制器的有界配置，物理实现不由商店另建一套。首版每类载具两个升级项、每项 L1–L2，单项最多一档增益；下面百分比是候选值，验证失败则缩小或撤回该项。

| 载具/项目 | 候选 L2 效果 | 必须保留的限制 |
| --- | --- | --- |
| 汽车动力 | 加速度提高约 10% | 初期不提高最高速度，不削弱连续碰撞 |
| 汽车操控 | 转向响应时间缩短约 10% | 保持稳定性与转向限幅，禁止跳变航向 |
| 飞机动力 | 同条件爬升能力提高约 10% | 依现有飞行动力学实现，保持飞行包线 |
| 飞机操纵 | 操纵响应时间缩短约 10% | 保持角速度限幅、相机与输入稳定 |

若现有控制器不支持某参数，先完成技术设计和校准，未完成前不出售。升级前后用同场景固定输入比较，玩家可预览并在临时试驾中体验；试驾不写入购买状态。

玩家可免费切回已拥有配置。配置切换在停车/暂停或安全重入时生效。提高性能不能使汽车穿墙、飞机绕过碰撞，也不能把基本可用操控作为收费升级。审计使用标准配置；额外验证最强合法配置在 30/60/120Hz 的稳定性。奖励赛如涉及成绩必须记录配置版本。

### 7.1 商店与建筑装修

商店增加独立的外观商品目录，与性能配件明确分区。玩家用城市金币购买建筑涂装、墙面喷绘等内容，形成“收租 → 购买喜欢的装饰 → 装修建筑 → 驾车欣赏街区”的支线。外观不增加租金或车辆性能，不成为经营必需品，不使用大模型生成。

| 商品 | 应用方式 | 首轮范围 |
| --- | --- | --- |
| 建筑涂装 | 指定建筑外墙配色 | 一种经核验的海滨酒店模型，三套配色（含免费原色） |
| 墙面喷绘 | 预设墙面槽位放置预制图案 | 两款图案：海浪、棕榈；一个墙面槽位 |
| 招牌套装 | 替换兼容的入口/屋顶装饰 | 后续扩展 |
| 灯光套装 | 调整装饰灯配色 | 后续扩展，不覆盖数据状态灯 |
| 载具涂装 | 汽车/飞机兼容部位换装 | 后续扩展，与性能配件分离 |

购买为永久解锁、可反复使用，同一存档的所有兼容建筑均可应用；免费恢复原色和切换已拥有款式。不按每次喷涂消耗道具，不重复出售已拥有商品。原型价格：额外配色每套 40 金币，喷绘每款 60 金币；只是调参起点。启动 300 购买一套配色与一款喷绘后剩 200。

交互：选中酒店 → 装修 → 选择配色/墙面图案 → 昼夜预览 → 确认购买 → 应用。商品卡展示价格、已拥有状态、适用模型和部位；无兼容目标时不允许购买并说明。取消预览恢复原状态且不扣钱，购买与应用是独立状态，购买后暂不应用仍保留权益。

首轮不做自由涂鸦、任意位置喷射、图片上传或动态生成贴图。现有酒店分类/模型不保证可独立换材质：开发先核验酒店实例选择、UV/墙面分区、合批与实例材质隔离。若当前种子没有兼容酒店，功能显示未就绪；先制作确定性酒店测试场景，再决定正式城市接入，不以贴图缩略图当作已支持。

### 7.2 渲染与保存契约

- 定义稳定商品 ID、版本、兼容模型、装饰槽位和预制资源；购买只接受商品目录白名单。
- 存档分开保存 ownedCosmetics 与 buildingDecorations（稳定资产 ID、模型/槽位、配色与图案 ID）。同款多建筑复用，无逐建筑重复收费。
- 预览使用临时覆盖，退出/取消清除；正式配置仅经确认保存。钱包扣款与商品所有权原子提交，应用失败不丢失已购权益。
- 实例化/合批材质不能改一栋导致整批变色；贴花须避免闪烁、背面穿透、覆盖窗户和脱离墙面。
- 装修不改变碰撞、路面、建筑体量及数据楼高；保留必要的 Harness、选中态和异常状态识别。
- 刷新、切时间窗口、重新布局后按稳定身份恢复；模型换型不兼容时暂停装饰并保留权益，恢复原材质，不错误应用到另一栋楼。
- 资源使用本地打包预制素材，贴图数量、显存与 draw call 在目标设备测量；性能不通过先缩减商品/槽位，不无限复制材质。

## 8. 首次 15–30 分钟体验

1. 识别几栋自己的 Session 建筑，查看收益资产与租金来源。
2. 获得启动金币，理解市政、道路、载具和装修四种投资的区别。
3. 选择第一笔投资，不强制统一教程购买路线。
4. 如果修路，亲自驶过新路线；如果升级载具，进入对照试驾；如果升级市政，增加两栋收益楼并预览日产变化；如果选择装修，在酒店昼夜预览后应用喷绘，再驾驶经过欣赏效果。
5. 自由驾驶或完成一个可选挑战，查看账本和下一项可负担目标。
6. 退出保存，下次回来查看累积租金。

不需要 NPC 对话、生成脚本、完整会话摘录或答题。离线收租用可控测试时钟验证，不要求玩家现场等待。首次结尾让玩家自行提出下一项建设愿望。

## 9. 数据与技术架构

```text
已有领域查询 → 注册的 City 投影 → 稳定建筑身份与展示
                                      ↓
玩家命令 → Economy / Municipal / RoadWorks / VehicleUpgrades / Cosmetics
                                      ↓
                 原子游戏存档与变更协调器
                                      ↓
             共享 GameRuntime / 世界与载具适配器 / UI
```

数据查询复用现有业务逻辑，不复制成本策略。City 插件不读 DB、日志或任意 SQL。标题缺失用明确的通用标识，不猜测任务结果。租金与真实账单完全分离。

规则层独立于 CityEngine 和帧循环；注册的宿主存储接口执行写入。世界工程用可恢复操作记录协调存档与场景应用：prepared/applied/committed/rolled_back，加载时完成恢复，不出现扣钱但道路永久丢失。

存档至少包含 save/schema/rules 版本、revision、模式、金币与待收租金、计时余数和水位、收益槽与稳定资产映射、市政等级、工程操作记录、已购配件与当前配置、已解锁外观与逐建筑装饰配置、挑战结算标记和有界账本。多窗口写使用预期 revision。

导入、改窗口、换地图种子不重置钱包；工程与建筑重排须迁移到合法位置，无对应位置时禁用并说明，不能复制工程奖励。personal/demo 隔离。存档迁移失败保留上一个有效版本。完整游戏重置与分析数据删除分开处理。

## 10. 界面与体验反馈

主要入口：收租总览、建设目录、车库、机库、道路工程地图和装修商店。收租显示产出速度、累计时长、上限、资产贡献；购买显示总成本、已解锁/已购买/已装备状态和效果预览。

每次投资既有数据反馈，也有使用反馈：新收益槽、可驶过的路、可感知的加速/操纵差异、指定酒店的涂装变化。首版可使用轻量外观变化，不承诺人群仿真。失败说明原因并提供恢复，不只显示内部错误码。

暂停与退出不产生经营惩罚。施工应用等待安全状态时可取消。少数据用户可完成全部基础循环；操作困难者无需挑战也能靠租金推进。默认天气不因真实 Findings 惩罚驾驶。

## 11. 《游戏设计艺术》视角与验证

以下为项目应用，不是书中原文或固定评分标准。

| 视角 | 本版检查问题 | 最小验证 |
| --- | --- | --- |
| 核心体验 | 工作积累是否带来拥有感？ | 玩家能认出自己的建筑并提出建设目标 |
| 玩具 | 没有金币时驾驶和探索是否好玩？ | 5 分钟无奖励自由体验 |
| 有意义的选择 | 三类投资是否有真实差异？ | 玩家能够解释取舍，不是都被迫先买同一项 |
| 四要素 | 机制、故事、美学、技术是否一致？ | 真实 Session 提供背景，工程与配件提供规则，音画表现变化，技术保证可用 |
| 经济与平衡 | 收租与主动玩法是否相互补充？ | 比较只收租、只挑战、混合三种策略 |
| 反馈与存在感 | 花钱后是否立即理解改变了什么？ | 关闭面板后体验新路/车辆，市政展示明确收入预览 |
| 迭代 | 最大风险是否先验证？ | 先做单循环，不以增加剧情与模型掩盖乏味 |

两条主要失败处置：若升级无感，先修效果与表现；若只能等钱，调整启动/租金/任务节奏。不能靠要求更多真实 Agent 使用或增加抽卡刺激补救。

## 12. 测试与定稿门禁

### 12.1 必过规则与实机测试

- 重复领取、重启、并发、时钟倒退/前跳、容量切换：不双计、溢出或追溯增发。
- 余额不足、重复购买、事务中断：无部分扣款，权益与账本一致。
- 数据缺失/删除、改窗口、地图重建：经营身份可解释，游戏不依赖摘录。
- 道路工程应用失败、应用时退出：可恢复或退款，不留下无路面碰撞体。
- 每个工程双向实驾；每项升级固定输入对比；最强配置与标准配置均验证碰撞及帧率稳定性。
- 无模型、无网络、单 Harness、少量会话：完整基础循环可用。

固定种子模拟至少 1,000 条经济行为序列，覆盖不同资产数量、只收租/只挑战/混合策略和投资顺序，报告首升时间、余额分布、不可达状态及主导策略。计算正确不等于游戏有趣。

装修专项验收：购买重试只扣款一次；取消预览无变更；同款可用于两栋兼容实例且互不串色；未拥有款式不能绕过校验应用；重启/切窗口后保留外观；模型不兼容诚实降级；昼夜及近远视角不闪烁/穿透，碰撞与数据识别保持正确。应用故障保留权益并允许恢复原色。

### 12.2 玩家测试

先 3–5 人发现问题，再 8–12 人验证修订。目标比例向上取整并记录实际人数；仅为初步验收，不宣称统计显著。使用知情的本地记录/访谈，无后台遥测。

- 至少 80% 独立完成收租/购买/体验闭环，并区分金币与真实费用。
- 至少 70% 能说明市政、道路、载具与装修投资的不同收益；能识别装修不增加收入或性能。
- 至少 60% 在无奖励阶段主动驾驶或探索；至少一半提出具体下次目标。
- 三种首投路径都可继续成长；载具升级盲测或同条件比较能被辨认，不能只靠面板描述。

当前只可定稿为原型开发基线。玩法最终冻结需要规则测试、道路与载具实机测试、玩家测试共同通过。目标设备、规模和性能预算在实现前记录；未实测不能宣称完成。

## 13. 交付顺序与首版预算

| 阶段 | 交付 | 完成门槛 |
| --- | --- | --- |
| P0 经济纸面/纯规则原型 | 租金、购买、三条投资路径、配置表 | 数值算例与异常时间测试通过 |
| P1 收租与市政 | 钱包、4→6 收益槽、市政 L1–L2、稳定身份、存档 | 重启与数据窗口变化不丢进度 |
| P2 车库/机库与升级 | 两设施 L1–L2、车/飞机各两项配件、试驾 | 有可测差异，物理与碰撞回归通过 |
| P3 道路工程与完整试玩 | 两个预设工程点、2–3 个可选人工挑战 | 完成 15–30 分钟闭环与真人测试 |

增加 P3 装修子交付：一个经过模型核验的酒店类型、三套配色（含免费原色）、两款喷绘、一个预设墙面槽位、昼夜预览和权益保存。先完成模型适配检查再出售，和基础收租/市政交付解耦，不阻塞 P1。商场可作为未来世界内商店入口；首轮使用面板入口，不要求先开发商场等级或室内场景。

首版不需要新 NPC 系统、新模型运行时、动态编剧、完整社会模拟、任意道路绘制或随机商城。地图规模沿用现有城市，不为首版要求重做全城布局。工程接入能力不足时先完成一个可验证陆地工程，再扩第二个，不能用占位按钮充数。

## 14. 后续扩展与变更控制

后续可逐步增加其他市政建筑、更多有限等级载具配件、更多建筑适配与招牌/灯光/载具涂装、游艇、租户事件。角色/Session 故事需要先改善素材质量，再验证额外价值；模型最多先润色固定事件的开场/结束文本，不改变任务目标、奖励和结果。无模型始终可玩。

现有离线数据政策保持：不上传个人数据，不向插件开放原始日志、路径或任意 SQL。未来云端生成需要独立产品决策，本方案不作授权。

冻结基础方向：收租、市政、道路、汽车和飞机升级，以及有限范围的商店装修。可调：价格、产量、容量、性能增益。延后：角色关系、社会仿真、抽卡、生成剧情。每次修改记录证据、预期效果、规则/存档影响和复测结果，不以添加新系统替代验证已有循环。
