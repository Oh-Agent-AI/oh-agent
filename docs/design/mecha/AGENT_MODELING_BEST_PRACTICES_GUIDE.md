# Agent 建模最佳实践指南

**版本：** 1.0  
**日期：** 2026-10-30  
**适用范围：** AI Agent 制作实时 3D 角色，尤其是需要分件、绑定、动作、压缩并进入游戏运行时的机械角色  
**依据：** Khronos、Blender、meshoptimizer、three.js 官方资料，以及 Codex 与 Claude Code 最新建模会话的对照分析

> 本指南补充项目现有《Oh Agent City 3D 角色资产创建方案》。具体角色的视觉、尺寸、动作和性能合同仍以[项目资产方案](./2026-10-26/MECHA_3D_CHARACTER_ASSET_PIPELINE_SPEC.md)为准。

## 1. 核心原则

Agent 建模的目标不是“生成一个看起来像模型的文件”，而是交付一个**外观可辨、结构可靠、动作正确、运行时兼容、结果可复现**的资产。

1. **先定义验收，再开始建模。** 面数、体积、节点和动作数量只是合同的一部分，不能替代视觉与动态质量。
2. **保留源资产，候选与正式资产分离。** AI 高模、Blender 源工程、试验 GLB 和正式 GLB 是不同的交付层。
3. **按模型来源选择路线。** 结构化手工模型适合删除结构细节；AI 碎三角网格通常需要分件、修复、减面和重新烘焙。
4. **几何负责轮廓与运动，贴图负责平面细节。** 不用实体几何堆积文字和板缝，也不用贴图掩盖关节或轮廓缺陷。
5. **静态正确不代表动态正确。** 能加载、无开口、不穿地，都不能单独证明跑步不浮空、关节不脱节或攻击能命中。
6. **规则状态与演出状态分离。** 动画只能呈现规则已接受的事件，不能决定命中、伤害、占格或胜负。
7. **每轮试验留下证据并可回滚。** 保留基线、变量、指标、截图、报告和保留/撤回决定。
8. **不把候选称为成品。** 明确区分草稿、候选、已接入和已验收。

## 2. 开始前的资产合同

Agent 必须先写出资产合同；缺失项应标为假设或待确认，不能静默编造。

### 2.1 视觉合同

- 角色必须保留的剪影、比例、配色、标识和装备。
- 正面、侧面、背面、3/4 视图及必要的顶视图。
- 实际游戏视距、近景视距、镜头角度、昼夜和背景条件。
- 低多边形、写实、硬表面等风格，以及允许的切面程度。

### 2.2 结构合同

- 坐标系、单位、朝向、原点和脚底基准。glTF 使用右手坐标系、Y-Up，并以米为单位。[R1][R2]
- 战场占格、根节点所有权、视觉节点允许改变的局部范围。
- 活动部件、机械轴心、滑轨、连接面、装备挂点和不可删除的承重件。
- 稳定节点命名、材质命名、动画片段命名和实例化要求。

### 2.3 性能与交付合同

至少记录以下指标的目标或“待实测校准”：

| 类别 | 指标 |
|---|---|
| 几何 | 三角面、顶点、网格/primitive 数、实例数 |
| 渲染 | 材质数、绘制调用、透明材质、实时阴影成本 |
| 纹理 | 图集数量、分辨率、纹素密度、文件体积、GPU 内存 |
| 动画 | 片段、轨道、关键帧、时长、帧率、循环方式 |
| 文件 | GLB 大小、扩展、解码器、加载时间 |
| 运行时 | 目标设备、帧率、实例规模、昼夜和地形场景 |

**禁止把其他角色的面数直接复制为预算。** 3.5k 对某台结构模型可能足够，对另一台 AI 网格可能意味着关键机械结构消失。

## 3. 选择生产路线

| 路线 | 适用输入 | 主要优化手段 | 主要风险 |
|---|---|---|---|
| 结构化建模 | 手工、程序化、CAD 风格模型 | 删除倒角和小件，减少圆柱分段，平面细节贴图化 | 删除连接件、轮廓损失、低边轴毂内切半径缩小 |
| AI 网格整理 | 高密度碎三角、自动绑定或自动减面结果 | 分件、拓扑修复、选择性镜像、分档减面、重新烘焙 | 非流形、碎壳、错误法线、姿态不对称、跨肢体错绑 |
| 混合路线，推荐 | 外观较好的 AI 初稿与明确机械合同 | 保留视觉基线，重建关键关节和部件，按运行时合同接入 | 工作量较大，需要同时管理源模型与结构化部件 |

选择路线后先做一个代表角色。若修复 AI 网格的成本持续高于重建，应改用结构化建模，AI 仅保留为视觉与贴图参考。

## 4. 标准生产流程

### 阶段 0：冻结基线与完成定义

1. 保存原始模型、参考图、来源、许可、生成服务及版本。
2. 导出基线 GLB，记录尺寸、面数、材质、贴图、节点、动画和体积。
3. 渲染统一机位的正面、侧面、背面、3/4、实际游戏视距图。
4. 列出不可退化的关键部位：轮廓、关节圆轮、拳、脚、装备接口、标识和动作接缝。
5. 定义本文第 7 节的阶段门和证据。

**阶段门：** 后续每个候选都能回答“相对哪个基线、改变了什么、哪些指标改善、哪些指标退化”。

### 阶段 1：按运动功能分件

将模型划分为：

- 刚性件：装甲、盾、炮、外壳、机械拳。
- 柔性件：仅确有需要时采用蒙皮变形的区域。
- 关节件：旋转轴、轴毂、滑轨、活塞和连接面。
- 功能件：武器挂点、维修工具、无人机、传感器。
- 接地件：脚底和用于判定接触的参考点。
- 装饰件：可以贴图化或删除，但不能承担结构连接。

机械装甲优先使用刚性节点；柔性蒙皮只用于真正需要变形的区域。每个活动件的原点位于机械轴心或滑轨基准，而不是默认网格中心。

**不要仅凭“看不见”删除零件。** 颈架、内圈和连接件在静止视角可能不可见，在动作中却可能承担连接或遮挡作用。

### 阶段 2：逐件修复拓扑与法线

先报告，再修复。每个部件至少统计：

- 连通壳、开口边、非流形边和非流形顶点。
- 碎壳、重复面、零面积面、细长三角面。
- 自相交、朝内面积、异常边界和部件间距离。

推荐顺序：

1. 删除无功能碎壳和重复面。
2. 处理退化面与明显碎片。
3. 修复非流形边、顶点和局部错误连接。
4. 对无法直接补洞的区域进行局部重铺，避免无限重复同一补洞操作。
5. 补洞并逐连通壳校正朝向，再复查全件。
6. 重新运行动作，检查修复是否暴露或制造关节问题。

Blender 提供面朝向显示、翻转和重新计算法线工具；但“重新计算”不会替代对多壳、自相交和自定义拆分的检查。[R6]

**阶段门：** 无意外开口、非流形和反向壳；双面渲染不得被用来掩盖法线错误。合理保留的叠压、自相交或开放件必须登记原因和视觉影响。

### 阶段 3：选择性镜像与实例化

只有以下条件同时成立时才镜像：

- 几何形状应对称。
- 原始静止姿势和关节坐标也对称。
- 标识、UV、材质和装备接口允许复用。
- 镜像后在完整动作范围内仍保持连接。

躯干和头部的对称化通常应在减面前完成，避免减面后中线拼缝碎裂。左右形状相似但姿势不同的肢体不得直接互相替换。

关节验收应排除轴毂等装饰遮挡，直接测量两侧功能网格或连接面的距离。相同几何可使用实例化降低重复数据，但动态 AO、独立损伤和独立材质状态可能需要单独处理。[R2]

### 阶段 4：分档减面，而非一次压到目标

1. 从当前基线制作至少两个候选，例如约 2/3 与 1/2 面数。
2. 优先处理平坦区域内部碎面、不可见小件和不影响轮廓的几何。
3. 用顶点组或独立部件保护肩甲外缘、胸甲折线、关节圆轮、拳脚、装备接口、UV 缝和材质边界。
4. 每档重新检查多视角近景、实际视距和完整动作。
5. 选择满足质量的最低成本候选；若低档损伤关键结构，恢复局部基线网格。

Blender Decimate 支持对称、顶点组权重，以及 Planar 模式下按法线、材质、UV 缝和锐边限制溶解，适合执行区域化减面。[R4]

同时记录平均偏差、P95 和最大偏差，但不能只凭这些数值决策。**平均表面误差很小，也可能同时丢失一个膝轮或一条标识。** 关键特征清单和近景图是必需证据。

### 阶段 5：UV、烘焙与材质

#### 几何与贴图分工

| 保留几何 | 优先贴图化 |
|---|---|
| 改变剪影的装甲和武器 | 文字、编号、徽记 |
| 机械轴、活塞、关节轮廓 | 板缝、细条纹、通风格栅 |
| 手、脚、装备接口 | 不改变命运的小表面起伏 |
| 动作中改变遮挡关系的部件 | 游戏视距下不可辨的微细节 |

#### 烘焙与 UV 要求

- 从高细节源模型向低模烘焙，保留细节来源，不凭空重画关键标识。
- 检查射线方向、最大距离、cage 和遮挡，避免底层薄壳污染表面。
- 跨面标识逐面检查，尤其是法线改变和低模面交界处。
- 保持合理纹素密度与 UV 岛边距，为过滤和 MIP Mapping 留 padding。[R2][R5]
- 唯一图集通常使用 0–1 UV；重复纹理和有意共用 UV 应明确记录。
- 动画模型使用切线空间法线图时，烘焙与运行时的空间约定必须一致。[R5]
- 活动部件之间的 AO 可能随动作失效，不能把静态接触阴影当作始终正确的动态光照。[R2]

保留无损主纹理，再按目标生成 WebP、KTX2 等交付版本。**WebP 主要改善传输与文件体积；GPU 压缩纹理还影响显存，二者不能只按文件大小比较。**[R2]

### 阶段 6：绑定、动作与接触

1. 按真实静止姿态和机械截面确定轴心，不直接复制另一台模型的动作数值。
2. 区分原地动画与游戏世界位移；角色根节点位置由规则或移动系统拥有。
3. 循环动作检查首尾姿态；glTF 不定义跨片段混合，混合由运行时引擎实现。[R2]
4. 交叉淡化必须同时检查命中时刻、支撑脚和速度峰值，不能默认“加 0.15 秒混合”就是修复。
5. 攻击按预备、发力、接触、回收检查；接触帧必须能映射到战斗事件。
6. 行走检查支撑相、抬脚相、穿地、双脚浮空、脚滑和不同帧率的一致性。
7. 对所有动作检查关节间距、附件连接、装备穿插和地面关系。

推荐动态指标：

| 指标 | 能发现什么 | 不能单独证明什么 |
|---|---|---|
| 关节两侧功能网格距离 | 脱节、错误镜像 | 所有穿插都已消失 |
| 脚底最低点与支撑相 | 穿地、双脚浮空 | 没有脚滑 |
| 近地脚部点的世界位移 | 脚滑、位移不匹配 | 坡地接触正确 |
| 切换帧顶点位移 P95 | 动作姿态跳变 | 命中时序正确 |
| 攻击部位到目标表面距离 | 明显打空 | 包围盒相交就是有效命中 |
| 30/60 fps 同时段采样 | 帧率相关运动 | 真实战斗节拍完整正确 |

阈值应按角色尺度、地形和镜头校准。所有采样都要说明是否扣除了根节点平移与转向、是否覆盖每一帧，以及使用平地还是实际地形。

### 阶段 7：真实运行时与战斗演出

先在预览器验证，再进入真实游戏。至少覆盖：

- 加载器、节点合同、片段映射、缺失动作回退。
- 多个实例的骨架/动作独立性，共享资源不会被意外修改。
- 实际视距、昼夜、相邻角色、装备遮挡和地形。
- 完整自动战斗，而非只播放一个动作或运行一局的一部分。
- 移动、攻击、受击、血量、击退和倒地的顺序与同步。
- 帧率、控制台错误、资源释放和正式资产回退。

战斗演出使用**有序、带时间、可校验的事实流**：

- 事件 ID、顺序号、行动者、目标、实际血量变化和命中时刻。
- 移动结束、我方结算后、敌方结算后、下一轮准备后的分阶段位置快照。
- 血量事件能够重建最终规则状态；缺失、重复或不一致时明确拒绝生成演出。
- 前一轮演出未结束时，后续回合不得静默覆盖队列。

**不得直接拿回合最终状态补播整段动画。** 这会丢失中间击退、受击和血量变化，也会造成“拳头尚未接触，血量已经下降”。

### 阶段 8：压缩、回导与发布

压缩前记录节点、材质、动画和扩展合同。压缩后必须重新导入并渲染，不能只比较文件大小。

`gltfpack` 会优化缓存、量化几何、合并网格、重采样动画并裁剪节点；这些操作可能破坏应用依赖的命名节点、材质或自定义数据。按合同使用 `-kn`、`-km`、`-ke` 等保护选项，并检查未知属性和扩展是否被丢弃。[R3]

- Meshopt 输出需要运行时支持对应扩展；three.js 使用 `GLTFLoader.setMeshoptDecoder`。[R3]
- 量化后检查 UV、法线、蒙皮、关节和动画；必要时提高精度或对特定数据保留浮点表示。
- 动画重采样后比较每条轨道、片段时长和接触帧，不只看片段是否还存在。
- 纹理转换只由一个明确步骤负责，避免重复有损转换；若项目脚本要求固定顺序，写入管线并做回读验证。
- 使用 Khronos glTF Validator 检查格式、buffer、accessor、动画和图像问题。[R7]
- Validator 通过之后，仍要在目标引擎完成视觉、动作和性能验收。

**发布门：** 正式 GLB、源工程、清单、验证报告、实际运行截图、性能数据和回退版本成套存在。

## 5. Agent 的单轮执行协议

每轮只处理一个可验证假设：

```text
观察现状
→ 提出可证伪的原因假设
→ 保存基线并只改变有限变量
→ 生成候选
→ 运行静态、视觉、动态或运行时检查
→ 对比基线
→ 保留、继续试验或撤回
→ 记录证据与剩余问题
```

每轮目录建议包含：

```text
REPORT.md           结论、变量、证据、限制和下一步
metrics.json        几何、纹理、动画、接触与运行时指标
compare.png         同机位基线/候选对照
candidate.glb       可重新导入的候选
commands.md         工具版本、参数与复现命令
source.json         源资产哈希、来源和许可信息
```

执行约束：

- 不用“测试通过”替代测试未覆盖的结论。
- 不用包围盒相交宣称真实接触，不用最短距离宣称没有穿插。
- 试验导致新退化时，先撤回，再报告结果；不要为了保住本轮成果扩大例外。
- 跨 Agent 借鉴时检查实际文件和独立采样，不只引用对方总结。
- 正式资产保持可回退，未验收候选不得静默覆盖。
- 外部生成或下载前确认资产权利、服务条款和上传范围；不上传本地日志、路径或用户数据。

## 6. Codex 与 Claude Code 经验对照

| 维度 | Claude Code 的有效经验 | Codex 的有效补充 | 合并规则 |
|---|---|---|---|
| 模型路线 | 区分结构模型与 AI 网格 | 保留 Assault 的视觉优势 | 按来源选路线，不为统一面数牺牲识别特征 |
| 分件 | 机械部件逐件修复、刚性节点绑定 | 从动作问题反查结构 | 分件同时服务拓扑、关节和运行时合同 |
| 镜像 | 只在合适部件使用；错误上臂镜像后回滚 | 强调独立复核 | 形状与姿势都对称才镜像，关节检查排除轴毂 |
| 减面 | Gunner 结构简化；Support 多档比较选约 8k | Assault 10k/8k 对照并恢复腿部细节 | 多档试验、区域保护、按关键特征选档 |
| 贴图 | 平面细节烘焙、图集和 UV 复用 | 修复 UV 量化后的颜色异常 | 烘焙后必须在目标运行时回读 |
| 动作 | 按真实关节和静止姿态重调 | 量化跳变、脚滑、目标距离和帧率 | 视觉检查与数值采样共同验收 |
| 压缩 | WebP 与 meshopt 实践，保留节点和轨道 | 强调真实加载与独立实例 | 压缩后重跑完整资产合同 |
| 战斗 | 模型合同与动作测试 | 血量事件、演出队列、分阶段快照 | 资产验收与战斗时间线验收分开 |
| 失败处理 | 回滚错误镜像并补新检查 | 撤回前冲和不良混合试验 | 失败必须转化为回归检查，而非只写总结 |

会话中的数字用于说明方法，不作为通用阈值：

- Gunner 低模试样：19,146 → 3,536 面，烘焙后约 530 KB。
- Support：多档比较后选择约 8.5k 面；后续修复版约 568 KB。
- Assault：14,987 面基线生成 10,048 和 8,007 面候选；10k 方向保留更多关键细节，恢复腿部后为 11,050 面。

这些结果当时仍有未提交、未完整跑局或未通过战斗验收的部分，不能据此声称对应角色已经最终完成。

## 7. 统一质量门与交付清单

| 阶段门 | 必须提供的证据 | 不能替代它的检查 |
|---|---|---|
| G0 合同 | 参考、单位、节点、动作、预算、许可 | 口头描述目标 |
| G1 静态结构 | 分件、轴心、拓扑、法线、尺寸报告 | 一张全身截图 |
| G2 视觉 | 多视角近景、实际视距、昼夜、基线对照 | 平均表面误差 |
| G3 动态 | 连续帧、接触、关节、切换、完整动作采样 | 不穿过地面的单帧检查 |
| G4 运行时 | 实际加载、完整战斗、事件同步、控制台与回退 | 预览器能显示 |
| G5 发布 | Validator、回导、性能、清单、源工程、回退版本 | GLB 文件变小 |

只有全部适用阶段门通过，状态才可写为“已验收”。其他状态统一使用：

- **草稿：** 尚未形成稳定候选。
- **候选：** 已完成部分对照，仍有未通过或未验证项。
- **已接入：** 已进入开发运行时，但不代表动态或战斗验收完成。
- **已验收：** 合同中的全部适用项均有当前版本的证据。

## 8. 常见反模式

- 先规定“所有角色必须 3k”，再寻找证明它可行的截图。
- 对整片 AI 网格直接减面、自动绑骨、导出并交付。
- 只看全身轮廓，不检查关节、拳脚和装备近景。
- 一律镜像左右部件，或用轴毂遮住关节缝。
- 用双面材质掩盖反向法线，用整体抬升模型掩盖所有穿地。
- 把动作混合当作万能修复，却不检查接触帧和脚部支撑。
- 用瞬时前冲让攻击“命中”，但没有步态、障碍和碰撞处理。
- 让动画直接消费回合结算后的最终位置和血量。
- 压缩后只报告体积，不检查节点、动画、UV、法线和解码器。
- 把其他 Agent 的总结当作当前文件的独立验证。
