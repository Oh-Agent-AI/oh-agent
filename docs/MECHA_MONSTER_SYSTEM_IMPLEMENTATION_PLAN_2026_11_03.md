## 1. 执行结论

采用“**保留战斗权威内核，扩展怪物内容注册与表现适配器**”的路线，不整体替换当前怪物系统。

首轮内容目标为：

- 10 个威胁等级；
- 10 个基础怪物物种，每级一个；
- 每个物种一个可提前宣告、可应对、可回放的专属技能；
- 同一物种允许生成多个视觉变体，但技能身份保持稳定；
- 普通 Three.js 模型始终可用，SDF / Ray Marching 是增量表现路线，不是玩法上线前置条件。

实施拆成两条轨道：

```text
轨道 A：怪物规则内容
物种定义 → 意图生成 → 技能结算 → 预览一致 → AI / 回放 / 远程兼容

轨道 B：怪物视觉表现
现有模型 + 生命核 → 表现适配器 → 单个 SDF 原型 → LOD / 降级 → 战场接入
```

轨道 A 可以先交付可玩内容；轨道 B 未通过性能和兼容性验收时，不得阻塞轨道 A，也不得接管战斗规则。

## 2. 目标与非目标

### 2.1 目标

1. **增加战术多样性**：不同怪物改变玩家的走位、目标优先级和击杀顺序，而非只提高 HP。
2. **保持公开谜题**：敌人不暗中换目标，不用未宣告技能，不依赖随机结果制造难度。
3. **建立内容扩展能力**：新增怪物不需要继续扩张 `enemy.ts` 的条件分支。
4. **让形态服务识别**：外观、蓄力动画与技能语义一致，但不能代替格子、目标和伤害预览。
5. **保持契约可信**：预览与实际结算一致，事件与状态变化一致，回放可复现。
6. **可控交付**：每批怪物都有独立开关、规则测试、视觉降级和回退路径。

### 2.2 非目标

首轮不做：

- 一次交付几十个独立技能或完全随机的技能组合；
- 用 SDF 场决定棋盘命中、占地或伤害；
- 引入任意 GLSL、JavaScript 或网络脚本执行器；
- 让 GPU 浮点结果、音频、鼠标或帧率影响权威战斗；
- 为十种怪物同步重做城市战场搜索算法；
- 在没有基准数据时承诺移动端 60 FPS；
- 为提升难度而隐藏意图、修改命中结果或增加不可解释随机数。

### 3.2 当前限制

- `BossSkill` 只有 `smash | sweep | skip`。
- `BossScriptId` 同时承担部分内容选择与策略选择，继续堆枚举会快速失控。
- `MatchState` 目前以单个 `boss` 加 `raiders[]` 为权威结构，不能假设视觉分裂会自动成为真实单位。
- `TurnEvent` 主要表达移动、行动、击退、敌方攻击和结果，尚缺少通用护盾、地形、召唤和阶段迁移语义。
- 城市遭遇搜索和 Boss 放置按 2×2 主怪占地设计。
- 现有模型依赖 `THREE.Group`、Mecha Rig、动画和 GLB 升级路径；SDF 原型不能直接替换一个零件函数就算接入完成。

### 3.3 首轮约束

1. 十种主怪先统一使用现有 2×2 规则占地；子体使用 1×1。其他脚印尺寸另立任务。
2. 不改变现有 `flat / shore / ridge / alley` 的含义；它们表示地形，不表示怪物物种。
3. 旧脚本与旧技能 ID 保留，已有 golden 不因注册表重构而改变行为。
4. 新技能先支持本地 PvE；远程仅在协议、双端规则版本与回放测试通过后开放。
5. 部署确认前不得生成新的首回合敌意；部署完成后才进入既有 `enemy_prepare` 流程。

## 4. 内容模型：等级、物种、技能、外观四轴分离

### 4.1 四个概念

| 概念 | 职责 | 不应承担 |
| --- | --- | --- |
| 威胁等级 `threatLevel` | 解锁顺序、遭遇预算、行为复杂度 | 单纯线性缩放 HP |
| 物种 `speciesId` | 数值、移动、技能、目标偏好、战术身份 | 任意随机换技能 |
| 技能 `skillId` | 宣告、目标、效果、事件与预览 | 直接操作 DOM / Shader |
| 外观 `visualGenome` | 几何、材质、光核、粒子和视觉变体 | 决定权威命中与状态 |

等级主要增加“需要同时处理的问题数量”，不是把同一种攻击放大十倍。

| ---: | --- | --- | --- | --- | --- | --- |
| 1 | 孢群体 `spore_leaper` | 孢子弹跳 `spore_leap` | 宣告落点和范围；按合法落点移动并结算范围伤害 | 离开落点、击退改变落点、封堵通道 | 敌方移动 + 范围伤害 | M2 |

### 4.3 技能共同规则

每个技能必须回答：

1. 谁施放，选择了什么目标？
2. 哪些格子危险，持续多久？
3. 玩家移动或击退后，哪些内容重新投影，哪些保持绑定？
4. 目标死亡、出界、被占用或阶段结束时如何落空？
5. 多单位效果的固定结算顺序是什么？
6. 对预览、事件、回放和 UI 分别输出什么？

首轮禁止：

- 玩家提交后无事件地重新选择更高价值目标；
- 视觉上命中但规则未命中，或规则命中但无可理解反馈；
- 无限召唤、无限护盾、永久地形或无上限连锁；
- 让“高等级”获得玩家不可见的额外行动。

## 5. 目标架构

```text
Encounter Content Assignment
  speciesId + contentVersion + visualSeed
                │
                ▼
Monster Definition Registry
  stats / footprint / movement / plannerPolicy / skills / visualRef
                │
        ┌───────┴────────┐
        ▼                ▼
Enemy Planner       Monster Presentation
  选技能与目标         读取状态与事件
  生成 EnemyPlan       生命核 / 形态 / 动画
        │                不修改战斗事实
        ▼
Authoritative Rule Core
  validate → reproject → resolve → events → phase/outcome
        │
        ├───────────────► Preview / Replay / Remote Snapshot
        ▼
TurnEvent + PresentationStages
```

### 5.1 内容注册表，而不是脚本运行时

采用编译期注册、白名单 ID 和 TypeScript 实现：

```ts
type MonsterDefinition = {
  id: string;
  contentVersion: number;
  threatLevel: number;
  footprint: { width: 2; height: 2 };
  maxHp: number;
  move: number;
  basicSkills: string[];
  signatureSkill: string;
  plannerPolicy: string;
  visual: {
    generator: string;
    seed: number;
    parameters?: Readonly<Record<string, number | string | boolean>>;
  };
};
```

该类型是设计示意，落地时以现有类型导出和兼容策略为准。

原则：

- 静态定义不反复复制进每帧表现数据；
- `MatchState` 只保存 `speciesId`、动态技能状态、冷却、护盾、子体和阶段等权威事实；
- 快照消费者必须能根据 `ruleset + contentVersion + speciesId` 找到同一套定义；
- 已发布 ID 不静默改变语义，行为不兼容时升级版本或新增 ID。

### 5.2 技能处理契约

每个技能按三个阶段实现：

```text
prepare   根据只读状态选择目标并生成可序列化意图
reproject 根据玩家造成的位移、死亡和地形变化更新已允许变化的投影
resolve   按固定顺序执行效果，返回状态变化与事件
```

约束：

- `prepare` 不读取墙钟、DOM、音频或 `Math.random()`；
- `reproject` 不偷偷替换已绑定目标；
- `resolve` 不直接调用表现层；
- 所有动态效果均有上限、合法性和终局检查；
- 同一种技能在预览和正式结算中走同一个规则实现。

### 5.3 效果原语顺序

只在对应物种需要时实现，不提前建设通用脚本引擎：

1. `damage`：伤害、护盾拦截、死亡和健康事件；
2. `move / push / pull / swap`：合法性、落点、顺序和碰撞；
3. `terrain`：持续区域、剩余回合、叠加与清除；
4. `status / link`：来源、条件、时长和失效；
5. `summon`：数量上限、出生格、ID、生命周期与胜负关系；
6. `phase / core`：触发一次、阶段快照、技能组迁移；
7. `board transform`：仅用于 L10，有界、可预览、可回放。

每个原语必须输出可投影事件，禁止静默修改状态。

## 6. 状态、事件与 UI 改造

### 6.1 权威状态

按需增加，避免一次性加入所有字段：

- Boss：`speciesId`、技能动态状态、阶段 ID；
- 通用状态：护盾、持续效果、链接来源与剩余回合；
- 地形效果：效果 ID、来源、格子、剩余回合；
- 子体：稳定 ID、物种、HP、意图和寿命；
- 内容版本：用于回放和远程兼容性判断。

`visualSeed` 只有在需要跨端重建完全相同外观时才进入比赛内容描述；纯本地视觉效果不得进入战斗计算。

### 6.2 意图与事件

`Intent` 需要从“技能 ID + 格子”逐步扩展为可验证的意图数据：

- 技能与内容版本；
- 施放者、绑定目标、方向；
- 原始格子和当前投影格子；
- 持续回合、次数或阶段；
- `planned / reprojected / void` 及明确原因。

`TurnEvent` 可保留现有事件并增加有判别字段的新事件，不建议把所有语义塞进一个任意 payload。至少需要覆盖：

- 护盾创建、吸收、破裂；
- 地形创建、触发、消退；
- 强制位移和交换；
- 子体生成、死亡、到期；
- 链接建立和断开；
- 核心迁移和阶段切换；
- 空间映射及每个受影响实体 / 格子的结果。

### 6.3 UI 与 UX

每个新物种上线必须同时交付：

- 怪物名称、等级和招牌技能的简短说明；
- 当前意图、目标、危险格与持续时间；
- 选中怪物后的技能详情和反制提示；
- 落空、改投影、护盾吸收、断链和阶段变化反馈；
- 不依赖颜色 alone 的图标或纹理区分；
- 阵营环、生命条、格子高亮和攻击方向在抽象外观下仍清晰。

表现层的“核心变亮”只能作为辅助信息，不能代替 UI 的权威宣告。

## 7. 城市遭遇与内容分配

### 7.1 不改变地形搜索职责

`CityMechaSite` 继续描述地形、建筑和出生位置。首轮在遭遇生成后附加内容分配：

```text
CityMechaSite（地形事实）
  + EncounterContent（speciesId / contentVersion / visualSeed）
  = MonsterEncounter（可进入的战斗内容）
```

建议：

- 给遭遇稳定的 `encounterId`；
- 使用显式城市 / 遭遇 seed 的命名 PRNG 或固定内容表选择物种；
- 禁止用对象地址、遍历顺序或 `Math.random()` 作为跨会话内容依据；
- 缓存键包含城市版本、内容版本和遭遇 seed；
- `matchFromSite()` 通过明确参数接收怪物内容，不从 UI 全局变量反查。

### 7.2 出生与组合约束

- 主怪首轮继续走 2×2 安全检查；
- 子体出生必须在技能执行时重新验证，不复用过期空格；
- 同屏组合按威胁预算生成，而不是简单按最高等级叠加；
- 控制、护盾、召唤和范围伤害的组合要做“不可解局面”检查；
- 部署区、保护建筑和必须通行格不能被新技能无提示封死。

### 7.3 推荐敌人组合

首轮只开放经过测试的组合：

- 流环体 + 基础 Raider：训练直线规避与优先级；
- 晶簇体 + 输出型敌人：训练破盾与转火；
- 引力核 + 范围攻击：训练站位，但需限制同回合必死连锁；
- 织网体 + 单个护卫：训练断链，不首轮叠加多个链接体；
- 多核生命单独作为阶段 Boss，不叠加 L10。

## 8. 视觉表现实施路线

### 8.1 表现适配器

在现有 `createBoss()` / `createRaider()` 之外增加适配层，而不是一次性删除 Rig：

```ts
interface MonsterVisualAdapter {
  root: THREE.Group;
  update(view: MonsterPresentationView, dt: number): void;
  setQuality(level: MonsterQuality): void;
  dispose(): void;
}
```

实际接口还需覆盖现有动画系统要求的包围盒、点击代理、位置、阵营和 GLB / Rig 生命周期。

实现顺序：

1. `RiggedMonsterVisual`：包装当前模型，行为不变；
2. `CoreEnhancedMonsterVisual`：现有模型 + 生命核 / 轨道粒子；
3. `GeometricLifeformVisual`：受控 SDF 原型；
4. `ProxyMonsterVisual`：低性能或 Shader 失败时回退。

### 8.2 技能视觉语义

| 技能 | 推荐表现 |
| --- | --- |
| 孢子弹跳 | 核心压缩 → 落点亮起 → 外壳展开 |
| 环轨穿刺 | 环体对齐方向 → 轨道同相加速 → 射线释放 |
| 蚀格 | 孔洞向目标方向扩张 → 地面出现独立规则标记 |
| 棱镜护盾 | 晶面闭合 → 受击时出现局部裂纹 → 破盾碎裂 |
| 分群围猎 | 结构预分离 → 规则生成子体 → 子体获得独立标识 |
| 相位交换 | 双核心同相 → 两端落点明确显示 → 位置切换 |
| 引力井 | 轨道向核心收束 → 牵引方向箭头 → 范围攻击 |
| 神经链接 | 两核心建立光线 → 链接状态图标同步 |
| 核心迁移 | 旧核心衰减 → 新核心先点亮 → 阶段技能切换 |
| 空间折叠 | 只可视化已宣告映射；禁止用粒子遮挡规则格 |

### 8.3 SDF 接入门禁

SDF 先用于一个城市遭遇怪物，不直接进入所有战场。必须验证：

- Shader 编译和链接错误可见；
- 非空画面、相机边界、薄表面和数值稳定；
- Three.js 场景深度、遮挡、阴影和后处理；
- 点击代理和 2×2 视觉锚点；
- 屏幕占比变化时的 GPU 成本；
- 多怪物同屏成本；
- 降级模型和完整资源释放；
- 浏览器截图 / 录屏和目标设备实测。

禁止把独立全屏 HTML 原型的运行结果当作城市场景集成验证。

### 8.4 降级顺序

```text
完整 SDF + 光核 + 粒子
  → 低分辨率 / 低步数 SDF
  → 烘焙网格或简化几何 + 光核
  → 当前 Rigged Boss / Raider
```

质量切换不得改变怪物位置、HP、意图、技能、命中或比赛结果。

## 9. AI、预览、回放与远程

### 9.1 敌方 AI

- 每个物种通过 `plannerPolicy` 声明目标偏好和技能选择策略；
- 固定输入必须产生固定 `EnemyPlan`；
- 多种候选得分相同时使用稳定排序；
- 强度主要来自更好的合法决策，不来自读取玩家草稿或暗改结果；
- 新技能加入本地自动战斗矩阵，检查胜率、回合数、僵局和效果触发率。

### 9.2 玩家 AI / 求解器

玩家推荐器无需第一轮理解全部长期组合，但必须：

- 能识别新危险格、强制位移和护盾；
- 不把被护盾完全吸收的攻击当作有效伤害；
- 不推荐会导致不可见后续伤害的非法假设；
- 对不支持的复杂技能显式降低推荐置信度或退回保守策略；
- 保持固定局面、固定 doctrine 的可复现输出。

### 9.3 预览与回放

每个技能必须通过：

```text
previewPlan(state, plan).log === playTurn(state, plan).log
preview stages === actual presentation stages
重放初始快照 + 命令 = 同一最终状态与事件
```

涉及多步效果的技能还需验证事件中每个健康、位移和状态变化的顺序。

### 9.4 远程兼容

首轮新怪物只在本地 PvE 开放。远程开放前必须：

- 明确版本化内容描述，禁止客户端自行选择不同技能定义；
- 双端校验 `ruleset / contentVersion / speciesId`；
- 版本不匹配时明确拒绝或回退到双方支持的旧内容，不静默降级战斗规则；
- 快照包含所有权威动态状态，不能只传视觉 seed；
- 只传输声明过的比赛字段，不扩展为任意文件、日志或主机数据访问；
- 不传输或执行远端 arbitrary Shader / 脚本；视觉生成器和参数均走白名单与数值边界检查；
- 覆盖重复命令、迟到快照、断线重连、阶段技能和召唤物 ID 的同步测试。

## 10. 测试策略与验收门禁

### 10.1 每个技能的必测矩阵

1. 正常宣告与结算；
2. 边界格、遮挡、脚印和不可达位置；
3. 目标死亡、移动、被击退和落点占用；
4. 重新投影与落空原因；
5. 多目标固定结算顺序；
6. 护盾、地形、召唤等效果的创建与结束；
7. 最后一击、建筑失守、机甲全灭、超回合等终局优先级；
8. 预览 = 实际；
9. 初始输入不变、非法计划原子拒绝；
10. 序列化恢复与完整重放；
11. AI 固定局面确定性；
12. UI 能解释目标、范围、持续时间和反制。

### 10.2 旧行为保护

- 旧 `smash / sweep / skip` 和四种 `BossScriptId` 的 golden 保持；
- 旧远程 v1 内容不因新增可选字段而改变字节语义；
- 部署、任务、城市选址、威胁层和健康事件现有测试全部通过；
- 新内容通过显式开关启用，关闭时走旧路径；
- 不为消除失败而刷新 golden，契约变化必须单独评审。

### 10.3 自动战斗与平衡

扩展现有本地 balance / distribution 脚本，至少记录：

- 各物种在固定地图与固定难度下的胜率；
- 平均 / P95 回合数；
- 技能使用率、落空率、有效伤害和反制率；
- 建筑损伤与机甲存活分布；
- 召唤数量、地形持续时间、护盾吸收和链接存活时间；
- 同 seed 重跑的一致性；
- 无合法行动、无限循环和异常终局数量。

这些数据只用于本地开发和评审，不新增遥测或用户数据上传。

### 10.4 视觉与性能

先记录当前模型基线，再锁定目标设备预算。至少比较：

- 平均与 P95 帧时间；
- SDF 平均 / 最大步数与屏幕覆盖比例；
- 同屏 1、2、4 个怪物；
- 城市、战场、远程观战三种场景；
- DPR、窗口尺寸和质量档；
- Shader 编译失败、WebGL 不可用、标签页隐藏和恢复；
- 几何、材质、纹理、 framebuffer 与粒子的释放。

没有实测数据时，只能报告“未验证”，不能宣称满足 10 KB、60 FPS 或移动端兼容。

## 11. 分阶段实施

### M0 — 冻结基线与内容开关

交付：

- 建立旧 Boss / Raider 规则、预览、远程与表现基线；
- 确定 `speciesId / contentVersion / visualSeed` 的归属；
- 增加本地新怪物内容开关，默认关闭；
- 为技能测试建立统一 fixture 和事件断言工具；
- 记录当前城市与战场帧时间基线。

退出条件：

- 开关关闭时行为与当前版本一致；
- 基线测试可重复，后续技能无需复制整套测试脚手架。

### M1 — 注册表、技能契约与表现适配器

交付：

- 引入怪物定义注册表和稳定 ID；
- 把旧 Boss 包装为首个注册物种，不改变旧行为；
- 建立技能 `prepare / reproject / resolve` 契约；
- 抽出当前模型表现适配器；
- 在现有模型上实现一个生命核视觉原型，但不绑定战斗结果。

退出条件：

- 旧脚本 golden 全通过；
- 新增一个测试技能不需要修改整条敌方结算循环；
- Rigged 与 CoreEnhanced 外观可切换且规则状态不变。

### M2 — 第一批可玩物种：L1、L2、L4

交付：

- 孢子弹跳、环轨穿刺、棱镜护盾；
- 对应意图、事件、UI 和反制说明；
- 城市遭遇内容分配；
- 固定敌人组合与自动战斗矩阵。

选择理由：先验证移动、直线、多目标和伤害拦截，不立刻引入召唤与棋盘变换。

退出条件：

- 三个技能均通过完整技能测试矩阵；
- 玩家能在提交前理解范围、目标和护盾结果；
- 旧内容可一键回退；
- 至少形成三种不同的合法应对策略，而非统一集火 Boss。

### M3 — 位置与持续区域：L3、L6、L7

交付：

- 蚀格、相位交换、引力井；
- 持续地形和有序强制位移；
- 多单位落点预览与碰撞 / 失败原因；
- 地形和位移对 AI 评分的影响。

退出条件：

- 多单位效果顺序稳定且可解释；
- 无无限循环、交换抖动、牵引叠格和地形永久残留；
- 终局发生时的后续效果严格遵循既定规则。

### M4 — 多实体协同：L5、L8

交付：

- 分群围猎、神经链接；
- 子体 ID、数量上限、生命周期和胜负关系；
- 链接建立、断链和快照恢复；
- 子体与链接的表现快照及 UI 标识。

退出条件：

- 任意回合子体数有硬上限；
- 召唤不会覆盖已有实体或制造不可达状态；
- 重连 / 回放能恢复相同子体与链接；
- 视觉分裂与真实子体生成一一对应。

### M5 — 阶段 Boss：L9

交付：

- 核心迁移、阶段技能和一次性触发；
- 阶段 UI、核心位置和技能组说明；
- 阶段边界、死亡、回放和 AI 测试；
- 一套经过评审的多阶段 Boss 战。

退出条件：

- 阶段只迁移一次，不在预览 / 重放中重复触发；
- 玩家能在阶段改变前理解触发条件和下一技能；
- 阶段变化不会绕过部署、回合和 outcome 规则。

### M6 — 终局物种：L10

交付：

- 有界空间折叠；
- 完整映射预览、顺序和回退；
- 终局 Boss 组合与专项平衡；
- 远程兼容评审后，才决定是否开放对应内容。

退出条件：

- 所有空间变化提前完整宣告；
- 不产生未定义实体位置、丢失目标或不可重放状态；
- 不依靠隐藏随机、性能差异或动画时机决定结果；
- 若预览和远程契约不能保持可信，则该物种不上线，而不是简化验证。

### 并行 V1 — 单个几何生命体视觉原型

可在 M1 后并行，但不阻塞 M2：

- 只选择 Flux Ring 或低复杂度光核外壳；
- 先在城市遭遇点接入；
- 保留当前 Boss 自动回退；
- 完成性能、遮挡、拾取、截图与资源释放验收。

### 并行 V2 — 战场几何外观

仅在 V1 通过后开始：

- 接入技能意图和事件；
- 统一本地 / 远程表现；
- 提供三档质量与“跳到结果”；
- 不用视觉开发进度延迟规则内容修复。

## 13. 工程风险与回退

| 风险 | 早期信号 | 控制与回退 |
| --- | --- | --- |
| 技能分支继续膨胀 | 每加一个物种都修改多处 switch | 在 M1 建注册表；保留薄编排层 |
| 预览与真实结果分离 | 护盾、牵引、召唤后 log 不一致 | 共用规则实现；技能级 preview/actual 门禁 |
| 多实体状态失控 | 子体覆盖、ID 冲突、终局后继续行动 | 稳定 ID、硬上限、终局检查、快照测试 |
| 抽象外观损害可读性 | 看不清阵营、朝向、攻击范围 | 保留格子与 HUD；视觉验收不替代 UX 验收 |
| Ray Marching 性能失控 | 像素越多帧时间越高、移动端发热 | 限制屏幕覆盖、LOD、烘焙网格和旧模型回退 |
| 远程版本分裂 | 同物种双端结果不同 | 内容版本握手；不兼容则拒绝新内容 |
| 等级变成数值膨胀 | 打法不变，只是战斗更长 | 以行为复杂度和组合问题验收，控制 HP 增长 |
| 内容过多拖慢交付 | 同时开发十技能与 SDF | 按 M2–M6 分批，视觉与规则解耦 |
| 平衡依赖上传数据 | 为调参新增遥测 | 仅用本地固定 seed、自动战斗和人工评审 |

## 14. 发布策略

1. 新内容默认只在开发 / 本地评审开关下出现。
2. 每个批次先发布规则与现有 / 增强模型版本，SDF 另行开关。
3. 任一技能出现预览不一致、回放分歧或不可解终局时，只关闭该物种，不回滚整个系统。
4. 旧遭遇始终可选择旧 Boss 内容，确保回归与问题定位。
5. 远程新内容单独评审，不因本地 PvE 完成而自动开放。
6. 每次发布说明列出：新状态字段、新事件、协议变化、降级路径和已运行测试。

## 15. 完成定义（Definition of Done）

“十级怪物系统完成”必须同时满足：

- 十个物种均可通过合法城市遭遇进入战斗；
- 每个招牌技能有意图、反制、规则事件、UI 和测试；
- 预览、结算、回放一致；
- 旧内容与部署流程无回归；
- AI 不会在固定输入下产生非确定结果；
- 视觉质量切换不影响任何规则结果；
- 每个物种可独立关闭并回退；
- 未通过远程验证的内容明确标记为本地 PvE；
- 所有 SDF 性能与兼容性声明都有实际设备和截图 / 录屏证据；
- 文档明确区分已实现、已验证、待实现和不支持。

## 17. 一页执行摘要

```text
不重写战斗内核
不一次并行十个技能
不让 SDF 决定规则
不让视觉变体随机改变技能身份

先建注册表与测试门禁
→ L1 / L2 / L4 验证基础技能
→ L3 / L6 / L7 验证地形和强制位移
→ L5 / L8 验证召唤和协同
→ L9 验证阶段 Boss
→ L10 最后实现有界空间变化

现有模型 + 生命核先提升表现
→ 单只城市 SDF 原型
→ 性能与兼容性通过后再进入战场
→ 永远保留普通模型回退
```

最终验收标准不是“有十种模型”，而是玩家看到怪物和意图后，能够理解：

> 它准备做什么；我可以通过移动、击退、破盾、断链、封出生或改变击杀顺序中的哪一种方式应对；提交后游戏会严格按照已公开规则结算。
