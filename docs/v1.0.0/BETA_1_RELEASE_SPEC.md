## 1. 产品承诺与规格效力

用户安装后无需填写套餐、预算或 API Key，即可看到本机真实 AI 用量与有依据的费用估算；能够找到高消耗会话、校准一组计费关系、撤销校准，并在来源或重算失败时恢复。日常可通过菜单栏和自愿开启的预算提醒持续使用。

Beta 用于验证上述日常闭环，不承诺完整账单管理、全量工作流成本归因或完整 v1.0.0 功能。

本文是 Beta 的独立范围与放行合同。[完整 PRD](../AGENT_VITALS_APP_V1_0_0_PRD.md) 继续约束正式 v1.0.0；本文明确延期的功能及验收只对 Beta 不构成阻塞，不删除原需求、不勾选原 AC、不降低正式版门槛。本文未明确纳入的功能均不属于 Beta 承诺；已存在的接口和历史用户数据仍须兼容并遵守数据完整性要求。

本文定义两种交付状态，不能混称：

| 交付 | 可接受的分发 | 放行条件 |
|---|---|---|
| 内部测试构建 | 指定协助测试者；清楚标注未签名测试包 | G01–G08 全通过；G09 签名可暂缺，缺项必须写在构建清单中；不能对外宣布 Beta 已发布 |
| 对外发布 `v1.0.0-beta.1` | 目标用户可自行下载安装 | G01–G09 全通过，包括 Developer ID 签名、公证及干净环境安装 |

不存在“只因版本名带 beta 就免验收”的例外。生成安装包、源码测试通过或浏览器 mock 通过，均不等于发布通过。

## 2. 平台、执行环境与数据范围

- 架构：仅 Apple Silicon / arm64。Intel、Windows、Linux 不纳入 Beta 桌面支持承诺。
- 系统：首批支持 macOS 26.5.2，这是本次盘点的本机系统版本；该版本仍须完成干净用户安装验收。其他系统版本不宣称已验证。对外发布前安装配置的最低版本与支持说明必须一致，不能沿用 `11.0` 配置却宣传广泛兼容。
- 稳定执行环境：Codex、Claude Code、DSH。每种执行环境均需单独安装/仅该执行环境有日志的验收，不要求用户同时拥有三种执行环境。
- WorkBuddy：保留现有接入，界面标为“实验支持”；缺少的路由/用量维度明确不可用。实验标签不能豁免数据丢失、重复计量、错误计费和其他执行环境受影响的缺陷。
- 仅承诺本机已导入记录，不声称覆盖账户所有设备、官方账单或实时完整配额。
- 初次优先近 30 天；历史增量导入可暂停、恢复。查询只对已导入范围负责，范围和进度可见。
- 升级范围：项目已有 v0.11/v0.12 数据；分别使用真实来源的脱敏旧库夹具验证。若某版本缺少可验证旧库，必须在发布前补齐，不以新建同 schema 库替代迁移证据。

### 3.1 计费边界：不得因 Beta 简化而改变

1. 原始 facts 不因声明修改、撤销、显示币种或时区变更而改写；声明是独立用户证据，有作用范围和修订记录，不伪装成日志观测。
2. 自动判为订阅必须有官方订阅路由及适用范围的明确证据；仅拥有订阅不能覆盖全部会话。当前 endpoint 不能覆盖日志显式 `model_provider=openai`；无 marker 的配置回退必须保留 `route-config-fallback` 来源。
3. 自定义端点、第三方路由、缺失或冲突证据默认 `metered_estimate`、`has_unresolved=true`，显示原因。用户声明不能消除已知相反路由证据，也不能把实际第三方用量包装成官方订阅。
4. 未知 provider、缺价、缺缓存TTL/阶梯维度或无法唯一归因，不丢 tokens、不填假0、不随意套近似型号。不确定金额为 null/未计价，并说明覆盖。
5. API等价价值、按量估算、订阅合同和实际付款分开；组织承担不等于免费；第三方缺实际价时仅提供带说明的原厂参考估算。
6. 套餐金额可“不清楚”；支持币种、周期、生效/终止日期的正确展示。确认套餐不生成已付款记录。不确定路径不接受候选、不写确认声明、不触发归因重算。
7. 既有账单及已确认支出预算保留原币、来源、覆盖和旧口径，可查看；Beta 不新增账单编辑/导入与已确认支出预算创建入口。不将旧预算自动转成观察预算，不将旧¥1重置成新默认。
8. 各消费面同一时间窗、时区、筛选、basis、币种、价格/声明/结果版本下必须相等；分页不能替代全量合计。原始数值比较按合同精度进行，UI舍入规则另行核对。

### 3.2 “已写好但延期”的界面处理

- 下节延期功能默认不进入 Beta 导航、主操作或宣传；不能只在按钮旁标“实验”后仍让未完成写流程可达。
- 已存在的只读 workflow/MCP 接口可保留兼容；响应继续如实报告 partial/unavailable，不能为放行改成 complete。
- 已有行为问题列表若保留，标“事件观察”，按组计数、分页、可看脱敏证据，不宣称六类事项或完整五态处理已完成。
- 原有支出数据保留只读访问和必要说明；关闭新增入口不等于删除数据。

### 6.1 六项 MCP PARTIAL 的 Beta 处理

Q06/Q07/Q08/Q09/Q10 的高级 workflow 洞察，以及 Q14 的跨执行环境 canonical 归一，属于 D04/D05。保留既有 MCP 合同与冒烟脚本输出，既有 `PARTIAL` 不改判成 `EXACT/EXPLAINED`。另建 Beta 适用性报告标记“延期、原状态、缺失证据、用户影响、后续验收”。

只有这六项可在 Beta 范围报告中延期。Q10 的高级失败事件关联延期，不豁免 B05 的用量时间线或会话费用；Q14 的全量归一延期，不豁免模型按 harness/raw 消歧。任何泄露、错误数值、伪造关联或其他 MISMATCH 仍阻断 Beta。完整 v1.0.0 的 M5 门槛继续不通过，不能把 Beta 结论复制过去。

### 6.2 Beta 性能基准

标准机：受支持 macOS、Apple Silicon、16GB；固定脱敏数据集：1万会话/10万facts、另有1GB日志集（包含近30天数据）。固定夹具指纹、执行环境分布、CLI/价格版本和冷/热缓存条件。

- 启动、总览与会话首页各测20次并保留每次原始耗时；P95采用排序后的第19项，冷/热缓存分开报告。
- 启动可交互P95≤3秒；已有数据总览P95≤1秒、会话首页P95≤2秒。
- 1GB日志首次解析测5次，每次新数据根；首份真实摘要中位数≤90秒，最慢≤5分钟；不得把5次测量冒充可靠的人群P95。
- 同步完成后稳定观测15分钟：App及其自有子进程合计平均CPU≤1%（以一个逻辑核为100%），驻留内存合计≤250MB；记录采样方法。
- 导入中连续操作导航、暂停、退出，不能发生超过2秒的持续交互无响应。未导入记录必须显示覆盖限制，不通过默默截断数据过门槛。

百万facts正式基准延期，不代表大型现有用户数据可被忽略；已知大库崩溃、损坏、假成功仍是阻断缺陷。

### 6.3 阻断缺陷定义

- P0：数据丢失/污染、错误计费或虚构确定性、敏感数据无提示外发、破坏源日志。
- P1：B01–B12任一承诺路径无法完成；安装/启动失败；不可恢复同步/重算；金额跨面不一致；范围内性能或核心可访问性不达标。
- P2：不影响操作与理解的排版、非核心文案或已明确延期的增强；必须有记录，可带入Beta。

规则是 P0/P1 清零，不允许因签名、环境、权限或样本暂缺就改为“已通过”。环境问题应换测试方式/隔离用户或留作待验收。

不运行 Rust 自动格式化。有效的 golden 合同变更需单独审查，不为过门槛刷新。发生源码变更后重跑受影响检查；最终打包前完整门禁跑一次，冻结后不再以无变化的重复全量回归计进度。签名后核对包内容未变；对实际分发包执行安装及核心冒烟。

## 8. 执行顺序与停止扩展规则

1. 按本文盘点 B01–B12 与现有代码，只列实际缺口；关闭延期入口；整理当前改动为可追溯提交。
2. 先 T01–T05，确保首次价值与数字可信；再 T06–T10，关闭计费/恢复/预算主链；最后 T11–T13 与性能、迁移、隐私。
3. 在有权限的隔离测试环境完成真实 `.app` 操作。辅助功能自动化持续不可用时，交由测试者手工操作并保留步骤与证据，不继续堆 mock 代替。
4. 开发期间可准备签名环境、干净测试用户、三名独立试用者和文档；这些准备不要求引入新功能。
5. 固定候选→完整门禁→独立试用→签名公证→最终分发包验收→发布。任一步失败只修影响该门槛的缺陷。
6. Beta 发布后开始正式版12人两周试用；按 D01–D08 回补正式范围，原 RELEASE-01–05独立验收。

范围冻结后，仅接受 B/T/G 阻断缺陷及必要修复。新执行环境、新MCP工具、高级workflow推导、架构美化和额外报表进入后续清单；不得借修复扩张首发范围。不得以“源码存在”关闭验收，也不得以改名/重建包宣布完成。
