## 0. 一句话结论

「待处理」tab 现在把**两种性质完全不同的输出**混在一张表里：能一次点击解决的工单（缺价卡、归属未确认）和用户根本解决不了的行为事实（全权限高频、重试循环）。本规格把它拆成三个分区——**待办**（只收可无脑解决项）、**模型 × Harness 对比**（决策证据面，回答"该用谁"）、**证据明细**（按需下钻的原始命中）。判据只有两条，来自产品定位本身：

1. **无脑解决**：进「待办」的每一项，用户不需要判断——表单预填好，只输入无法推断的字段，点击后能看到结果（回执/计数变化），且可撤销。做不到这四条的，**不伪装成任务**，降级为决策面的证据。
2. **findings 是决策证据**：它的终局不是"清空收件箱"，而是让用户回答"哪个模型 × 哪个 harness 划算"——谁便宜但费 token、谁缓存命中高、谁反复撞限流。账单/省钱线的成熟度（一句话总结 + 预填 + 直达设置页）是全 tab 的基准线，不是特例。

## 1. 目标与判断标准

1. **默认视图零噪音**：打开 tab 首屏只见「待办」与「对比」，不见 SV6xx 分组行。行为规则的命中是证据，不是待办。
2. **100% 可行动**：「待办」区每一项都有专属动作按钮 + 预填 + 状态反馈；`diagnostic-only` 兜底文案不出现在待办区。
3. **决策面可排序**：模型 × harness 组合按"浪费调整后单位会话成本"排序（排序启用条件见 §4.6），"名义便宜但实际费 token"的组合必须露馅。
4. **不编数**：浪费率仅 DSH 有证据（waste 检测器只存在于 `harnesses/dsh`），其他执行环境显示 `—`；墙钟时间用会话事件跨度近似并如实标注；输入侧全零时缓存命中率是 `null` 不是 0（`HourlyCell::cache_hit_ratio` 现行为）；推断值（如任务画像）一律带 `inferred` 标记。
5. **金额纪律沿用**：成本按币种分栏，永不跨币种相加；跨执行环境只有 token 面允许总计（预算、冲突、重叠永不出跨执行环境单一数字——与 Skill 体检 tab §0 同一条纪律）。
6. **性能预算（v2 新增）**：首屏（待办 + 对比）**只允许读 authority SQL 聚合**（已同步库上的毫秒级查询），永不触发会话日志扫描——现 `sessions_issues` 路径在代码注释里自认"冷 cache 时几十秒"（`workbench.js:6706` 一带），这条路径只允许出现在③证据明细的显式请求里。对照 2026-09-05 tab 卡顿事故与 Skill 体检规格 §1.4 的同类纪律。

这些从未被组合成"哪个组合划算"的对比视图——这是本规格要补的缺口，不是新造数据。

### 2.6 实机抽样验证（2026-09-19，经 MCP）

三个代表性样本确认了分区设计的现实意义，同时暴露两个新事实：① flash-0731 的 57.0M token 行**几乎全部来自一个 49.8 小时会话**（`sr_1f7589`，473M 总量、7 模型混用、982 次工具 40 失败）——②行的展开必须带"贡献 Top 会话"；② 该会话的 Bash 指纹 `fnv1a64:82f4029c` 与 issues 月报最大重复调用组（20,475 次 / 155 会话）同源——**指纹跨链**应作为②展开内的可见证据。另确认：多模型会话（1 会话 7 模型）使"行为发现按模型归组"存在结构性歧义（§4.7）。

## 3. 三分区设计

### 3.0 本月发现（数据挖掘摘要，2026-09-19 用户反馈落地：「findings 应该是发现问题，类似数据挖掘报告」）

tab 首屏第一区。每条结论 = 一句断言 + 它依据的数字 + 能带来什么（收益/动作），全部由**确定性规则**从②的数据推导（`decision_matrix::dig_findings`：中位数偏离、跨度阈值、币种一致性——**规则生成，非 LLM**，区头明示）。后端只出结构化字段（kind + 数字），中文句子由前端模板组装（与 `remedy_for`→labels 同一条「后端出数、前端出话」纪律）。首批三条规则，每条至多一条、全量上限 4 条：

1. **cost_outlier**：同币种内单会话成本 > 2× 中位 且缓存命中 < 50%，且存在命中 ≥ 90% 的更便宜对照行（修复方案的同币种证据）——缺对照不报，不凭空宣称"该换谁"。收益 = 每会话差 × 会话数。
2. **marathon**：贡献 Top 会话跨度 > 24h 取最长——带 span/token/失败数与"无单会话熔断"的待拍板回指。
3. **currency_split**：可计价行币种不唯一 → 排序禁用的口径失真，动作直通"明确计费方式"。

②行内同步挂异常旗（与后端同判据的展示层）：outlier 行「单会话成本异常」、低命中行「命中 N%」。条件不满足时规则**诚实缺席**（空态文案"本月没有触发结论规则的异常"），有测试钉住。

### 3.1 待办（行动面）

- **准入门槛**（四条全满足才进）：动作明确、表单预填完成、点击后有可见结果、可撤销。
- 首批成员全部是已验证流程：PRICE_COVERAGE（补价卡，预填 provider/model）、ROUTE_UNCONFIRMED（声明归属）、预算触顶、source_failure（查看数据源）、billing_candidate/group（明确计费方式）。
- **SV6xx 一律不进**。行为规则命中是"发生了什么"的事实陈述，不是"该做什么"的任务。
- 每项展示：一句话（发生了什么 + 影响多少）+ 主按钮（预填跳转）+ 状态迁移（稍后/已解决/不适用）。
- **预算待办必须带归因**（2026-09-19 用户反馈：只给"设置预算范围"没回答"为什么超"）：卡片正文列出同币种已计价部分的前三大组合（各带特征：低缓存命中/马拉松会话），混合币种如实标注未折算未计入；主按钮是「看超在哪」（定位②对比面），预算设置降为次按钮。行为证据行**只读**——状态迁移只保留给有待办语义的组（§8：行为命中没有"解决"语义）。
- 状态迁移后显示计数反馈：「已处理 1 项，待办 12 → 11」。

### 3.2 模型 × Harness 对比（决策面）

- 行 = `(harness, model_id, provider_id)` 组合（数据源 `hourly_by_harness_model` / `hourly_by_harness_provider`，provider 归因沿用 2026-09-18 合并的时间线判定）。
- 列：会话数 · token 总量（四桶可展开）· 名义成本（价卡/目录计价，**币种分栏**）· 单位会话成本 · 缓存命中率 · 浪费率（仅 DSH）· 撞限流频次 · 权限风险标记（口径见 §4.7）。
- 默认排序：**浪费调整后单位会话成本**（§4.3；启用条件 §4.6）。
- 行展开内容：四桶 token · 计价口径与价版本 · **贡献 Top 会话**（§3.3，懒加载）· **指纹跨链**（该组合会话的 invocation_fingerprint 与 issues 重复调用组的对应关系，实机已验证同源案例）· 撞限流/权限聚合数。
- 「便宜但费 token」的判定不靠用户心算：名义单价与单位会话成本并排，配合浪费率/命中率，差距自明。
- tab 顶部一行**新鲜度条**（§4.8）：stale 执行环境名单、同步中状态、数字截止时刻。

### 3.3 证据明细与下钻链（查证面）

现分组表（`renderFindings` 的规则表 + 明细表）整体降级到这里：从②行或「查看全部证据」入口进入，severity/rule 筛选沿用。它回答"这个数字是哪些命中构成的"，不承担首屏。**这是唯一允许走重路径（扫会话日志）的分区**，且仅在显式展开时（§1.6）。

**下钻终点是原始会话（脱敏轨迹）**。链条：②行展开 → 贡献 Top-N 会话（懒加载，按 token 贡献排序，数据面见 §5.3）；③证据行 → 会话详情（`workbench.js` 现有 issue → `showSession` 跳转路径，接进本链即可）；会话详情内可再进 TraceGraph 轨迹视图。服务端能力已备（`sessions_search` / `session_detail` / `session_trace`），本规格只做接线，不新增存储。**「原始」= 脱敏 workflow timeline + 轨迹图，永不是原始 JSONL / 调用参数 / 原生会话 id**（session_ref 是不透明引用）——与 issues_summary 的 code-aware redaction 同一条隐私边界。

**轨迹图的已知盲区要如实呈现**（2026-09-19 实机核验）：`branch_state` 恒 Live（废弃分支与真实路径不可区分——恰是浪费分析最需要的信号）、`ModelChange` 节点不产出（多模型会话的切换时点只能从 usage 节点侧面看）、turn 级成败无信号源。UI 不得暗示图比数据知道得更多。

### 3.4 叙事摘录层（本地 UI 专属，v2 独立成节）

轨迹的编号叙事（turn-0…turn-N）对用户太抽象。补一个**本地 workbench 命令** `session_narrative(session_ref)`：复用 `source_paths_for_session`（`trace_service.rs:137`）的现场路径解析 + 适配器重读（不存 path、不新建定位机制；适配器已有 `is_pure_text_user` 等 query 识别信号，只是未带出文本），每 turn 提取用户 query 首条与 AI 回复关键信息（各截断 ~120 字）。

三条信任边界：
1. **不进 authority 库**——摘录是呈现时生成的，库保持"计费/行为事实"纯度，不存对话文本；
2. **不进 MCP 面**——脱敏纪律约束的是 agent 消费面（issues_summary"never expose raw errors or invocation arguments"）；本地 UI 给用户看自己的数据不构成泄露。两个信任层，分开处理；
3. **诚实降级**——截断文件/非纯文本 turn 显示"该 turn 无可读摘要"，不静默跳过。

语义级内容（如"这 turn 在重构代码"的判断）若未来需要，只允许出现在本层（本地、呈现时、可弃），永不落库——与 §4.9 任务画像的 `inferred` 纪律同界。`TraceNodeType::UserTask` 进图（方案 B）留 P2+ 另议，走 spec §2.1 修订。

## 4. 决策面指标口径

1. **名义成本**：现有计价输出（价卡覆盖 `claude_day_cost` 路径 + 目录），按币种分栏，不跨币种合计。
2. **浪费率**（仅 DSH）：`waste 检测器增量 token / 输入侧 token 总量`。非 DSH 执行环境显示 `—`，**不显示 0**。缺 usage 样本的 turn 按 waste.rs 现纪律跳过（AC-08「缺一不得展示」）。
3. **浪费调整后单位会话成本**（排序用）：`名义成本 / 会话数 × (1 + 浪费率)`。**近似排序指标**，列头与 tooltip 明说"近似，仅用于排序提示"；该数字**永不进账单/对账/导出面**（与 `metered_estimate` 不得当账单是同一条纪律）。会话数 = 该组合出现的会话数（sessions 口径）。
4. **墙钟时间**：第一版用会话事件跨度（首末事件时间差）近似，标注"跨度近似"；真任务耗时口径留待后续版本。
5. **撞限流频次**：SV607/608 命中数聚合，标注"每会话均值"。
6. **排序启用条件（v2 新增）**：仅当**参与排序的行计价币种一致**时排序控件可用；币种不一致时禁用并显示原因（当前依赖待办④把 codex custom 换成 CNY 申报口径）。**禁止汇率折算排序**——FX 折算只允许出现在 metered_view 的 ≈ 显示（既有纪律）。**订阅行不参与排序**（月费 ÷ 会话数无决策意义，单会话列显示 `—`）。**未计价行恒排最前**并标「成本未知」——未知比已知贵更值得先看。
7. **行为标记的归组口径（v2 新增）**：SV607/608/610 的聚合**只到执行环境级**，作为②行展开内的"执行环境级证据"呈现，**不做 per-(harness,model) 归组**——多模型会话（实机 1 会话 7 模型）使 session→model 为 1:N，任何单模型归组都是编造。per-model 归组列为 P3 评估项，前提是行为指纹与模型归因先解决。
8. **新鲜度呈现（v2 新增）**：tab 顶部新鲜度条读 `data_status` 的 coverage/freshness：stale 执行环境名列出（如"workbuddy 数据截至 09-12"）；同步进行中显示"同步中 · 数字截至 HH:MM"；引用 stale 执行环境数字的行加行内标注。这是 MCP envelope"引用数字前先读 coverage/freshness"纪律的 UI 版。

## 5. 后端改动面

1. `remedy_for()` 扩 10 个 match arm（SV601–SV610 → 各自专属 remedy_id），前端 labels map 补对应文案。**不改 `make_finding` 的 findings JSON**——remedy 属 issues 表，golden 与 Python/Rust 对等零牵动。
2. 新增决策面聚合查询（`agent-vitals-data` 层，复用 `hourly_by_harness_model/provider` + issues 按 harness × rule group），一个新只读 IPC（如 `decision_matrix`），**含每组合的贡献 Top 会话列表**（session_ref + 跨度 + token 贡献 + 失败数，供②行懒加载展开）。
3. 新增桌面命令 `session_narrative(session_ref)`（§3.4）：本地 UI 专属，**不注册进 MCP 工具面**；实现复用 trace 的路径解析与适配器重读，加 memo。
4. 新增新鲜度读取：`data_status`（或其轻量子集）作为首屏第一批并发命令。
5. `sessions_issues` 载荷不变；③证据明细沿用其重路径（显式触发）。
6. 状态反馈纯前端：transition 前后各读一次 rollup 计数。

## 6. 验收标准

分期标记：〔P1〕〔P2〕〔P3〕；未达成分期前置条件时按分期验收，不提前。

1. 〔P2〕打开 findings tab 首屏：只见待办区与对比区；SV6xx 分组不出现在待办区。〔P1 期间〕首屏 = 待办区 + 收起的证据区，同样无 SV6xx 于待办区。
2. 〔P1〕`remedy_for("SV601")…("SV610")` 均返回非 `diagnostic-only` 的专属 remedy；前端对应文案可显示；行为 findings 载荷字节不变（golden `--diff` 通过）。
3. 〔P1〕待办区每项有预填动作按钮；任意状态迁移后 3 秒内出现「待办 N → N−k」反馈。
4. 〔P1〕**首屏性能**：authority 已同步时，待办 + （P2 起）对比首屏可见时间 < 1s；冷 cache 也不触发会话日志扫描（③显式展开除外）。
5. 〔P1〕新鲜度条可见：stale 执行环境名单 / 同步中状态 / 数字截止时刻至少三者之一在应显示时显示。
6. 〔P2〕对比区每行显示 §3.2 全部列；非 DSH 执行环境的浪费率显示 `—`；输入全零组合的命中率显示 `—`；行为标记以"执行环境级证据"呈现在行展开内，不做 per-model 归组。
7. 〔P2〕贡献 Top 会话块懒加载可用：session_ref + 跨度 + token 贡献 + 失败数；「查看轨迹」进入该会话轨迹视图。
8. 〔P2〕排序规则遵守 §4.6：币种不一致时禁用并说明；订阅行不参与；未计价行恒排最前；浪费调整列带「近似」标注且不出现在导出面。
9. 〔P3〕③证据行 → 会话详情 / TraceGraph 下钻接线完成；轨迹图盲区（分支/切换/turn 成败）在 UI 上有如实标注。
10. 〔P3〕`session_narrative` 可用且三条边界成立：不落库、不进 MCP 面、无可读摘要明说。
11. 全 tab 无跨币种合计、无跨执行环境金额合计（token 总量除外）；墙钟/跨度近似处有标注。

## 7. 分期

- **P1（小，先行）**：remedy 补全 + 待办/证据两分区 + 状态计数反馈 + 新鲜度条。改动面：`issues.rs` 一个 match、workbench.js 渲染重排、`data_status` 轻量接入。**首屏走 authority 聚合，重路径只留给③**。
- **P2**：决策面对比表（`decision_matrix` IPC + 表格渲染，含贡献 Top 会话与失败数、查看轨迹入口、撞限流列（每会话均值）、行为标记执行环境级聚合）。
- **P2 已显式推后至 P3**（2026-09-19 实施时记录）：指纹跨链展示（需要 invocation_fingerprint→组合的执行环境级对齐，多模型会话归组歧义同 §4.7）；Top 会话严格懒加载（当前首查一次性带回每组合 3 条，性能无碍）。
- **P3**：排序启用（依赖待办④统一币种）、③证据行 → 会话详情/TraceGraph 下钻接线、`session_narrative`、任务画像（§9.5）评估、跨度近似升级真耗时口径的评估。

## 8. 明确不做

- 不调 SV605/610 的触发阈值来"消灭"命中——事实就是事实，治理的是呈现，不是证据。
- 不把行为 findings 变成可一键"已解决"就完事的工单——它们没有"解决"语义，只有"采纳与否"的决策语义。
- 不做跨执行环境/跨币种的任何单一汇总数字。
- 不做行为发现的 per-(harness,model) 归组（§4.7）与汇率折算排序（§4.6）。

## 9. 待拍板清单（v2 新增）

实现前需要用户/评审定夺的开放项，不在本规格内自作主张：

1. **tab 名**：「待处理」名不副实（主业已是对比决策）。候选：「发现」「优化」「洞察」。影响 P1 的文案与导航。
2. **单会话熔断**：实机报告发现预算缺"单会话阈值"档（473M 单会话零提醒）。属预算设置（`budget_profiles`）的相邻变更，不在本规格范围——但 P1 的待办区文案依赖它是否存在。
3. **无障碍基线**：仓库有 a11y 验证先例（`verify-workbench-v010-closeout` 检查输入框无障碍名称）。新 tab 的表格/展开行/按钮是否列入同等检查，需定基线。
4. **skill 轴**：发现 tab 对 skill 执行问题天然兼容（`skills_summary` 的 calls/成功率/重试/时长/版本回归列已备，②加轴切换即可），但 2026-09-19 实机数据显示覆盖极薄（9 月仅 4 skill / 6 调用 / 全 unknown / 仅 claude-code）。数据缺口按收益排序：① `skill_finished` 的 outcome 字段疑似未写入（事件在库而 succeeded/failed 全零，`workflow_summary.rs:86-87` 的计数永不命中——疑似一行 bug）；② skill 版本采集（现全 `<unknown>`，版本回归检测等于没开）；③ retry 与 skill 指纹配对；④ codex/dsh 执行环境接入；⑤ skill→token 归因（最难，可长期 unknown）。①②修复后再拍板：进 P3 还是独立迭代。与 Skill 体检 tab 的边界：体检 = 静态定义健康（doctor SV101–508 同源），本 tab = 运行时执行表现，互不重复。
5. **会话任务画像**：补"这次会话在干什么类型工作"（修改型/检索型/研究型/运维型…）维度，让②从"谁便宜"升级到"什么活该用谁"。两条实现路径纪律不同：**确定性推导**（工具 mix 规则，原料 = §7 规范化工具名已全量入库，纯 SQL 可算）可进库但必须标 `inferred`（与 provider 归因的 `route-config-fallback` 同一条"推断留痕"纪律）；**语义分类**（文本判断）只允许留在 §3.4 本地呈现层，永不落库。是否做、先做哪条，待拍板。
