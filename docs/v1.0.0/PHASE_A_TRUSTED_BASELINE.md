# v1.0.0 Phase A：可信基线

## 目标

建立所有后续页面共用的本地数据、金额、价格与结果版本合同。完成后，系统宁可显示未知、未计价或待确认，也不能显示假零、把第三方路由当官方订阅，或让不同消费面读到不同版本的结果。

## 范围

- 版本边界与诊断版本映射：REQ-001–004。
- 成本与证据纪律：REQ-089–096。
- 公共价格目录、离线回退和历史缺价处理：REQ-097–108。
- 数据/服务契约：REQ-143–149。

当前已完成但仍需和其余项整体验收：REQ-103、REQ-144。

## 必须先落地的合同

1. 分离公共价目、用户计费声明、实际付款/账单、预算、原始事实和派生估算；个人信息绝不进入公共资产。
2. unknown/custom/冲突路线默认 `metered_estimate + has_unresolved`；原厂价卡不能改变事实中的 provider 身份。
3. 查询统一接受时间窗、时区、来源/执行环境/provider/计费口径，并返回金额、覆盖、原因、版本与来源。
4. 配置修改经校验、幂等写入、影响预览、后台重算与状态查询；原始事实不可被用户声明覆盖。
5. 菜单栏、工作台、CLI 和 MCP 只读同一结果版本；失败期间继续读取上一个完整结果。

## 关键工作包

- 价格目录更新链路：官方来源优先、规范化、校验、版本/指纹/来源记录、离线旧版本回退和指数退避。
- 历史价格策略：区分历史有效价、当前价参考估算和完全未计价；历史重估创建新结果版本，绝不改写旧账单。
- 统一计费声明：支持账户、路由、执行环境、模型和有效期的范围；保存前可预览影响，撤销生成修订。
- 公共计算：token 守恒、去重、跨日、币种精度和覆盖计算只能在公共服务完成，前端不能重算。
- 结果发布：原子切换或版本绑定，防止摘要已新而会话仍旧。

## 验收锚点

- AC05–AC10、AC13–AC17、AC21；其中 AC13/14 需在 C 的 UI 闭环中最终复验。
- 干净安装没有任何个人套餐或预算；数据库/查询错误不能伪装为零或正常空态。
- 对同一筛选与结果版本，菜单、总览、日历、会话、CLI 与 MCP 的金额和覆盖一致。

## 退出条件

所有本阶段 REQ 在权威 PRD 中有实现与测试证据；至少一个真实价格更新/离线回退演练通过；一项有范围的声明变更可预览、重算、撤销，并证明原始事实不变。之后 B/C 才可依赖这些接口做体验层。

## 当前实施单元：声明作用范围与修订链

现有本地声明表只证明“声明不是付款”，尚不足以影响归因。下一纵切面必须同时交付：账户/路由/模型/执行环境及有效期范围、不可变 revision、撤销产生新 revision、按范围列出受影响事实的只读预览，以及失败时不发布半新结果。未满足这些条件前，不将声明接入总览、日历、会话或预算结果。
