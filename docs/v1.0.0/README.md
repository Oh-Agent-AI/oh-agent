[v1.0.0-beta.1 执行计划](./BETA_1_EXECUTION_PLAN.md) 将上述范围拆为七个阶段和可跟踪任务，定义关键路径、职责、夹具、阶段出口、缺陷回归与 Go/No-Go。执行状态应记录在发布规格规定的独立验收台账中。

[设置页信息架构与表单规格](./BETA_1_SETTINGS_PAGE_SPEC.md) 是 Beta 1 M2「设置中心」的 UI 合同：基于设置 tab 整页截图与源码核对，归纳当前页面"乱"的四类根因（四层标题三套命名、三套预算表单与"分"单位、十个实心主按钮、十五句免责与原始 reason code 上卡面），给出 5 分区左栏导航（数据源 / 计费与套餐 / 预算 / 统计与数据 / 关于与诊断）、"分区→设置项→控件"三层结构、按钮四级与"一页一个主按钮且必须是待办"、货币主单位输入、一句说明上限、reason code 映射表；预算收口为唯一的"按量估算观察预算"表单（固定 80%/100%，旧预算与已确认支出预算只读），账单录入/CSV 与价格在线更新按 D01 隐藏；含 IPC 映射、mock 形状修正（`warning_ratio_bp` 万分比）、四项待拍板决定（总览预算卡改读 `budget_profiles.estimate`）与结构守卫验收。

[线路单位成本与「现在该用谁」决策规格](./ROUTE_UNIT_COST_DECISION_SPEC.md)（**范围 `v1.1`，不进 Beta.1**）把决策卡从配额展示提升为"当前可用性 + 边际成本 + 切换成本 + 稳定性"的决策组件：按线路（执行环境 × 服务商 × 模型族，聚合前先归一）计算用户自己用量结构下的稳态/切换首轮单价（价卡不完整不按 0），多日窗口的命中率稳定性分级（阈值按线路自适应；单日事故 ≠ 不稳定），可复算的 W1 缓存低命中嫌疑金额，按自然周、按当周价卡与汇率快照计算的动态排名与名次归因，以及与排行分离的订阅时间窗口提醒（Codex 正向阈值 + Claude Pro 限流事件三态）。核心原则：只比钱不比质量、缓存不可迁移、未知不参与推荐。Beta.1 只保留"有明确配额证据的 Codex + 参考备选文字"。附 2026-09-13 真机锚点与试跑结果。

## 不可并行的边界

1. A 的本地数据合同、结果版本和价格/证据语义先稳定；B 和 C 不得各自计算金额或维护第二套配置。
2. B 的首份 L0 结果依赖 A 的查询及口径，但其 UI、来源发现和导入流程可在 A 的稳定契约上并行。
3. C 的计费确认、预算、提醒、菜单栏与会话视图必须共用 A 的声明、影响预览和版本化重算链路。
4. D 可提前准备性能数据集、文档和打包脚本，但签名公证、迁移演练及正式安装验收只能在功能稳定的 RC 上完成。
5. E 不是代码测试的替代品；外部试用、签名公证与真实设备证据都不能预先勾选。
