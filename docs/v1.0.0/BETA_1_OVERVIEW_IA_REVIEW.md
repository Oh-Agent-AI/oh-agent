## 1. 结论

`BETA_1_UI_UX_GAP_ANALYSIS.md` §5 要求的**搬迁**已经做完：tab 改名（Token 日历→用量、Issues→待处理、数据源→设置）、设置按六个分区重排、导出/保留期/统计时区/价格目录/诊断下移。

但 §4.1 要求的**重建**没有做完。总览的替换内容比 §4.1 规定的更薄，而且三张条件卡是被 CSS **无条件删除**、不是被搬走。实测：1500px 视口下首屏内容约 600px，其余约 60% 为空白。

一句话概括观感来源：**这个页面只保留了文档要求删掉的东西，没有建起文档要求补上的东西。**

四类偏差（逐条对照见 §3）：

| # | 偏差 | 性质 |
|---|---|---|
| A | 条件性卡片被无条件删除（预算 / 本月实际支出 / 单位成本） | 实现与规格冲突；预算卡是功能性丢失 |
| B | §4 要求分开的两个轴被合并（价格覆盖 ↔ 路由/缺价） | 可信度卡在告警页面上报「100%」 |
| C | §4.1 要求「主动作之后展示」的趋势被折叠进 `<details>` | 首屏失去唯一的趋势入口 |
| D | 结论句跨币称「含」（`本月实付 ¥8.64（含订阅月费 $20.00）`） | 违反钱不分币相加的口径契约 |

另有两处独立缺陷（§3.5）：同步时间按 UTC 截断（与同页本地时间差 8 小时）、note 行括号不配对。

## 3. 逐条偏差（对照 §4 / §4.1）

### 3.1 [A] 条件性卡片被无条件删除

**规格原话**（§4 第 80 行）：预算进度「高但条件性 | **仅配置后出现摘要卡**；操作入口跳设置；未配置不显示 0%」。

**实现现状**：

```css
/* workbench.css:247 */
.month-band .secondary-metric { display: none; }
```

这条规则命中 `workbench.html:89 / 94 / 99` 三张卡（本月单位成本、本月实际支出、预算），**无 `open` 态、无 media query、无第二落点**。

最严重的是预算卡：`workbench.js:615-617` 仍在取 `ov-budget-amount/-fill/-sub` 并写入，`workbench.js:637-641` 连 `no_budget` 分支都写了（"尚未设置预算 · 成本统计不受影响"）——**JS 完整实现了文档的"仅配置后出现、未配置不显示 0%"规则，CSS 在两种情况下都把它删了**。两层直接冲突，且以 CSS 为准。

后果：mock 中预算已配置（月 100 CNY，已用 68%，level=warn），按文档应显示摘要卡，实际全站看不到任何预算读数；设置页只保留了预算的**输入表单**（`#ov-budget-settings`），读数没有任何落点。这是**功能性丢失**，不是排版取舍。

**处置**：删掉 `.month-band .secondary-metric{display:none}`，把「未配置不显示」交回 JS（已经实现了）；预算卡回到首屏（见 §4）。

### 3.2 [B] §4 要求分开的两个轴被合并

**规格原话**（§4 第 73、75 行）：价格覆盖是**第三主卡**且「显示未计价 tokens **并可下钻**」；「数据读取失败/缺价 | 高 | **与计费待确认分开**；若更紧急则取代其成为本页唯一主动作」。

**实现现状**：`renderOverviewCoverage`（`workbench.js:509-531`）把两者合成一张卡，且公式只算价格轴：

```js
// workbench.js:527
const coverage = Math.max(0, Math.min(1, 1 - unpriced / total));
```

`unresolved`（路由证据缺口）**完全不进公式**，只降级成副行小字。于是 mock 的 `unpriced=0 / unresolved=18000` 渲染成绿色的 **`100% 可计价`**，而同一份 payload 的 `health` 是 `warn`，紧邻的横幅还在说"金额可能为估算/部分覆盖"。

后果：专门用来传达"可信"的卡，在告警页面上报全绿，用的还是仓库规定"绿色 = 好状态"的强调色（`workbench.css` 中 `.trust-card .amount { color: var(--accent) }`）。这是 §4 明确要求分开的两个轴被合并后的直接产物——**价格覆盖确实是 100%，但用户读到的是"一切正常"**。

**处置**：拆成两条独立状态行（价格覆盖 / 路由与缺价），颜色由 `health` 决定而非由百分比决定；价格覆盖保留下钻入口（§4 明确要求）。

### 3.3 [C] 趋势被折叠

**规格原话**（§4 第 76 行）：「趋势和服务商分布 | 高 | **主动作之后展示**」；§4.1 线框（第 109 行）把「用量与名义成本趋势 / 服务商分布」画在**可见流**里，位于主动作之后。

**实现现状**：趋势（`#ov-days-list` 本月逐日）、双轨账、决策卡、数据源，全部进了一个 `<details>`（`workbench.html:118-189`），摘要文案是「查看费用组成、趋势与数据来源」。首屏因此没有任何趋势/分布的入口。

注意这里与 §4 第 86 行不冲突：§4 说"完整逐日移到用量页，总览只留**小趋势**和查看用量"——要实现的是**小趋势**，而不是把趋势整个折起来。

### 3.4 [D] 结论句跨币称「含」

`renderMonthVerdict` 渲染：`本月实付 ¥8.64（含订阅月费 $20.00）`。

`¥8.64` 是 CNY 按量实付；`$20.00` 是 USD 订阅月费。二者是**两种币、两种口径，从未相加也不可能相加**（`total_actual_spend` 只含 CNY 一栏）。"含"字是假的，而这恰好是 v0.9 整套分币词表要保护的不变量（分币分栏永不相加）——现在这条不变量不是被违反在脚注里，而是被写进了**页面最显眼的一句话**。

§4 第 79 行只要求「已确认支出……仅有数据时出现并标'已记录部分'」，并没有要求把实付写进标题句。这句是重构前的历史产物（审查 UX#2），本次重构保留了它却删掉了被它引用的卡片（"明细见下"指向的正是被隐藏的本月实际支出卡）。

**处置**：删掉这句话，改由 §4 的三主卡承载（口径分栏，不成句）。

### 3.5 两处独立缺陷

| 位置 | 现象 | 根因 |
|---|---|---|
| `workbench.js:693`、`workbench.js:5119` | `上次同步：成功 08:14`，同页 note 写 `数据更新于 16:14` | `sync.at.slice(11, 16)` 直接切 ISO 原串的 **UTC** 时位；note 走 `formatStatisticsDateTime`（东八区）。§5.1 第 125 行明确同步状态要用文字承载时间，即这个时间是可读信息，不是装饰 |
| `workbench.js:676` | 屏幕上是 `数据更新于 16:14）` | 非过期分支 `"数据更新于 " + freshHHMM + "）"` 自带右括号、没有左括号（过期分支才是配对的） |

### 3.6 文档卫生

- `workbench.html:61-71`：一段描述"今日五 tile / 恰好一个 hero"的注释块，在本次重构后**悬空**——它描述的今日行已被移进嵌套 `<details>`（`workbench.html:120-149`），注释却留在月度带上方，指向了错误的元素。
- `workbench.css:1019-1020`：`.wb-foot { display: none; }` 符合 §4 第 95 行「删除固定页脚」，但 `workbench.js:763` 仍写入 `wb-foot`——是死代码；且 §4 要求"数据根简写**放设置**"，目前 `data_home` 反而经由 `#ov-note` 漏回总览底部（实测渲染出"浏览器调试模式"）。
- `workbench.css:1262`：`.cards.month-band .stat .amount { font-size: 18px; font-weight: 600; }` 给**每一张**卡同一个字号字重。HTML 注释声称"恰好一个 hero（名义）"，但全仓**没有任何 `.hero` 规则**——设计意图只存在于注释里，所以 `374K` / `≈¥114.60` / `100%` 三张不同量纲的卡视觉上完全等权，没有视觉入口。

## 4. 目标信息架构（§4.1 的实现级细化）

§4.1 给了首屏顺序，但没给"每块显示哪些字段、异常态怎么变"。下面是可直接落实现的细化。

### 4.1 页面职责（承 §3.1）

总览只回答一件事：**本时间范围用了多少、费用是什么口径、哪里需要我确认。**

因此总览**只承载口径轴**（名义 / 按量 / 订阅 / 未计价），**时间轴全部归"用量"页**。推论：总览不得出现完整逐日（§4 第 86 行已是此意），也不得复现"用量""设置"已有的数据。

### 4.2 首屏结构

```text
本月 ▾   [今天 | 7天 | 本月 | 自定义]        已更新 16:14 · 3个来源正常，1个需检查

┌ 本月支出 ──────────────┐ ┌ 今日消耗 ─────────────┐ ┌ 预算 · 按量实付 ───────┐
│ 按量实付   ¥8.64  CNY  │ │ 246K tokens           │ │ 68%   ¥68 / ¥100  预警 │
│ 订阅月费   $20.00 USD  │ │ 按量实付  ¥3.21       │ │ █████████████░░░░░░░░ │
│ 名义(诊断) ≈¥114.60    │ │ 名义(诊断) ≈¥9.40     │ │ 日预算 ¥5 · 未超       │
└────────────────────────┘ └───────────────────────┘ └────────────────────────┘
      ↑ 口径分栏，永不相加        ↑ 只此一张，不另建五卡排     ↑ 仅配置后出现

⚠ 路由与缺价：18K tokens 未定 provider｜本月按量金额可能偏低            [数据状态]
✓ 价格覆盖 100% · 无未计价 token                                    [查看价格依据]

12.59B tokens 的付费方式待确认；当前仍按原厂 API 价格估算   [确认计费方式] [稍后]

▸ 费用构成 · 趋势 · 服务商分布                                       （主动作之后）
```

### 4.3 每块一个问句

| 块 | 回答的问句 | 数据源 | 空态 |
|---|---|---|---|
| 时间范围行 | 这些数字是什么范围的、多新 | `read_overview.sync` + 时间范围选择器 | — |
| 本月支出 | **我这个月要付多少** | `data_monthly_summary.total_actual_spend` + `by_provider` | 无数据（不渲染 0） |
| 今日消耗 | **我今天用了多少** | `data_daily_summary` | 无数据 |
| 预算 | 还剩多少额度 | `read_overview.budget` | 未配置 → 整块隐藏（§4 第 80 行） |
| 路由与缺价 | 数字受什么影响 | `data_status.data.health/unresolved_tokens` | 干净 → 收敛为一行浅色 ✓ |
| 价格覆盖 | 名义成本能解释多少用量 | `data_status.data.unpriced_tokens` | 干净 → 收敛为一行浅色 ✓ |
| 主动作 | 我现在该做什么 | `billing_import_candidates` | 无候选 → 整块隐藏 |

### 4.4 三条硬约束

1. **口径分栏，永不相加。** 「本月支出」是多栏块：按量实付、订阅月费**分币各自成栏**，跨币只分栏、单币才出合计。不得出现"含"字句（§3.4）。
2. **颜色来自 `health`，不来自百分比。** 可信度是**状态**，不是分数。`100% 可计价` 这种写法必须消失（§3.2）。
3. **可完善事项 ≤3，主按钮唯一**（§4.1 第 113 行）。同屏两个"18K"必须合并为一（§3 实测）。

### 4.5 与 §4.1 的差异说明

§4.1 线框把三主卡定为 `名义成本 / 已观测用量 / 价格覆盖`。本文据此**保留**这三者是主卡，但调整两点，理由如下：

- **主卡次序**：§4 第 71-73 行明确"名义成本"是**第一主卡**、"已观测 tokens"第二、"价格覆盖"第三。当前实现渲染顺序是 tokens → 名义成本 → 可信度，与规格相反，应改回。
- **「本月支出」上升为主卡**：§4 第 79 行把"已确认支出"列为**条件性**。但 §3.1 定义总览要回答"费用是什么口径"，而只有实付回答"要付多少"。建议按条件性处理——**有实付数据时**它排第一，无数据时让位给名义成本。这一条是本文对 §4.1 的**建议修订**，需拍板（§8）。

## 6. 不变量与守卫

前四条是设计不变量；**I5 是防复发机制，没有它前四条会在下次重构里静默失效。**

- **I1 口径分栏永不相加。** 「本月支出」是多栏块，不是"含"字句；跨币只分栏，单币才合计。
- **I2 可信度是状态，颜色来自 `health`，不来自百分比。**
- **I3 一个 tab 一类问题。** 总览不得复现"用量"/"设置"已有的数据；总览不含完整逐日。
- **I4 首屏可完善事项 ≤3，主按钮唯一。**
- **I5 可见性守卫（新增）。** 本轮的根因是测试**看不见 CSS**：`scripts/verify-workbench-kpi-decide.mjs` 用 `node:vm` + 假 `document` 跑真实 `workbench.js`，断言的是 `textContent`，因此 `display:none` 对它完全免疫——预算卡的诚实性断言至今仍打印 `ok`，而用户看不到那张卡。

  **落地方式（两样现成的东西组合）**：`apps/desktop/ui-dev/public/tauri-mock.js` + 无头 Chrome（本轮已跑通）。新增 `scripts/verify-workbench-visibility.mjs`：

  1. 起 vite serve（或静态服务 `ui/` 并注入 mock）；
  2. 无头 Chrome 打开 `workbench.html`，等渲染稳定；
  3. 对**渲染器写过的每个 id** 断言 `getComputedStyle(el).display !== "none"` 且 `el.offsetParent !== null`；
  4. 反向断言：CSS 中不存在 `display:none` 规则命中这些 id（防止"JS 写了但 CSS 藏了"再次发生）。

  与静态解析 CSS 相比，这条守卫跑的是**真实 DOM**，能抓住任何隐藏机制（`display`、`visibility`、零尺寸、被 `details` 收起）。清单应显式列出必须可见的 id，新增 KPI 时同步登记。

## 7. 决策更新：今日消耗必须有一张 KPI 卡

**决策（用户，2026-09-13）：今日消耗很重要，总览至少要有 KPI 卡。**

这与 §4 第 77 行「今日 tokens / 今日名义成本 | 中 | 默认放菜单栏；总览选"今天"时间窗时复用三主卡，**不再另建一排"今日卡"**」存在表面冲突。调和如下——**两者针对的不是同一个对象**：

- §4 反对的是**"另建一排"**：重构前那排五 tile（今日 tokens / 今日名义 / 今日单位成本 / 今日实际 / 缓存命中）与月度带逐张对仗，其中今日单位成本、缓存命中已被 §4 第 81/82 行判为"从首屏移除"，这一排本就是被否掉的对象。
- 本次决策要的是**一张卡**，不是一排。

**结论（取代 §4 第 77 行的"不再另建"表述）**：

1. 首屏第一行固定三卡：**本月支出 / 今日消耗 / 预算**。
2. 「今日消耗」只装两个决策相关字段：**今日已观测 tokens** + **今日按量实付**；名义成本作诊断脚注，不给主位。
3. **不**恢复今日单位成本、今日缓存命中率（仍按 §4 第 81/82 行移除）。
4. 菜单栏保留今日（§4 第 77 行"默认放菜单栏"不变）；总览这张卡是应用内入口，与菜单栏是同一数据的两个 surface，不是重复排卡。
5. 时间范围选择器（§4 第 70 行要求）作用于**趋势/次级区**，不改变第一行三卡的固定语义——避免"选了 7 天，本月支出卡变成 7 天支出"这种口径漂移。
