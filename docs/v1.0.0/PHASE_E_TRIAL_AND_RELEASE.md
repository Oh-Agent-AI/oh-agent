# v1.0.0 Phase E：试用与正式发布

## 目标

用外部目标用户和全部发布门禁证明 v1.0.0 值得正式发布，而非仅证明代码测试通过。

## 范围

- PRD 第4节成功指标与本地最小事件的合规测量。
- PRD 第17节的 12 名目标用户、两周试用、三项指定任务、留存与卸载原因记录。
- AC01–AC28 的最终矩阵复验。
- RELEASE-01–RELEASE-05 的最终放行。

## 试用设计

1. 招募至少12名目标用户，覆盖官方订阅、混合订阅/API、API 为主、升级用户及无日志用户的代表性情形。
2. 记录首次 L0 价值、找额外费用、找高消耗会话、确认套餐影响三项任务的成功与耗时；仅记录最小事件，不记录会话正文、路径、账户或密钥。
3. 两周内观察有效使用、菜单/工作台查看和校准完成；访谈继续保留意愿、可感知价值与卸载原因。
4. 对未达阈值的数据报告样本量、偏差、原因与后续迭代结论，不用后台追踪或强制提醒补样本。

## 发布放行清单

- 成功指标与试用证据完整（RELEASE-01）。
- 无障碍、隐私、性能、恢复验收通过（RELEASE-02）。
- 安装、签名、公证、平台支持与外部依赖真实完成（RELEASE-03）。
- 所有测试门禁通过（RELEASE-04）。
- 独立逐项终审、全部需求证据和最终提交完成（RELEASE-05）。

## 退出条件

所有 237 项在权威 PRD 中逐项具备实现与证据；发布阻断项为零；正式安装包已在目标机器验证。若两周试用的留存目标不足，必须给出可审查的归因与下一轮决策，不能将“代码已合并”误报为产品发布成功。
