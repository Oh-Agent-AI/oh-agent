# 本地 PvE 上一回合复盘

## 本轮范围

依据主工作树升级计划 §12.3，补充上一回合的实际结算摘要，帮助玩家不必逐条计算事件。只使用已提交回合的 `lastLog` 和同一次结算经 `buildHealthTimeline` 校验的生命值时间线；没有更改规则、AI、远程协议或数据范围。

- 显示敌方倒下的不同单位数、实际落空行动数、机甲累计扣血和全部建筑累计扣血。
- 受损是该回合各次扣血的总和，不用后来治疗抵消；建筑包含非守卫目标的建筑。敌方倒下是实际生命由正变为不大于零，不判断是谁击杀。
- 缺少或未通过校验的时间线时，生命值相关统计显示 `—` 和不可用说明；落空仍从已接受事件计数。不会将未知显示为零。
- 原有实际事件及顺序生命值明细保留在「上一回合结果」中；真实落空的原因继续优先显示。动画完成或跳过后显示，预测与结果分开。
- 小屏统计采用单列，并避免城市全局 `dl` 样式覆盖；面板可滚动，完整定义在展开内容及无障碍描述中。

## 验证与边界

- 回合统计单测覆盖伤害与治疗、重复倒下去重、事件落空、空时间线及缺失/校验失败的时间线；不修改输入。
- 独立 synthetic Chromium 通过真实界面部署、提交和跳过演出，按控制器的实际事件及已校验时间线独立核对四项统计；中英文桌面和 390px 手机检查默认可见、标签不拆行、面板不遮挡目标与操作，且可展开与键盘滚动。
- 原有组件级浏览器测试覆盖落空原因、完整事件和生命时间线不可用状态。截图位于 `artifacts/mecha-clarity-p0/turn-recap/`。
- 这不是全局失败复盘：没有可靠证据时不推测最大伤害来源、可避免性、跨回合致命事件或击退的策略价值；尚需真实设备、Tauri 与可访问性人工验收。短屏或较长落空信息可能需滚动查看统计。
- 额外全 HUD 回归发现 640×480 在提交后移动列表的选择控件无法完整显示/命中，需继续排查；该问题不属于本轮四种摘要尺寸的通过结论。旧 `verify-city-mecha-settings-layout-browser.mjs` 仍查找已不存在的 `.mecha-card-action`，未完成部署即检查战斗卡片，因此本轮不能作为通过的回归证据。
