# 机甲战棋 v1.5：状态效果与表现实施规格

状态：实施规格，未表示功能已完成或开放。
日期：2026-11-06
关联：`MECHA_V15_SEQUENTIAL_TURN_SPEC_2026_11_06.md`、`MECHA_STATUS_ENCOUNTERS_PROPOSAL_2026_11_06.md`。

## 1. 目标与范围

在本地 PvE 逐台行动模式中，让玩家能预判、遭受、识别和应对中毒、燃烧、冻结、眩晕。状态的规则、血量、命令限制、视觉、回放与重启恢复必须一致。首批由四种怪物施加给机甲；本规格不新增玩家机甲施加状态的技能，不开放 PvP、远程、挑战码或其他对象的状态效果。

数值是首轮测试基线，可在发布前通过版本化配置调整；正式规则版本发布后不得原地改变其语义。四种状态和对应命中已接入隔离的本地测试规则，开发入口支持指定怪物；正式入口尚未开放。当前实现进度和未完成的发布条件见第 10 节。

## 2. 玩家可见规则

| 状态 | 测试数值 | 效果与对策 |
| --- | --- | --- |
| 中毒 | 2 个己方回合，每回合结束受 1 点伤害 | 躲避孢群体预告范围；可继续移动和行动 |
| 燃烧 | 2 个己方回合，每回合结束受 1 点伤害 | 躲避流环体预告射线；可继续移动和行动 |
| 冻结 | 1 个己方回合 | 不能主动移动，仍可攻击、维修或待机；可被外力位移 |
| 眩晕 | 1 个己方回合 | 不能主动移动或行动；可被外力位移，不阻止玩家结束回合 |

状态由敌方阶段施加后，从紧接着的己方回合开始计时；即使机甲提前行动，也要等整个己方回合结束才结算一次，不以点击次数计时。中毒与燃烧的伤害在敌方行动前结算，实际生命值变更、死亡和胜负都按权威规则处理。若因持续伤害终局，停止尚未执行的敌方阶段，并明确记录发生顺序。

同一目标、来源和类型重复施加时，保留较大的伤害和剩余回合数，不累加；不同来源独立存在，按固定来源 ID 顺序结算。中毒与燃烧可共存。冻结与眩晕可共存，限制取并集；各自独立到期。同一技能一次命中同一机甲最多施加一次，重复命令或动画播放不得再次施加。来源死亡不清除已施加状态；目标死亡时移除其状态且不再触发后续伤害。状态不可由普通移动撤销；回合重置恢复回合起点状态及持续时间，并保留已消耗的重置次数。

命中但直接伤害为 0 时仍视为命中并施加状态；未命中、目标死亡、技能取消或完全被明确声明可阻挡状态的护盾吸收时不施加。当前机甲没有通用状态护盾：首发不虚构该机制，今后引入时须由护盾合同和测试明确声明。持续伤害不受机甲防御减免，按照独立伤害事件扣血；首发无净化、抗性和免疫，界面不得暗示它们存在。

## 3. 首批怪物与预告

| 对象 | 技能及权威命中 | 状态与预告 |
| --- | --- | --- |
| 孢群体 | 现有孢子弹跳，落点范围内被该技能实际命中的存活机甲 | 中毒；预告落点、范围、伤害及中毒持续时间 |
| 流环体 | 现有环轨穿刺，射线上按既定次序实际命中的存活机甲 | 燃烧；预告射线、穿透顺序及燃烧持续时间 |
| 晶簇体 | 新增「棱晶寒束」；敌方准备时绑定一个合法射线方向及目标格，执行时沿该方向结算，目标离开后不追踪 | 冻结；预告射线及冻结限制。既有棱镜护盾不隐式冻结 |
| 引力核 | 现有引力井牵引；仅在被牵引机甲因接触活体单位、可受伤建筑或障碍而无法进入下一格，且权威结果明确记载撞击时触发 | 眩晕；预告牵引方向、预计落点、可能撞击和眩晕，不能证明碰撞时标记未知 |

棱晶寒束的首轮实验配置为射程 4 格、直接伤害沿用当前大怪攻击与目标防御的既有计算、无独立冷却；这些数值在发布前需要实战验收。攻击沿用环轨穿刺的棋盘直线和遮挡规则，但只命中最近的一个合法机甲，方向在预告时固定；无合法射线时使用既有护盾意图。奇数回合优先寒束、偶数回合使用护盾，回合编号保存在权威状态中，回放必须复现。引力井现有位移结果若不携带足够的阻挡对象与碰撞证据，先扩展规则结果，不能用“没有移动”或攻击血量变化推断撞击。边界、水面或其他未列出的不可进入地形不触发眩晕；是否伤害碰撞双方仍遵循既有碰撞规则，本功能不额外改动伤害。

预告显示的是当前棋盘下的预测，玩家移动、推挤或击杀怪物后需要重算；目标选择和技能方向的绑定语义不能被重算悄悄替换。实际未命中时显示落空，不播放状态命中演出。

## 4. 权威状态、事件与顺序

新增显式启用的状态规则版本及有界状态账本，写入对局权威快照和回合检查点；每条记录至少包含版本、状态类型、目标实体、来源实体、强度、剩余受影响己方回合及稳定实例标识。实例和命中标识由对局内确定性输入生成，不包含 City 数据。严格校验实体、数值和上限；重复 ID、无效状态或不支持的规则版本必须拒绝，不能部分提交。

建议在现有统一效果链上增加明确的 `ApplyStatus`、`TickStatus`、`RemoveStatus` 和命中/碰撞证据；规则权威负责目标解析、生命变更、去重与结算，渲染只消费结果。版本化事件至少有 `applied/refreshed`、`damage`、`expired/removed`，包含来源、目标、实例、命令及触发技能关联、回合、先后序号和伤害前后血量。旧 `TurnEvent` 与 v1.4 线协议不得被未经版本化地改写；新事件采用独立版本或明确的适配层，事件与快照在同一命令事务中提交。

一个 `EndPlayerTurn` 的顺序：①确认是否放弃尚可行动的机甲；②按机甲固定 ID，再按状态类型与来源 ID 的固定顺序结算当回合状态伤害与到期；③每次伤害后处理死亡及胜负，清理死亡目标的剩余状态；④未终局时沿用现有环境、敌方动作、冷却和下回合准备顺序；⑤敌方每次真实命中先结算直接效果与死亡，再对仍存活的目标施加状态；⑥生成下一玩家回合机会及检查点。持久化确认后公布该次原子结果。眩晕机甲不应被误算为有未使用行动机会；冻结机甲仍可行动，仍属于需要确认放弃的对象。

规则层拒绝冻结目标的主动移动和眩晕目标的主动移动/行动，返回可本地化错误；预览与确认共用此校验。强制位移不受这两个主动操作限制。任何异常、失效目标、旧 revision 或保存失败不得留下半次伤害、状态或行动消耗。预览克隆权威状态和确定性上下文，不能扣血、递减状态、写日志或改变随机源。

## 5. 演出、交互与无障碍

每种状态均有三种不同用途的反馈，所有表现只由已验证事件和快照驱动：

| 状态 | 命中瞬间 | 持续期间 | 扣血/消失 |
| --- | --- | --- | --- |
| 中毒 | 短促毒雾与命中文字 | 机甲附近绿色毒性粒子及「毒」图标 | 每次伤害有数字和轻量受击；到期毒雾消退 |
| 燃烧 | 火花与火焰扑附 | 低强度火焰/烟及「燃」图标 | 每次伤害同步数字与火焰闪动；到期熄灭 |
| 冻结 | 冰晶包覆和短暂凝结 | 冰晶轮廓及「冻」图标 | 到期冰晶碎散；强制位移不解除状态 |
| 眩晕 | 冲击与短促失衡 | 头顶环形闪光及「晕」图标 | 到期图标和环形闪光消失 |

图标显示剩余己方回合，选中详情说明来源、伤害和限制；中英文、键盘、触屏、屏幕阅读器均可读取，不能只靠颜色表达。预告与实际状态要明显区分，未知结果明确显示未知。状态持续特效必须绑定实体而非棋盘原格；位移、死亡、单位复用、取消、重置、退出和重载均正确释放或根据最终快照重建，避免残留与泄漏。

持续特效有并发与粒子上限，不遮挡单位、血槽、格子或点击；支持缩放及低性能降级。减少动态效果时使用静态图标/轮廓和文字，保留所有信息。跳过、暂停、窗口恢复、演出中断和重播后，模型、血槽、状态图标与最新权威状态收敛；不能因动画结束回调触发结算。资源加载失败时降级到文字与图标，不阻止对局。

## 6. 持久化、版本与范围边界

状态规则与怪物技能必须带显式内容版本，并在初始遭遇、命令回放、自动检查点和摘要中固定。已存在的 v1.5 试验归档若无法证明旧语义，明确拒绝或使用旧解释器；不得静默以新技能重放旧记录。v1.4 的规则、存档和远程协议保持原有行为。新格式须同步更新浏览器与 Rust 的闭合校验、尺寸上限、版本白名单以及旧记录兼容测试；不可通过放宽为任意 JSON 实现兼容。

自动检查点覆盖状态账本、技能选择顺序、检查点、撤销/重置权利和命令去重证据；恢复后同一已提交命令重试返回原结果，不能再次触发状态或伤害。保存失败和不确定确认沿用锁定并重新读取策略。仅存必要的合成/匿名战斗数据，不扩大 City、日志、路径、MCP、导出或远程权限。测试入口必须明确为本地怪物练习，不能把未支持的远程/PvP/挑战码悄悄降级为其他模式。

## 7. 迭代顺序与交付门

1. **契约和基线**：冻结四种状态、触发证据、棱晶寒束与引力撞击规则，建立 v1.4 和旧 v1.5 归档基线；确定新版本字段与兼容策略。产物：可执行合同测试和版本迁移方案。
2. **权威状态**：统一状态效果接口接入对局、限制、回合顺序、死亡和重置；为真实技能提供显式命中/碰撞证据，实装寒束。产物：四种效果均可在纯规则对局中触发、过期、重放和拒绝非法命令。
3. **本地遭遇与 UI**：在显式测试入口选择四种怪物，提供预告、图标、剩余回合、限制说明和中英文无障碍；实现状态特效和中断收敛。产物：浏览器能从部署完成完整状态遭遇。
4. **持久化与宿主**：更新回放、检查点、Rust 校验及版本策略；验证浏览器刷新和隔离 `.app` 正式插件进程重启。产物：重启后状态、命令和视觉投影一致。
5. **验收和启用**：完成矩阵、性能、真实桌面包人工走查及用户可见提示；全部通过后，才将本功能纳入 v1.5 的启用评估。不得把单元测试或合成探针当作最终包视觉验收。

## 8. 验收矩阵

## 10. 实施进度

已开始权威层试验：显式携带 `mecha-status-encounter:v1` 的测试局具备有界状态账本、冻结/眩晕的指令限制、结束回合持续伤害与到期、死亡清理、重置及内存命令重放。状态变化使用版本化事件，旧局不创建状态账本。开发环境可通过 `mechaV15=1` 与 `mechaStatus` 指定四种怪物进行本地测试；正式产品入口尚未开放。

在上述隔离规则局中，孢群体与流环体的真实命中已分别接入中毒和燃烧，并验证目标被击败时不施加状态。引力井增加了带阻挡对象和格子的碰撞证据，障碍、存活建筑和单位可触发眩晕；水面与山地不触发，全部牵引被挡时也可结算真实碰撞，阻挡对象变化会使旧投影失效。上述行为仅在显式状态试验规则中启用，不改变旧规则。

状态持续回合递减现在产生显式事件，孢群和流环的存活目标命中会在状态施加前产生带技能、目标及格子的命中事件。这些事件为后续逐项核对演出和回放提供证据；目前还没有完成这些事件与状态快照、动画的全程校验。

已加入状态账本事件核对：对比施加、刷新、扣血、递减、到期、移除和最终账本，要求施加事件有对应技能命中或碰撞事件，并拒绝被篡改的技能强度、缺失扣血及重复计时。新增几何核对会检查命中目标所在格、射线/范围和引力位移与阻挡对象，并拒绝缺失的命中或撞击证据。表现阶段快照现在包含状态账本，并用己方回合结束边界核对敌方行动前后的状态；敌方击杀机甲时，在捕获敌方阶段快照之前清理其状态。隔离规则局的基础演出须同时通过账本、几何、阶段、血量与提示事件核对，证据不足时拒绝播放。

渲染器已有受验证状态事件的基础瞬时颜色提示，持续伤害的血量变化可调度到对应提示；提示使用有界共享资源，中断时释放。机甲血槽旁已接入多来源状态文字、剩余回合及中英文无障碍标签的投影，播放期间按事件更新。场景级持续状态视觉已实现：毒雾粒子、火焰环、冰晶轮廓与眩晕环附着到机甲节点，随实体移动，并在状态移除、死亡或场景卸载时清理；减少动态效果时保留静态形状。生命周期测试覆盖节点迁移、重复帧有界、状态移除和 reduced-motion。

四种状态怪物均已通过独立合成浏览器遭遇：实际部署、命中状态事件、演出启动与跳过、状态标签、对应操作限制及刷新后检查点恢复。引力核使用有阻挡证据的战场。此证据来自开发测试入口，不等于状态版 Tauri 正式插件重启、人工视觉检查或完整无障碍/性能矩阵；这些发布门仍未完成。

在浏览器合成战场检查截图后，已将冰晶线框收至机甲轮廓附近并降低亮度；调整后的冻结遭遇截图确认状态标签清楚、冰晶不再大幅覆盖单位。该检查仅覆盖冻结场景，另外三种特效的细节仍需视觉验收。

已检查毒、火与眩晕遭遇截图：毒雾与火焰贴附目标，状态标签没有遮挡血槽；眩晕环初版不够明显，已加粗提亮并移至机甲头部高度，调整后眩晕截图可辨识且未盖住标签。此为合成浏览器截图检查，桌面 `.app` 仍需验收。

晶簇体寒束已在隔离规则局中实现固定射线、首个机甲命中、冻结及护盾交替，覆盖躲避、拦截、目标死亡和旧规则护盾回归。新 `v2` 回放记录规则版本和怪物种类，前端通过重执行校验，Rust 宿主仅接受封闭的版本和字段；合成前端生成的冻结检查点已通过宿主 SQLite 单元测试和 CAS 校验。旧 `v1` 回放仍使用旧合同。状态预告、完整特效、四种状态端到端验证、真实桌面包重启与视觉验收仍未完成；当前试验版本不能用于发布。
