# Agent City：城市生机感优化 SPEC

日期：2026-10-04。状态：草案，可用于实现评审；本文不代表功能已完成。

关联：[城市模块](CITY_MODULE.md)、[城市规划](CITY_PLANNING_SPEC.md)、[渲染质感](CITY_RENDER_QUALITY_SPEC.md)、[分享导出](CITY_SHARE_SPEC.md)。本文补充动态环境与活动规则；不替代道路、布局、数据投影及导出契约。

## 1. 目标

默认航拍距离下，用户能辨认城市作息、季节变化、交通与港口运转，以及真实会话的活跃状态。优先把已有系统组织成相互一致的行为，而非增加更多同时运动的物体。

成功标准：同一机位能清楚读出日间公共中心、黄昏滨水活动、深夜安静的区别；同一日期回放可复现；活动不遮挡建筑数据、地标或道路；90/366 天窗口不产生频闪和密集事件。

数据语义保持：楼对应会话，楼高对应 token 对数映射，城区对应宿主。人流、交通、天气、季节均为环境模拟，不表示用户真实地点、人口、出行、天气或工作作息。界面帮助说明一次即可，不在每个物体上重复技术说明。

## 2. 源码核查与实现缺口

核查路径基于本地工作区 2026-10-04 状态，实施前应再次核对差异。

| 系统 | 当前证据 | 本期需要解决的缺口 |
| --- | --- | --- |
| 昼夜 | `engine/CityEngine.ts:updateDaylight`：实况/回放取本机小时；航拍固定约 15:00→19:36 | 本机时间与统计时区可能不一致；统一模式定义 |
| 天气 | `engine/cityWeather.ts:weatherAt`：按日期哈希，日内雨量包络 | 属于合成天气；需与同一日历状态、地图种子协同 |
| 行人 | `engine/cityWildlife.ts:Pedestrians`：默认上限 220，街区环线；输入来源为城区 `carPaths` | 缺少市政/车站/滨水步行目的地；车流路径不应直接被视为可达步行网 |
| 鸟群/萤火虫/流星/火山 | `engine/cityWildlife.ts` 已有昼夜关联 | 部分使用 elapsed，部分按 dt 累加；日期种子不等于任意 seek 可复现 |
| 气球/水龙卷/浮灯 | `engine/cityAmbient.ts` 已存在 | 调整出现条件和密度，避免城市画面变成特效集合 |
| 树木 | `engine/cityParts.ts:applyFlora` 使用 GLB 材质和实例色；程序树也有实例色 | 季节更新需覆盖两条路径，只修改树冠，保留树干、常绿与热带品种 |
| 车船 | `engine/cityParts.ts:update` 按 `distance += speed * dt` 推进 | 需要固定初相位和可求值路径；船目前不构成有停靠节奏的渡轮服务 |
| 施工 | `cityModel.ts` 构造 busyness，`cityParts.ts` 已用其控制吊车旋转 | 不是“只差接线”：视觉已接入，字段来源是总 token / 会话年龄，不能称为近期实测增速 |
| 导出 | `CityEngine.ts:export…` 固定 dt、reset、逐帧编码；航拍 cursor 压缩增长历史 | 导出复现与任意游标复现分别验收；导出 30 fps 不证明实时性能 |

基于提供的 48.3 秒导出视频，已有明确阻碍：约 27 秒高架转角接缝、15–24 秒主体裁切、大面积空路网、夜窗过亮。它们是视觉验收前置缺陷；本期不通过加特效掩盖这些问题。

## 3. 时间与确定性契约（V0，所有新增行为的前置条件）

新增纯状态求值层，建议文件 `engine/cityLifeState.ts`，由 CityEngine 统一传入各系统。输入不包含原始日志、路径或新敏感字段。

```ts
type LifeFrameInput = {
  mode: "live" | "replay" | "film";
  seed: number;
  statisticsTimezone: string;
  cursorMs: number;             // 当前数据日期，模式入口一次确定
  motionSeconds: number;        // 活动相位，调用方显式传入
  snapshotVersion: string;      // 本地快照标识，不导出为机器标识
  quality: 0 | 1 | 2;
};
```

输出包含日历日期、日内小时、季节权重、日夜权重、天气权重、人流目标权重、事件索引；不允许子系统自行读取 Date.now 或 Math.random。

| 模式 | 日历/季节 | 日内光照与人流节律 | 动作相位 |
| --- | --- | --- | --- |
| 实况 | 统计时区下的当前日期 | 当前小时 | 从固定时间锚点推导，保持连续 |
| 回放 | 统计时区下的 cursorMs | 一天以内窗口可跟随小时；长窗口使用固定或用户指定日内时刻，默认日间 | 从 cursorMs 与固定锚点推导；暂停时动作也冻结 |
| 航拍/导出 | 跟随 plan.cursor，季节允许跨月插值 | 片长内固定日间→黄昏→夜晚艺术曲线，避免几十个昼夜快速循环 | 固定影片时间，和数据时间独立；片尾日期、动作相位显式求值 |

长窗口快速 seek 时直接求值最终状态；连续播放时季节用连续日期插值，不增加依赖上次画面的低通滤波。季节历法默认北半球温带虚构城市，标记为环境设定；热带生态带不强行变成落叶冬景。

确定性单位是 `(seed, snapshot, timezone, mode, cursorMs, motionSeconds, quality, lifeVersion)`。同一输入必须与播放历史无关。跨机器逐像素相等不是 WebGL 的承诺：逻辑状态应一致，同环境导出允许规定的像素容差。

周期动作按初相位和绝对时间计算；间歇事件按固定时间桶定位最近候选，固定上限求值，禁止倒放时重跑无限历史。分配稳定对象 ID，种子由城市 seed、系统、对象 ID、事件桶组成，不依赖可见对象数组顺序。

渐进加载/模型更新保持已有对象 ID 与相位；地图规模变化时重新计算可达路线，但不得复用旧规模的禁建边界。缓存键覆盖规模、生态带、季节版本及影响对象分配的规划版本。

## 4. 第一批：已有环境系统协同（V1）

### V1a 季节树色

- 北半球温带使用春/夏/秋/冬连续权重；月份只是关键点，按当地日期平滑过渡。
- 落叶树：新绿→深绿→暖黄/橙→低饱和冬色。常绿树只轻微调整明度；棕榈等热带树保持绿色。
- 本期只做树冠颜色，不宣称冬季落叶；改变树冠稀疏度另立几何/可见性方案。
- 保留生态带与宿主基调；建筑、树干、公园设施、屋顶花园非树木部件不可被统一染色。
- 颜色只在权重超过量化阈值时更新，目标最多 5 Hz；正常实况季节几乎无需每帧上传。直接 seek 立即应用。
- 新增主场景 draw calls：0。不得新增贴图或季节切换时重建整城。

### V1b 行人聚集节律

- 提取可达的步行环线并标注公共中心、社区公园、滨水休闲三种目的地；复用公共用地、河岸与街区数据，不新增用户行为字段。
- 市政/车站中心：白天权重高；滨水：傍晚权重高；社区：全天保留低基线；深夜全局密度降低。先使用下表艺术目标，实际机位验收后校准。

| 当地时段 | 公共中心 | 社区 | 滨水 | 全局人数倍率 |
| --- | --- | --- | --- | --- |
| 06–09 | 0.6 | 0.4 | 0.2 | 0.55 |
| 09–17 | 1.0 | 0.5 | 0.35 | 1.0 |
| 17–22 | 0.4 | 0.65 | 1.0 | 0.85 |
| 22–06 | 0.15 | 0.2 | 0.25 | 0.2 |

- 权重连续插值；通过稳定哈希选取可见实例，保持现有 220 上限。先让群体在宏观机位可见，不放大单个人偶到建筑尺度。
- “迁移”是目的地区域人数重分配，不宣称已实现个体跨城寻路。实例换区域需要确定性的消隐/显现，不可瞬间闪现或穿越河流。
- 没有滨水可达路径时退化到社区公园；桥梁缺少可用步行空间时禁止跨桥迁移。
- 新增主场景 draw calls：0，沿用现有实例网格。

### V1c 鸟群与天气联动

- 清晨优先采用河岸起飞/盘旋的既有路线；雨量上升时可见鸟数平滑降至晴天的约 20%，不通过透明度变成“幽灵鸟”。
- 夜间/大雨隐藏实例后停止无意义的矩阵上传；天气与人流读取同一 LifeState。
- 新增主场景 draw calls：0。不新增鸟种、不新增贴图。

## 5. 第二批：港口成为活动焦点（V2）

- 从现有 harbor 公共用地选取一个主港，建立经过水域与净空验证的离港航线；缺少合法航道时不生成渡轮，禁止船穿陆地或桥面。
- 复用船队类型；表现一艘轮廓清楚的渡轮。循环为进港→减速→靠泊→停留→离港，朝向沿航线切线连续变化。
- 建议近港周期 90–150 秒，靠泊停留 15–25 秒；均为艺术时间，不对应真实船班。长历史回放不能随数据倍率把船加速数千倍。
- 周期、泊位、初相位由 seed 决定；停靠时关闭尾流，航行时尾流强度跟速度变化，低画质无尾流。
- 港机后续可加一段低速水平移动；无作业模拟时不宣称装卸完成，不追加复杂吊索。
- 单项新增主场景 draw calls ≤2；优先沿用船实例网格，只在确有需要时添加一个合并尾流网格。
- 航拍至少有一个 3 秒以上能读出进港或靠泊行为的镜头，不仅在远海有一个移动小点。

## 6. 第三批：真实数据的克制反馈（V3）

现有 `busyness` 是 `tokensTotal / max(0.75h, generatedAt-startedAt)` 的对数压缩，仅对快照判定的活跃会话非零。注释中的“近期吞吐”与实际计算不一致，实施时应修正说明。

V3a 不扩数据面：只增强真实快照活跃状态。最多一组窗灯轻微呼吸和既有吊车运动，呼吸亮度变化建议 ≤15%，避免整栋频闪；不能改变已映射的 token 高度。施工强度说明为估算，不称为实时增速。

V3b 如需实时速率：须先建立版本化数据来源，声明采样时间、增量窗口、缺失/过期状态和来源。没有历史速率时，回放使用已有总量插值，不能复刻不存在的历史脉动；不足以估计时退化为稳定活跃标记。新增投影遵守最新版 AGENTS.md 的内置插件、权限、MCP/export 分面规则，单独契约评审。

动画频率不映射到模型性能/服务质量，亮度也不代表实际费用。新增主场景 draw calls：0；不为每栋楼增加真实光源。现有吊车上限以及无吊车楼的退化表现需保持明确。

## 7. 可选与暂缓项

| 项目 | 决策 | 理由/约束 |
| --- | --- | --- |
| 红绿灯 | V2 后可选 | 必须至少配固定相位停车区：红灯等待、绿灯恢复；不做通用避碰，不允许车流无视红灯 |
| 鲸跃 | 默认关闭的彩蛋，后置 | 远海不抢城区焦点；与数据无关；事件绝对时间求值，水花复用池，≤2 calls |
| 异常响应车 | 暂缓 | Finding 不等于紧急事故；先用已有城区信标，避免暗示具体会话位置或现实事故 |
| 环境音 | 独立可选，默认关闭 | 显式开启、本地资源、音量可调；窗口隐藏暂停；无外部请求；素材授权登记 |
| 水龙卷/流星/火山/极光 | 保留但控制 | 默认 city 氛围限制同时出现的强事件；节目效果不能覆盖数据主体；关掉不应改变其他随机序列 |
| 人物骨骼动画、室内细节、多人与网络 | 本期不做 | 与宏观可读性、离线边界或本期成本不匹配 |

## 8. 性能预算与退化

以下是增量验收目标，不是现有性能实测。固定数据、相机、窗口、画质、机器与分辨率比较基线。

- 每项新增主场景 draw calls ≤2；必须同时报告阴影、倒影、后处理产生的总渲染调用差值，不能只报主场景。
- V1 总主场景增量目标为 0；V1+V2 新资源增量目标 ≤16 MiB，无新大图集，不增加每栋楼灯源。
- V1+V2 新增 CPU 更新 p95 ≤1 ms、GPU 帧耗时 p95 增量 ≤10%；若超预算优先降低密度/更新频率，不牺牲 UI 响应。CPU 与 GPU 分别测量。
- 无新特效驱动的整城重建；无逐帧对象数组分配；实例属性只在实际变化时上传。隐藏粒子停止更新；雾不等于裁剪，不能把雾作为 draw call 优化证据。
- 低画质：季节色、人流节律保留，减少人数和鸟数，保留渡轮主体，关闭尾流、稀有事件和新增透明效果。
- 中高画质：依次恢复群体密度、尾流；新增效果不扩大现有阴影贴图。
- 暂停回放冻结环境动作；页面离开/后台遵守现有节流与资源释放流程；重新进入不能增加重复对象或事件计数。

## 9. 验收矩阵

### 逻辑和边界

1. 同一时刻从前进、倒退、直接 seek 三种方式到达，行人分配/位置、船的位置与停靠状态、季节权重、鸟群可见数一致。
2. 至少覆盖 5 个 seed、30/90/366 天窗口、闰日、跨年、统计时区与系统时区不同的机器；时区有夏令时转换时不出现负进度或事件重复。
3. 无河、无港口、空会话、未完分页、跨规模档位、雨天/深夜均有明确退化，不产生陆地船只或穿楼行人。
4. 120 秒连续渲染与直接采样 120 秒状态一致；同环境重复导出关键帧以规定容差比较，不用编码文件哈希代替画面验收。
5. 历史快照不带瞬时 token 速率时，V3 不出现自称“实测增速”的表现。环境状态不会改写统计字段或异常数量。

### 视觉

- 固定宽景、城区中景、港口中景三机位，记录白天/黄昏/深夜和四季对比。
- 默认中景至少两个活动区域的密度变化在不放大情况下可辨；夜深明显更安静，但不是全城消失。
- 夏秋变化在全景可辨；常绿/热带不会整城变橙；树干不染成叶色。
- 渡轮停靠朝向合理，无瞬移；桥下通行具备净空，水花/尾流不留在陆地。
- 每个重要行为被展示至少 3 秒；镜头不能用裁切主体换取更多运动物体。沿用 2.39:1 黑边时以有效画面构图。
- 同一镜头的显著事件最多 1 个（渡轮靠泊可和低强度常规车流并存），不出现流星、鲸跃、水龙卷同时争抢注意力。

### 真机性能

使用原生 `.app` 的实时交互录屏，并同步记录帧耗时、内存及 draw calls；包含首次进入、30→90 天切换、seek、环绕、后台返回。逐帧离线导出仅用于画面和确定性验收，不作实时流畅性证据。提交附基线/改后同条件表和关键帧。

## 10. 实施拆分与完成定义

| 阶段 | 实施点 | 完成门槛 |
| --- | --- | --- |
| V0 时间状态 | CityEngine + 新纯状态模块；修改已有系统求值接口 | seek 路径独立、时区一致、live/replay/film 明确 |
| V1 季节/人流/鸟群 | cityParts、cityFlora、cityWildlife、cityWeather | 三机位对比、零新增主场景 calls、无新数据字段 |
| V2 渡轮 | cityPlan/cityLayout 航道描述 + cityParts 船动作 | 航道与净空守卫、靠泊镜头、性能增量达标 |
| V3 活跃状态 | 先改说明与弱反馈；速率投影另立评审 | 明确估算/真实证据、历史降级、无伪造增速 |

本文只要求制定并评审上述 spec；实施阶段按 V0→V1→V2→V3 交付。几何接缝、镜头裁切、楼型重复另由规划/质感工作处理，并在同批截图验收中一并检查。每阶段完成后更新本文状态和实测预算，不通过仅“draw calls 没增加”宣告完成。
