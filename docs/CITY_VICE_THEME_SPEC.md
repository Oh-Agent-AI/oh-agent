# Agent City：Vice City 致敬与迈阿密海滨强化 SPEC（2026-10-05）

状态：修订草案，待实施与截图验收。本文定义目标，不代表功能已经完成。

范围：优先优化酒店、道路、棕榈树、沙滩及其空间关系，再补充霓虹、救生塔和游艇。允许修改 City 插件规划、渲染、镜头和必要展示文案；不修改 Rust 投影、数据库、SDK 数据契约或 cityModel 的统计含义。游戏模式不在本轮范围内。

相关文档：docs/CITY_MODULE.md、docs/CITY_UX_SPEC.md。代码根目录：apps/agent-city/ui/src/engine/。

## 1. 背景与诊断

目标是让用户从场景本身识别出“80 年代迈阿密海滨 / Vice City 致敬”，不是依靠标题告诉用户主题。

现有粉彩、棕榈、霓虹和水色提供了氛围基础，但截图中的沙滩与城市空地材质接近，道路像直接铺在沙上，酒店仍偏数据高塔，植被缺少连续的海滨节奏。

第一识别锚点是空间序列：

**粉彩 Art Deco 酒店 → 人行道 → 海滨大道 → 棕榈步道 → 干沙 → 湿沙 → 浅海**

该序列应在默认镜头中可见。符号装饰不能替代海滨基础，不以“堆够三个符号”作为通过条件。

## 2. 目标与非目标

目标：

- 默认镜头能辨认连续酒店街、棕榈大道、宽沙滩及海岸层次。
- 白天靠轮廓、街区关系与材质成立，日落和夜晚用灯光强化，不依赖 bloom。
- 风格化真实感：材质有尺度、地表有用途、建筑有落地关系，不追求概念图的写实复杂度。
- 少量和大量会话均可成立；装饰不伪装成数据建筑。
- 确定性、增量更新稳定、资源可释放；节能档保留主要识别锚点。
- 使用实际浏览器与原生截图验收；生成式概念图不作为通过证据。

非目标：游戏机制、全城写实重建、逐楼独立材质/灯光、街景级室内模拟、宿主导航重做。HUD 遵循 CITY_UX_SPEC.md。不强制所有实时/回放场景固定黄昏，不篡改数据时间。

## 3. 第一批：海滨基础（主交付）

### B1 海滨规划与稳定街段

代码落点：cityPlan.ts、cityLayout.ts。

- 引入明确的迈阿密海岸配置，如 miami-coastal；不必新增用户主题开关。seed 控制变化，配置约束平缓海岸、热带植被与连续海滨街段，避免随机成寒带或山地主题。
- 输出海岸采样、海滨道路/步道、沙带和装饰候选区；类型与字段在实施时确定并补测试。候选点包含陆海侧、方向、地形高度和净空信息。
- 避让地块、道路、码头、公共设施和其他装饰；无空间时减少装饰或明确降级，不强行穿模。
- 固定 seed 的增量更新不得迁移已有建筑；规模扩张沿用稳定规则。
- 允许扩展内部规划契约，必须更新消费者、缓存失效与 geography/layout 测试，不向 Rust 投影加字段。

### B2 沙滩与岸线质感

代码落点：cityTextures.ts、cityParts.ts，消费 B1。

- 根据地表类型、海岸距离与高度生成干沙、湿沙和浅水过渡，不只按最终 RGB 判断地表。
- 干沙暖浅、细颗粒与低频沙纹；湿沙略深、平滑且沿岸连续。城市空地不能统一变成沙地。
- 近景有颗粒尺度、中景有干湿层次、远景有海岸带；合理平铺与过滤，避免闪烁、摩尔纹及明显重复。
- 地面/水面不得出现连续黑缝、悬空边缘或 z-fighting。泡沫为可选增强，限制范围与开销。
- 沥青、人行道、铺装和沙滩使用不同材质参数。优先共享图集/程序材质，不默认扩大现有 2048 地面图集。

### B3 海滨大道与棕榈步道

代码落点：cityRoadPaint.ts、cityPlan.ts、cityFlora.ts、cityParts.ts。

- 大道有连续沥青、标线、路缘与人行道，并连接酒店入口、桥梁和路网。
- 棕榈沿步道成排；默认视距下能辨长树干与展开叶冠，高度、种类和朝向确定性小幅变化。
- 沙滩少量散植，不做随机密林；避让路口、入口与主要视线，检查树根高度及穿路。
- 复用现有资源和实例化；节能档降低细节/密度，不隐藏全部标志性棕榈。

### B4 Art Deco 酒店轮廓

代码落点：cityParts.ts、cityTextures.ts。

- 强化宽体量、阶梯平屋顶、圆角、水平遮阳带和适量阳台；区分酒店、公寓与玻璃办公楼。
- 原型由街区功能决定，Harness 色保持可辨，token 高度映射不变，不为美术效果静默截断高度。
- 先测 waterfront 与 Deco 命中数量。高 token 海滨楼可以强化低层裙房/立面，保留数据主体高度。
- 附件共享几何/材质，正确适配施工、生长、回放隐藏和增量更新。
- 少量会话下允许纯装饰设施，但与数据建筑可区分，不进 Session 拾取、数量或 token 统计。

### B5 昼夜配方与默认镜头

代码落点：cityTheme.ts、citySky.ts、CityEngine.ts、cityCinematic.ts。

- 统一主题与昼夜配方，例如天空配方显式接受 theme，避免独立常量互相覆盖。
- 白天青蓝海水与粉彩立面；日落粉紫天空、暖窗与青色海水分离；夜间保留道路和建筑轮廓。
- 天气调制受控、幂等；不靠极高曝光或 bloom 掩盖问题，调参须前后截图验证。
- 默认镜头展示酒店—棕榈—沙滩序列与城市规模；resize 不重置用户镜头。
- 实时/回放时间语义保留；可选观景时段须显式标注，不改数据游标。
- 照片与后台视频复用主题与海滨构建逻辑，固定输入可复现。

## 4. 第二批：符号强化（基础验收后）

- S1 救生塔：架高值守小屋、平台、檐顶、楼梯；条纹为辅助，不用易读成灯塔的窄高圆柱。合法沙带内建议最多 2–3 座。明确夜间材质/环境光路径，不假定现有路灯自动照亮。
- S2 招牌与霓虹：优先酒店入口、竖招牌和水平饰带，不把高楼腰线竖管等同招牌。建筑与公共设施门控分别核对；青粉不覆盖全部 Harness 色。稳定对象 ID 决定布点，不随最高楼排名迁移。原创招牌共享图集/几何。
- S3 游艇与地标：少量飞桥游艇沿合法航道运行，验证尾迹与码头避让。棋盘步道、霓虹拱门可选，不要求全部实现；新地标纳入规划净空与缓存。文案不能代替视觉验收。

## 5. 架构、数据与资源边界

- City 插件内实现，宿主不新增迈阿密业务分支。
- 会话/token/活跃状态、opaque handle、覆盖范围和数据诚实性不变，装饰与统计分离。
- 新几何、图集、材质和 shader 同时兼容主场景与后台导出；dispose 完整，避免换 seed/反复导出累积资源。
- 静态缓存纳入影响结果的配置版本和 seed，旧缓存失效重建。
- 无新增外部网络或用户数据上传。现有 ≤5 MB 素材预算及许可登记保持；程序图集虽不增文件，也计运行时内存。
- 参考 Tiny Skies 代码/素材时登记来源与许可，不因程序化而免除台账。

## 6. 性能预算与测量

取消未经验证的“总新增 ≤2 draw calls”承诺。实例化是手段，不是固定开销保证。

| 项目 | 要求 |
| --- | --- |
| 批处理 | 按几何、材质、pass 合并；禁止逐酒店独立材质/灯光 |
| 调色 | 优先复用 uniform，不为调色新增 pass |
| 装饰 | 实施前列通道/实例容量，实测主 pass、阴影、反射、后处理成本 |
| 基线 | 固定设备、窗口/DPR、数据、seed、时间、天气、镜头与画质，测前后值 |
| 指标 | FPS、帧时间 p50/p95、draw calls、triangles、纹理/几何数量；内存注明工具与限制 |
| 帧率 | 目标设备普通档稳定 ≥30 FPS；记录硬件与基线，不引用无条件的 64–120 FPS |
| 资源 | 10 次 seed 重建、至少 3 次导出/取消后无持续资源增长；区分稳定缓存与泄漏 |
| 节能 | 降阴影/反射/bloom/装饰密度，保留酒店轮廓、岸线层次与主要棕榈列 |

各批建立实测预算表，未测项目标记未验证，不宣布余量充足。

## 7. 截图与交互验收（必需）

### 7.1 可复现证据

记录 commit/dirty diff、插件构建版本、平台、窗口/DPR、设备、数据来源/数量、seed、时间/天气、画质与镜头。测试控制不得改变生产数据语义。

- 浏览器使用合成/脱敏 fixture；原生按既有授权读本地投影；不上传数据。
- 同条件保存前后实际截图；白天/日落/夜晚的全景、中景海滨街、近景岸线，普通与节能档均检查。
- 覆盖少量/大量会话、宽/窄窗口、中英文，以及主场景/照片/视频生成帧。说明哪些条件复用证据、哪些未测。

### 7.2 通过条件

- 默认全景可辨酒店街、棕榈大道、连续沙滩，不靠标题提示。
- 近景干湿沙自然，无连续黑缝、明显纹理重复闪烁；道路/酒店/步道关系成立，无压地块、悬空或树木穿路。
- 夜间不过曝；节能档关闭 bloom 仍可辨主题。
- 固定至少 20 个 seed 检查候选点净空和降级；测试增量更新、输入重排、同 seed 重建稳定性。
- 识别测试至少 5 位未参与开发者，不显示主题标题，观看白天/夜晚全景并记录原始回答。目标每种时段至少 4 位识别为迈阿密/80 年代热带海滨；说出 Vice City 为额外证据，不宣称普遍识别。
- Tab 保持镜头/回放；resize/侧栏切换检查边界和瞬时闪烁。静态截图不能证明无闪白，须交互观察或录屏另记结果。

### 7.3 回归与报告

- City UI typecheck、npm run verify:city（修订时七个脚本）、npm run verify:react。
- 受影响的 geography/layout、素材、昼夜门控、资源释放、主场景与导出一致性测试。
- 原生通过正式 App bundle，不运行裸二进制。区分新增回归与既有失败，不刷新快照掩盖问题。
- 无计划中的数据契约变更；如实际涉及 Rust/Python/golden，另行评审，不预先宣称零影响。
- 报告附本地截图路径，逐项标通过/失败/未测。原生、导出或识别测试未完成时不标记整体完成。

## 8. 分期与提交

1. 海滨样板：B1–B4，交付完整空间序列，先实际截图评审。
2. 全场景整合：B5、多 seed/规模/画质适配，完成浏览器/原生及资源回归。
3. 符号强化：按效果选择 S1–S3，逐项测量与截图，不为凑数量扩大范围。

各批独立可回溯提交，例如 feat(city): establish Miami beachfront streetscape、feat(city): unify coastal lighting and framing。规格不授权自动提交或合并。

第一批成功标准是“海滨基础成立”，不是“符号齐全”。UI/UX 调整并行保留，游戏方案后续独立评审。
