# F1 算法 SPEC：需求驱动的增量路网（CITY_ROAD_SIMULATION_PROPOSAL §4「F1 前先出算法 SPEC」）

状态：待评审 · 2026-10-07 · 基线 = `worktree-city-backdrop-off` 当前提交（骨架 + G1 剪枝 + S4 裁切块 + 确定性数学）。

## 0. 目标与非目标
- 目标：主干/连接路由「几何放射 + 事后剪枝」改为「需求点 → 最小成本路径接入」；回放时骨架先于支路、支路随楼出现。
- 非目标：建筑落位、地块切分（S4/F3 沿用现状）、渲染。统计面不变（路网只影响形态）。

## 1. 输入
| 名称 | 来源 | 说明 |
|---|---|---|
| 成本场 C(x,z) | `terrain.height/slope`、`coastDistance`、`inRiver`、保留地 | 粗网格，格宽 24（2 档岛约 70×70 格） |
| 需求点 D | 会话楼地块中心，按 `startedAt` 升序 | 每城区按街区聚合为「街区重心」，上限 200 个 |
| 骨架 S0 | 核心环岛 + 环线 + 环岛/河岸路（现行生成器） | 先验骨架，不参与寻路 |

## 2. 成本函数（每格）
```
c = 1                                   基础
  + 6 · max(0, slope − 0.25)            坡度惩罚 → 主干沿等高线（还 D-绕行）
  + (inRiver ? 40 · 跨距系数 : 0)       过河：单价 × 宽度，A* 自选最窄处（D-桥址的一般化）
  + (coastDistance < 10 ? ∞ : 0)        不入海
  + (保留地内 ? ∞ : 0)                  不穿用地/地标
  − 0.6 · onExistingRoad                沿已有路段打折 → 复用而非并行（替代「拥挤主干」守卫的事后处理）
```
邻接 8 向，对角乘 √2；全部用 `detMath`（跨引擎一致，见 CITY_ROAD_SIMULATION_ANALYSIS §2）。

## 3. 循环（种子化、固定遍历序）
```
network ← S0
for 每个时间桶 t（回放窗口等分 12 桶）:
  for d in D[t]（按 startedAt, id 排序）:
    path ← A*(d → network 最近节点, C)          曼哈顿启发式 × 最小格成本，确定性 tie-break（格序号）
    network ← network ∪ simplify(path, ε=4)     Douglas–Peucker 后按 localConstraints 接入（现有 connectToNetwork 规则）
  升格（F2）: 路段介数 > θ(t) 的支路 → 次干（宽 8）；> θ' → 主干（宽 12）
  记录 birth[edge] = t
```

## 4. 必须新增的守卫
1. **前缀稳定**：对任意 t1 < t2，`edges(t1) ⊆ edges(t2)`（按几何 + 宽度不降）。增量规划不天然满足；当前「几何 + 剪枝」满足，切换时这是回放不跳变的唯一保证。
2. **跨引擎一致**：`verify-city-cross-engine` 扩展到 F1 输出（V8 = JavaScriptCore）。
3. **性能**：700 会话、M1，L1–L3 < 120 ms；超预算自动退回现行生成器并在 HUD 诚实标注。
4. **不劣于基线**：City planning 四项指标（锐角 ≤5、穿用地 0、无入口 ≤3、拥挤 ≤10）+ 桥均跨距 ≤ 81.6。

## 5. 降级条件
需求点 < 8、A* 失败率 > 10%、或超时 → 整城退回现行生成器（同一 (seed, tier) 恒定选择，避免帧间切换）。

## 6. 分步
F1a 只替换「街网节点 → 骨架」的接入（现 `connectToNetwork` 的孤岛接回与横街接入），守卫全绿后
F1b 替换主干放射；F2 加 birth 时序与介数升格，渲染侧按 birth 揭示路面（需地面贴图按时间桶分层，单独评估性能）。

## 7. 待评审决定
