# Creator Studio 工作区信息架构

2026-11-25

编辑器默认只展示场景、一个与当前状态匹配的下一步，以及右侧 Agent。城市、玩法和剧情沿用各自的保存及校验规则，在同一个工作区里通过「内容」打开工具。这个结构延续体验报告的画布优先原则，也落实重构说明中的临时检查器和 Agent 常驻设计。[体验设计评审](CREATOR_STUDIO_V2_EXPERIENCE_DESIGN_REVIEW_2026-11-22.md#4-推荐信息架构) · [编辑器重构说明](CREATOR_STUDIO_EDITOR_REFACTOR_IMPLEMENTATION_2026-11-22.md#2-目标界面和入口) · [Agent 体验重设计](CREATOR_STUDIO_AGENT_EXPERIENCE_REDESIGN_2026-11-23.md) · [Oh Agent UX 指引](OH_AGENT_UX_GUIDELINES.md)

## 页面、抽屉与作品

| 位置 | 用户要做的决定 | 显示内容 |
| --- | --- | --- |
| 项目库 | 继续哪个作品，是否新建 Game | 筛选、名称、详情以及当前能执行的操作。Game 的创建和切换归这里。 |
| Host 顶栏 | 是否返回、打开内容或进入发布流程 | 「返回项目库」「内容」及适用于当前 Game 的「发布」。打开内容时优先沿用上一次工具，新进入 Game 时默认打开玩法。 |
| 画布 | 现在在看什么，下一步做什么 | 作品或场景名称、保存状态、场景和反馈。Game 缺场地时，「配置场地」直接打开玩法工具并定位场地。 |
| 内容抽屉 | 手动编辑哪类内容 | 「世界」打开已有城市并按需展开新建、导入、导出和安装。「玩法」配置当前 Game 的场地和规则。「剧情」打开或创建 Story，再编辑剧情与角色。 |
| Agent 栏 | 指令发给谁、作用于哪个作品、是否确认 | Agent 选择器、当前作品、输入、执行状态和变更卡。打开剧情时显示 Story 的任务，关闭抽屉后可以继续给当前 Story 发指令。 |
| 底部反馈 | 当前候选如何验证、哪里失败 | 试玩相关操作和诊断。内容与反馈分别按需展开。锚点 ID、JSON、过程事件和证据保留在高级详情中。 |

World 提供场景上下文，Game 与 Story 各自拥有版本。打开或关闭工具时保持同一画布实例。切换作品时由实际关联的场景决定视口。Story 工具保留未保存编辑，离开工作区前需要保存或主动放弃。Story 试玩仍显式选择安装目标 City。继续创作时通过右栏的「当前作品」核对 Agent 操作对象。

## 实现与验收

- 项目库打开 City 和 Game 时落到画布与 Agent。打开 Story 时自动展开剧情工具，仍使用同一工作区。工具条只在打开「内容」时出现。
- 场地配置复用现有地图、选点和校验保存。玩法规则及原始 ID 仍从对应工具的高级详情打开。关闭内容后回到画布，Agent 的目标与任务保持当前作品范围。
- 手动验证从项目库直进剧情，Game → 剧情 → 世界 → 剧情，关闭抽屉后检查画布和草稿，再重新打开内容。测试用浏览器宿主和合成项目，桌面保存及试玩的真机验收单列。

作品历史、按当前 City 聚合其已安装内容、共用的场景与剧情对象选择仍需真实数据接入。交互只在具备相应操作时显示。预览渲染、生成候选、测试与发布分别使用现有结果和确认入口。
