# Oh Agent 简约 UX 指引

版本 v0.1 · 2026-11-10 · 设计提案。适用于工作台中的 City、Creator Studio、Shop，以及 City 内嵌小游戏。

仓库已有 City 的场景与 HUD 规范、桌面工作台的基础样式变量、官方插件的工具栏与生命周期协议。本文补充跨应用的布局、组件行为和功能接入约定。City 的相机、回放和 HUD 细节沿用专项规范，数据权限以现行仓库政策和宿主契约为准。[City UX SPEC](CITY_UX_SPEC.md) · [官方插件接入指南](OFFICIAL_PLUGIN_INTEGRATION_GUIDE.md)

## 1. 布局

宿主管理应用切换、窗口边缘、应用标题和顶部工具栏。WebView 管理页面内容、上下文操作和局部反馈。工具栏保留当前任务的常用动作，次要命令进入宿主提供的「更多」。活动中的「退出」和进行中的「取消」留在任务旁，键盘与窄窗口都能找到。[Apple HIG：Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)

| 应用 | 默认主区 | 按需显示 | 窄窗口 |
| --- | --- | --- | --- |
| City | 全幅场景，在相关地点显示小游戏入口。边角放摘要、回放入口和当前玩法 HUD | 选中建筑或游戏入口后打开详情。玩法只显示目标、进度、暂停与退出 | 详情改为可关闭面板。当前操作和回放控件按实际高度避让 |
| Studio | 左侧对象列表，中间画布，右侧属性检查器。顶栏保留项目名、保存状态与「试玩」 | 规则、诊断和 Agent 提案从当前对象或任务打开 | 对象列表与属性检查器共用一个面板位置，一次显示一个。保留选中对象与草稿 |
| Shop | 「浏览」和「已拥有」。目录卡片显示预览、名称、内容类型和关键状态 | 商品详情显示兼容范围、版本与当前下一步 | 目录改为单列。详情进入独立页面，返回恢复筛选、滚动和焦点 |

按 WebView 实际可用宽度折叠面板，优先保住主内容、当前动作和退出路径。宿主侧栏变化时重排内容，保持选择和编辑状态。Studio 在对象列表中提供画布选择的等价入口。[Apple HIG：Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)

### City 地图上的游戏入口

- **3D 城市标出可玩的地点。** 例如机场旁显示「飞行练习」，停车场显示「自由驾驶」，赛道起点显示「检查点竞速」。默认显示轻量图标，选中后显示玩法名和「开始」。同一地点有多个玩法时，点击地点后列出可选玩法。地图图标提供可访问名称。
- **小地图用于发现和定位。** 提供「游戏」图层和可用键盘访问的入口列表。点击或选择一个地点后，聚焦 3D 场景中的同一入口并打开玩法卡片。卡片显示玩法名、一句玩法说明与「开始」。暂时不可玩时显示原因和可行的下一步。
- **开始与返回沿用同一个活动流程。** 玩家确认「开始」后才进入准备阶段，退出后回到进入前的视角、所选地点与可用焦点。小地图、3D 标记和工具栏「游戏」列表使用同一份可用入口与状态，方便玩家直接找到同一玩法。
- **入口由城市挂载决定。** 新小游戏通过 `mountId` 标识挂载，通过 `entryAnchorId` 绑定当前布局中的入口位置。地图和工具栏使用同一个挂载标识启动。布局升级导致锚点失效时，地图隐藏无坐标的标记，已挂载列表保留条目与修复提示。现有车、飞机和机甲入口可以作为接入参考。[SDK API 草案](AGENT_CITY_SDK_API_2026_11_10.md)

## 2. 组件

| 组件 | 使用约定 |
| --- | --- |
| 按钮与菜单 | 每个任务区设一个主按钮，文案用动词加对象，如「应用皮肤」「开始试玩」。高频操作直显，低频命令放菜单。纯图标提供可访问名称，开关公开选中状态 |
| 列表、卡片与检查器 | 列表负责定位与选择，卡片用于带预览的目录，检查器用于查看或编辑当前对象。选中状态在画布和列表同步 |
| 表单与差异预览 | 字段用可见标签，错误贴近字段。选择或拖放提供点选、列表或数值输入等替代方式。变更预览列出对象、改动、受影响的挂载和可定位诊断 |
| 对话框 | 用于需要立即决定的操作，如放弃未保存改动或确认购买。打开时焦点进入，关闭时回到触发项或合理的后续位置。提供明确的取消或关闭按钮。[WAI-ARIA 对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) |
| HUD、状态与通知 | HUD 只显示当前任务所需信息。可等待的操作就地显示进度，短提示用于确认结果，失败或需要处理的信息留在原位置并给出下一步。进度播报按阶段更新 |

样式以工作台现有的 `--ui-*` 语义变量为基准。间距采用 4、8、12、16、24 px，桌面控件默认高 32 px、圆角 6 px。粗指针常用目标采用 44×44 CSS px 的产品目标。使用本地系统字体和一致的矢量图标，City 皮肤负责场景视觉，操作文字与面板使用可读的界面色。工作台的样式变量若要跨 WebView 使用，需显式在各应用提供映射。

普通文字对比度至少 4.5:1，有辨识要求的图标、控件和状态至少 3:1。焦点清晰且不被浮层挡住，状态同时用文字或符号表达。表单、菜单与对话框可用键盘完成，画布输入仅在活动取得控制时捕获，编辑文字或输入法组合时让出快捷键。支持减少动态效果，中英文自然换行。[WCAG 2.2](https://www.w3.org/TR/WCAG22/)

### 官方 UI 组件系统

Oh Agent 工作台、City、Creator Studio 和 Shop 采用同一套官方 UI 组件系统。建议在仓库内建立独立的 React 包 `@agent-vitals/ui`，统一发布样式变量、基础组件和交互约定。各官方 WebView 在自己的入口显式引入同一份样式与组件。组件接收本地化文案、状态和回调，宿主桥接继续由 App SDK 提供。

| 层 | 归属与首版范围 |
| --- | --- |
| 官方共享 UI | 从工作台已有的样式变量、`Button`、`Field`、`SelectInput` 和 `StatusPill` 起步。对话框、进度与错误反馈按实际接入需要纳入。共用颜色语义、尺寸、焦点、禁用和加载行为 |
| 工作台外壳 | 导航、标题和顶部工具栏由宿主渲染。官方 WebView 继续通过工具栏协议提交命令 |
| City | 驾驶和飞行已共用 `GameSessionPanel`，新增小游戏可沿用。3D 标记、小地图和工具栏共用玩法入口状态及启动逻辑。玩法卡片、HUD、坐标投影和相机由 City 管理，面板内部采用共享 UI |
| Studio 与 Shop | Studio 持有对象检查器、差异预览与试玩流程。Shop 持有商品卡片、购买与安装流程。两者用同一套基础组件呈现业务状态 |

官方 UI 包随客户端源码构建。City 皮肤调整场景外观，官方控件继续使用统一的交互语义与可读性要求。共享包的采用范围是官方界面，外部插件继续按 App SDK 的接入契约运行。

## 3. 功能接口

同一个功能从工具栏、页面按钮、快捷键或场景对象发起时，调用同一个应用处理入口。Agent 经授权的 MCP 接口调用同一项目服务。页面读取服务返回的状态与诊断，宿主检查权限、当前实例及输入范围。按钮可用性是界面提示，执行时仍按实际状态裁决。

| 功能 | 用户看到的流程 | 接入边界 |
| --- | --- | --- |
| 宿主工具栏 | 主动作和「更多」，可用时执行 | 复用现有 `Tool`、`connect`、`publishToolbar`。命令 ID 稳定且有命名空间，标签可翻译。先装命令处理器再发布首个完整快照，空工具栏用 `publishToolbar([])`。现有回调同步，异步任务结果由页面反馈 |
| City 活动 | 入口 → 准备中，可取消 → 进行中，可暂停或退出 → 结果 → 回到原场景 | 工具栏与场景入口共用活动准入。玩法经受信任的场地与输入适配器接入，释放场景资源后恢复对应的界面和焦点 |
| Studio 修改 | 选择对象 → 查看修改与诊断 → 保存。冲突时保留提案并提供重新预览 | UI 与 MCP 共用 `edit_preview`、`edit_commit` 所对应的项目事务。提交带预期 revision 和 operationId。超时按同一操作 ID 查询或重试，过期预览重新生成 |
| Studio 试玩 | 「试玩」固定已保存版本 → City 玩家操作 → 返回项目与结果。交接前发现未保存内容时先留在 Studio 决定 | 宿主持有试玩快照、runId 和返回上下文。Agent 发起无头试玩并读取证据。无效的选中对象回退到项目视图 |
| Shop 内容 | 详情 → 获取或购买 → 安装 → 应用皮肤或添加小游戏。小游戏添加时选择场地、预览绑定再确认 | Shop 读取权益、安装、兼容性和应用状态。宿主复核内容引用与权限。目录浏览、购买、安装及挂载各自呈现结果 |

工具栏一行描述现有接口。活动、创作和商品流程描述目标行为，实现按 SDK 与 Creator Studio 架构推进。工具栏协议以现有 `button`、`select`、`enabled` 和 `placement` 为准。进度、诊断和恢复入口放在插件内容区。[SDK API 草案](AGENT_CITY_SDK_API_2026_11_10.md) · [Creator Studio 软件架构](AGENT_CITY_CREATOR_STUDIO_ARCH_2026_11_09.md)

### 异步状态与返回

- 加载、空状态、失败和结果未知各有明确文案。「正在确认是否保存」期间保留修改内容，以服务状态判断是否提交。重复触发同一写操作时沿用其操作 ID。
- 可取消的任务显示「取消」，收到终态后更新界面。异步返回须匹配当前实例和任务，过期结果不能覆盖用户已打开的其他项目或活动。
- Esc 优先处理最上层菜单或对话框，其次关闭临时面板，再交给当前玩法的暂停或退出规则。宿主切换应用前处理未保存内容，恢复时按可用性还原项目、选择和面板。
- Shop 的兼容性提示给出原因和下一步，例如「当前城市缺少驾驶路线」及「选择其他场地」。已拥有、已安装、已应用和已挂载使用各自的文案与动作。

## 4. 首轮验收

1. 在桌面正常和窄窗口中，从 3D 标记、小地图入口列表和工具栏定位并启动同一挂载。用键盘走通选择、开始、取消准备、退出和焦点恢复。活动失败时能从原入口重新开始。
2. 在 Studio 用同一对象完成预览、保存、冲突后重新预览和试玩返回。检查未保存提示、固定 revision 和对象定位。
3. 在 Shop 从目录进入详情并返回，恢复筛选和焦点。分别呈现已拥有未安装、安装失败、场地不兼容和已挂载。
4. 以上路径检查中英文、可见焦点、减少动态效果与内容重排。宿主工具栏分别在浏览器预览和原生 WebView 验收。

组件系统先以工作台和 City 为首批接入方。抽取基础样式与组件后，选用一个工作台表单和一个 City 面板验收同一组件的视觉、键盘、焦点和加载行为。Studio 和 Shop 从首个页面使用同一组件入口。
