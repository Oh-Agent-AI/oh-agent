# Agent City：可分享城市 SPEC（2026-10-01）

把城市从「工作台里的一个可视化页」推进到「用户愿意导出、发给别人看的作品」。本文定义范围、
约束、分期与验收标准；现状与分层见 `docs/CITY_MODULE.md`，本文不重复。

状态：草案，待评审。所有条目尚未实施，除非标注「已完成」。

## 1. 目标与非目标

**目标**

- 用户能一键带走两种成品：**航拍视频**与**海报图片**，在任何机器上导出结果一致、顺滑。
- 单张图、单段视频不靠解说就能读懂「这是我这段时间用 Agent 做了多少事」。
- 画面质感达到可传播水准：近景不单调，夜景可用。

**非目标**

- 不做云端分享链接、不做账号、不做任何上传。导出物落在本机，由用户自己决定发到哪里。
- 不做配乐（素材授权另立项，见 §9）。
- 不改城市的数据语义：楼 = 会话，高度 = token（对数），城区 = 执行环境。视觉增强不得引入新的「看起来像数据」的元素。

## 3. 现状（已完成）

- 航拍：布局推导的镜头路径，速度 ∝ 离地高度，视觉角速度 p95 ≤ 0.65 rad/s，5 个种子守卫
  （`scripts/verify-react-city-cinematic.mjs`）。默认地形全长约 100s。
- 主题：日光 / 日落霓虹（屋顶霓虹描边 + bloom，仅画质 ≥1）。
- 公共用地 3D 地标、棕榈与行道树、吊车与施工、生长回放。

## 5. P1：视频导出

### 5.1 确定性离线渲染（关键设计）

当前航拍按**墙钟**推进（`elapsed`），低帧率机器会掉帧、录出来卡顿，且两次录制不一致。
导出必须改为**按帧推进**：

```text
for frame in 0 ..< ceil(durationSec × fps):
    t = frame / fps
    camera ← plan.position(t), plan.target(t)       // 纯函数，已存在
    cursor ← plan.cursor(t)                         // 纯函数，已存在
    parts.applyCursor(cursor, immediate=true)       // 跳过施工补间，直接到目标进度
    parts.update(1/fps, t)                          // 车、船、云、水面按固定步长
    render → 编码一帧
```

- 注视点阻尼（当前在引擎里按墙钟做）必须改为以 `1/fps` 为步长的同一公式，保证导出与实时
  预览的镜头一致。
- 所有动画源（车辆、船、云、水面 `uTime`、吊臂、警示灯闪烁）只读 `t`，不读 `performance.now()`。
  这是 P1 的主要改动面：逐项审计 `cityParts.update` 与 `CityEngine.updateScene`。
- 导出期间关闭自动画质降档（`accountFrame`），固定为导出档位。

### 5.2 编码

2026-10-04 实施更新：默认使用 WebCodecs H.264 + MP4，不启用 MediaRecorder/WebM 回退；保留固定帧时间戳及 Worker 隔离。采用经本轮范围评审的 MIT `mp4-muxer@5.2.2`，版本锁定和许可证随包。详见 `CITY_MP4_EXPORT_2026-10-04.md`（含上游停止维护风险）。下面为原始方案比较。

- 首选 WebCodecs `VideoEncoder`（H.264，MP4 封装）；不可用时退回 `MediaRecorder` + `canvas.captureStream(0)` 手动 `requestFrame()`（WebM/VP9）。
- MP4 封装需要一个 muxer。**不引入第三方依赖**的前提下，优先评估 WebView 是否原生支持；
  若必须引入，限 MIT/Apache、纯 JS、打包进前端产物，单独过依赖评审。
- 写文件走 Tauri `dialog.save` + `fs` 写入，不经任何网络。

### 5.3 规格

| 项 | 完整版 | 短版 |
| --- | --- | --- |
| 时长 | 当前规划（默认地形约 100s） | 25–35s |
| 镜头 | 全部段 | 开场推近 → 环绕最高楼 → 拉升收尾 |
| 分辨率 | 1920×1080 | 1920×1080；另提供 1080×1920 竖版 |
| 帧率 | 30 | 30 |
| 码率 | 12 Mbps | 12 Mbps |
| 黑边 | 2.39:1 宽银幕，烧录进画面 | 竖版不加黑边 |
| 字卡 | 烧录（Canvas 2D 叠加，不是 DOM 截图） | 同左 |

- 短版由 `planCinematic(..., { cut: "short" })` 生成，复用同一速度剖面与守卫。
- 竖版：相机 FOV 与机位按 9:16 重算，城区字卡移到画面下三分之一。

### 5.4 交互

- 工具栏「航拍」改为下拉：`播放航拍` / `导出视频（完整）` / `导出视频（30 秒）` / `导出竖版`。
- 导出时显示进度条（帧数 / 总帧数）与取消按钮；画布可见但不可交互。
- 导出完成提示文件路径，提供「在 Finder 中显示」。

### 5.5 验收

- 同一数据导出两次，逐帧哈希一致（允许编码器非确定性：比较解码前的 RGBA 帧）。
- 在画质最低档机器上导出的视频无掉帧：帧数 = `ceil(duration × fps)`。
- `verify-react-city-cinematic.mjs` 增加短版与竖版的节奏断言（同一阈值）。
- 导出过程 `read_network_requests` 为零（开发态用浏览器 mock 验证）。

## 6. P2：海报导出与脱敏

### 6.1 机位

三个固定机位，均由布局推导（同航拍规则，不写死坐标）：

| 机位 | 描述 |
| --- | --- |
| 俯瞰 | 全城 45° 俯视，岛屿完整入画 |
| 天际线 | 低机位黄昏，最高楼居中偏右三分线 |
| 地标特写 | 环绕段中的一帧，仰拍最高楼 |

### 6.2 摘要卡

叠加在画面左下（Canvas 2D 绘制）：

```text
{窗口}  ·  {会话数} 个会话  ·  {token} token
最大城区  {执行环境}  ({该执行环境会话数})
最高的楼  {日期} 的一次 {时长} 会话
agent-vitals
```

不出现金额。金额涉及计费口径（名义 / 实付 / 订阅，见 `ATTRIBUTABLE_WASTE.md` §6），
脱离工作台上下文单独出现必然被误读。

### 6.3 脱敏档位

| 档位 | 执行环境名 | 会话日期/时长 | token 数 | 默认 |
| --- | --- | --- | --- | --- |
| 标准 | 显示 | 显示 | 显示 | ✓ |
| 匿名执行环境 | 替换为「城区 A/B/C」 | 显示 | 显示 | |
| 仅城市 | 不显示 | 不显示 | 不显示，只留画面与署名 | |

任何档位都**不包含**：会话标题、路径、模型 ID、项目名、Finding 内容。这些字段在导出代码
路径上不可达（导出函数只接收聚合 DTO，不接收 `SessionRow`），由类型保证而非运行时过滤。

### 6.4 规格与验收

- PNG，2× 渲染分辨率（默认 3840×2160），可选 4×（受 `MAX_TEXTURE_SIZE` 限制时自动降级并提示）。
- 导出的 DTO 类型守卫：新增 `verify-react-city-share-contract.mjs`，断言导出函数签名不含
  `SessionRow`，且三档输出中不出现 fixture 里的会话标题/路径字符串。

## 7. P3：画面质感

### 7.1 夜景主题

- 新主题 `night`，与 `day`/`vice` 并列，同样只改观感不改数据。
- 窗户点亮：立面着色器增加 `aLit` 实例属性（0–1），由会话的**最近活跃时间**决定：
  在建（active）楼全亮，越久未活跃越暗。窗格级随机由 `hashSeed(id, floor, column)` 决定，确定性。
- 街灯：现有路灯几何加自发光灯头；车辆加前后灯（自发光小方块，进 bloom）。
- 天空：深蓝到黑，加程序化星点（天穹着色器内 hash 噪声，无纹理）。
- 画质 0 档：关闭 bloom，窗户亮度改为直接提高漫反射，保证可读。

### 7.2 楼型多样化

在 `facadeFor` / `applyConstruction` 之外增加**屋顶轮廓**维度（与立面正交）：

| 轮廓 | 适用 | 规则 |
| --- | --- | --- |
| 平顶 | 默认 | 现状 |
| 退台 | tower/landmark | 已有 upper shaft，增加第二级 |
| 斜顶 | residential/waterfront 低层 | 楔形实例几何 |
| 尖顶 | landmark 前 5% | 细长锥 + 天线 |
| 屋顶花园 | commercial 中层 | 屋顶绿块 + 2–4 棵小树 |

- 选择规则只依赖 `(zone, archetype, seed)`，不依赖数据之外的随机。
- 每种轮廓一个 `InstancedMesh`，draw call 增加 ≤ 5。

### 7.3 地标塔

- 全城 token 最多的会话获得专属造型（与 7.2 的尖顶区分：更高的冠部、环形灯带）和一道
  夜间光束（仅 `vice`/`night`）。
- 航拍的环绕段已以它为圆心，无需改镜头。

### 7.4 海滨低层建筑

- `waterfront` 分区内低于中位高度的楼改为装饰艺术风格低层体量（圆角转角、水平条纹、遮阳棚）。
- **会动布局**：体量宽度变化影响地块利用率断言。先在 `verify-react-city-layout.mjs` 补充
  「waterfront 楼宽 ≤ 地块宽 − 0.8」的断言，再改体量。

### 7.5 验收

- 每个主题在三个固定机位截图，人工评审一次后冻结为视觉基线（存 `fixtures/city-visual/`，
  只做人工比对参考，不做像素级自动断言——软件渲染与 GPU 渲染差异过大）。
- draw call 预算：高画质 ≤ 60，省电档 ≤ 35（当前约 24）。
- 帧时间：M1 级别机器高画质 ≥ 50 fps（真机测，记录在 PR 描述里）。

## 8. P4：个人化地形与称号

- 种子由「本机安装 ID」派生（已存在于设置中则复用；不存在则首次生成并本地保存），**不来自
  账号、不来自任何网络标识**。
- 允许用户在设置里「重新生成我的岛」（换种子）。
- 称号：基于聚合统计的确定性规则表（例：深夜会话占比 > 40% → 「夜猫子之城」；Codex 占比
  最高 → 「重构港」）。规则表放 `cityTitles.ts`，中英双份，每条规则可单测。
- 代价：
  - `layoutCity` 默认种子从常数变为参数，`verify-react-city-layout.mjs` 与航拍守卫改为多种子。
  - 公共用地坐标、城区锚点目前写死，必须改为由种子 + 海岸形状推导，否则换种子后会落进海里。
    航拍守卫的多种子测试已能发现这类问题（净空、城区字卡数量）。
