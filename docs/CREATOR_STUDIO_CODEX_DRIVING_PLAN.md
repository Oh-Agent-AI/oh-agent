# Studio 复杂创作实施方案

用户在 City 或 Game 编辑器选定 Agent、描述目标，并可附上当前视口截图。以「在咖啡馆门口创建一辆玩家能开的黄色汽车」为首个验收任务。用户可以查看实际生成的车辆、试驾并审阅变更，确认后才保存到作品。

## 1. 让 Agent 看懂当前位置

- Studio 在提交任务时提供可选的「附上当前视口截图」。复选框默认关闭，同意范围为本次执行和所选 Agent。界面提示联网 Agent 可能将图片提交给其模型服务。
- Rust Host 在 ACP 初始化完成后检查图像能力。启用附件时向官方 Studio WebView 请求有界 JPEG，核对作品 ID、权威修订与帧对应的视口修订，再通过 ACP 内容块交给 Agent。复用现有 MCP 截图预算。
- City、Game 分别走已有渲染器采集入口。Game 使用独立项目视口，旧版从使用统计构建的城市视口不提供截图附件。Story、无画面、画面过期、连接不接收图像时提供明确反馈。目标和任务状态仍沿用现有任务台账，截图只用于本次会话上下文。
- 验收覆盖有图、无图、视口切换和不支持图像的连接。进一步用打开真实 City/Game 的 Studio 验证发送时刻的画面。

## 2. 给 Codex 可编程的创作环境

- 先读取作品版本、选中对象、场景布局与可用资产。截图辅助定位，可靠对象引用来自 Creator SDK 的场景查询。
- 优先复用现有驾驶模板和 TS 驾驶内核。给 SDK 增加可验证的地面车辆定义，连接模型、碰撞体、道路出生点与驾驶参数。实例化、玩家交互、动力学和输入在 TS Runtime 内生效。
- 当模板无法覆盖目标时，Host 为该任务提供作品级临时工作区。复用现有代码工作区的读取、补丁、构建和测试能力，授权绑定任务、作品和基准修订。先接通已有预览工件，再考虑扩大 SDK 的可编辑范围。
- 验收从空车位创建实例，校验道路锚点和资产引用，生成可加载的预览工件。Agent 能读构建和运行诊断，修正后再次验证。

## 3. 让编辑器看见结果并完成试驾

- Host 将通过验证的预览交给 Studio，绑定作品修订、预览标识和任务。Studio 在隔离预览实例中应用结果，视口标记新增车辆，Agent 侧显示运行时实际确认的阶段。出现更高修订时重新验证。
- TS Runtime 跑一段可重复的测试输入，检查上车、向前移动、转向、制动和碰撞，并保留观测值。用户随后可在相同预览中手动驾驶。发布和真实安装沿用已有独立操作。
- 验收同一任务从截图和描述开始，车辆在视口出现，玩家可驾驶，任务卡显示可核对的运行结果。确认生成一个保存修订，重复确认沿用 Host 回执。退回、取消或版本冲突时清理临时预览，基准作品可重新打开。

## 交付和验收口径

| 阶段 | 主路径 | 必验失败场景 | 通过证据 |
| --- | --- | --- | --- |
| 视口上下文 | 用户选择 Codex ACP，输入目标并勾选截图。Host 发送文本与一张 JPEG。 | 作品或版本被切换、切回旧统计城市、Agent 不支持图像、截图超预算。 | 测试 Agent 收到预期图片块，真实 Codex 能识别合成 JPEG，真实 Studio 能采到当前画面。 |
| 项目内编程 | Codex 在本次任务的工作区读取模板、编辑车辆交互、构建、读取诊断并再次构建。 | 修改越界、工作区 CAS 冲突、引用其他工作区的构建、重试时旧任务已经取消。 | Host 能从任务和作品回溯到执行授权、工作区修订与不可变构建。 |
| 场景试驾 | 渲染新车，玩家走近交互、驾驶并离开。Agent 读取同一次预览的测试结果。 | 不存在的道路锚点、车身与地面或障碍物相交、范围外的驾驶参数、用户退回或预览过期。 | 一次可复现的测试运行与人工试驾，确认后产生唯一的新作品修订。 |

## 第 2、3 阶段的接口约定

- 工作区解析顺序为「任务 → 作品 → 基准修订 → 临时工作区」。每次写入携带预期源码修订。构建与试玩都校验构建归属及其输入快照。现有工作区的测试和预览接口接受全局 buildId，接到 Studio 前需补上归属验证和任务级授权。
- 第一版地面车辆定义包含稳定对象 ID、受信资产引用、原有 City 道路出生锚点、物理配置引用和可驾交互。优先复用 TS 的 `createCityCarSession`。通用车身配置经 SDK 校验后进入 Runtime，项目特有的赛制和交互留在游戏包内。
- 预览结果至少包含任务 ID、基准修订、构建 ID、预览 ID、实际加载状态。测试再关联地面版本、输入序列、执行步数、车辆位移及碰撞观测。提交走已有 Host 滚动修订与幂等回执，载入成功和试驾通过由运行时分别上报。

## 工作区构建与真实 ACP 验证

- 工作区源码写入按预期修订检查，独立 MCP 进程的写操作串行处理。构建从只读的输入视角消费经核对的临时快照。构建身份包含工作区 ID 和所用源码修订，临时路径从源码映射中移除，同一修订重建得到相同的构建 ID。
- 工作区级测试、预览和发布校验构建归属，测试及发布的 provenance 使用封存修订。当前工作区仍可重复测试自己的历史构建。早期未绑定工作区的构建需要重建一次，Studio 的通用封存构建预览入口继续按原合约读取已有 buildId。
- 本机真实 Codex ACP 在只读模式下，每次只批准合成工作区的指定 MCP 调用。Codex 自行读取和修改 TypeScript，将示例移动速度从 10 改为 30，生成封存构建并调用无头测试，结果为 route_complete，40 tick。真实 MCP 回归同时验证旧构建仍能复现原来的 120 tick，以及跨工作区复用被拒绝。
- Studio 接线仍需将授权绑定到任务、作品与基准修订，过期或取消时撤销。开发 CLI 的显式本地写权限只用于合成工作区验证。现有无头测试通过 Node 导入编译后的脚本，Studio 自动运行生成代码前需要隔离执行器。地面车辆定义、实际道路试玩和人工保存是独立验收项，合成场景中的移动测试无法覆盖这些行为。
