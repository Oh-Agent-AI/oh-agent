# Landing 改版 Spec：由 Agent 历史生成个人数据世界

状态：**本地预览已实施并完成开发验收，公开发布待验证**。规格日期：2026-10-15；实施更新：2026-10-16。见 [实施与验收记录](../website/landing/RELEASE_REVIEW.md)。

本文件定义 `website/landing/` 下一版的定位、内容、视觉、交互与发布验收。本文中的目标文案和体验要求不代表已经实现；实施进展见 §11。

## 1. 产品定位与文档关系

用户确认的方向：分析和可视化用户使用桌面 Agent 留下的数据，以历史数据驱动城市、回放与游戏化探索。Agent City 是首页当前重点展示的体验，后续其他玩法须按实际发布状态介绍。

首页需要让访问者依次理解：

1. 这是分析桌面 Agent 使用历史的 macOS 应用。
2. 自己的会话记录可以生成一座可探索、可回放的城市。
3. 点选数据建筑，可以进一步了解对应的活动与用量。
4. 会话数据留在本机，无需上传到云端进行分析。

2026-10-16 用户确认产品品牌改为 **Oh Agent**，体验名称使用 **Agent City**。官网中英文品牌、标题、CTA 和分享文案统一；工程目录、已有部署路径与内部应用标识保持兼容。本轮未执行域名迁移、账号或商业套餐变更。

本 spec 对新版首页的信息架构、主视觉与转化路径优先于以下旧文件；旧文件中的历史检查结果不可视为当前发布事实：

- `LANDING_VALUE_FIRST_SPEC.md`：保留证据与金额口径要求；原诊断优先 Hero 和屏序由本文替代。
- `LANDING_POSITIONING_AND_GTM_2026.md`：保留隐私原则、支持范围诚实披露；首页主叙事由本文替代。
- `LANDING_VISUAL_REDESIGN_REVIEW.md`：其二维监测故事与“不使用 Three.js”属于上一版视觉决策；新版允许复用 City 场景。

产品边界依从 `AGENTS.md`、`CITY_LOCAL_DATA_PROJECTION.md`、`CITY_UX_SPEC.md` 和 `CITY_DATA_LEGIBILITY_SPEC.md`。如实现与文档冲突，以待发布构建的代码和实测为准，先修订承诺清单再上线。

## 2. 目标用户、价值与闭环

首要用户：已经使用 Claude Code、Codex 等受支持桌面 Agent，机器上已有可分析记录，希望回顾使用历史、理解用量，并喜欢可探索的数据可视化的个人用户。首发不承诺覆盖任意办公 Agent 或任意框架。

价值层次：

| 层次 | 用户得到什么 | 首页如何呈现 |
| --- | --- | --- |
| 吸引 | 看到自己的 Agent 历史拥有独特的空间形态 | 城市主视觉与样例交互 |
| 理解 | 看出来源、会话规模和时间活动 | 点建筑、切换窗口、时间回放 |
| 实用 | 查看用量、费用依据和值得复核的会话 | 实际分析界面与支持范围 |
| 信任 | 在本机探索私人历史 | CTA 附近的隐私说明与可核验源码 |

期望闭环：**看到样例 → 下载 → 读取本机可用记录 → 看到自己的城市 → 探索对应会话 → 后续回来查看变化或导出作品**。

Aha moment：用户认出某段真实使用历史对应的城市变化，并能选中建筑理解其来源。漂亮的合成城市只是体验预览，不计为个人数据激活。

## 3. 实现基线与发布承诺

2026-10-15 本轮源码与规格检查得到的基线；本表是改版输入，不替代发布前实测：

| 项目 | 当前证据 | 首页处置 |
| --- | --- | --- |
| 旧首页 | `index.html` 仍以 checkup、burning money 和日志检查为 Hero；统计 Demo 在 City 前 | 更新 Hero、屏序、导航及中英文 meta |
| 网页城市 | `city-host.js` 合成 fixture；有 `city3d/` 时挂载 iframe，否则保留 canvas 示意 | 常驻标注“样例城市 · 模拟数据”；禁止请求真实本机记录 |
| 网页协议 | 当前 host 返回 `city:v1`；本机文档为 `city:v2` | 先核对生产插件 SDK；演示协议适配是 P0，不假定可直接搬到首屏 |
| 本机 City | `city:v2` 本机投影，默认最多返回 500 个会话，提供覆盖字段，不分页 | 不宣传完整全历史；城市覆盖数量由数据驱动 |
| City 费用与诊断 | 费用尚未投影；Findings 为 partial 汇总 | 费用与完整诊断展示在分析界面，不能拼成 City 已支持功能 |
| 视觉语义 | 会话对应建筑，token 规模影响楼高，执行环境组织城区 | 楼高不代表产出质量、任务成功或工作价值 |
| 拍照和影片 | 存在实现与后续迁移记录；旧首页写死 2560×1440，与其他规格不一致 | 分别验证格式、尺寸、保存与降级；验证前不写固定规格 |
| 下载与公开源码 | 页面已有 GitHub 链接；本轮未核实公网发布状态 | 发布时核实可访问资产、架构、系统要求及签名/公证状态 |

回放的生长、施工与灯光只使用当前真实映射能解释的含义。不能用“任务正在完成”“成功率上升”等文案解释视觉动画。背景建筑须与数据建筑可区分，并且不计入数据数量。

## 4. 页面结构与推荐文案

英文为默认语言，提供完整中文切换。每一屏围绕一个主要问题设计；屏高随内容与设备变化，不强制每节占满视口。

### 4.1 导航与 Hero：让用户理解并进入体验

导航：Agent City / Insights / Privacy / FAQ；中文：城市体验 / 数据洞察 / 隐私 / 常见问题。右侧常驻 macOS 下载入口与语言切换，窄屏收起次要导航。

推荐英文：

> Your agents work. Your world grows.
>
> Explore your desktop agents’ sessions as a living city. Replay activity, inspect usage, and discover patterns — with your session data kept on your Mac.

推荐中文：

> Agent 在工作，你的世界在生长。
>
> 将桌面 Agent 的会话记录变成可探索的城市。回放活动、查看用量、发现变化，会话数据留在你的 Mac。

Hero 主 CTA：`Explore the sample city` / `探索样例城市`，滚动并激活 §4.2。

Hero 次 CTA：`Get for macOS` / `下载 macOS 版`，进入下载区；若只有测试版，必须明确 beta。导航和终屏以下载为主要动作。

CTA 下方信任带：`On-device analysis · No API key required · MIT open source`，中文“本机分析 · 无需 API Key · MIT 开源”。MIT 与下载状态均须经过发布核实。

2026-10-16 用户确认首屏直接使用 City 前端运行 mock 数据。嵌入 `apps/agent-city/ui` 构建产物，通过 city:v2 提供 mock 会话；不另画城市替身。桌面与平板超过 600px、可见且未要求减少动态或节省数据时自动启动；窄屏和 reduced-motion 保留主动进入。常驻标明 mock 会话。失败时展示当前演示生成的预览和明确重试。

页面 title 候选：`Oh Agent — Your agents work. Your world grows.`；中文“Oh Agent — 让 Agent 历史鲜活起来”。description、OG 和分享图同步定位，域名不预先改为未部署地址。

### 4.2 样例城市：让用户理解“这就是我的数据会变成的样子”

标题：`Explore a week of agent activity.` / `探索一周 Agent 活动。`

使用同一份确定性的 mock 数据；按用户 2026-10-16 的密度要求，默认 30 天、2000 条会话，7 天为 469 条。前端绘制上限为 4000，2000 条不会因该上限被聚合。此为网页合成演示，不修改原生本机投影的 500 条限制。优先提供三个动作：选择建筑、播放/暂停时间、切换 7/30 天。只有当生产 City 支持并经网页集成验证的动作才出现。

交互区常驻可见：`Sample city · Synthetic data` / `样例城市 · 模拟数据`。附一句“安装桌面应用后，基于本机可用会话生成你的城市”。说明不藏在 tooltip 或页脚。

首次进入只提示一个动作：“点选一栋数据建筑”。选择后显示来源、时间、token 与事件数量等已声明字段，并明确仍为样例数据。没有真实跳转目标时不出现“打开真实会话”按钮。

网页演示禁用宿主数据读取、安装授权、原生日志查看等能力。不支持的功能从演示工具栏隐藏；页面不得通过伪成功提示模拟保存或真实数据连接。

演示失败、无 WebGL 或未构建 `city3d/` 时展示真实产品静态图或演示视频，并提供“查看演示”和下载动作。普通 canvas 概念动画可作为标注的示意图，但不得冒充可交互产品或用它掩盖协议错误。

### 4.3 数据如何形成城市：给视觉一个可理解的含义

用同一座城市的三处标注解释映射：

| 标注 | 页面表达 | 必须遵守 |
| --- | --- | --- |
| 数据建筑 | 一栋建筑对应一段被纳入视图的会话 | 背景建筑不冒充用户会话 |
| 城区与规模 | 来源组织城区；token 用量影响建筑高度 | 不描述成收入、成果或生产力 |
| 时间 | 回放已记录活动在所选时间窗的变化 | 不描述成任务完成进度 |

窗灯等具体映射若未能在代码和界面图例中核实，不作为独立数据指标宣传。配一条轻量说明：“画面体现记录中的活动与用量，不评价任务质量。”

### 4.4 洞察：从城市继续理解使用历史

标题：`Get to know your agent habits.` / `看懂你的 Agent 使用习惯。`

最多三项，每项配当前产品真实界面截图，截图使用安全演示工作区，并标明样例：

1. 用量：按来源和时间查看记录中的 token 与活动趋势。
2. 费用：区分实际记录金额、订阅费与按量名义估算；不跨币种直接相加。
3. 会话：查看可用轨迹和支持的异常线索，按证据复核。

费用能力是桌面分析视图能力，不暗示已在 City 建筑详情中实现。订阅“值回成本”如展示，必须同时标明订阅实际费用和 API 等价名义估算，两者差额不能称为已经节省的钱；利用率没有明确额度分母时不显示百分比。

删除当前首页反复出现的 checkup、burning money 与检查日志主叙事。啄木鸟 ASCII 可用于该屏的轻量品牌点缀，不能和城市争夺主视觉。

### 4.5 留下作品：可选屏，有验收证据才上线

展示实际导出的图片或影片，并给出本地保存的操作描述。文案：`A view worth keeping.` / `把这段历史，留成一张风景。`

只展示发布版本实际可用格式和画质。用户自行分享导出文件；不新增云端作品链接、自动发布、排行或成就体系。公开素材不包含任务摘录、路径或可识别私人信息。

如果当前导出能力尚未验收，本屏从发布范围移除，不阻塞核心 landing 改版，也不写“即将支持”占位。

### 4.6 隐私：让用户知道记录在哪里处理

标题：`Your history stays on your Mac.` / `你的历史，留在你的 Mac。`

三步小图：`本机 Agent 记录 → 本机分析 → 本机城市与图表`。说明会话数据不上传，默认不引入遥测、云端分析或账号。

下载公开价卡、版本信息及用户明确选择的官方资源可能联网，这些请求不携带会话记录。避免“整个应用绝不联网”的表述。

网页样例和已安装应用的数据来源区别在本屏再说明一次；源码与 LICENSE 使用已核实链接。隐私承诺在 Hero 就可见，本屏提供具体解释。

### 4.7 支持范围、FAQ 与下载

来源列表取待发布版本的支持矩阵，不根据网页 fixture 中出现的来源名称推断支持。区分使用记录、费用、轨迹和 City 数据的覆盖，不使用框架无关或所有 Agent 都支持的笼统承诺。

FAQ 至少回答：需要什么本机记录；网页是否读取了我的会话；安装后无数据怎么办；建筑代表什么；费用是否真实账单；支持哪些系统和 Agent；应用是否开源。

下载区展示三个可理解步骤：下载安装 → 根据提示读取本机已有记录 → 进入自己的城市。没有日志、没有权限、读取失败、记录不完整分别说明处理方向；不承诺固定 30 秒首次生成。

终屏文案：`See the world in your agent history.` / `看看你的 Agent 历史，会长成什么样。`

下载 CTA 仅指向核实过的可访问 Release 或安装包；点击行为符合文案。尚无可公开下载构建时，使用“查看发布进展 / View releases”，不虚设下载成功。系统最低版本、芯片架构、版本号及安装提示根据实际安装包填写；签名与公证分别核实，不沿用旧文案。

## 5. 视觉与动效要求

- 延续深色底与薄荷绿品牌色；以城市日落、灯光和空间层次作为视觉记忆。警示色只用于真实演示中的对应状态。
- 桌面正文建议 16–18px，辅助说明至少 14px；Hero 英文标题约 48–72px，中文约 40–60px，随宽度调整并检查实际断行。颜色和字号以可读性验收，不为追求科技感压低对比度。
- 首屏单一主视觉；减少重复卡片、大面积 ASCII 背景和多处同时运动。啄木鸟保留为品牌角色，可出现在标识与洞察区域。
- 交互按钮使用文字说明。窄屏操作目标至少 44×44 CSS px，适应 360px 视口；正文和重要状态不省略为不可理解的截断文本。
- 使用本地字体栈、本地素材和本地打包引擎。无外部字体/CDN依赖，不新增追踪脚本。
- 图片/影片预留宽高，减少布局跳动；不自动播放声音。提供暂停动效，遵循 reduced-motion；减少动态时仍可手动探索城市。

## 6. 演示加载、性能与降级

1. Hero 使用当前 City 前端；桌面可见时自动加载 mock 城市，窄屏、减少动态和节省数据时由用户进入。加载期间显示明确状态，见 §4.1 的 2026-10-16 更新。
2. 同页最多一个活动 3D 实例；离屏、标签隐藏后挂起。无使用意图的移动访问默认保留静态预览。
3. 通过生产 SDK 的明确 ready/失败信号展示交互，不再靠固定 900ms 将 iframe 当成已就绪；启动 20 秒未成功展示可操作的重试与静态替代。
4. 校验 `city:v2` 数据契约、来源身份与字段；仅注册网页演示需要的方法。既有 `city:v1` fixture 必须升级或有明确的、经测试的兼容路径。
5. 导航滚动、页面按钮与 FAQ 不依赖引擎启动成功。WebGL context 丢失有明确恢复/静态降级，不静默显示损坏画面。
6. 性能验收目标：360×800 和 1440×900 视口分别检查布局；记录浏览器、设备、网络和构建版本。另以 Lighthouse 默认移动模拟配置跑 3 次，LCP 中位数目标 ≤2.5s、CLS ≤0.1；未达到则记录实际结果与优化项。此处是工程目标，不作为用户端速度承诺。

## 7. 文案、隐私与增长边界

- 中英文具有相同支持范围、模拟数据标识、金额含义和下载状态；动态文案、aria、失败态和分享 meta 均覆盖双语。
- 分享图使用城市实际渲染图与一句产品定位，配置绝对 URL、canonical、OG、Twitter card；所有地址依实际部署站点填写。
- 不宣传自动干预、健康分、进度百分比、已验证省钱金额、任务成功率或尚未发布的游戏模式。
- 不请求用户上传 sessions 来生成城市；不提供网页本机日志授权入口。内嵌插件仍遵守宿主投影权限，landing 只接收合成样例。
- 增长测量优先使用公开 Release 下载数、GitHub stars、用户自愿反馈和小规模可用性测试；不新增客户端行为上传。没有站点访问数据时，不把下载数写成下载转化率。

## 9. 验收标准

### 9.1 内容与易用性

- 首屏可见 Agent 历史可视化、macOS、隐私和两个明确 CTA；不必滚到中段才发现城市。
- 找 5 位未参与开发、符合目标画像的使用者看首屏 5 秒；至少 4 位能说明产品用途，且不会认为它在自动完成任务或上传日志建城。记录原话；这是小样本可用性门槛，不代表市场验证。
- 进入样例后，至少 4/5 位能在无口头引导下选中数据建筑并找到来源与用量；能区分模拟数据与自己的记录。
- 中英、360px 窄屏及桌面均无文档横向溢出；主要操作不遮挡、文字不压在城市关键区域。
- 图例可解释建筑、规模与时间；背景建筑不被误认为自己的会话。所有费用保留口径与未知状态。

### 9.2 功能与工程

- CTA、锚点、语言切换、FAQ、动效暂停、键盘焦点和演示加载/重试可用。
- fixture 与生产 SDK 契约一致；实际点选建筑、切换窗口、播放/暂停均通过浏览器交互验收，不能只靠静态选择器存在证明。
- 分别验证无 City 构建产物、协议拒绝、加载超时、无 WebGL、reduced-motion 和页面隐藏；均有可理解结果。
- 挂起后渲染循环停止或进入已有明确节能状态；引擎失败不影响下载和导航。
- 检查页面全部网络请求：无用户日志上传、遥测或第三方追踪。来源于本地的素材与合成 fixture 不夹带开发者私人信息。
