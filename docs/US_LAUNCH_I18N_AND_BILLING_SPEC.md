# 美区首发：国际化与费用可信展示 SPEC

日期：2026-09-29  
状态：Draft / 部分实施、未验收（进度见 [任务跟踪](US_LAUNCH_I18N_TASKS.md)）  
产品：Agent Vitals 智能体监测  
范围：macOS 桌面应用、配套英文安装说明和落地页金额口径

## 1. 目标与发布边界

让英文用户独立完成「安装 → 发现本地记录 → 看懂用量与费用 → 查看会话证据」，不因语言、时区、币种或费用来源产生误解。

首发必须交付：

- 英文与简体中文核心流程完整；支持跟随系统与手动选择。
- 界面语言、地区格式、统计时区、原始金额币种相互独立。
- USD 是美区新建表单的建议币种，不是全部历史金额的目标币种。
- 原币种分栏；明确区分账单记录、订阅声明、按量估算、API 等价估算。
- 缺失、部分覆盖、已有折算均有可理解的提示。
- 不新增用户数据上传、汇率联网、云账户或遥测。

不在首发范围：实时外汇服务、银行结算对账、税务发票、汇兑损益、自动币种合计、所有 ISO 币种的录入、完整 CLI 多语言化。可见但非首发核心的高级入口也必须有英文标签和可理解的错误，不能以“高级”豁免。

本文是增量需求，不授权改写原始用量、用户账单或声明。预发布旧估算可按价卡与 FX V2 的本地升级流程失效并重建；公开机器契约的变化仍需单独评审和测试。

旧三轴规格允许结算币默认 CNY，并允许 fallback 估算按 `fx_estimate` 转换。产品尚未正式发布；[价卡与 FX V2](PRICING_CURRENCY_AND_FX_V2_SPEC.md)现明确取代这两条面向新计价的规则。不为旧派生估算保留永久兼容：升级时可在本地备份与影响预览后使其失效并重建，证据不足则未定价。原始用量、用户账单、价卡、订阅及预算输入不能被清理或静默改值；Python/Rust parity 和各消费面仍须验收。

## 3. 国际化需求

### I18N-01 偏好与首次启动（P0）

逻辑偏好为 `language = system | en | zh-Hans`、`format_locale = system | explicit locale`、`statistics_timezone = system | explicit IANA zone`；实际存储须复用现有设置所有者，不建立两套权威。

- 新安装：语言跟随系统，不支持语言回退英文；地区格式跟随系统。
- 已有用户：保留已选择的时区、预算和币种；没有语言偏好时跟随系统。
- 统计时区解析由后端提供统一结果；无法解析系统时区时使用 UTC 并明确提示，不静默落上海。
- 用户可切换语言；切换不清空筛选、未提交表单或会话选择。
- 新建 USD/CNY 表单：已有编辑值 > 明确选择/现有相关设置 > 美区地区默认 USD；非美区默认策略沿用既有规则并记录。英文语言本身不得决定美元。

### I18N-02 翻译资源与错误（P0）

- React 建立统一 `t(key, parameters)` 入口及 `en`、`zh-Hans` 资源；稳定语义 key，禁止把中文整句当业务枚举。
- 采用支持参数与复数的实现；禁止通过字符串拼接构造英文复数、日期或带金额的完整句子。
- 后端业务枚举保持稳定。错误提供安全 code + 参数，前端映射文案；未知错误提供本地化兜底及可复制安全错误码。
- 首发覆盖：导航、总览、用量、会话/轨迹、设置、计费确认/修订/撤销、预算、空状态、加载/失败/重试、权限、更新、菜单栏和应用通知。
- 模型名、供应商名、用户内容不翻译；原始本地错误不可自动上传翻译服务。
- 缺翻译回退英文，生产 UI 不直接显示 key；CI 检查键集合、参数和复数分支。
- macOS 原生菜单与 WebView 使用同一语言偏好，通过构建产物/共享资源映射衔接；不得形成独立设置。

### I18N-03 统一格式化（P0）

- 集中提供 money、number、token、date/time、duration 格式化接口；组件不得直接拼 `$`/`¥` 或自作计价。
- 使用地区感知格式；混合币种视图明确写 USD/CNY，单币种紧凑视图也需在标题或可访问标签中标明代码。
- 不默认所有币种都有两位小数；首发录入仅开放已支持币种，其他来源币种只读保留，不擅自除以 100。
- `null` 显示 `— / Unavailable`；确认为零显示零；非零小额不能因两位小数变成“免费”，可显示 `< USD 0.01`。
- 货币输入校验精度、范围和安全整数；禁止 `parseFloat` 宽松吞掉分隔符后写入错误金额。USD/CNY 精确到分，更细估算保留后端既有精度与舍入规则。

### I18N-04 时间边界（P0）

- 显示地区不改变时间戳；统计时区控制今日、月份、预算窗口和修订生效日。
- 供应商峰谷价格时区、账单结算周期与用户统计时区独立，不覆盖源证据。
- 使用 IANA 时区日历运算；不将“一天”固定为 24 小时处理夏令时。
- 切换时区后相关视图一致刷新并失效旧聚合缓存；若后端需要重建，展示处理中/失败，不混用新旧窗口。
- 日期型账期不经浏览器 UTC Date 隐式转换，避免月初变成前一天。

## 4. 费用语义与展示

### BILL-01 费用分桶（P0）

| 用户标签 | 语义 | 不可误解为 |
|---|---|---|
| Recorded charges / 已记录费用 | 来源明确的账单或计量金额，保留证据等级 | 银行已扣款；除非存在支付证据 |
| Declared subscription / 已声明订阅 | 用户填写的订阅价格与周期 | 已验证账单 |
| Estimated metered cost / 按量费用估算 | 按路由/价卡等依据估算 | 实际支付金额 |
| API-equivalent estimate / API 等价估算 | 参考 API 单价换算用量 | 订阅外额外费用 |
| Allocated subscription cost / 订阅分摊成本 | 月费按既定规则分摊 | 当天实际扣费 |
| Unpriced usage / 未计价用量 | 有用量，缺价格或必要依据 | 零费用 |

这些是展示分类，不要求直接新增或重命名既有 basis 枚举；实施前提交既有枚举到展示分类的完整映射测试。`harness_billed` 也不得仅凭名称被标记 paid。

### BILL-02 汇总、覆盖与重复计算（P0）

- 同币种、同可相加口径才汇总；不同币种分栏。禁止以各币种数值相加生成 Total。
- 真实/记录费用与 API 等价估算不可叠加；订阅分摊不可再次叠加订阅月费。
- 同范围账单替代估算时需匹配计费方、账户/订阅标识（来源可用时）、周期与覆盖范围；不按同一个 provider 全局吞掉估算。
- 部分账单覆盖只替代匹配范围。范围未知时并列说明，不编造完整总额。
- 用户声明不变成原生日志证据；修订/撤销必须保持现有版本链、历史生效范围和跨页面一致性。
- 覆盖提示包括未计价用量和原因；不能以“所有金额都能解析”推导“所有用量都已覆盖”。
- 总览、日历、会话、预算消费统一后端语义；不得在各页面独立决定订阅或重算金额。

### BILL-03 预算（P0）

- 保留 confirmed/estimate 两类口径；V2 切换造成的预发布估算预算变化需预览并重建，不能默默变换预算币种或用户输入。
- 估算预算中的订阅分摊需明确显示；旧 FX 派生值必须失效，不能称为实际支出预算。
- 缺汇率/缺价展示“覆盖不完整”，不得显示“预算充足”作为确定结论。
- 更换预算币种必须明确重新输入金额或确认参考换算；不能把 CNY 100 自动变成 USD 100。
- 同一范围所有金额和预算状态在后端计算；语言变更不得触发预算警报。

## 5. 汇率政策

### FX-01 首发（P0）

- 不接入新汇率 API，不因选择英文请求汇率；不添加硬编码“实时”备用值。
- 新的默认费用视图展示来源币种；旧 `fx_estimate` 派生结果按价卡与 FX V2 的发布前本地重建流程处理，不继续进入新费用路径。
- 首发的用户手动参考折算仅为即时 what-if，必须可辨认为估算；能提供的 source/target currency、rate、rate basis、price snapshot/version、rate date 必须透出，未知字段如实为空。无日期手动率不能生成历史折算账本。
- 旧结果无法安全重建时显示未定价/覆盖不完整，不把应用启动时间补作汇率日期。
- 不改变源账单金额，不把未知价格通过换汇变成可计价。

### FX-02 后续参考折算（P1，另行批准）

可选 `reference_currency` 只影响显示，返回独立转换对象，不覆盖金额事实：

```text
source_amount + source_currency + amount_basis + provenance
conversion?: target_amount + target_currency + rate
             + rate_date + fetched_at + rate_source + fx_snapshot_id
             + pricing_snapshot_id + usage_revision
             + stale + conversion_policy + report_revision
```

“当前参考汇率”只用于即时 what-if；未来的历史参考报表必须按事实日期绑定不可变 FX 快照，封账后查询不得使用当前汇率重算。晚到事实或来源勘误只能创建可见修订，不能覆盖旧报表；无合法历史日汇率则保留原金额。封账时机和修订规则按[价卡与 FX V2 §6.2](PRICING_CURRENCY_AND_FX_V2_SPEC.md)另行评审。联网需先修订仓库网络政策和产品隐私说明，即使请求不含用户数据也不能直接新增。

## 6. 工程分层与兼容要求

1. 摄入/存储：不因语言或地区改变事实；保留现有金额单位、来源与时间语义。
2. domain/billing/query：提供已分桶金额、覆盖、时间窗口及安全元数据；按需增量扩展契约。
3. runtime/Tauri：传递统一偏好和后端投影；不另造价格计算器。
4. React/原生展示：翻译与格式化，不判断账单真伪、不换算费用。

金额继续采用现有整数最小单位/精确定点方案；禁止浮点累计形成支付金额。JS 超安全整数必须拒绝不精确渲染或使用字符串/精确类型，不能静默取近似数。

新字段采用版本化策略；旧响应缺少 FX 元数据或无法重建时显示依据不足/未定价。CLI JSON、MCP、导出或 golden 契约如需变化，须列出消费者、升级方案和 parity 测试；MCP/默认导出继续脱敏。预发布旧估算不承诺数值稳定。
