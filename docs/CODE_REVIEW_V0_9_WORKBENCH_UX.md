# 产品体验审核：控制面板视觉页（总览 + Token 日历）（2026-09-05）

- **素材**：两张真机截图（总览页、Token 日历页）。
- **状态对齐**：截图 = `f110066`（同步时间 22:13）；10 条代码缺陷修复 `29c0717`
  在 22:17 落库——**截图早于修复 4 分钟**。本审核逐条标注「已修 / 仍开」，
  引用行号以当前 `main`（29c0717）为准。
- **视角**：产品用户（一个要管理多执行环境 AI 开销的开发者），不是代码正确性——
  正确性见 `CODE_REVIEW_V0_9_STAGE_A_D_KPI_BILLING.md`。

## 总评

诚实性优先的设计立场（无数据绝不渲染 0、口径标签上卡面、归属待核、范围外
明示）在同类工具里少见，方向正确。**但当前诚实性的表达成本几乎全部转嫁给了
用户**：同一屏出现四套互相对不上的金额、三处自相矛盾的陈述、以及大量内部词表
直出。用户打开总览的第一个问题——「我今天花了多少钱」——在页面上**没有直接
答案**：最醒目的绿色大字是一笔他（订阅制下）根本不用付的标价反事实，真付的
钱是一张灰色的「无数据」。

## P0 —— 伤信任 / 挡住主任务

### 1. 同屏自相矛盾：「无数据」vs「0.00」（仍开）

截图左中「今日实际支出 **无数据**」，同一屏右上副行「实际 **0.00**（币种未声明）/M」。
同一个量（当日账单级实付）两种说法——正是 spec §0.1 禁的"看似完整的总额"在 UI
上复活。`29c0717` 给副行加了「跨币未折算」前缀，但双标仍在：`workbench.js:568-572`
对空 map 求和得 0 → 渲染「实际 0.00」，而 :578 同一数据的 tile 渲染「无数据」。
**修**：空 → 副行同步「无数据」；或统一为「账单级实付：无（订阅内 + 未出账）」。

### 2. 本月四个对不上的钱数，页面不排位

同屏并存：名义 `$1497.60 + ¥580.67`｜实际 `¥232.00 + $20.00`｜预算 `已用 0%（¥0/¥600，
仅 DSH 实测）`｜双轨账 DeepSeek `估算 ¥452.87`。每个都带了口径标注（好），但用户
没有工具知道**哪一个回答"我这个月要付多少"**。预算卡 0% 与旁边 ¥232+$20 的视觉
冲突，就是 2026-09-01「两卡打架」事故的残留形态——口径标注字号救不了数字对撞。
**修**：页首加一行"本月结论"：`实付 ¥232.00 + $20.00（含订阅月费 $20+¥114+¥118；
DSH 实测 ¥232；其余为标价/上界诊断，不计账单）`。把四个数字变成一个结论 + 三个
展开。

### 3. 视觉层级倒置：最贵的字给了最不像钱的钱

名义成本是全页最大、唯一绿色的金额（hero），而它是**标价反事实**——订阅制用户
一分钱都不用付；用户真付的「实际支出」是无色卡 +「无数据」。**修**：实际支出
升到 hero 位或同等权重；名义保留但加显眼徽标「标价口径 · 非账单」。绿色作为
"金额正常"的语义色也应重审——名义 $333 是绿色的，实际 ¥232 是灰的，颜色在说
反话。

### 4. 「可汇总总额 0.00」大浅色盒（仍开）

日历页下方浅色大块 `可汇总总额 0.00`——用户刚看完头部 `¥580.67 + $1497.60`，
紧跟着一个 0.00，第一反应是"出错了/钱没了"。浅底色块在暗主题里长得像错误横幅；
裸 `toFixed(2)` 无币种；脚注里的「spec §4：estimate/api_equivalent」是内部词表
（见 #10）。机制：`workbench.js:868-876`，任一执行环境非 unavailable 就按有数据渲染，
哪怕 summable 恒 0。**修**：0.00 时降级为行内灰字「账单级实付：无（DSH 数据
过期，Claude/Codex 为估算口径）」；只有真有 summable 金额才升格为卡片。

## P1 —— 可读性 / 一致性

### 5. 币序机制性不一致（仍开）

名义 `$ + ¥`（by_provider 插入序，anthropic USD 在前）｜实际 `¥ + $`（Rust
BTreeMap "CNY"<"USD"）｜日历头部 `¥ + $`（写死，workbench.js:975）｜日历格子按
执行环境序。同一屏三 种排序，扫读时 $/¥ 位置不固定。**修**：定一条规则（建议 CNY
优先——中文语境、主要支出是 ¥），`fmtCurMap` 一处排序，格子与头部共用。

### 6. 日历格子三段钱串无执行环境标注（仍开，f110066 新引入）

`¥214.76 + $166.82 + $5.34` 哪段是哪家？只能靠页脚图例 + 固定顺序反推；4 号格
`$514.40 + $97.11` 只剩两段 `$` 时连顺序锚都没有（Claude 与 Codex 全 USD）。
tooltip 也不解决：`workbench.js:1025-1029` 的 title 把 token 按执行环境拆开了，耗费行
却是同一串无执行环境的 costs。**修**：格子副行加执行环境前缀（`DSH ¥… · CC $… · CX $…`
）或执行环境色点；tooltip 的耗费行按执行环境逐行列。

### 7. DSH 过期在格子上不可见

DSH 自 09-01 过期，02–05 格子里的 `¥` 段消失——用户会读成"这天没用 DSH"，
实际是"DSH 没测到"。过期声明只在下方概览行（⚠ 过期 · 最后观测 09-01），与上方
格子无视觉关联。**修**：DSH 过期期间，格子 tooltip 加一句「DSH 数据过期（最后
观测 09-01），¥ 段缺席 = 未测到，非零支出」。

### 8. 未来日与"没测到"同款

今天 09-05，6–30 全是未来，却与过去无数据日渲染完全一致（同底、同灰 day 数字）。
用户无法区分"还没发生"和"发生过但没测到"——这两个状态下诚实性语义完全不同。
**修**：未来日降透明度或斜纹（`.cal-cell.future`），今天之后的格子不参与"无数据"
解读。

### 9. 暗底暗字 chip：unavailable 状态几乎不可读（仍开）

截图日历页 DeepSeek Harness 行的 chip 在真机上读不清：`.chip` = `--muted` 灰字 +
面板色边框（workbench.css:629-635），且 renderSourcesPanel 给 unavailable 行挂的
`li.no-data` 类**在 CSS 里没有任何规则**（挂了类没样式）——降级状态恰好是最新
对比度、最需要看清的状态。**修**：给 `.no-data` 定降级样式（更暗的底 + 达标
对比度的文字），chip 文字保证 ≥4.5:1。

## P2 —— 文案 / 词汇

### 10. 内部词表直出 UI

- 「实际 0.00**（币种未声明）**」——这个数是算出来的跨币混和，不是"忘了声明
  币种"；fmtCur(null) 的兜底文案用在了错误的语义上（workbench.js:309）。
- 「**可汇总总额**」——spec 词。用户词汇：「账单级实付」。
- 「**spec §4：estimate/api_equivalent 不冒充真实账单**」「**spec §4 unresolved
  不得归零**」——英文标识符 + 规格编号直接上界面；设计依据留注释，界面说人话。
- 「含未定价 tokens · **待补价卡**」——"补价卡"是开发者待办，用户状态是
  「部分用量暂无法估价」。
- 「processed（**四桶和**）」「数据覆盖 3/3（**分母 v1**）」——保留"已处理
  token（含缓存读写）""数据覆盖 3/3"即可。

### 11. 「值 1.1×」太省

MiniMax 行的「值 1.1×」是"用回本了"的压缩；对照 Anthropic 行「⚠ 归属待核
（66× 与用量矛盾）」——后者是好文案（状态 + 数字 + 原因）。建议前者同样展开：
「值回月费 1.1×」。

### 12. 命中率副行难懂

「跨执行环境 · 命中决定缓存价占比」需要读者自己完成因果推理。建议：「98.5% 的输入
走了缓存价（跨执行环境）」。

## P3 —— 抛光

13. **预算副行一行三段**（截至 01:19 + 已用 0% + 日预算 ¥30）换行后阅读碎片化；
    ⚠ 过期信息建议升为卡面状态色条，不再挤在副行。
14. **截图按钮**（wb-screenshot，截图到剪贴板，workbench.html:20）与「刷新」
    并排占据主导航，视觉权重过高；功能合理（反馈/存证用），建议收进次级菜单
    或加图标与「刷新」作视觉分组。
15. **新鲜度三种表达**：总览「上次同步：成功 22:13」/ 日历头「（新鲜）」/ 概览行
    「⚠ 过期 · 最后观测 09-01」——三种组件、两套语义（同步成功 ≠ 数据新鲜）。
    建议统一一个新鲜度组件（状态点 + 相对时间 + 口径），同步状态另用一行。
16. **今日 tokens 1.16B 无锚点**——巨大数字没有"是多还是少"的参照；副行口径词
    （四桶和）换成了上面 #10 的建议后，可再加一行轻参照（如 vs 昨日 / 本月日均）。

## 亮点（保持）

- 「无数据绝不渲染 0」在格子、tile、summable 三处都贯彻了（#1 的 0.00 是漏网
  之鱼而非立场问题）。
- 双轨账「⚠ 归属待核（66× 与用量矛盾）」——异常自检直白可见，是整个面板里
  最好的一条文案。
- 预算卡「仅 DSH 实测」口径上卡面、数据源面板列「范围外：WorkBuddy」、日历
  页脚给图例——诚实性的基础件都在，缺的是把「哪个数回答哪个问题」的层级
  整合出来。
