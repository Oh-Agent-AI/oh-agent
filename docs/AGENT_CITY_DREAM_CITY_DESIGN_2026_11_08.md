- **日期** 2026-11-08
- **状态** 设计提案，待实施
- **关联** [实施 SPEC 与代码架构](./AGENT_CITY_DREAM_CITY_IMPLEMENTATION_SPEC_2026_11_08.md#54-代码分层与落点) · [远程 3D 方案](./AGENT_CITY_REMOTE_3D_PROPOSAL_2026_11_08.md) · [远程布局一致性 SPEC](./AGENT_CITY_REMOTE_LAYOUT_SYNC_SPEC_2026_11_08.md)

## 1. 产品目标

岛主在桌面 Agent City 点击「开启梦境」，生成一个专属城市链接，可发给朋友。访客用手机或电脑浏览器打开链接，经岛主授权后进入与桌面布局一致的 3D 城市，自由游览，在路边开车，在机场起飞，或在城中开一局机甲战棋。

同一个梦境链接可分享给多位朋友。每个浏览器配对后获得独立权限和独立的玩法状态。甲访客撞车、乙访客打坏建筑，双方都只看到各自的结果。岛主的真实城市、会话数据和桌面战棋存档不会接收这些操作。现有「手机续玩」仍用于接管桌面正在进行的对局，停止远程时可以交还进度。

**梦境就是一份可访问的城市快照。** 浏览器用现有 Agent City 的 Three.js 引擎加载这份快照，再通过原有玩法入口初始化游戏。每位访客的独立状态来自现有玩法的新实例。梦境层负责分享、授权和提供城市快照，玩法负责自己的状态、输入和生命周期。

首版采用**桌面在线、主动开启、限时访问**。沿用中继传输，不在中继持久保存城市内容。桌面关机后仍可访问、公开目录和跨设备继承梦境进度属于后续产品决策。

| 用户入口 | 城市来源 | 玩法状态 | 生命周期 |
| --- | --- | --- | --- |
| 手机续玩 | 建链时的城市快照和当前棋局 | 桌面宿主持有权威对局，停止后可交还 | 随远程对局 |
| 开启梦境 | 发布时的城市快照 | 每位访客在浏览器独立运行 | 随梦境发布和该访客授权 |
| 持久梦境（后续选项） | 可离线访问的已发布版本 | 独立梦境存档，另行定义 | 随发布、过期和删除策略 |

## 2. 岛主与访客流程

1. 岛主选择「开启梦境」，预览城市、选择访客可用玩法，查看中继地址、开放期限和将被分享的字段。默认发布城市几何、公开地标和玩法入口，默认隐藏会话名称、用量和私有标签。首版优先实现这一默认投影。
2. 桌面读取当前生效的布局并做发布检查。模型未就绪、地图与玩法入口不匹配或超过传输预算时，说明原因并保留发布面板，避免生成打不开的链接。棋局、开车和飞行入口分别检查，缺少合格出生点的玩法显示不可用。
3. 发布成功后显示「复制链接」、到期时间、等待授权的访客、已授权的访客以及「关闭梦境」。链接只标识这一份发布和版本。建议试用默认两小时，具体时长和人数由运行数据决定。
4. 访客打开链接，先看到授权等待页。浏览器生成独立凭据并提交访问请求，岛主可以允许或拒绝。通过后访客看到城市和可用玩法，手机触控、桌面键鼠分别提供适配。
5. 访客选玩法，结束后回到城市。重开当前游戏只重置当前访客的状态。首版刷新页面可重新验证同一浏览器的访问凭据，游戏进度随页面生命周期清除，并在离开前说明。
6. 岛主可撤销单一访客、停用邀请入口或关闭整座梦境。岛主可在后续版本显式发布新版。首版每个链接绑定一份固定快照，更新通过新发布完成，进行中的访客游戏保持在原地图上，直至原发布结束。

链接路径示意为 `/dream/<publicationId>#<inviteSecret>`，沿用配置的中继站点。链接可以转发，接收者持链接申请访问，最终授权由岛主决定。邀请密钥与浏览器访问凭据、WebSocket 连接票据分别管理。浏览器凭据只代表一次配对，不承诺识别物理设备。同一链接可以签发多个独立授权，单个授权也可以独立撤销。邀请密钥通过片段传入，客户端只在加入请求中提交，页面和日志避免记录完整链接或凭据。

## 3. 现有方案如何复用

| 现有模块 | 可复用部分 | 梦境首版要补的部分 |
| --- | --- | --- |
| `cityDisplayProjection.ts`、`RemoteCityScene.tsx`、`CityEngine` | 从桌面最终布局导出几何，浏览器恢复城市和镜头 | 提取与机甲棋局无关的城市投影，使用独立版本和字段白名单。现有 v2 外层绑定战场 `site` |
| `remote_gateway.rs`、`remote_gateway_projection.rs` | 桌面授权入口、宿主校验与中继连接 | 抽出按注册能力和会话隔离的通用远程通道，City 发布与可信投影校验由应用适配承接。当前机甲使用固定会话键，需要移除这一通道层限制 |
| `relay/worker.ts`、`remoteAccess.ts` | 房间注册、浏览器配对、临时票据、重连与撤销思路 | 为梦境定义独立权限。当前访客邀请模型限制单个已授权访客，机甲 v1.5 宿主拒绝 `match.join`，需要多访客梦境路由 |
| `DrivingWorld`、`SurfaceDrivingWorld`、`DrivingSimulation` | 驾驶入口、`DrivingState`、仿真、路面和碰撞查询 | 从快照恢复路面和碰撞世界，接入浏览器输入和现有 HUD |
| `GameSession`、`FlightWorld`、`FlightSimulation`、`FlightInput` | 飞行会话、`FlightSimState`、仿真、输入与镜头 | 用快照构建机场、地形、障碍与边界，通过浏览器适配层进入现有飞行会话 |
| `SequentialMechaMatch`、`SequentialController`、`SequentialTurn`、`CityMechaWorld` | v1.5 本地棋局入口、状态、战斗规则与 3D 棋盘 | 用快照中的战场初始化新的 PvE 棋局，复用现有部署、攻击、结算和回放流程 |

快照使用桌面实际生效的几何，包含规划修改和背景楼。浏览器可按兼容版本恢复确定性的基础地形。道路连通、建筑落位和玩法出生点以快照为准。共享布局层的标识和外观参数应分开，避免脱敏别名改变楼型、城区配色或其他影响场景辨识的细节。现有布局恢复已经在工作区接入，真实桌面与手机的同场景对照和 payload 测量仍是前置验收。

## 4. 数据流和状态归属

```mermaid
flowchart LR
    D["桌面 Agent City"] -->|"用户授权后导出固定布局"| H["桌面梦境宿主"]
    H <-->|"HTTPS 配对与 WSS 转发"| R["中继"]
    R <-->|"每个浏览器独立授权"| B["访客浏览器"]
    B --> C["城市渲染与玩法入口"]
    C --> G["浏览器内驾驶、飞行、战棋"]
```

- **桌面宿主**持有发布快照和管理权限。岛主关闭梦境时，停止签发票据、撤销已授权访问并终止连接。正式城市和本地棋局继续由桌面的原入口管理。
- **中继**负责房间和访问授权，持久记录范围限于短期房间、邀请、票据和撤销元数据。场景正文通过连接转发。发布操作生成城市链接，连接操作按浏览器配对。首版需要桌面保持可用。
- **访客浏览器**在内存持有城市副本和独立的游戏状态。转向、油门、飞行操纵和战棋落子由浏览器本地处理。手机网络延迟主要影响加入、加载和重连，游戏操作不等待中继往返。
- **断线与退出**。临时断线时暂停玩法，短时重连成功后继续内存中的当前局。授权撤销、过期或宿主关闭时退出梦境，清除页面内的梦境状态。已经送达访客设备的内容无法保证事后收回，因此分享预览和最少字段是主要保护。

首版不做同一城市中的实时多人竞速、编队飞行或战棋 PvP。若以后实现多人同场，应另设权威玩法会话，明确状态同步、作弊边界和失败恢复。

## 5. 合同、授权与传输预算

| 建议合同 | 内容与职责 |
| --- | --- |
| `DreamPublicationV1` | 随机发布 ID、当前快照版本、创建和到期时间、可用玩法和授权策略。可持久化的部分仅包含现行政策允许的短期授权元数据 |
| `DreamCitySnapshotV1` | 渲染器兼容版本、脱敏的城市几何、外观、初始镜头、玩法入口以及必需的碰撞或棋盘描述。ID 限于本次发布内的引用 |
| `DreamVisitorGrantV1` | 发布 ID、浏览器配对 ID、授权范围、过期时间和撤销状态。中继只保存凭据校验所需的摘要 |

以上合同只描述发布、城市和访问。游戏状态由现有玩法类型及会话管理，直接在浏览器内运行。`DreamCitySnapshotV1` 只提供玩法初始化所需的地图与入口，例如路面、跑道和战场。车辆速度、飞行姿态、战棋回合和伤害由相应玩法实例维护。

桌面宿主和浏览器各做一次合同校验。校验范围包括版本、完整字段白名单、引用完整性、坐标边界、数组数量及消息大小。玩法能力只用于加载所选场景和玩法资源，远程入口不开放桌面通用 IPC、SQL 或文件查询。访客访问只接触批准的展示投影，日志、提示词、路径、原始会话 ID、凭据和成本数据不进入快照。分享面板按现行要求说明目的地、授权范围以及传输未采用端到端加密。

沿用现有 **230 KiB 场景预算和 256 KiB 消息预算**作为首版设计约束。实际检查完整消息封装的 UTF-8 字节数。先用合成样本和经过授权的真实城市测量分位数，再按需要复用道路点和地块引用、减少重复字段。任何坐标量化需先验收地面碰撞和战棋落点。超限应在发布前提示。3D 模型、纹理和音效随网页的版本化静态资源提供，快照只携带布局和玩法所需数据。

建议将访问协议分为三个动作。桌面用宿主凭据注册发布并处理允许、拒绝、撤销和关闭。浏览器凭邀请提交加入请求，批准后用自己的凭据换取短时单次连接票据。建立连接后，访客只能读取指定版本的梦境快照和接收访问状态。首版无需提供远程游戏命令接口。发布只有在宿主与中继均就绪后才展示链接，注册失败或取消时释放已创建的房间。

重连时校验发布仍然有效、浏览器授权仍然有效、快照版本与当前页面一致。中继在快照转发前再次检查授权，避免撤销与请求同时发生时继续交付。宿主断开时停止发放新票据，并通知已连接页面暂停。重连只恢复原发布，版本不兼容时提示刷新页面或让岛主重新发布。每个发布的待授权请求、并发访客和快照读取频率都设上限，超出时给出可重试的反馈。

当前 [仓库数据政策](../AGENTS.md) 允许用户主动开启、对接收设备授权、限定会话且可撤销的远程 City 访问，要求中继不持久化场景和玩法正文。若未来要支持桌面关闭后的持久梦境、自动公开发现或长期存储用户快照，应先完成产品决策和政策评审。公开试玩可先评估完全由合成数据生成的展示岛。

## 6. 玩法设计

| 玩法 | 访客体验 | 实现和验收重点 |
| --- | --- | --- |
| 城市漫游 | 进入梦境后旋转、缩放、切换地标，并在地图上找到玩法 | 桌面和浏览器使用相同快照版本。校验建筑、道路、桥梁、机场、地标与镜头。浏览器自行保存本次视角 |
| 开车 | 选停放车辆或安全起点。支持加速、制动、转向和重置 | 复用路面和碰撞系统，验证斜坡、桥面、多层高架、撞楼和越界复位。移动端按钮失焦时释放输入 |
| 开飞机 | 从机场或可用出生点起飞，飞过城市并降落。可从安全位置重试 | 复用飞行仿真和世界碰撞，验证跑道、地形、建筑障碍、边界和相机。机场不可用时在入口说明 |
| 机甲战棋 | 进入独立 PvE，部署机甲、移动、攻击、结束回合，查看胜负 | 同版布局和战场描述建立 `RemoteArenaV1` 或兼容的内部棋盘。沿用 v1.5 命令校验、AI、状态效果与结算。攻击损伤只作用于当前访客棋局 |

低画质模式可减少阴影、粒子和环境动画。碰撞、棋盘格、战棋数值与权威规则共用同一套输入。玩法切换要释放相机、输入和场景所有权，再挂载新模式。设备失焦或切后台时暂停仿真。WebGL 不可用时显示可理解的兼容提示。

## 7. 实施顺序与验收

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| M0 布局基线 | 记录当前桌面与远程的同场景截图、几何摘要、真实场景体积。确认发布白名单及布局版本 | 同快照建筑、道路、设施和玩法起点一致。规划修订和背景楼三种档位有对照。确认典型场景在传输预算内 |
| M1 专属链接 | 建立独立梦境房间、岛主发布界面、访客授权、城市漫游、单人撤销与关闭 | 两个浏览器通过同一链接取得独立授权，分别撤销、到期与重连。未授权浏览器拿不到快照。关闭后已有连接失效 |
| M2 驾驶和飞行 | 接入浏览器本地仿真、触控键鼠、出生点、碰撞与回城 | 手机和桌面浏览器完成起步、过桥、碰撞复位、起飞与降落。在弱网情况下玩法输入仍由本地及时处理 |
| M3 战棋 | 以同版城市启动独立 v1.5 PvE，接通部署、战斗、效果和结算 | 两名访客各自打同一场地，一方破坏、重置或结束回合不影响另一方。梦境结束后核对桌面城市和已有棋局 |
| M4 试用 | 发布版本兼容提示、异常恢复、访问管理和实机验收记录 | 旧手机续玩链接行为通过回归。记录真实城市大小、手机加载和运行数据、撤销与超限的可见结果 |

实现时先打通「加载快照 → 挂载 CityEngine → 进入现有玩法」。将桌面 IPC、存档和输入设备等宿主依赖留在适配层，浏览器复用各玩法的状态、仿真和界面。发布有效期、访客人数上限、是否开放已授权的名称与用量，以及桌面关闭后是否可访问，分别作为产品参数或后续决策。
