## 2. 改动方案

Design Read：工具型战棋 HUD，优先快速识别风险、保留棋盘主体，使用现有小号文字与直角边框，不新增装饰色。
五个设计取向：信息密度低于旧图例、对比继承战术红/蓝/绿/黄、层级明确、装饰最少、动效不新增。
保护边界：当前红色敌意不依赖蓝色草稿；预测未知不等于安全；推挤仍由已验证的 `targetPreview.shove` 驱动；设置面板的常驻/hidden 生命周期不变；不改数据/远程授权。

| 旧条目 | 新处理 |
| --- | --- |
| 当前攻击格、敌方攻击方向 | 合并为“敌方攻击”，样例为来源框 → 箭头 → 斜纹危险格 |
| 执行草稿后的攻击格 | 保留为“草稿预测”，蓝色虚线样例；显示预测未知/无攻击格/有攻击格 |
| 两种威胁重叠 | 删除独立符号，实际重叠时显示一句“红蓝叠加：该格仍有危险” |
| 可移动、我方移动路线 | 合并为“移动”；绿色面样例 + 绿色路线箭头，不再使用与实景不符的 `✣` |
| 计划落点 | 有实际落点时显示，黄色菱形并注明尚未执行 |
| 可选目标、已选目标 | 删除图例条目；保留原棋盘选中/目标框及操作面板说明 |
| 推挤 | 只在棋盘的已验证推挤预览出现时显示 |
| 战场设置中的旧图例 | 删除旧 DOM，和右下角共用同一组件、同一 `cityView` 快照 |

两组：“威胁预告”和“当前操作”。没有操作标记时仅 2 行；当前开局 fixture 4 行；同时存在推挤时最多 5 行，取代旧 9–10 项。右下入口仍默认收起，展开内容允许窄/矮屏内部滚动。

精简的是解释列表，不是移除当前红色预告、蓝色预测或合法目标标记。移动图例对齐渲染器的优先级：被红色危险覆盖的可移动格不被当成可见的绿色区域；被检视的我方路线仍可触发移动说明。
