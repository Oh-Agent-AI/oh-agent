# City Repair 地形平整（推土机）系统方案

状态：T0（数据层）已实施（2026-10-22，见 §14）；T1–T3 未做。日期：2026-10-22。对应 `CITY_REPAIR_UPGRADE_PLAN.md` §3 P3-G（原「暂不做」），由本文取代其中的简述。
前置：`bdd27d80`（补丁改路后按原始地形重新平整；玩家画的桥不自动垫土）。

## 0. 结论

**两层都要，但职责不同，不能合并成一层：**

| 层 | 谁触发 | 做什么 | 现状 |
| --- | --- | --- | --- |
| **生成器土方** | 生成器铺路架桥时自动做 | 低地桥头垫土台（`surface/roadLandingGrading`，`ceaa2cce`），让默认城市的桥头车开得上去 | 已有；补丁擦掉生成器的桥时土台一起撤（`bdd27d80`） |
| **玩家土方（本文）** | 玩家用「平整」工具显式操作 | 垫高 / 削低 / 修坡道，写进补丁，可预览、可撤销 | 新增 |

为什么玩家改路时**不能**自动动土：画路工具的全部校验（`validateRoadAdd`、`wetSpan` 桥台延伸、岸坡、坡度 0.31）都是在**当时的地形**上做的。
提交后再自动垫土，等于事后改了校验通过的几何——`ceaa2cce` 之后一键修复一座桥也修不好，正是这个原因：
桥面按两端地形取平，土台的过渡带让旁边路面起伏，两者叠在一起就判 `height-conflict`。
所以玩家侧的土方必须是一个**先预览、按动土后的地形重新校验、再写入**的工具。

## 1. 要解决的问题

- **修不好的陡桥头**：45 个规划里有 5 个「桥头过陡」，体检找得到、试驾判得出「挡住」，但岸坡陡的范围比桥台能延伸的 20 还长，或桥面本身被高台顶得太陡。现有工具（擦、画、桥台延伸）都修不了。
- **修不好的陡路**：体检列出 25 段坡比 > 0.31 的地面路（最陡 1.27，多是通往山上地标的小路）。现在只能擦掉绕行，绕不开就没办法。
- **玩家的自由度**：SimCity 式规划里「推平一块地再盖」是基本操作；现在玩家只能挑地形，不能改地形。

## 2. 目标与非目标

**目标**
1. 玩家能在修复模式里垫高、削低一块地，或沿一条线修出均匀的坡道。
2. 动土后的地形是**唯一真源**：渲染地形、楼与设施落地高度、树、驾驶面、试驾、体检、画路校验读的是同一个高度场。
3. 每一笔都先预览（挖填范围、土方量、受影响的路和楼、红绿判定），确认后才写补丁，一步撤销。
4. 一键修复能用它：对「桥头过陡」给出「修坡道 + 重画桥」的组合方案。

**非目标**
- **不造陆、不挖海**：水面与陆地的分界不变（理由见 §4.3）。填海、挖运河是另一个量级的功能。
- 不做雕刻笔刷、侵蚀、自由画山——操作是有限几种带约束的几何体，不是任意高度图编辑。
- 不改生成器：生成器土方的算法和参数不动，玩家土方叠在它上面。
- 不动会话楼的存在性：平整可能让楼需要重新落地，但永远不删、不造会话楼（§15 口径）。

## 3. 地形管线

```
原始地形（规划器的函数场，按种子/档位确定）
   │
   ├─ 生成器土方：gradeRoadLandings(原始, 生成器的路)        ← 已有
   │
   ├─ 玩家土方：applyTerrainOps(上一步, patch.terrainOps)     ← 新增
   │
   ▼
生效地形 layout.terrain（唯一真源）
   ├─ 渲染：terrainSystem 网格、沙滩/海滨接地（seasideSystem）、树（natureSystem 读时取高）
   ├─ 落地：districts[].grounds、设施与地标的 y、广场 y
   ├─ 驾驶：compileCitySurface → 驾驶面 / 试驾 / 驾驶审计
   └─ 校验：planRoadRules（坡度、桥台、岸坡）、planAudit（陡路、楼在陡坡）、planSites（设施落位）
```

**两个基准，规则写死**（`applyPlanPatch` 里）：
- **重放基准** `T_replay` = 生成地形（含生成器土方）⊕ 玩家土方。道路重放（`replayRoadOps` 里的 `wetSpan` 桥台延伸）在它上面算几何。
- **最终地形** `T_final` = 原始地形 ⊕ 生成器土方（只算补丁后**仍在**的生成器桥）⊕ 玩家土方。

两者只在「被擦掉的生成器桥」的土台处不同——那里擦桥前后都没有玩家的桥面依赖它。

**玩家土方先于道路重放**：地形是最底层，这样画路时校验看到的地形（已含之前的平整）和重放时一致。
反过来，一笔新的平整可能改变**已有**道路的重放几何（岸坡变缓，桥台延伸变短），因此平整的校验包含「重放稳定」检查（§6.2）。

## 4. 数据结构

### 4.1 补丁字段

`PlanPatchV1` 增加可缺省字段（与 `highwayOps` 同一做法，旧存档不受影响）：

```ts
/** 玩家土方（docs/CITY_REPAIR_TERRAIN_GRADING_SPEC.md），按顺序叠加；可缺省。 */
terrainOps?: TerrainOp[];
```

`hashPlanPatch`：只在 `terrainOps` 非空时进指纹——没有平整的旧补丁指纹不变，静态城缓存不白白重画。
指纹变化会经 `activityKey` 触发地面与路网重画（`cityParts.ts` 的静态城缓存判据），地形网格自然重建。

### 4.2 操作

只做两种，都以「目标高度」描述（不是「加减多少」），重放幂等、和叠加顺序的直觉一致：

```ts
type TerrainOp =
  /** 平台：圆心 at、半径 radius 内拉到 height，外圈 falloff 内平滑过渡回原地形。 */
  | { t: "pad"; at: Vec2; radius: number; falloff: number; height: number }
  /** 坡道：沿 from→to、宽 width 的带子拉成从 from.h 到 to.h 的直线坡，两侧 falloff 内过渡。 */
  | { t: "ramp"; from: Vec2 & { h: number }; to: Vec2 & { h: number }; width: number; falloff: number };
```

- 坐标与高度量化到 0.01（同 `quantize`），保证序列化稳定。
- 权重函数用 smoothstep（同 `roadLandingGrading`），过渡带 C1 连续——不能在网格上留台阶。
- 多个操作按补丁顺序叠加：后一笔看到前一笔的结果（`h = mix(h_prev, target, w)`）。

### 4.3 硬约束（`applyTerrainOps` 内强制，校验之外的第二道保险）

| 约束 | 值（首版） | 理由 |
| --- | --- | --- |
| 不改水陆 | 原始高度 ≤ 0 的点原样返回；陆地点结果下限 0.05 | `wetSpan`、桥的拆分、海岸线、水面渲染都按 `height ≤ 0` 判水。不改水陆，画路重放与桥的几何就不会因平整翻转 |
| 单点改动幅度 | \|Δh\| ≤ 3（相对生效前） | 有界，防止拉出悬崖；也让「重放稳定」检查的影响范围有界 |
| 尺寸 | `radius` ≤ 40，`falloff` ∈ [4, 30]，坡道长 ≤ 120、宽 ≤ 24 | 一笔只动一个局部 |
| 坡道本身 | 坡比 ≤ 0.25（低于 0.31 的爬坡上限，留余量） | 修出来的坡车一定开得上去 |
| 总量 | 一份补丁 ≤ 64 个操作 | 高度场是热点函数（§8） |
| 山体 | 原始高度 > 12 的点不动 | 地标山、火山口不被削平；首版只处理低地与缓坡 |

超出约束的操作不写入；重放时遇到（旧存档、跨档后）则按 §7 进失效清单，不静默截断。

## 5. 交互

### 5.1 工具

修复面板新增「平整」工具（快捷键 G），两种模式：

- **平台**：按下取点 → 拖出半径 → 松开。目标高度默认取按下点的当前高度；滚轮 / `[` `]` 微调；按住 Shift 取「圆内平均高度」。
- **坡道**：点起点 → 点终点。默认两端取当前高度（即「把这段拉成均匀坡」）；起点吸附到路口或路面时取路面高度——这是修桥头的主要用法：从岸上的路拉一条坡到桥头位置。

### 5.2 预览与试算

沿用画路的两段式（`controller.ts` 的 hover / settle）：

1. **移动中（估算）**：地图上叠一层挖填色（蓝 = 削低、橙 = 垫高，深浅 = 幅度），面板显示土方量（填/挖立方数）与受影响范围。
2. **停住后（确切）**：在会话里把这一笔套到补丁上跑一遍，给出确切后果：
   - 受影响的路：坡度变化（变陡 / 变缓）、是否有路超过 0.31；
   - 受影响的楼与设施：落地高度变化、是否进入陡坡（> 0.55）；
   - 驾驶面安全网：编译这一笔周围的局部驾驶面，新出现解不出的路面片就拦（同 `session.surfaceVerdict`）；
   - 范围内有桥头时，自动试驾那座桥（`testDrive`），结果直接显示在预览上。

### 5.3 写入与撤销

点击确认写入 `terrainOps`，一步撤销 / 重做（复用会话的撤销栈）。面板「修改」列表里每笔平整一条，可单独定位、删除。

## 6. 校验

### 6.1 阻断（物理上做不到或破坏数据诚实，§15 口径）

| 码 | 条件 |
| --- | --- |
| `terrain-too-large` / `terrain-too-deep` | 超出 §4.3 的尺寸或幅度 |
| `terrain-on-water` | 操作中心落在水里 |
| `terrain-ramp-too-steep` | 坡道本身坡比 > 0.25 |
| `terrain-makes-road-steep` | 范围内有路段**因这一笔**新超过 0.31（每段和自己改前比，同 `3aa1e860` 修过的拖路口口径） |
| `terrain-buries-structure` | 高架、匝道、桥面下净空不足（地面顶到桥面或桥墩露空超过构造允许） |
| `terrain-moves-roads` | 重放稳定检查失败（§6.2） |
| `surface-unresolved` | 驾驶面安全网拦下 |

### 6.2 重放稳定

套上这一笔后重放整份补丁，比较已有道路的几何（路段 id 与点序列）。有变化就拦，提示「这次平整会改变已有桥的桥台——先擦掉那座桥再平整，平整后重画」。
因为水陆不变，只有 `wetSpan` 的桥台延伸会受岸坡影响，实际触发面很小；但必须拦，否则补丁重放结果和玩家看到的不一样。

### 6.3 提示（照做，面板写一行「注意：…」）

- `terrain-raises-buildings`：有楼落地高度变化超过 1；
- `terrain-road-steep`：范围内有路进入 0.2–0.31；
- `terrain-large-volume`：土方量超过阈值（纯提示，不限制玩法）。

## 7. 派生重算与失效

`applyPlanPatch` 在套用玩家土方后，需要同步更新所有「布局期取过一次高度」的字段：

| 字段 | 现状 | 处理 |
| --- | --- | --- |
| `layout.terrain`、`districts[].terrain` | 已随 `bdd27d80` 重新平整而更新 | 同一处继续 |
| `districts[].grounds`（会话楼落地） | 已按地块重取 | 同一处继续 |
| 设施 / 地标 / 广场的 `y` | 布局期算死 | **新增**：范围内的对象按 `terrain.height` 重取 |
| 背景楼、市政用地落地 | 布局期算死 | **新增**：同上 |
| 树 | 渲染期按 `terrain.height` 取 | 自动 |
| 地形网格顶点缓存（`terrainSampling`） | 按地形对象缓存 | 新对象即新缓存，自动 |
| 体检路段坡度缓存（`planAudit.gradeCache`） | 按地形对象缓存 | 自动 |

**跨档 / 生成器换代**（`planRemap.ts`）：平整操作按半径比缩放坐标与尺寸（高度不缩放）；
重定位后中心落水、或违反 §4.3 → 进失效清单（`terrain-op` 类，原因写明），**不替玩家猜新位置**（编辑器契约 §0.3）。

## 8. 性能

高度场是热点：地形网格 385² ≈ 15 万次取高，驾驶面编译几十万次。

- 操作用网格桶做空间索引：一次 `height(x, z)` 只看所在格子里的操作，范围外直接返回下层结果。
- 合成后的高度场按（下层地形对象, 操作指纹）缓存，同一份补丁只合成一次。
- 预算（4000 楼城市）：悬停估算 < 16 ms（只算挖填色，不碰驾驶面）；停住后确切试算 < 300 ms（局部驾驶面窗口，同试驾）；提交后整城重画 ≤ 现有画路提交的耗时 + 50 ms。
- 64 个操作的上限保证最坏情况下单次取高的开销有界。

## 9. 与一键修复联动

在 `planBridgeFix` 的搜索里加一档候选：当落笔被 `bridge-approach-steep` 拒绝时，尝试在拒绝的一岸生成一条坡道（从最近的路拉到桥头），
用**动土后的地形**重跑画桥校验。方案预览同时画出将删（红）、将建（绿）、将平整（挖填色），采用时一步写入（道路 + 地形），然后自动试驾。

验收以那 5 个「桥头过陡」为准（3 个海滨规划、4 座桥，见 `CITY_REPAIR_UPGRADE_PLAN.md` §6）：逐个报告「可修 / 不可修原因」，数字只许变好。
其中「对岸没有可接的路」的堤道跳板，平整也救不了——报告里如实写明。

## 12. 需要拍板的

1. **约束值**：单点 \|Δh\| ≤ 3、坡道坡比 ≤ 0.25、原始高度 > 12 的山体不动——可否？
2. **只垫不挖，还是可挖可垫**：只垫高更安全（不会挖出比水面低的洼地、不碰地下的桥墩），但修「高台顶着桥面太陡」需要削低。建议首版可挖，下限受「不改水陆」约束。
3. **范围**：首版是否只开放在桥头与陡路附近（体检条目上的「平整」入口），还是全图可用。建议全图可用，体检条目额外给一键入口。
4. **快捷键**：G（2026-10-22 核对，City 前端目前没有占用）。

## 13. 风险

- **高度场性能**：合成函数写不好会拖慢地形重建和驾驶面编译——§8 的索引与缓存是 T0 的一部分，不是后补。
- **与生成器土方的交互**：玩家在生成器土台上再平整时，两层的过渡带会叠加；需要合成用例覆盖「平台压在生成器桥头上」。
- **补丁存档兼容**：新字段可缺省、指纹只在非空时变化，旧客户端读到含 `terrainOps` 的补丁时会忽略该字段，导致显示不一致——需要在存档里带最低版本号，旧客户端遇到时只读提示，而不是静默丢弃。
- **视觉**：大面积平整会在自然地形上留下几何感明显的平台。过渡带用 smoothstep 并有最小宽度，首版接受；地表材质（草/土）随坡度变化已由地形着色器处理。

### 无界面实验：平整能不能修陡桥头（2026-10-22，T1 之前）

目的：在投入 T1 界面之前，确认「平整 + 重画」能修 §1 说的陡桥头。方法：30 个海滨规划（档位 1/2/5 × 种子 1703294958 + i·7919），
对每个「桥头过陡」沿引道从桥端往岸上铺坡道（长 12–80 逐个试，坡比 ≤ 0.25、单点 |Δh| ≤ 3），再试驾原桥；不行再在平整后的地形上跑一键修复的重画搜索。

| 规划 | 平整 | 试驾仍然挡住的真正原因 |

结论：
1. 当前生成器下「桥头过陡」只剩 3 座桥（`CITY_REPAIR_UPGRADE_PLAN.md` §6 记的 5 个桥头 / 4 座桥是旧生成器的数字）。
2. 平整对它该管的部分有效：可行的 2 处坡比都降到 0.25 以下、体检的「桥头过陡」消失。
3. 但 0 座桥因此变得能开——陡坡掩盖了别的缺陷：桥头驾驶面区域歧义（2 座）、断头桥（1 座）、真正的山路（1 座）。
