## 2. 统一关系、身份与物理条件（R0）

### 2.1 几何关系是共享输入

生成、提议期预筛、提交期终筛、修复、完整图与展示图报告调用同一关系分类器。
至少输出：`shared-node`、`endpoint-near-node`、`endpoint-on-edge`、`interior-crossing`、
`collinear-overlap`、`parallel-near`、`separate`；记录原边、子段参数、接触点/区间、距离与连接域。
宽路幅净距冲突单独测量，不能把中心线不相交等同于完整走廊安全。

沿用 0.01 坐标量化与 0.5 地面近接诊断范围，写入版本化配置；两者分别表示存储精度和
待处理关系，均不授予自动合并权限。沿线点按原边参数稳定排序后联合拆分、量化并复验。

实际折线迁移：用地距离、兼容site-access、桥旁距离、车站最近垂足及凯旋门宿主切线
改为逐实际线段度量；U形道路的首尾弦线不能作为道路或入口证据。扎堆采用共享、双向的
实际线段关系，每边对计一项，沿用25距离/15°角度/0.1–0.9重叠口径；关系携带参与几何证据。
端点角度采用邻接线段切向，链长累计整条折线。兼容距离仍不等于真实模型door/通道验收。
断头延伸按实际末端切向找宿主全部线段，35°/3单位合同及完整路幅终筛不能跳过；宿主
使用NetworkPatch拆分，保留任意原宽度、全部弯点和有序路径remap，逐端独立接受。
未知的新增道路宽度不通过5/8/12映射偷偷降级。其它旧直接改Map入口仍需迁移。
首批桥面、高架与地面保持独立图域；只有已声明、全宽干地且结构兼容的真实桥头可显式接地。
跨层投影接触不得吸附；需要未知高程才能判断的跨越返回 unsupported。

路型/路面 mesh 消费已接受的拓扑与几何。圆角、T、十字、环岛的渲染支持不替代图上接入。

### 2.2 稳定对象与关系身份

需求使用 `demandId/ownerId`；节点/边保存拆分、合并的 lineage 与显式 remap。
交叉、拥挤等关系违例使用 `(constraintId, participant lineage, contact identity)`，
同一边对多处接触也要可区分；坐标与图版本内的分量代表只作为证据，不作唯一语义身份。
缺少 `site/at` 的违例不得退化为同一个空键。无可验证 remap 的旧/新关系不得被假定为同一问题。

2026-10-11 U0首批迁移：事务验收保留事务前的全部required需求（包括未满足项），在草稿上
重新评价，而不是只在新派生需求表中查旧已满足项。必要owner/obligation、端点/分量锚点或岸路
run删除即拒绝；节点锚点只通过显式remap重绑，旧需求ID不变。分量合并后的district需求继续
按原锚点评价。这仅保护单次事务边界，跨事务先验目录、稳定岸路身份与嵌套授权仍按§9待实施。

同日后续迁移：六个市政owner及已选地标在骨架前登记用地需求；solve维护受保护持续目录，
最终plan/diagnose继续消费旧承诺，绑定随显式remap改变而ID/originAnchor保持。dispatcher处理
合法嵌套更新与已消费journal，策略篡改目录和父撤销均零副作用。海岸/河岸输入不重复计数。
该实现尚不覆盖生成前街区/必要走廊/冗余声明及稳定岸路run身份，不等于完整PlanningWorld。

P0 迁移实现：`Violation.identity` 可携带关系证据；未接地面关系暂以排序后的参与边 ID 与
实际折线共同编码。缺少 lineage/remap 时，参与几何改变但接触仍存在按新问题拒绝，不能仅按
总数下降接受。此保守规则可能拒绝保留原接触的合法几何细分，完整 lineage/remap 仍属 R0/R1
待实现；不得把当前证据键当作最终稳定身份。无显式身份的兼容违例保留 detail，避免空键合并。

P1 迁移实现：NetworkPatch 已返回 nodes/edges/paths/positions remap，solve 在策略草稿接受前
消费它，删除仍被引用的路段且没有显式替代路径会拒绝；曲线路径和反向引用均须保留实际几何。
该映射还未用于跨版本的接触身份继承，也不覆盖仍直接写 Map 的所有旧生成路径，不能据此
撤销上面的保守规则。地块与车流后置到 solve 完成后，产物报告 derivedNetworkVersion 和终筛
capacity；真实模型 footprint/入口、图面生成及冻结独立验收仍按本 SPEC 执行。

端点修复迁移：must-connect 的内陆端点现在有独立 endpoint-access 需求，不以主网分量已连通
代替端点继续接入；岸路需求按 run 而非展开后的端点序号定位。近接与绕行候选逐点、逐策略接受，
合法候选不被无关失败连带撤回；短腿近接的两个重绑方向分别评估。0.5诊断、24近接、35°普通
路口及原地形门限保持不变，较长路径使用既有320路线预算。先验需求生命周期及稳定映射仍待完善。

联合定线迁移：`relineSplits` 必须在同一NetworkPatch中保留外端点和属性、变更实际形状并拆边，
输出有序路径 remap，不把离线定线伪装成普通在线拆边。四岔搜索采用版本化2–12单位邻域，
中心/受影响远端维持35°与3单位下限；末段重建使用独立24单位预算、每端至多16候选，保护
主锚点和owner gate，不扩大0.5吸附规则。全路幅/地块/关系与整城接受仍是硬条件。
同端点规范边碰撞不可覆盖：节点重绑现在可显式请求直线地面合流，要求同端点、完全相同的
量化直线形状、ground-road及相同用途，保留最大原宽度与更高道路等级，两个原 lineage
均映射到该走廊。曲线、引道、桥面、用途不一致或未显式授权的碰撞继续零副作用拒绝。

### 2.3 道路用途与建筑可建性分开

建立版本化 `RoadCorridorPolicy`，显式区分普通街道、滨水道路、接地引道与桥面。
生成与修复必须消费相同的用途/结构、实际宽度、占地净距、水域与坡度条件。
建筑 `buildable` 不作为所有道路用途的隐式条件；滨水道路的合法条件必须显式定义、验证，
不能通过删掉水域/坡度检查获得合法性。现有阈值在标定与审阅前维持，语义变化单独记账。

首批滨水用途已显式落地：仅环岛/河岸已登记生成道路携带 `purpose: waterfront`，拆分继承。
基于原中心线净距>10、12宽的生成口径，路幅各采样点的陆地净距须>4；继续要求山脚退界>12、
高度<6、坡度≤0.9，以及原水域/用地/地块检查。普通道路不继承此合同，仍使用原建筑退界。
这一变更是建筑与道路用途语义分离，不是普通道路安全豁免；地面路口/联合修复消费相同
显式用途，但全部旧生成/搜索调用尚未迁移为统一用途策略，连续地形证明仍未完成。
短末段真交叉可使用24单位末段重建候选接入宿主，保留原末段等级和远端，owner gate、
主锚点仍保护；不得靠删除末段或升为引道规避普通道路合同。
诊断分别记录 `building-setback`、`road-slope`、`water-envelope`、`site-envelope` 等具体原因，
通过兼容映射保留旧 `slope/water-span/site-clearance` 汇总，不把改名当成数量改善。

既有路段不满足当前条件时，单纯拆节点不能解决；须提出重新定线/重选位置的联合候选，
或返回旧几何不合法。禁止因“这条路已经存在”跳过完整路幅校验。

### 2.4 生成准入与阶段预留

骨架、新增道路及修复道路不得采用相互矛盾的物理门限。射线量化后，在同一补丁草稿中
检查实际宽度、用途、地形和实体包络，再发布。桥段与两端地面接驳同时验证；若拒绝桥段，
必须重新验证保留前缀，不能继续使用已拒绝桥段产生的引道豁免。截短只是候选退让，
仍须通过必需需求、容量、面积/半径和全图预算；不得将所有困难主干截掉当作安全成功。

预留须按阶段区分已接受/硬约束与待调整名义选址。骨架不能被之后会重新选址的临时对象
提前阻断，也不能忽略已接受道路和入口。尚未发布但已规划的道路也参与冲突检查。
后续名义用地重选、骨架替代路线和派生产品需消费最新预留与网络版本。
当前仅有骨架输入筛选及滨海待发布道路索引；完整状态机和所有生成入口迁移仍待完成。

### 2.5 候选拒绝后的有界续试

A*到达目标格附近只表示产生候选，不表示已有可提交道路。重构后须检查全宽走廊、
节点夹角、实际交叉及NetworkPatch草稿的统一终筛；候选失败后继续原搜索堆的其它
入射状态及邻近目标，不重置扩展计数，不增加吸附距离或放宽物理门限。
预算耗尽须报search-budget与候选拒绝证据，不能报已证明无路；全部枚举候选失败也不能
推断全岛无解。保留完整拒绝原因供定位阶段、来源和物理子因。
必须有首个格点候选合法而宽走廊非法、后续安全候选成功的合成回归，以及预算耗尽零副作用
和重复结果一致的负例。请求级预算不替代后续仍待实施的整图累计预算。

曲线源点的初始入射状态与端点角度终筛必须共用源旁真实线段切向，不能重新采用端点弦线。
应有弦线朝向与末段相反、同一小预算下真实切向可接通的回归。

### 2.6 容量离散跳变与有界半径校正

用地/骨架/街块选择在半径改变时会离散跳变，不能将0或极低容量直接代入面积比例公式
并一次生成巨型岛。版本化校正每轮面积增长最多2倍，保留原4次重试与目标地块数；
原1.04容量余量仅在增长上限内使用，已满足容量不再放大。该参数是校正步长上限，
不是放宽物理、必达需求或最终容量的容忍值。

radiusHistory必须记录每轮半径、道路/街块规模、生成地块数和道路终筛后的实际容量。
生产产物不含墙钟；性能样本在测试工具中采集。耗尽重试仍未满足容量时，capacity.satisfied
必须为false，不能伪造足够地块或从验收分母剔除。需分别定位没有街块与终筛大量剔除，
后续再评估有界夹逼；非单调容量不能被当成平滑面积函数。当前增长上界不替代全图累计
几何/搜索预算、UI取消与完整半径/视觉验收。

## 3. 近接、短腿与重叠的局部重整（R1）

按关系分类调用有限候选阶梯，而非只调用通用 snap：

| 关系 | 候选 | 提交必须证明 |
| --- | --- | --- |
| 近邻端点 | 选稳定 canonical 节点并重绑全部相关边 | 保留主网锚点、已声明入口/桥头身份；owner、车流和岸路引用同步 |
| 端点贴边 | 内段联合拆 T；靠近宿主端点时消解短残段 | 实际腿长、角度和走廊合格；同位置所有参与边共用节点 |
| 重绑产生重复边 | 兼容边消解后合并节点 | 宽度/结构/形状/用途相容，继承需求引用；保留更宽边也须重验其全宽 |
| 短腿交叉 | 折叠短段、局部移点/重定线、适用时建环 | 不新增自环、失联、交叉或净距冲突；不可移动锚点保持 |
| 共线重叠 | 按重叠区间切分并共享兼容走廊 | 不丢支路/等级/路线引用；不兼容结构显式拒绝 |
| 多岔/锐角/并行扎堆 | 入射方向重整、支路改接、适用时建环或删除可选冗余边 | 主干、required 需求及实际容量保持；环路有真实入口和主网路径 |

普通拆边保持当前最短腿 3、最小夹角 35°；全局锐角诊断的 30° 不作为把普通拆边降到 30°
的理由。30–35° 的交叉须进入重定线或专门路型候选；若专门路型有不同角度能力，先给出其
道路扫掠面、转向几何与消费合同，再以具名版本规则验证。不能通过留下未接交叉回避锐角计数。

海岸截短只可移动已有明确 `coastRoadRunEnds` 声明的、无锚点/设施入口/车流/岸路/地块引用的
地面度1终点，并须证明原走廊存在地形或水域拒绝。新终点仍需处于海/河岸终止带，整段通过
物理与关系检查，端点声明与网络一起更新。靠近设施或水岸不构成删除原终点的授权；当前有
活跃岸路引用的终点保留，待统一 remap 后再支持连同引用一起调整。

若三岔的 mini-roundabout 因实体净距被拒、而删除候选边会增加分量或夺走唯一入口，允许有限的端点保持曲线改接：仅转弯低等级地面路，桥/引道、车流或岸路引用、街块边界引用均不在本策略中移动。曲线需以确定性候选角度和 handle 生成，入射及远端节点角度都≥30°、每折线段≥3、相邻折线转向≤15°；每段通过原宿主全幅地形/实体走廊与 parcel 净距检查，整图不新增交叉关系，owner/网络连通不丢。全部候选失败则保留路网并报告 site-clearance/空间冲突，不能删掉割边或把节点间隙当立交。

NetworkPatch 同时包含重复边移除、节点重绑、原边拆分与引用 remap。每个候选独立草稿，
拒绝零副作用；一个区域的失败不能撤销另一独立区域已可接受的改善。

主网分量接入迁移：`disconnectedComponents` 现在有独立求解策略，不能只等待内陆断头修复
偶然接通。按实际折线到主网的距离，为每个非主分量稳定排序并取至多12个有地面关联的
源节点，每节点依次单独接受direct-projection/node-merge/detour/grid-astar，沿用320路线预算。
目标必须为共享主锚点所在分量；已并网源不重复提议。该策略仅构造地面接路，未通过物理
检查的候选拒绝，不自动增加桥梁或修改原道路/设施。已声明岸路端点虽可为合法终点，
其整段仍须满足coastal-link与主网需求；桥/歌剧院整组联合重选和累计整图预算仍待完成。
候选半径/移动范围、数量和几何检查次数计入整图预算，不能靠增大搜索范围无限续试。
迁移 cityPlan 的碎边合并和临时 T 改边等直接修改入口，统一用相同补丁与提交校验。

## 4. 必需设施与实际入口的联合指派（R2）

### 4.1 拆分需求，不省略缺失设施

必需设施在生成前注册 `required-site-placement`；落位后注册 `required-site-access`。
统计分别报告未落位、入口节点丢失/owner 移动、入口至主网无路径、门至 gate 通道未验证。
两类需求可共享父 owner，但求解缺口计数互斥，未落位时不重复计入口不可达。
兼容 `siteWithoutDoorRoad` 汇总在迁移期继续输出，拆分后不减少测试分母或隐藏旧失败。

`plot-gate` 是规划接入代理。实际模型 door、通道和 foundation 是否受支持须分别标记，
没有物理声明的模型保持 pending/明确兼容覆盖，不得用 gate 路径冒充实际门口已验收。

### 4.2 候选生成与重试

物理合法位置不因首条连接路线失败而被认定为不可落位。保留原直接选址优先；原候选层
全部失败后，在原候选评估总预算内，对已通过硬门的失败路线位置续试绕行/A*，去重位置，
保持道路长度、地形、占地、路口和主网条件。续试数量进入owner obligation诊断；不能
拿容量满足掩盖必需设施缺失。nearest frontage和可达预筛必须消费实际折线而非端点弦线。

指定可选对象给required让位时，不得只对“旧位置已穿路”的对象触发备用选址；原临街候选
全拒后，仍须在既有有界snap内重选，并保持r+20的道路服务范围。提案使用当前候选实际
路网，而非已经拆分/撤销的trunk元数据；实体入水、骑路/朝向、重叠与已接受入口等共享约束
按owner身份复验，不能用重叠总数不增加代替安全。

凯旋门等依赖道路的对象不能把名义占位当成功。初期无合法宿主时，在接受后的实际宽地面
道路上重试；连续直线仅因图边分段变短不能丢失，曲线、路口、桥与不同宽度/用途不能被
合成虚假弦线。中点优先，再有限沿线探针，保留地形/净空/间距。owner搬迁暴露的旧近接
豁免端点必须在同一事务中修复，失败则整组拒绝，不允许先发布再留下新must-connect。

优先保留必需设施与其通道的可行区域，再安排可选内容。候选按以下有界阶梯扩展：

1. 合并短碎路段为连续 frontage，按名义位置和城区分散取样，避免预算耗在同一路口附近。
2. 两侧沿边位置与可行偏移区间联合取样；偏移由实际道路半宽、模型占地/入口及退界推导，
   不只依赖一个固定的 `radius+12` 圆偏移。
3. 当前临街候选全部失败时，在合适城区取其它位置，并试算服务路到主网；可复用 collector。
   实施中的必需设施联合指派器须保持候选层级：先耗尽原 frontage 与 0–168 单位局部区域；
   仅全部失败后追加 192–360 单位外圈、每圈 24 方位。以 gate 偏移 `r+8` 和接路上限 `r+30`
   预筛数学上不可达的点，不能筛掉可达候选；候选仍经完全相同的地块、干地、道路净距、
   地形、入口及原子连网硬校验。当前配置每次联合指派调用最多评估 1457 个候选，须由配置派生的
   测试守卫校验。此扩圈只改善有限候选覆盖，不证明全岛无解；拒绝数须与预算耗尽区分。
4. 尝试受影响的低优先级且允许重选的设施/道路局部交换；共享道路按需求引用保留。
   生产回退只在原完整候选集耗尽且诊断含 `site-spacing` 时触发；civic、harbor 和已有入口 owner
   固定，其余可移动预留仅在候选草稿内暂时让位。逐个候选运行相同的局部重选，再校验 required
   owner 净距≥半径和+10、地面道路不穿占地、站点重叠总量不增加；任一失败即零副作用并继续下一个
   候选。首个全体通过的 SitePlacementPatch 才同时提交用地、入口/接路 NetworkPatch、可选站点搬迁
   和歌剧院候选集。不能先接受必需设施再依赖后续修复“补救”可选设施冲突。
5. 局部失败触发有界骨架/岸点候选重选。仅有明确可用面积/容量缺口证据时触发半径校正。
6. 骨架阶段失败不表示最终道路增长后的选址失败。原必要需求必须保留；道路增长与主网接合后、
   地块接受前，只重试仍未落位的原owner，用当前接受道路重新生成真实frontage候选与联合服务。
   不重复搬迁已绑定设施、不删除已接受地块、不新增种子或模型名特例。新owner及整个道路提案
   必须保护既有owner、接触、桥头、必要路径与容量。候选须携带真实宿主/投影证据，改路后失效即
   拒绝。单轮上限不是整个请求上限：原指派、让位、后增长、半径重建的费用须汇入U5累计预算。

2026-10-11实施证据：2003037141/t1初始25边骨架无合法入口；后增长复用相同联合规则成功，
同R551.5432893255071、全部注册约束与unmet为0、容量1615/540。该命名回归不证明60岛成功率，
跨阶段累计预算、样本外港口/岸线及完整实体合同仍待闭环。

各阶梯共用 request/plan 预算、稳定排序与最新 reservation/terrain 版本。

局部穿路搬迁迁移：原搬迁因暴露旧近距豁免的支路端点而被整体接受门禁拒绝时，按owner
单独试算搬迁及新暴露端点接入，最后才可尝试原有短可选支路修剪。新端点、主干/锚点、
owner入口、岸路/河路/车流/街块边界及容量一起验收；不能先发布搬迁后再补断头。
所有必要路径保护包括曲线的仅端点引用，不能用曲线中点不在弦线上推断无人引用。
不可安全接通且支路必须保留时，搬迁也零副作用拒绝；桥/引道等更大联合重选仍待完成。

2026-10-11未服务岸线owner迁移：干燥/不重叠不表示服务已成功。未满足site-access也须调度
后置重选，复用原岸线候选层，与路口让位使用相同全宽净距/地形检查，保留原地块，邻近道路
必须属于主网；固定gate、海上owner及只靠近孤立道路不得通过。该路径仅修复兼容服务距离，
真实模型入口/通道仍按§9验收；不能将其计作完整AccessProof。
`candidate-set-exhausted` 表示已枚举集合失败，`search-budget` 表示搜索未完成，
均不等于证明全岛无解。修复期调用与生成期相同的联合指派器，处理未落位 obligation。

### 4.3 原子提交与失效规则

SitePlacementPatch 同时包含设施位置/朝向、占地/基础、入口/通道预留、接路 NetworkPatch、
owner/需求与引用 remap。所需能力全部通过才发布；后续道路/设施只能在其预留外生成。
任何设施搬迁须重验其关联桥头/道路以及其它被影响的入口，不能只检查该设施自身。
新世界版本下重读障碍；旧候选失败后继续有限候选搜索，不使用已过期的 blockers 快照接受。

## 5. 桥、堤道与岸侧接入联合接受（R3）

歌剧院候选必须联合试算：海上模型落位 → 岛侧入口 → 堤道 → 岸侧全宽干地引道 → 主网。
桥与模型均不能先发布再等待接路补救；岸侧不成立时换岸点、宿主或设施候选。
岸点中心高度 ≥0.3 只可用于粗筛，不是完整路幅干地/支撑证明。

主干跨河桥同样把两端接地与之后的可达路径作为整组骨架候选。
禁止在桥面已提交后因下一段入水/用地/山体而留下悬空桥端。
海上模型岛端可按明确入口合同作为合法尽端，岸端不得豁免接地和主网可达。

桥头保留具名的干地接驳/支撑空间；港口、庄园等后置挪位不得侵入。
冲突时重新试算受影响桥位/设施，而不是用“桥边不算道路穿设施”消除报告。
桥头环是可选接驳形态，只有全宽走廊、支撑、真实接地路径通过才使用；没有干地或宿主时
返回具体失败并重选。现有桥头保护继续执行，不允许删掉唯一引道换取断头下降。

### 5.1 本批路桥形态与后续结构能力

| 形态 | 实施范围 | 必须共同消费的产物 |
| --- | --- | --- |
| 普通桥、桥台与连续引道 | R3 必需：先实现已有桥的真实两岸接驳，复用现有桥面视觉 | 两岸节点/干地支撑、道路纵断面、全宽走廊、桥注册表、入口与车流路径 |
| 海上设施堤道与岸侧接驳 | R3 必需：联合选址，不允许孤立桥先发布 | 岛侧入口、岸点/引道、模型及主网接入的同一事务 |
| 弯曲引道、变宽过渡、桥头 T 接 | R1/R3 候选：空间受限时有界重定线，不强制建落地环 | 量化后折线/转向包络、宽度过渡、切向/高度连续、宿主拆边与引用 remap |
| 短高架跨越与升降坡道 | 后续独立结构批：以地面路线全部合法候选失败的证据触发 | 连接层、纵断面、垂直净空、墩柱占地和显式坡道；规划/渲染/车流一致 |
| 隧道与洞口引道 | 后置：仅对明确山体阻隔及地面绕行不可行/代价过大的样本评估 | 洞口干地、埋深/地下包络、水域冲突、地下连接与车辆高度/路径合同 |

当前已经有桥面、桁架/悬索桥与高架视觉，补新 mesh 不证明新增可行路线。
R3 的高度与引道几何必须由规划产物生成，渲染不得另行取两端最高值铺水平桥面而忽略高差。
后续短高架/隧道不作为近接、必需设施未落位或堤道接路失败的默认兜底；先完成 R0–R4。
本表明确结构能力边界，不把完整高架/隧道扩入本轮残留闭环的完成标准。

近接节点若已由≤0.5单位的非桥短边连接，合并节点时必须在同一 NetworkPatch 中删除该即将坍缩为自环的短边；不得先解绑或留下伪边。该提交只能保留原有、未被此次几何移动实质缩短的短支路（长度变化不超过节点间隙，且不能变为零长），其余新支路仍满足≥3单位及夹角、走廊、parcel、引用 remap 和交叉关系不新增等既有合同。桥边、长连接、属性/层级不兼容的重合边均不得按此规则删除；无安全候选时整个补丁零副作用并保留明确拒绝原因。

## 6. 需求驱动求解与后置产物（R4）

修复目录必须覆盖：未接地面关系、未落位必需设施、实际入口失联、非主网分量、桥头缺接地、
非法断头、锐角/扎堆和设施物理冲突。按需求与受影响对象调度；一次无改动时明确区分
无候选、候选全拒、预算耗尽、未支持能力和已收敛，不能仅报 `changes=0`。
路口规范化至少需返回接受数、逐交点拒绝位置与类型、预算耗尽状态；事务报告要保留这些诊断，
即使同一轮有其它交点已接受，也不能把部分失败折叠成单一 `changes` 数。

候选最小单位是一个受影响区域及其依赖闭包，可包含道路、设施、入口、桥注册表和预留。
候选中间态可以未闭合，但不发布；接受只检查最终草稿，不能提交暂时失去入口的前半步。

接受顺序如下：

1. 比较稳定安全违例及严重度。合法输入不新增安全问题；迁移期不安全草稿只接受原问题减少、
   且没有新增/加重问题的候选。以关系 lineage/remap 防止同数量的问题转移。
2. 已满足 required 需求与主网身份继续满足。需求向量按
   `[必需设施未落位或不可达, 必需街区不可达, 其它必需连接未满足, 必选冗余不足, 容量缺口]`
   字典序比较，前三项按 owner/需求互斥归类。诊断指标仍分别输出，不重复作为收益累计。
3. 所有必需容量与已发布建筑地址/映射保留。修复前的临时 parcels 可在同一草稿中重建，
   完成真实可用容量复核后才能接受；已发布地址须有确定性迁移/映射合同，不能靠删地块改善。
4. 安全或需求有严格改善即可接受，软评分下降不能否决必要修复；安全、需求持平时，
   仅软分严格提高的候选可接受。状态无变化不计进展。

最终安全路网和设施接受后生成/重建受影响地块、容量、车流和装饰，再做完整图与展示图终验。
所有派生产物绑定 network/site/reservation 版本；显示裁剪只能从已接受道路中恢复必要路径。
求解上限/半径重试/几何检查共用累计预算，耗尽或 unsupported 按既有失败传播设计处理。
未满足 required 或有非法安全关系的产物不能返回普通 success；兼容版本残留单独报告。
明确失败仍计入生成失败率与测试分母，不能通过使所有难样本失败取得零违例成功子集。

同时验证边枚举置换、端点反转、重复生成、V8/JSC 独立生成；平移/旋转需同步变换地理、
设施与道路，比较量化容差下的关系/路径/净距不变量，不要求任意旋转后的坐标哈希完全相同。

日常 `planning/solve/intent` 不只检查变化计数或 demand 有判定：完整与展示图都须检查
未接地面关系、必需设施落位/入口可达、断连、桥头连续性与容量。模块依赖清单包含这些检查。
迁移期用历史失败清单/上限做棘轮，新增关系和需求可先影子报告，但超限返回明确失败；
不能把影子阶段通过称为整批完成。单岛输出阶段版本、候选/拒绝/接受数及稳定原因样例。

### 7.3 最终目标与验收纪律

新能力交付的合法成功产物：未接地面关系为 0；必需设施落位且入口到主网可达；
保留的可用路网无非主网分量，必需分量全部进主网；桥头按结构合同连续；非法断头为 0；
物理安全与容量满足声明。
可选省略/合法尽端必须由预先定义的用途证明，不能把 failed required 改名。
未支持的模型物理能力仍显式 pending，不能宣称全部模型门/基础已覆盖。

旧普查上限只是兼容版本残留门槛，不是允许新版 success 带非法关系的定义；旧指标继续输出，
不通过新拆分名称、遗漏失败岛或改分母降低数字。新目标未达成前保留完成审计为未完成。

冻结相同源码/配置/物理声明后，执行四档调参/独立验收（t1/t3/t5/t10，60/30/20/10）、
相关模块、一次无缓存 full、跨引擎及布局/车流验证。审阅规划/场景 diff 和绑定相机的截图后
才允许更新 intentional golden；baseline 与源码重新绑定。独立集失败后只在调参/合成样本
定位通用规则，不能利用验收 seed 试参数。显式失败率单独设门禁，不能从成功子集报告推断可用性。

## 9. 一次性系统修改：规划一致性闭环（U）

### 9.1 目标、范围与非目标

本批替换“名义选址 → 分别修路/挪建筑 → 最后补断点”的生产协作方式，统一为有版本的规划
世界、先验需求、共享准入及原子事务。一次性指一套完整设计和一个联合交付门禁；允许按依赖
分步提交和迭代测试，不承诺一次搜索找到所有岛的解，也不允许局部策略通过即宣告全部修复。

必须纳入：现有生成入口、必要主干/环路/桥接、必需设施选址及接入、可选设施让位、未接关系、
内陆断头、并行扎堆、真实地块边界、引用/派生产物、明确失败传播及可取消的累计预算。
本批公共设施和地标须逐种登记实际占地、基础、入口及道路穿行能力；不得仍以圆半径证明模型安全。
未声明的模型返回 unsupported/pending，保留在覆盖分母，不能进入声称模型物理完整的 success。
普通桥和海上设施接驳纳入本批；新增隧道、完整高架路图、张量场及地形重塑不作为默认兜底。

已有/外部固定建筑不迁移。临时对象允许有限联合重选；已接受对象仅可经显式授权、完整依赖闭包
的替代事务重规划；已发布地址及入口保持或遵守已审阅映射合同，不能自动变成可选对象。

### 9.2 现有冲突的根因及替代方式

| 根因 | 当前风险 | 本批替代 |
| --- | --- | --- |
| 名义位置与已接受位置没有完整状态机 | 骨架与后置搬迁面对不同障碍 | Reservation 状态、固定性及版本显式化 |
| 局部避路与接路终筛口径不一致 | 0.7r/0.85r 让位可通过，却挡住全宽接入 | 同一实体包络与 RoadCorridorPolicy，数值仅作候选启发 |
| 有地块但没有合法入口通道 | 距离近、同分量被误认作可服务 | 落位与入口、通道、宿主及主网路径联合证明 |
| 后置修改只更新局部数组 | 入口、桥注册表、车流或需求引用失效 | 依赖闭包、lineage/remap 及版本检查 |
| 需求从修复后的图重新推导 | 删路/挪设施后必要连接可消失 | 生成前登记需求，状态变化不删除承诺 |
| 网格街块先定义道路、冲突后零散补救 | 支路扎堆、被截断、容量反复跳变 | 接受道路围合街区，再划地块并证明地址接入 |

上表是代码可观察的结构性风险，不代表每个失败样本均由全部根因造成。诊断必须输出实际失败
阶段及证据。0.7r/0.85r 等旧启发可用于排序或快速提议，不能作为最终物理准入。

### 9.3 唯一生产阶段与冻结边界

1. **建立固定世界与先验需求**：冻结地形、外部建筑和已发布对象；登记 required owner、
   主网锚点、必要走廊、桥两端接地、街区服务和冗余要求。需求可延迟绑定具体几何，不能延迟登记。
2. **接受骨架通行空间**：主干、环路、跨河桥与两端接地共同试算，提交完整走廊和路口空间。
   临时建筑位置只作偏好；真实固定建筑为硬障碍。骨架失败进入有限替代候选，不先发布半座桥。
3. **联合选址与接入**：required 设施优先，位置、朝向、基础、实际门、plot gate、通道、接路
   及主网路径共同接受；可选对象在剩余空间选址。原候选耗尽后才进入已声明的有界联合让位层。
4. **增长次干/支路并闭合拓扑**：消费已接受预留；真交叉/近接即进入共享分类和事务，
   不能把路面 mesh 的 T/十字/环岛当作接通证据。必要端点不能靠截短变成合法尽端。
5. **道路生成街区、街区生成地块**：在同层接受道路上提取有界面，河岸/海岸可作为具名非道路
   边界，交叉层不能形成虚假围合。临时网格可提供候选方向，不再作为道路与街区的最终权威。
   地块须有可建包络和合法 frontage；必要服务接路在最终冻结前纳入联合事务。
   默认生产消费者必须读取实际面与孔洞；包围盒仅作候选搜索范围，不能作为花园、配套或
   地标占地证明。矩形候选必须声明最小模型尺寸、候选数量与累计地形采样预算，失败记录保留，
   不得缩小到模型不适用尺寸或静默丢弃应有配套。铺地须扣除道路、固定设施及高架包络。
   展示裁剪保留使用中地块当前版本的frontage宿主及有序主网路径；引用失效单独报告，
   不得用附近可见道路替代冻结的服务证明。
6. **最终冻结与派生**：复验全部先验需求、物理、容量和引用后冻结，生成布局、车流、装饰及
   展示裁剪；终验同时检查完整图和展示图。冻结后禁止独立挪建筑、删路或修改桥高程。

第3–5步可以在有限预算内联合回退，但只能撤回临时草稿，或替换已接受对象的完整事务。
半径调整产生新的世界尝试，所有地形相关证据失效并重算；不得拼接不同半径的局部“成功”。
基础准入通过模型factory注册投影，不向求解器加入模型名称分支。未知模型仍计入未覆盖分母；
已注册模型遇到未支持参数或预算耗尽不能当作安全。有限干地/支撑采样通过只构成partial证据，
不升级为完整基础、入口、场景或连续支撑验证。实际渲染海面与规划干地阈值分开报告。
局部基础声明不授予实际外廓取代圆代理的权限；走廊准入须另有明确完整保守renderer-XY
覆盖声明和实际渲染验证。该权限仅改变实体road/highway几何核查，原路幅/setback、邻接plot、
岸线、入口、已接受预留与候选预算仍独立保留。未知/缺声明模型不得无保护放行。
新增物理准入暴露旧坏位置时，必须保留失败owner及拒绝原因，并按阶段追踪位置/朝向改变、
真实模型基础证据及原候选层各类拒因；不得改测试为容忍failed、移除owner或扩候选范围来通过。
普通地块frontage与酒店等辅助地块分别计入完整展示服务覆盖；后者尚无证明时明确unsupported，
不能凭普通地块的零违例宣称全城入口已验证。整街区配套预留须另报布局实际会话容量，
不得把预留前规划容量冒充预留后的可用地址数。
这明确区分城市级走廊规划与建筑级接入：固定建筑先于绕行，临时设施与通行空间共同确认，
不采用“全部建筑永久固定后才规划主干”或“道路可无视固定建筑”的单向顺序。

### 9.4 数据契约与证据失效

以下为拟实施接口语义，字段名可按代码风格调整，但不得省略其含义：

- `PlanningWorld`：network/site/reservation/terrain/policy/model 版本；唯一需求目录；索引；累计预算。
- `Reservation`：稳定 id、ownerId、用途、实际包络、层/高程、状态及关联需求。
  状态为 tentative/accepted/frozen/released，另有 immutable 标识。released 必须有具名理由；
  required 预留释放只可在同一事务内被合法替代。accepted 不等于可无授权移动。
- `AccessProof`：demandId、ownerId、模型门与通道、gateNodeId、host lineage、有序主网路径、
  使用的世界版本及物理校验结果。plot-gate-only 必须与 model-door-verified 分开输出。
- `PlanPatch`：位置/朝向/入口、道路/桥/预留修改、节点边及路径 remap、依赖闭包、预期版本。
  复用 NetworkPatch/SitePlacementPatch，不另建绕开现有检查的第二套提交入口。
- `PlanOutcome`：success/degraded/failed/cancelled，逐需求状态及原因、覆盖情况、容量、预算和
  版本；unsupported、候选耗尽、预算耗尽分别报告，不得伪装“已证明无解”。

证据只有在其所有依赖版本匹配时有效。拆边时可用可验证的有序 remap 迁移纯拓扑引用，
几何/宽度/层/owner 改变必须重新物理验证；索引和障碍快照也要重建或经版本化增量更新。
需求身份先于图存在；未满足需求同样必须保留。required 只能满足、被显式等价替代或报告失败，
不能因删边、丢 owner、改变端点分类或重新 measure 而从目录消失。

合法终点必须有先验用途声明并被校验：真实设施入口、已声明岸线终点或边界出口等。
near-site/near-coast 不再授予终点豁免；无法分类的内陆度1节点按待接通处理。

### 9.5 统一准入与区域联合修复

生成、选址、搜索、修复和终验调用同一物理策略：真实折线扫掠路幅、模型占地/通道、地形、
层和结构、路口腿长及夹角。允许粗筛假阳性，但粗筛不得拒绝终筛可行的候选而无明确覆盖边界。
实体容许穿行须由具名模型合同声明，例如凯旋门净空，不由设施种类字符串提供普遍豁免。

候选阶梯固定为：直接拆边/节点合并 → 有界重定线/改接 → 局部绕行 → 区域联合重选。
按冲突依赖闭包评估，不以全岛反复 clone 代替局部规划。并行扎堆优先在生成期拒绝重复走廊；
既有保护主干冲突用共享兼容走廊或重定线解决，禁止降低宽度或删除必要割边来降低计数。

庄园等可移动岸线对象允许复用既有岸线候选层，但必须与路口接入、旧入口/暴露端点及其它
受影响需求一起提交。该层不是扩大 snap；未登记候选、固定 owner 或无合法替代接入均拒绝。
对全部受影响实体与预留使用当前草稿终筛，不能只保证“新问题总数不增加”。

提交顺序：检查版本 → 构造依赖闭包草稿 → 检查共享物理/关系 → 核对需求身份与满足状态 →
重算受影响引用/地块/容量 → 发布全部变化及新版本。任一失败或取消，权威世界零副作用。
只保留新的未满足需求不够；事务不得损失原有 required 对象或已满足的通行承诺。

确定性逻辑使用操作数预算，墙钟只用于性能测量和调度，不进入生产哈希或改变候选结果。
耗尽、worker取消或版本过期均不发布部分草稿；已发布的最后一致状态可以只读保留。

### 9.7 测试矩阵与联合完成标准

新增测试须覆盖根因而非只锁 seed：

| 合成场景 | 必须断言 |
| --- | --- |
| 旧0.85r避让通过但全宽冲突 | 选址不能接受；合法联合候选可成功，门限未放宽 |
| 固定建筑挡路、临时设施挡路 | 前者绕行/明确失败且不移动；后者完整联合重选或零副作用拒绝 |
| owner移动、terrain更新、宿主拆边 | 旧证明失效；正确 remap 后复验，过期快照不能提交 |
| 未满足 required 的边/owner 被删除 | 需求仍存在且事务拒绝或等价替代，不靠重新 measure 消失 |
| 合法尽端与8个历史内陆断头分类 | 各有用途/证据；必须接通的端点不能新增合法标签获豁免 |
| 岸线重选和旧近距端点暴露 | 新路口、旧入口/断头及所有引用一起通过，否则完全撤销 |
| 路口三处历史关系、保护主干扎堆 | 拆边/改接/重定线保宽度与需求；不靠删除割边、扩大 snap |
| 桥面可行而岸端/后续路径失败 | 两端及 owner 整组重选/拒绝，无孤儿桥注册表 |
| 同层面提取、跨层投影、海岸边界 | 无虚假街区；地块实际可建且有服务，容量按最终产物计 |
| 预算耗尽、取消、事务中途拒绝 | 状态分类明确，权威世界不变，累计计数不重置 |
| 消费者复用过期布局/展示裁剪 | 显式重建或拒绝；入口、车流及必要主网路径不丢 |

沿用 §7 全部已知答案、命名生产回归、四档调参/独立集和变换检查。历史30岛、3处未接关系、
8个内陆断头只作带源码指纹的复现集合，不是当前数量，也不能替代完整验收分母。
比较 solve 前后必须固定地形、半径、初始需求及预留；若没有同世界对照，报告关联变化而非因果收益。

联合完成必须同时满足：

1. 成功产物全部 required 已满足、无未接地面关系/非法断头/非主网必需分量；桥两端接地，
   模型/道路/入口物理合法，容量满足，引用和派生产物同版本。锐角、扎堆等旧约束仍全部验收。
2. 必要对象、需求及地址没有减少；可选省略与合法终点均有先验合同和逐项证据。
3. 生产写入口、模型/入口、预算/取消和消费者覆盖清单无未解释空项；unsupported/pending
   不计入完整能力成功。本批不覆盖的隧道/高架明确列出，不混入已完成声明。
4. 同冻结源码/配置/模型声明，相关模块、无缓存 full、V8/JSC、四档独立验收及布局/车流通过；
   失败率、degraded率和耗时/内存另行报告，不从成功子集推断整体合格。
5. 失败/degraded 率及性能阈值在最终验收前锁定并审阅；未锁定就是门禁未完成。
   命名可解回归不接受通过显式失败代替修复；预算不足也不能宣称已证明不可解。
6. 视觉与规划 diff 审阅后才可更新 intentional golden；审计记录每项证据、源码指纹及未完成项。

每完成一个子批只登记局部进展；以上六项缺一，U 和“剩余问题全部完成”均保持未完成。

### 9.8 声明驱动能力与建筑解耦（2026-10-11）

新增建筑可以改变空间占用和最终规划结果，但不得要求在通用规划器中增加模型名字判断。
模型提供物理/入口数据，城市programme提供实例需求、优先级与固定性；规划器仅消费能力、
预留状态和世界版本。新模型的渲染实现及注册配置属于正常新增工作，不等于改变规划算法。

1. 复用PhysicalDeclaration作为实体、基础、入口通道、运动和净空的物理权威，不建立第二套
   按建筑名字验证的几何。规划DTO必须是声明的投影，包含来源/版本和覆盖级别。
2. 选址按能力组合（临街/岸线/海上接驳/跨走廊等）生成候选，修复按违例和依赖闭包调度。
   普通模型换名、尺寸或入口位置变化不增加策略；全新地下/升降等结构能力才扩展通用合同。
3. 实例移动由固定/接受/冻结状态及依赖授权决定，不由港口/车站等名称决定。迁移期SiteSpec
   可以登记旧placement默认mobility，但它不能授予搬迁已绑定/冻结实例的权限，也不代替状态机。
4. 需求从programme生成，不把六个市政名称或固定地标池当作永久的通用需求目录。
   禁止以模型名、seed、失败坐标或扩大snap/净距阈值为新能力兜底。
5. 验收新增：同声明仅换modelId/kind规划不变；缩放与偏置入口自动变换；缺失/非法声明明确
   unsupported；新普通建筑只改模型声明/注册/需求配置、不改规划算法。还需完整渲染及物理验证，
   不能用“诊所”别名合成测试证明新模型资产和基础已完成。

首批已迁移：PlanarAccessDeclaration为单入口ground-frontage的参数化几何DTO；jointSite读取
入口方向/局部位置，不再限定station/stadium。车站渲染与选址共用STATION_PLANAR_ACCESS数据；
体育场仍显式plot-proxy，未伪造门洞。偏置入口沿其朝外射线生成plot gate，声明不得超出当前
圆形plot envelope；该能力暂不支持多入口和完整通道/基础证明，不能计作完整AccessProof。
SiteSpec登记mobility/岸线目标参数，通用避路、近接让位、岸线重选与部分后置选址读取声明。
未知移动能力不默认为可搬迁，已绑定入口与海上依赖仍保护。

仍须迁移：全部kind特例、模型实体/基础/通道投影、programme及实例预留状态、跨走廊/海上
能力、真实门路Proof和版本失效。以上首批接口不降低§9.7的完整交付门禁。

### 9.9 基础落位与主干联合定线（2026-10-12实测补充，部分实施）

初始shore阶段的实际network快照证明，1703350391/t2与2003037141/t1在原264个局部位置中
都没有可直接搬入的完整候选。前者69个基础合格位置中65个与真实全路幅冲突，后者32个
中28个真实路幅冲突；其余仍受湿预算或名义邻居预留阻挡。只换圆筛或统一判定口径不足以
解决这两个样本，禁止把这些基础合格位置当空地发布。

1. 按声明识别基础违例与可搬迁owner，不按模型名/seed写生产分支。在已有候选预算内联合
   枚举owner姿态与阻挡道路集合；声明不足、owner冻结/绑定入口时显式拒绝。
2. 道路集合必须取全部真实折线段与原width，包含层/桥及依赖；不是只取最近中心线。
   两个实测线索分别涉及12宽主干的一段或相邻两段，需要先确定依赖闭包与真实结构权限，
   不能删边、降为8/5宽支路或假设桥可以按地面移动。
3. 同一PlanningWorld草稿内先保留必要需求，再联合重定线与owner落位；旧道路替换的新路径
   须保留等级/路幅/两端服务/lineage/必要车流映射，并在实际候选owner周围做全宽校验。
   失败草稿零副作用，不将新位置单独先发布；先验基础合格不代替最终网络上的道路准入。
4. 仍保留原岸线、湿圈、邻居/固定预留、服务与高架净距。名义邻居保护只有在双方实际声明
   与授权已齐备时才能由真实实体规则取代，未知港口/塔不能被推测为空地。
5. 提案从原候选/路径预算中消费，计入候选、A*、terrain、clone与取消总账；不能因为涉及
   两个对象而另起不受约束的循环。当前诊断里的最多5条展示记录不是新的生产搜索预算。
6. 验收同时检查foundation/道路走廊/真实入口/全图拓扑/parcel容量/需求分母/版本与派生闭包，
   并复验原规划主批与独立样本；命名样本恢复不等于U1/U2/U5或整体合并门禁通过。

诊断已记录候选坐标、当时边id/实际width/结构及净距，作为本节联合修复的实证定位。

实施进展：联合owner+保端点道路替换已接入原局部候选预算并有原子拒绝/发布守卫。实际XY声明
在迁移、roadThroughSite和避路修复中共用道路半幅+3；未声明模型保持原圆保护。新增节点依赖
