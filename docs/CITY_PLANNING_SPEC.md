# Agent City：种子地理与城市规划重写 SPEC（2026-10-02）

状态：草案，待评审。替换 `cityPlan.ts` 的地理与规划部分，调整 `cityLayout.ts` 的选址，下游统一读布局输出。
现状分层见 `docs/CITY_MODULE.md`，分享相关见 `docs/CITY_SHARE_SPEC.md`；本文只管「岛怎么生成、城怎么规划」。

## 1. 问题

| # | 现象 | 根因 |
| --- | --- | --- |
| P1 | 换种子岛形几乎不变 | 海岸是写死折线，种子只加 ±19 抖动；公共用地、城区锚点、街区网格范围都是常量 |
| P2 | 让岛形真变化后，城市容量差近一倍 | 实测 20 个种子、700 会话：可用地块 1136–1960。岛先定，会话后塞，小岛装不下就溢出成背景楼群 |
| P3 | 城市像「方格纸盖在岛上」 | 全岛一张均匀方格；分区按网格行列号判断，不看离岸、河、山；锚点与公共用地和地理无关 |
| P4 | 岛形一变下游悄悄出错 | 相机边界 `urbanBounds`（±570）、`buildable` 里的 `z > -308`、北环高架 z、太阳/阴影盒、航拍、航线、远山都隐含「岛在原点附近、这么大」 |

结论：顺序反了。应当**先有地理，再沿地理规划，规模跟数据走**。

## 2. 目标与非目标

**目标**
- 不同种子得到明显不同的岛（轮廓、河、山、核心位置），且任何种子都是一座完整可用的城。
- 城市规模随会话数伸缩：任何种子、任何会话数（0–2000）都装得下，不靠背景楼群兜底（>2000 才允许）。
- 路网、分区、公共用地沿地理生成，看起来像「长出来的」城市。
- 下游不再含岛形常量。

**非目标**
- 群岛 / 半岛连陆 / 环形湾等跨水城区（D2 决定；本 SPEC 默认「同一类热带海岛的变体」，见 §9）。
- 改变数据语义：楼 = 会话，高度 = token（对数），城区 = 执行环境，颜色 = 执行环境色。
- 交通仿真（路口优先、避碰）。

## 3. 不变的契约（必须继续成立，守卫已覆盖）

- **确定性**：同一数据 + 同一种子 → 同一座城（地址逐个相等）。
- **输入顺序无关**：buildings / districts 反序得到同一布局。
- **刷新不搬家**：带 `previous` 时已落位的会话保持地址；分页追加只占新地块。
- **数据无关的地理**：第 1–2 层只读种子与「规模档位」（§4.2），不读任何会话字段。
- **种子持久化**：首次生成、落盘、只在用户重置或手动输入时改变（`city_seed_config` / `reset_city_seed` / `set_city_seed`，已实现）。

## 4. 分层设计

```text
seed, scaleTier
  └─ L1 地理  geography.ts   → LandField（海拔/离岸/离河/坡度/可建）、coast、river、ridge、core
       └─ L2 骨架 skeleton.ts → 主干道、次级街网、桥、街区多边形、分区
            └─ L3 用地 landuse.ts → 公共用地、小区（执行环境城区）划分、中心花园、配套位
                 └─ L4 落位 cityLayout.ts（保留现有规则）→ 会话 → 地块
下游：CityEngine / cityParts / cityCinematic / 太阳与阴影 —— 只读 layout.bounds / layout.core
```

每层是纯函数，输出可序列化，单独可测。L1–L3 按 `(seed, scaleTier)` 缓存（现有 `plans` Map 扩展键）。

### 4.1 L1 地理

**岛形**：极坐标轮廓 `r(θ) = R · (1 + Σ a_k cos(kθ + φ_k) − Σ bay(θ) + 0.07·fbm)`，k ∈ {2,3,5}；
整体拉伸 `stretch ∈ [0.78, 1.28]` 与旋转 `spin ∈ [0, 2π)`；1–3 个海湾（高斯凹口）；可选一个半岛（高斯凸起）。
`r ≥ 0.42R` 防止断裂成多岛。

**面积按规模缩放**：`R` 由目标可建面积反推（§4.2），先粗算再按实测可建面积二分 3–4 次校正，
保证「可建地块数 ≥ 目标」。这一步只依赖 `scaleTier`，不依赖具体会话。

**山脊**：方位 `ridgeAngle` 随种子；山体占该方向最外侧一带，高度 `smoothstep × (30 + 65·fbm)`。

**河流**：82% 有河。源头取山脊上最高点附近，按坡度下降方向 + 噪声扰动步进到海，宽度从 8 渐宽到 40。
（替换现在固定南北向的 `riverX(z)`。）

**城市核心点 `core`**：在可建地上取评分最高的点：平坦（低坡度）、离岸 120–260、离河 30–120（无河则忽略）、远离山脊。

**生态带 `biome`**（种子决定，影响植被、地面色、海水色，不影响数据语义）：
| 生态带 | 植被 | 地面 / 水色倾向 |
| --- | --- | --- |
| tropical 热带 | 棕榈、芭蕉、灌木丛 | 白沙、青绿浅海 |
| temperate 温带 | 阔叶落叶树、圆冠树 | 绿草、蓝灰海 |
| boreal 寒温带 | 松、杉（锥形针叶） | 暗绿、岩石多、深蓝海 |
| savanna 稀树草原 | 伞形金合欢、枯草丛 | 黄褐土、蓝绿海 |
| eastasian 东亚园林 | 樱花、垂柳、松 | 绿草、碧水（与小区花园同一语汇） |

山地高处按海拔叠一层（松 → 裸岩）。同一座岛内允许一个主生态带 + 一个次生态带（按离岸 / 海拔过渡），避免整岛同一种树。
植被模型来源见 §4.5。

**输出 `LandField`**：`height / coastDistance / riverDistance / slope / buildable(x,z)`，以及 `coast`、`river`、`ridge`、`core`、`bounds`（岛包围盒）。

### 4.2 规模档位（让城市装得下，又不让地图随每次刷新变）

`scaleTier = clamp(ceil(totalSessions / 400), 1, 5)`，目标地块数 `400 × scaleTier × 1.35`（35% 余量给公共用地、花园、配套、道路损耗）。

- 档位只在跨越边界时变化，日常刷新、分页追加不变 → 地图稳定。
- 档位变化 = 岛按比例放大（形状同种子、同方向，只是更大），属于「城市在扩张」，可接受；
  已落位会话的地址按比例映射到新地块（最近邻 + 冲突让位），不打乱相对位置。
- 档位写入布局输出，航拍与相机读它决定取景距离。

### 4.3 L2 骨架

**主干道**：从 `core` 放射 5–7 条，方向避开山脊与深水；遇河生成桥（桥址取河最窄处）；沿途按坡度绕行（等高线偏移）。
再连一条环线（离核心约 0.55R）。主干道宽 8。

**次级街网**：主干道把可建地切成若干区域；每个区域取其主方向（最近主干道的走向）铺 40–55 × 34–50 的街区，
临海与山脚的街区边沿顺岸线 / 等高线裁切。街宽 5。整张路网必须连通（守卫）。

**分区**（取代行列号判断），对每个街区按评分取最高：
| 分区 | 主要条件 |
| --- | --- |
| downtown | 离 core < 0.25R |
| waterfront | 离岸 < 90 |
| commercial | 临主干道 / 交汇点 |
| residential | 其余；山脚坡度略高处优先 |
| parkland | 河两岸 25 内（不建楼，做滨河绿带） |

### 4.4 L3 用地

**公共用地按条件选址**（不再有写死坐标）：
| 类型 | 选址条件 |
| --- | --- |
| civic（市政广场） | core 所在街区 |
| station | 主干道交汇点中离 core 0.3–0.5R 的 |
| harbor | 离岸最短、水深最大的海岸段内侧 |
| stadium | 坡度最低、面积最大的连续 2×2 街区 |
| tower（观景塔） | core 附近高处 |
| park | 河岸 parkland 中最宽一段（无河则取海湾内侧） |
| school / culture / market | 主仓库未提交改动中的新类型：按服务半径在居住/商业区均匀布点（合并时纳入） |

**小区（执行环境城区）划分**：按会话数比例把剩余可建街区划给各执行环境，用以 core 为圆心的扇区 + 种子扰动做加权 Voronoi，
保证每个小区连成一片、与邻区以主干道或河为界。小区中心街区固定为**中心花园**（湖、假山、亭，已实现）。

**配套**（学校 / 商场 / 医院，已实现）：仍按每 45 会话一座，只占小区内空街区；落成时刻随规模。

**致敬型地标**（程序化几何，不复刻任何具体建筑，不下载现成模型）：种子从下表抽 2–3 座，按条件选址，构成这座岛的「名片」。
| 地标 | 形态 | 选址条件 |
| --- | --- | --- |
| tv-tower 电视塔 | 细塔身 + 圆盘观景舱 + 天线 | core 附近高处 |
| sail-opera 帆顶剧院 | 3–5 片弯曲白壳 | 海湾内侧、离岸 < 60 |
| arch 凯旋拱门 | 方墩拱门 | 主干道放射起点 / 环线交点 |
| pagoda 宝塔 | 5–9 层逐层收分、檐角上翘 | eastasian 优先，公园或山脚 |
| lighthouse 灯塔 | 白红条纹圆塔 + 灯室（夜间旋转光束） | 海岬（离岸最近的凸点） |
| ferris-wheel 摩天轮 | 圆环 + 辐条 + 吊厢，缓慢转动 | 海滨分区 |
| suspension-bridge 悬索大桥 | 双塔 + 主缆 + 吊索，替换一座过河桥 | 河最宽处 |
| twin-towers 双子塔 / twist-tower 扭转塔 | 两座连廊塔 / 逐层旋转的塔 | downtown，与会话地标塔错开 |
| villa-complex 地中海庄园 | 白灰泥横带楼 + 临水拱廊 + 红陶四坡顶 + 端头钟塔（低层纪念性，总高 ≤30） | 海湾内侧静水岸（与帆顶剧院错开）；tropical 生态权重 4，其余 1 |

海滨会话酒店的格栅鳍片冠、商业楼顶立牌与主干道双柱广告牌不是独立地标：它们分别随酒店封顶
（`hotelCrownPlan`，约 1/3 平顶）、商业高楼封顶（`rooftopSignPlan`，约 1/5 出牌）出现，规格见
CITY_LANDMARK_BACKLOG.md 的 L-1/L-2。

地标为纯装饰：不进统计、不可拾取、不占会话地块；不改「token 最多的会话是天际线焦点」的规则（地标高度上限为该会话楼高的 0.9）。

### 4.5 素材

- 地标：全部程序化，零素材体积。
- 植被：Kenney Nature Kit（CC0，kenney.nl），只取 15–20 个树种 / 灌木的 GLB，压缩后预计 < 1 MB；
  入库 `assets/` 并登记 `LICENSES.md`，受 `verify-react-city-assets.mjs` 的 5 MB 总预算约束。
  加载失败时退回现有程序化树（与贴图素材同一套降级规则）。
- 每种树一个 `InstancedMesh`，按生态带启用 4–6 种；draw call 增量 ≤ 6。

### 4.6 L4 会话落位

保留现有规则：各执行环境在自己的小区内，按 `(startedAt, -height, id)` 从中心花园向外取地块；`previous` 已占的地址保留。
溢出（> 档位 5 容量）才进入背景楼群。

扩展 `scripts/verify-react-city-layout.mjs`，新增 `scripts/verify-react-city-geography.mjs`：

## 8. 风险

- **主干道放射 + 等高线绕行**是最复杂的部分，可能出现锐角路口或死胡同。缓解：先做直线放射 + 截断，绕行作为第二步；连通性守卫兜底。
- **档位放大时的地址映射**可能让少量楼换邻居。缓解：映射只在档位变化时发生（罕见），并在守卫里钉住相对次序。
- **性能**：L1 二分校正与 L2 路网生成在首次进入城市页时计算。预算：700 会话、档位 2，L1–L3 合计 < 120 ms（M1）；超出则缓存到 `state/`。
- **与主仓库未提交改动冲突**：`cityPlan.ts` 被整体替换。处理方式是吸收意图而非逐行合并（见 §4.4 school/culture/market、只显示已开发街区的道路）。
