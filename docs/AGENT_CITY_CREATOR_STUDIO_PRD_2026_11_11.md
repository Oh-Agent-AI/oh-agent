# Agent City Creator Studio 产品需求

状态：待评审
日期：2026-11-11
配套文档：[Creator Studio 代码架构](AGENT_CITY_CREATOR_STUDIO_CODE_ARCHITECTURE_2026_11_11.md)

## 1. 产品目标

Creator Studio 是 Oh Agent 内置的官方 App Plugin。用户在实时 3D City 中搭建自己的城市，通过直接操作和侧边栏 Agent 对话共同编辑，在同一视口试玩、保存并发布内容。现有「修复城市」的建筑、道路操作与实时预览是产品基础。

City 是当前产品中心。一个用户可以拥有多个城市实例，每座城市可以安装和布置多个兼容的小游戏。SDK 面向用户与第三方 Agent，GitHub 托管和 Shop 分发为后续交付阶段。

## 2. 用户与价值

| 用户 | 目标 | 主要操作 |
|---|---|---|
| 玩家创作者 | 按自己的想法搭建可玩的城市 | 选择、拖动、对话修改、试玩 |
| Agent 开发者 | 用 SDK 或 MCP 协助创作 | 查询项目和选区、提交有界变更、查看结果 |
| 内容开发者 | 分享城市风格和小游戏 | 创建内容、校验、打包、发布 |

## 3. 体验与信息布局

- 顶部显示城市名称、保存状态、撤销、重做、试玩和发布入口。
- 主区域是实时 3D City，可缩放、旋转、选取对象和进行地图编辑。画面继续由 City Runtime 驱动。
- 场景工具包含选择、建筑、道路和游戏入口。根据所选工具展示必要的上下文控件和校验提示。
- 侧边栏显示 Agent 对话、当前选中对象、变更预览及应用或取消操作。用户可以通过文字继续修改，也可以在地图上手动调整。
- 试玩开始时固定当前草稿版本。结束后回到同一项目、位置和编辑上下文。

示例流程：用户选择一栋建筑，对 Agent 说「把这栋楼移到广场旁」。Agent 给出目标位置的 3D 预览和说明。用户确认后修改保存到当前草稿，随后可以拖动建筑继续调整。用户选择「试玩」，在当前城市进入小游戏，结束后返回编辑。

## 4. 功能范围

| 功能 | MVP 要求 | 后续能力 |
|---|---|---|
| 城市项目 | 打开或从现有城市创建一个草稿，显示保存与失败状态，重新打开可恢复 | 多城市管理、复制城市、版本历史 |
| 实时编辑 | 复用建筑选择、移动、预览和校验。保留已有道路修复体验 | 增加地形、可导入模型和更丰富的道路工具 |
| Agent 协作 | 以选中的建筑为上下文，完成一次可视预览、确认提交和手动后续调整 | 多对象编辑、生成街区、对话驱动道路和游戏设计 |
| 小游戏 | 在同一城市布置并调整竞速入口或检查点，试玩并结算 | 更多游戏类型、跨城市绑定和组合 |
| 试玩 | 固定草稿版本，从 Studio 当前视口进入并退出，显示结果 | 录制与回放、自动试玩 |
| 内容分发 | —（对外安装与内容包规范延后至独立里程碑） | GitHub 目录、官方 Shop、购买与社区供给 |

MVP 验收基于一座现有城市和官方竞速玩法。城市风格、第二座城市、独立安装和商店分别验收，避免阻塞首次实时创作体验。架构应保留世界、皮肤和玩法独立组合的契约。

## 5. 交互规则

1. 用户或 Agent 发起编辑时，场景显示对象和目标位置。无效位置给出原因，用户可以调整或取消。
2. Agent 的预览应用前展示变更范围。用户确认后提交，确认与提交结果在界面可见。
3. 玩家操作和 Agent 修改使用同一项目版本。发生并发修改时，提示版本变化并重新读取或预览。
4. 保存失败时保留当前可见编辑状态，明确提示失败并允许重试。关闭或切换项目前处理尚未保存的修改。
5. 撤销和重做作用于已提交的编辑。撤销后由项目服务生成新版本，避免覆盖其他来源的修改。
6. 玩家开始试玩时，保存并固定所选版本。试玩结束、取消或失败后恢复编辑上下文。运行中的规则与场景绑定保持该次试玩的快照。

## 6. 数据与授权

城市创作数据按本地项目保存。Agent 默认取得完成当前操作所需的项目、选区和受限场景信息。真实 Agent Vitals 数据继续走官方插件已授权的 typed API，浏览器预览使用合成数据。连接任何远程模型或服务涉及用户数据传输时，需要遵守仓库现行的数据策略与独立产品决策。MVP 的 Agent 执行通过本机已授权的外部 Agent 与 MCP 完成。对话侧栏的默认接入方式为：侧栏作为 Studio WebView 内的对话面板，Agent 请求经活动 Studio 的 MCP 路由到达项目服务；是否改为宿主直接路由作为备选在实现时评估，需保留会话身份、授权与单次请求边界。

## 7. 验收

| 编号 | 可观察结果 |
|---|---|
| A1 | 打开现有 City 的创作草稿，建筑、道路和既有修复结果正确呈现 |
| A2 | 玩家选中并移动建筑，能看到预览、校验和保存结果，重启后位置保持 |
| A3 | Agent 根据当前选中建筑提出移动，用户看到 3D 预览，确认后地图更新并保存 |
| A4 | Agent 和玩家连续编辑同一对象，旧 revision 提交被拒绝且不会覆盖新修改 |
| A5 | 用户调整竞速入口或检查点后在当前视口完成一场竞速。取消与失败可以返回编辑 |
| A6 | 保存失败、无效位置、Agent 断连及试玩启动失败均显示可理解状态；应用崩溃或强杀后重开恢复到最后一个完整 revision、无半写状态，已保存版本可恢复 |
| A7 | 既有 City 建筑和道路修复可继续使用，旧补丁按迁移方案保留或导入；进入 Studio 后撤销栈仅含本次会话操作，旧修复会话历史不继承（预期降级） |

## 8. 成功指标与待决事项

内部试用记录完成创作到试玩的比例、首次完成时间、编辑成功率（提交成功次数 / 提交尝试次数）、保存失败率和每次修改后是否继续编辑。指标先以本地、用户主动参与的试用记录收集，遵守现行数据政策。

待评审事项包括 Agent 侧栏授权的细节（接入方式已按第 6 节默认确定）、试玩中的编辑入口（数据层已由试玩快照固定语义覆盖，仅剩 UI 决策）、旧补丁导入的用户体验，以及发布内容的真实数据脱敏范围。
