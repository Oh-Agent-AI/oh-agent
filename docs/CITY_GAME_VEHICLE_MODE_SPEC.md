# Agent City 城市驾驶模式 SPEC

创建：2026-10-09；修订：2026-10-15。状态：待评审 SPEC，本文不代表实现或验收完成。范围：在现有 City 插件游戏模式内增加单车驾驶体验；不是完整 GTA 克隆。上位设计：[CITY_GAME_MODE_IMPLEMENTATION_PLAN.md](CITY_GAME_MODE_IMPLEMENTATION_PLAN.md)；交互规范：[CITY_UX_SPEC.md](CITY_UX_SPEC.md)；飞机校准参考：[CITY_GAME_FLIGHT_CALIBRATION_SPEC.md](CITY_GAME_FLIGHT_CALIBRATION_SPEC.md)。

## 1. 目标与产品边界

让用户在熟悉的 Agent City 中驾驶一辆车，沿程序化道路自由探索，并可完成一类简单驾驶挑战。体验借鉴 GTA 的“第三人称城市驾驶与探索”，不追求 GTA 的犯罪叙事、开放世界内容量或真实车辆模拟。

首个 MVP（V2）目标：

- 从 City 通用游戏入口选择“驾驶”，进入一辆可驾驶车辆；不要求先实现步行角色、上下车或车库。
- 在实际道路表面上完成加速、刹车/倒车、转向、车身姿态反馈、相机跟随和安全碰撞响应。
- 交付自由驾驶、暂停、重置和退出；短程检查点挑战与最佳成绩属于后续 V3，不阻塞首版。
- 驾驶结束回到进入游戏前的数据视角；不会改变真实会话、楼宇统计或其他分析数据。

明确不做：武器、警察/通缉、犯罪、行人伤害、多人/网络、任务奖励等级、车辆购买/升级、交通 AI、完整步行模式、可破坏环境、游戏录制。环境车辆在驾驶期间隐藏、退出后恢复；动态交通碰撞留后续。

## 2. 现有能力与缺口

当前 City 游戏代码已提供可复用的宿主运行时：单一 Three.js renderer 与帧循环、游戏相机所有权、互斥/暂停/退出状态机、画布焦点输入、固定步长、布局快照、HUD、结果与 `plugin.state` 档案端口。飞机模拟、飞机碰撞与路线任务不可直接作为车辆物理复用。

| 能力 | 当前证据/状态 | 驾驶模式影响 |
| --- | --- | --- |
| 道路拓扑 | `CityLayout` 有 `roadNodes`、`roadEdges`；edge 含 `points / width / kind / bridge` | 可作为可驾驶路网候选；仍需验证连通性、宽度、交叉口和不同 seed 的覆盖率 |
| 道路渲染 | `systems/roadSurfaceSystem.ts` 绘制普通路面；`systems/roadSystem.ts` 绘制桥梁/高架等结构 | 视觉网格不等于可碰撞路面；必须从同一来源构造物理/路面查询，避免错位 |
| 路面高程 | `layout.terrain.height(x,z)` 可查地形；桥梁布局 `BridgeLayout` 目前只有端点、角度、长度 | 桥面/坡道可能没有足以驾驶的高度剖面；高架道路与地面碰撞不能凭平面假设 |
| 飞行世界 | `FlightWorld` 主要有障碍盒、地形和出生点 | 可借只读布局快照、网格查询与生命周期思想；不可将其 AABB/安全出生点当成道路碰撞系统 |
| 车辆物理 | 仓库当前未声明 `cannon-es` 或 Rapier 车辆依赖 | 必须先做小型物理技术验证，再选择依赖或轻量自研方案；不要未经验证引入完整物理框架 |

**首要技术风险不是车模，而是“渲染道路是否构成连续、可寻址、能贴地的驾驶表面”。** 实施前必须先在多个 seed、不同城市规模、桥梁/河道/坡地上验证路面数据与视觉一致性。若该条件不满足，应先补道路表面契约或缩小为已验证的平地试验赛道，不得让车辆凭视觉上路、实际穿地/悬空。

## 4. 用户流程与操作

1. 用户在 City 通用工具中选择“驾驶汽车”，首版直接进入自由驾驶准备；V3 再提供挑战选择。默认数据模式不变。
2. 系统检查 City 已就绪、无航拍/视频导出冲突，选择可驾驶道路上的安全出生点；失败时给出可理解原因并允许重试/退出。
3. 车辆静止出生于安全路面，显示短控制说明，用户按键开始行驶。V3 挑战在安全起点就位后自动进行三秒倒计时，不需要额外驶入触发区。
4. 用户可暂停、继续、重赛或退出。Tab 隐藏、失焦、长帧、WebGL context lost 遵循现有游戏模式恢复语义；不追赶后台时间。
5. 退出时移除车辆、物理世界、事件监听和本模式资源，恢复相机/回放/标签/选择等原始状态。

初始键盘映射建议：W 加速，S 刹车/倒车（速度接近 0 后切换倒车），A/D 转向，Space 首版不绑定（手刹留后续），R 回到最近安全道路点，Esc 暂停/继续。必须用 `KeyboardEvent.code`，仅游戏画布聚焦时消费；输入框、宿主控件、输入法组合不被拦截。首版不要求鼠标锁定、手柄或触控。

车速/档位等 HUD 仅为游戏状态，不显示用户数据、token、session、异常内容；碰撞和成绩不得解释为 Agent 效率或工作表现。车辆仅可进入显式验证的窄路肩缓冲区，显示驶离道路提示；缓冲区也须有合法支撑，外沿作为封闭边界。不允许穿越楼体/水域后永久困住。

## 5. 技术架构

### 5.1 共用运行时与隔离

沿用单 renderer、单 rAF、单相机所有者和游戏退出事务。飞机与车辆是同一 City 游戏宿主中的不同 vehicle adapter；不要复制第二套 CityEngine、相机生命周期、React 每帧状态或插件桥接。

建议将当前游戏引擎编排逐步收敛为：

```text
GameRuntime / GameSession
  ├─ Shared lifecycle: enter / pause / resume / restart / exit / ReturnState
  ├─ VehicleAdapter: FlightAdapter | CarAdapter
  ├─ VehicleWorld: FlightWorld | DrivingWorld
  ├─ Mission: RaceMission | RoadCheckpointMission
  └─ GameHud: shared shell + vehicle-specific control/telemetry panel
```

当前 `GameSelection` 仅覆盖 practice/race，后续扩展应使用显式 `vehicle: "plane" | "car"` 与 `activity: "free" | "challenge"`（或等价强类型），避免继续堆叠特定插件/载具分支。此 SPEC 不要求立即重构飞机代码；先提取必要的生命周期接口，保持既有飞机验收不回退。

车辆模拟与道路查询保持纯逻辑模块，不依赖 React；Three.js 层只将模拟状态同步到车模、车轮和相机。HUD 以事件/低频快照更新，不逐帧 React render。物理更新加入现有固定步循环；不得创建独立动画循环。

### 5.2 道路表面与 DrivingWorld

新增只读 `DrivingWorld` 快照，输入为进入时冻结的 `CityLayout`，输出至少包括：

- 可驾驶路段图：道路节点、边、中心线采样、宽度、路类、连通关系、是否桥梁/坡道；过滤人行 promenade、装饰道路和不允许驾驶的段。
- 路面查询：给定 `(x,z)` 返回最近合法路面、中心线切线、横向偏移/路宽、地表高程、坡度与有效性；桥面必须有与实际渲染一致的高度剖面。
- 空间索引：最近道路与静态碰撞候选查询有界，不能每个物理步扫描整张 road graph 或全部建筑。
- 静态碰撞：沿用建筑/地标数据作为保守障碍，但为道路表面、路缘、桥梁分别建模；不要把飞机使用的宽松盒直接当车辆可通行判定。
- 安全恢复点：来自已验证路段的采样位，车辆 footprint、朝向、地面高度和四周净空全部通过校验；无点时拒绝启动。

道路数据应成为渲染与驾驶共同消费的来源，至少共享路面采样/高程定义。若现有道路中心线无法给出实际 road mesh 的边界、高度或桥坡，先补 `RoadSurface` 数据契约；不从屏幕截图反推物理表面。

### 5.3 车辆动力学决策门

本轮选择轻量 arcade/bicycle 模型作为首版实现方向；不要求悬挂、跳跃和翻车物理。V1 先验证其道路贴合、扫掠碰撞和手感；只有该方向无法通过验收时，才用同一测试路段评估 RaycastVehicle，并记录决策后调整方案。下表保留备选取舍：

| 方案 | 优点 | 风险 |
| --- | --- | --- |
| 轻量 arcade/bicycle model（速度向量、横向抓地、转向随速度变化、坡度贴合） | 依赖小、容易适配固定步长和确定性，也容易保持“休闲、可控” | 轮胎悬挂、跳跃、路面冲击和翻车反馈较弱，需仔细控制横向滑移 |
| `cannon-es` RaycastVehicle（或经评估的等价库） | 轮胎射线、悬挂、摩擦和接触点较成熟，适合路缘/坡道/起伏 | 仓库当前无此依赖；需评估打包体积、初始化/释放、固定步集成、determinism、地形网格成本与 WebView 性能 |

选择门槛：比较 City 道路贴合精度、碰撞可控性、输入延迟、30/60 FPS 下稳定性、城市最坏种子 CPU P95、额外内存/包体、重复重置与清理结果。未测前不写死“必须用 Cannon/Rapier”或“自研即可”。MVP 应选择能达到稳定可玩体验的最低复杂度方案；不追求完整汽车工业级轮胎模型。

无论选哪种，车辆至少有位置、朝向、线速度、角速度/转向状态、接地状态、模拟时钟；固定步长积分与渲染插值；速度上限/加速度、制动/倒车、横向摩擦、转向响应均配置化，单位按城市世界单位标注。连续碰撞检测或受限子步进避免高速穿楼；车辆车轮/底盘视觉状态服从物理姿态，不能各自独立漂移。

### 5.4 相机、输入与物理反馈

- 车辆相机归 `cameraOwner=game`，使用平滑追尾与障碍遮挡处理；鼠标 orbit 仅在暂停/退出驾驶后恢复。
- 车速可控制镜头距离/FOV 的轻微变化，reduced-motion 偏好可关闭冲击 shake/FOV 动态。
- 碰撞反馈先通过减速、短暂镜头/车身响应、HUD 提示传达；不可将随机逐帧抖动作为唯一反馈。轻微擦碰与不可通过障碍需有不同处理。
- 进入合法路肩时保留控制；异常越界后可回到最近安全路段；恢复应重置速度并给短暂免重复触发保护，不造成任务瞬移计时作弊。

## 6. 首版自由驾驶与后续挑战

### 6.1 自由驾驶

- 一辆程序化/项目自有低模车辆，视觉风格与 Agent City 协调；不得直接依赖参考仓库外链模型。
- 安全道路出生点；开放道路自由行驶；建筑、桥墩、水域和地图边界有碰撞/恢复。
- 无交通 AI、无行人、无犯罪/伤害系统；背景车在驾驶期间隐藏，退出恢复。
- 玩家可随时 Esc 暂停、R 安全复位、退出返回原视角。

### 6.2 检查点挑战（后续 V3）

- 路线从经过验证的连通道路图上生成，不通过楼内、步道、断头路或无高程桥面。
- V3 初版建议 5–8 个检查点，路口前有足够预告，避免强迫高速急转；可以固定一条验证路线起步，再扩展确定性变体。
- 检查点顺序、方向、有效路面和宽度需校验；使用连续路径/区域穿越判定，不能只靠一个低帧率点距离检测。
- 倒计时、任务时钟、暂停、超时、重赛、退出沿用现有 race mission 合约；车辆碰撞罚时是否加入，先由用户体验决定，首版推荐只做轻量复位，不叠复杂罚时规则。
- 成绩仅按 `courseId + vehiclePhysicsVersion + rulesVersion` 比较，记录最终时间与复位/碰撞数；失败不覆盖最佳成功成绩。不奖励 token、等级或虚拟货币。

## 7. 状态、存档与数据隔离

- 飞机与汽车模式互斥，一次只允许一个活动 vehicle session。进入前检测城市就绪、摄影/导出/忙碌状态。
- 复用当前游戏模式暂停来源、Tab 隐藏与恢复行为；结果面板不自动重开，退出与清理幂等。
- 使用现有插件隔离 `plugin.state`，建议新增 `vehicle-profile:v1`，或评估是否把同一游戏档案升级为包含 `vehicles` 的兼容 schema；不可因新载具覆盖旧飞机成绩。
- 只存用户偏好与有限挑战纪录，不存 session handle、提示词、工作路径、车辆行驶轨迹或真实分析数据。损坏/未知版本遵循现有档案保留与只读降级规则。
- 无授权插件端口时使用内存并标明“本次设置不保存”；浏览器预览如使用 localStorage，必须准确标明“仅保存在当前浏览器”，不可声称不持久化；不访问 authority DB，不请求任意 Rust IPC，不新增外网依赖/遥测。

## 8. 建议目录与 API 草案

实际目录以当前代码复用为准，候选新增模块：

```text
apps/agent-city/ui/src/game/
  DrivingWorld.ts            冻结路网、路面/高程/净空查询、空间索引
  DrivingSimulation.ts       固定步长车辆状态与动力学（纯逻辑）
  DrivingCollision.ts        道路边界、建筑、地形、边界扫掠
  CarVisuals.ts              车身/车轮视觉同步、资源释放
  DrivingCamera.ts           追尾相机目标与遮挡约束
  RoadCourse.ts              确定性道路路线生成与可达性校验
  RoadMission.ts             检查点进度、计时、终态
  VehicleAdapter.ts          载具生命周期接口；Flight/Car 分别实现
  DrivingHud.tsx             速度、挑战进度、简短控制提示
```

候选载具接口：`prepare(world) / reset(spawn) / step(input, dt) / snapshot() / dispose()`。所有创建的物理世界、几何、材质、监听和临时对象必须由该适配器释放；CityEngine 继续拥有 renderer 与统一帧循环。

## 9. 迭代计划

分为三个阶段：V1 为技术门槛，V2 交付自由驾驶 MVP 并完成原生 UAT，V3 为后续挑战扩展。每一阶段的证据独立记录。

### V1：道路可驾驶性与物理选型 Spike（先做，硬门槛）

- 审计 `roadNodes/roadEdges/points/width/bridge` 与实际 road mesh，统计不同 seed/scale 的连通分量、可驾驶边长度、窄路占比、端点连接误差。
- 明确道路/桥梁 surface 高度来源，制作最小 `DrivingWorld` 查询原型；验证桥面、坡道、交叉口、路缘/地形一致性。
- 在静态测试世界验证 arcade 模型；仅在不达标时比较 RaycastVehicle。不接宿主完整 UI，先测输入、操控、碰撞、帧时和包体。
- 输出决策记录：采用模型、物理参数量纲、道路契约缺口、性能基线、许可证/版本与不采用方案理由。

验收门槛以 §13 的固定夹具矩阵为准：所有标记为开放的路面和出生点必须通过验证；普通非空城市夹具至少有一个可玩连通区域。未通过则补路面契约或明确排除对应结构，不带病进入 V2。覆盖率须同时列出候选路长、开放路长及排除原因，不通过缩小分母伪造全城可驾驶。

### V2：自由驾驶垂直切片

- 加入车辆 adapter、输入、车辆相机、道路贴合、碰撞与安全复位。
- 接入既有暂停/退出/恢复/UI 状态；验证切换 Tab、失焦、resize、连续进退与 WebGL 错误。
- 完成 §12 玩家车模型，覆盖浏览器预览和合成布局；稳定后构建原生 `.app`，通过 `open` 启动完成自由驾驶 UAT，达标后才可开放正式入口。

验收：能够从安全道路出生点连续驾驶至少 5 分钟；转弯/制动/倒车可控；桥坡和路口不悬空/穿地；碰撞可恢复；退出后相机和 City 标签/回放状态恢复；重复 20 次进退没有车辆/监听/物理体累积。

### V3：检查点挑战与原生 UAT

## 12. 玩家汽车建模与视觉契约

### 12.1 现有模型的结论

`systems/ambientSystem.ts::buildCars` 当前使用 `BoxGeometry(2.5, 0.8, 1.2)` 与 `InstancedMesh` 绘制环境车，无独立车轮、车窗或灯组。可用作驾驶原型占位体；正式玩家车单独构建，不替换全城环境车，也不改动它们的实例绘制路径。

首版选择项目自有程序化低模双门敞篷跑车（珊瑚粉车身、米白双座），使用 Three.js 几何体与本地材质即可完成，不引入 GLB 下载、在线素材、外部建模服务或模型生成依赖。后续可用本地 GLB 替换，但须保持同一尺寸、坐标与动画接口。

### 12.2 尺寸与节点

以下为首轮调参起点，必须在 V1 根据路宽校准并锁定配置；世界单位不是现实米，HUD 首版显示“速度”游戏读数，不直接标为 km/h。

| 项目 | 约定 |
| --- | --- |
| 局部坐标 | +X 向前、+Y 向上、+Z 向右；heading=0 朝世界 +X；转向与 yaw 的符号以转换函数及测试锁定 |
| 根节点 | `carRoot` 原点为四轮接地面的中心；模拟与碰撞均以此为位置基准 |
| 初始包络 | 长 2.8、宽 1.4、高 1.15；轴距 1.8、轮距 1.15、轮胎半径 0.24 |
| 层级 | `carRoot → bodyPivot → chassis/cabin/windows/lights`；四个独立 `wheelSteerPivot → wheelSpinPivot → wheelMesh` |
| 转向 | 只有前轮转向，轮胎滚动按实际有符号行驶距离/轮半径计算，倒车反转；轮轴为局部 Z |
| 车身反馈 | `bodyPivot` 做有界俯仰/侧倾；轮子接地姿态与碰撞体不跟随纯视觉摇摆 |
| 细节 | 车身主色、深色车窗、轮胎与轮毂、前后灯、保险杠；提供开放座舱、双座和简化方向盘；无需开门或驾驶员 |

尺寸由一个配置源提供，渲染、碰撞和道路准入共享；不为适配窄路动态缩车。碰撞使用简化车体 OBB/凸包，不做逐三角车模碰撞。路面支撑查询采用四轮接地点，不能仅查车身中心。

### 12.3 动画和资源接口

`CarVisuals.update(state)` 接收插值后的车位、heading、路面姿态、转向角、累计滚动距离、制动和倒车状态。模型不读取键盘、不积分物理、不访问道路或业务数据。刹车灯随制动点亮；倒车灯随倒车状态点亮；首版不要求动态投射车灯。

目标预算：单辆玩家车 ≤10,000 个三角形、≤12 个新增 draw calls（正常行驶视角、主渲染通道，阴影开销另列），不使用实时反射或新增全屏后处理。材质按部件共享；自有资源在退出释放，共享资源不得重复 dispose。

验收需提供前/侧/后和跟车视角截图；检查轮胎方向、倒车滚动、四轮接地、转向轴心、灯光状态、坡面姿态和昼夜辨识度。占位盒子不得作为正式玩家车交付。

## 13. 首版实施约束与发布门槛

本节将前文候选项收敛为本轮可执行约定；任何数值均为待验证目标，不是既有实测成绩。

### 13.1 分层路面查询

建议新增共享 `RoadSurface` 数据模块，普通路面参考当前 `terrainSurfaceHeight + ROAD_SURFACE_LIFT` 的实际定义，高架参考 `expresswayDeckHeights`，桥梁从当前绘制高度提取同源剖面。优先提取纯数据采样器，避免模拟模块依赖渲染 system。

查询形态为 `sampleSupport({ x, z, previousSurfaceId, previousY, maxStep })`，返回成功或结构化失败：

- 成功包含 `surfaceId / layerId / height / normal / tangent / signedLateralOffset / usableWidth / connectedSurfaceIds`。
- 失败包含 `no-surface / outside-open-area / excessive-slope / excessive-step / insufficient-clearance / ambiguous-layer`。
- 同一 XZ 可以返回多层候选；按上一合法支撑面和显式连接选层。桥下道路与桥面即使投影相交，也不能自动切换或建立连接。出生和复位必须提供明确 surfaceId。
- 可行驶面包含经验证的路口连接区域；路口不可仅按“最近中心线”跳边。四轮支撑及车体扫掠净空验证共同决定可通行性。
- 可用宽度排除人行道/路缘，并为车辆左右各留至少 0.2 世界单位余量。路肩作为独立缓冲面校验，不计入道路准入宽度。坡度、台阶上限、转向半径在 V1 配置中固定并记录，不沿用飞机参数。
- 首版仅开放有验证结果的连通分量。未验证桥梁、高架及其入口必须有可见封闭提示和物理边界，不能显示可上桥却实际掉落；若某个 seed 无可玩区域，拒绝进入并解释原因，不偷偷换成合成城市。

### 13.2 运动、碰撞和复位规则

- 固定模拟步长沿用当前 1/60 秒、每帧最多 5 步和长帧暂停策略；渲染只插值，不补跑后台时间。
- W 向前驱动；S 在前进时先制动，持续按住且速度进入零速阈值后倒车；倒车时 W 对称地先制动再前进。W+S 同按只制动，A+D 同按回正。
- 首版无腾空/翻车模拟；车身姿态由合法支撑面拟合，高速转向限幅。不允许靠强行贴地跨越断路、陡坎或桥层。
- 静态碰撞沿移动路径扫掠，轻擦沿接触切线滑动并减速，正撞停止；不把穿透后的瞬移当普通碰撞响应。建筑占地按实际朝向生成碰撞包络，避免粗盒封死合法道路。
- 只在完整车体净空、四轮合法支撑且非碰撞状态时更新最后安全点。R 复位到该点、速度归零、清输入；失效时回出生点。候选均无效则暂停并允许退出。
- 环境车在驾驶期间隐藏，退出恢复原密度与状态，避免无碰撞装饰车穿过玩家车。环境船等无关对象不受影响。
- 首版仅允许暂停时调整跟车距离/角度；恢复前清空旧键值。相机从车辆到理想位置做遮挡查询，缩短距离，校验近裁剪面不穿墙、不入地。

### 13.3 集成和数据边界

`GameSelection` 扩展时须显式区分 vehicle 与 activity，并为原飞机调用点提供兼容迁移。共享控制器保留生命周期；驾驶与飞行各持有模拟/输入/世界/视觉适配器。首版无需实现道路挑战模块或新增成绩 schema，也不要求大规模重构飞机模块。

进入驾驶需通过现有游戏入口发布开关；飞机、驾驶、航拍、导出互斥。准备阶段取消/失败也必须释放半创建资源并归还相机。进入时冻结布局和游标，退出后再应用待更新投影，恢复应按现有生命周期契约避免旧选择引用失效建筑。

浏览器自动化使用合成/脱敏夹具；真实本机数据仅用于已授权官方内置插件的本地展示，不进入截图附件、测试日志或导出。不开新数据投影、不查询 authority DB、不记录路线或输入序列；运行期资源全部本地打包，无后台外网请求。完整原始日志、凭据、canary 仍不可访问。

### 13.4 验收矩阵与证据

V1 固定 seeds 1、7、42、2026、65537，分别覆盖 0/90/500 会话合成布局，共 15 个城市夹具；另建平路、坡道、T/十字路口、弯道、桥头和上下双层道路的专项夹具。锁定生成器版本及配置；自然城市没生成的结构由专项夹具补足。

- 所有开放路段按 ≤0.5 世界单位间隔采样中心和轮迹，所有样本支撑合法；路面查询与共享渲染表面高度误差 ≤0.05。每个声明连接均校验车体能够跨越；排除列表须可追溯。
- 所有非空城市夹具至少提供一个安全出生点和累计中心线长 ≥100 世界单位的可达区域；空城无合格道路时明确不可进入。候选道路/开放道路长度、连通分量、结构排除原因全部列出。
- 最大配置速度下不能穿楼、跨越封闭边界或在上下层间跳变；30/60/120 Hz 渲染、同固定输入步数得到一致模拟结果（浮点容差在测试中声明）。
- V2 浏览器与原生 bundle 分别连续驾驶 ≥5 分钟，覆盖转弯、刹停、倒车、坡道、撞墙和复位；20 次进入退出后无新增遗留车辆、监听或相机所有权。
- 验证准备失败/取消、失焦、输入框、隐藏/显示、窗口缩放、长帧、context lost、退出后回放与选中恢复；飞机既有 verify 脚本继续通过。
- 性能在同一机器、同一城市/相机、同 DPR/画质对照开启前后，每项至少采样 60 秒；目标模拟与查询 CPU P95 ≤2ms/帧（60Hz），总帧 CPU P95 增量 ≤4ms。报告硬件、浏览器/WebView、renderer、draw calls 和资源计数；目标未达不得宣称通过，先降复杂度复测。
- 原生启动仅通过构建后的 `.app` 并 `open`；不得直接运行 menubar 裸二进制。报告绑定源码 revision、工作树差异、夹具配置、执行命令和截图；开发入口通过不等于正式发布验收。

文档阶段只检查规格与源码对应关系。落地阶段运行 UI typecheck、build、新增 driving world/simulation/session 验证及受影响的既有飞行验证；共享道路几何提取需补跑路面/桥梁/规划相关守卫。只有实际修改 Rust 或宿主协议时再运行对应 Rust 测试和 clippy。发布前完成 bundle UAT；不通过更新 golden 掩盖失败。

### 13.5 正式出生点契约

本节把「正式出生点应在 SPEC 中明确配置」（2026-10-16 协调决策）落为可实施契约。**产品出生点与审计诊断起点是两类对象，不得混用**：`最长道路中点`只是审计诊断起点，不能成为产品出生点或道路放行依据。

**数据形状（`DrivingSpawnSpecV1`，建议落 `game/driving/spawnPoints.ts`）**：

```ts
export type DrivingSpawnSpecV1 = Readonly<{
  schemaVersion: 1;
  /** 世界身份：必须等于宿主 capture 的 worldRevision（surface+solids 的 SHA-256），随布局失效。 */
  worldRevision: string;
  spawns: ReadonlyArray<Readonly<{
    id: string;                    // 稳定标识，进成绩分组与回放日志
    x: number; z: number; heading: number;
    layerId: string;               // 显式层（地面/某高架），不接受"最近层"推断
    regionId?: string;             // 可选校验锚：region 不匹配则拒绝
    /** 车头朝向必须与该层区域中心线切向一致（±45°），防止背向来车。 */
    requireTangentAlign?: boolean;
  }>>;
}>;
```

**校验规则（进入时执行，全部通过才可用于出生）**：
1. `worldRevision` 与当前冻结世界一致；布局/建筑任何变化使旧 spawn 表整体失效，不做坐标漂移补救。
2. 每个点：整车四轮支撑合法、车身 OBB 净空（含 §13.1 侧余量与 §13.2 结构/建筑碰撞）、距任何开放边界 ≥ 2 世界单位。
3. 每个点属于至少一个开放图（§13.6）连通分量；孤立可站立点（如被断开的匝道）不得作为产品出生点。
4. 朝向校验（`requireTangentAlign` 默认 true）：与所在车道行驶方向夹角 ≤45°。

**派生与审计的关系**：每城 spawn 表由规划器从开放图**自动派生后人工/产品确认**（候选=各最大连通分量的最长直段起点、匝道合流点等），派生脚本与确认记录入库；审计诊断仍可用最长道路中点，但输出里必须标注 `diagnostic-only`。

**失败语义**：spawn 表缺失/全部校验失败 → 拒绝进入驾驶并给出原因（与 §4 流程一致），不允许静默回退到坐标猜测或合成城市。

### 13.6 道路自动通行检查与试跑

首版需具备自动验路能力：有向路网检查、整车几何/支撑检查、使用实际驾驶模拟和碰撞模块的固定步自动试跑。测试涵盖双向道路、各合法路口转向、桥头/匝道跨层、出生点到开放区域的端到端路径；禁止中心线瞬移或自动复位后算通过。

原始候选清单在自动关闭前冻结并作为覆盖分母。所有正式开放单位必须有与当前几何、障碍、车辆配置、物理/控制器和用例版本一致的三层证据；单纯跑通一条路线不能认证整城。控制器开不过去、取消、超预算或过期结果标为待验证，不直接判道路阻塞。已确认阻塞需拓扑或几何证据；版本改变旧结果失效。

本地以文字配合绿/红/黄显示已验证、已确认阻塞、待验证，并支持当前实例内定位。真实城市证据保持本地内存，不自动保存试跑轨迹或扩展 MCP/export 数据面。合成 CI 保存可复现夹具及故障注入报告。具体模块、key、覆盖、失败归因与发布门槛以 [架构设计 §11–13](CITY_DRIVING_ARCHITECTURE_SPEC.md) 为准。
