## 1. 背景与目标

Oh Agent 的定位是 **Agent Roblox**。Agent 创建 City 和游戏，人类游玩与分享。现有桌面侧栏把创作、游玩、本机用量和维护工具摆在同一层。查用量的老用户已经有顺手的路径，新用户则需要更快找到可以玩的内容和创作入口。

本期固定四个一级 Tab，顺序为 **Overview / City / Studio / 设置**。Overview 继续展示 Token，City 和 Studio 分别承担游玩与创作。六个旧页面转入二级入口，原有功能继续可达。macOS 状态栏菜单新增「打开 City」「打开 Studio」。

本期交付导航、入口和必要的页面提示。Creator Studio 内部编辑器、游戏运行时、用量计算、本地存储、迈阿密及内置游戏拆仓各自沿用现有项目计划。Market 按后续阶段推进。

## 2. 用户与关键路径

| 用户 | 场景 | 目标路径 |
| --- | --- | --- |
| 日常使用 Agent 的用户 | 想查今天用了多少 Token，或追查某个执行环境的用量 | 状态栏看摘要 → 点击今日 Token 进入用量明细，或从执行环境子菜单直接打开近期会话。工作台内从 Overview 下钻 |
| 第一次体验 Oh Agent 的玩家 | 没有本机会话数据，想先看看有什么可玩 | City → 可立即体验的内置内容 → 开始游玩 |
| 创作者 | 想让 Agent 做一个玩法，或继续已有项目 | Studio → 创建或打开项目 → 审阅已有候选版本 → 在 City 试玩 → 返回原项目 |
| 排查问题的用户 | 遇到同步异常、预算提醒或 Skill 问题 | 从现有状态栏项、通知或 Overview 提示抵达对应页面，也可从设置进入诊断工具 |
| 收到作品的玩家 | 想从朋友分享的入口进入本次体验 | 现有受支持的包或远程入口继续走各自流程。后续由作品页按兼容性提供试玩或安装 |

## 3. 一级导航与界面职责

| 顺序 | 简体中文 / 英文 | 首屏与核心动作 | 页面职责 |
| --- | --- | --- | --- |
| 1 | 总览 / Overview | 保留今日、本月 Token 等现有用量摘要，提供「查看用量明细」和可见的「进入 City」入口 | 承接近期活动、已有会话下钻、费用和预算摘要。异常时提供进入对应处理页面的入口 |
| 2 | City / City | 进入现有 City，能找到并启动至少一种随应用提供的可玩体验 | 游玩、启动已安装体验、执行从 Studio 发起的试玩，以及进入已有远程功能 |
| 3 | Studio / Studio | 打开现有创作工作台，继续项目或进入已有创建流程 | 创作、审阅、试玩、管理候选版本与发布版本。界面标签用 Studio，插件身份沿用 `creator-studio` |
| 4 | 设置 / Settings | 保留现有设置分区，增加「诊断与工具」分区 | 管理数据源、计费、预算、通知、数据、关于、MCP，以及低频维护入口 |

### 3.1 默认页面与跳转优先级

1. 从明确入口启动或唤起窗口时，进入该入口的目标。包括状态栏快捷项、会话深链、预算通知和 Studio 试玩交接。较早残留的目标不得覆盖当前操作。
2. 普通唤起已经打开的工作台时，保留当前页面。首次打开且没有明确目标时进入 Overview。
3. 二级页显示页面标题、所属一级项与返回入口。来自通知、状态栏或深链时，缺少来源页则返回所属一级项。从 Studio 发起的试玩沿用原有交接，返回对应项目和可恢复的上下文。
4. 折叠侧栏后仍可找到四个入口。中英文界面都应明确显示当前页面，键盘可操作，切换时焦点位置可预期。

### 3.2 页面反馈

| 情况 | 界面行为 |
| --- | --- |
| Overview 没有导入数据 | 显示没有可用记录，提供数据源设置。City 和 Studio 入口继续可用 |
| 数据同步失败或费用无法确认 | 展示现有状态和可执行的处理入口。保留估算与不确定性标识 |
| City 或 Studio 载入失败 | 在目标页说明失败并提供重试或返回。用户仍能切换其他 Tab |
| 旧会话或试玩目标失效 | 在对应模块说明目标不可用，并提供返回列表或原项目的入口。无法恢复上下文时提示用户重新选取 |

## 4. 旧功能迁移表

一级导航只展示四项。下表中的旧页面继续作为可访问的二级路由，优先复用现有页面和状态。

| 原 Tab | 本期常驻入口 | 继续可用的快捷路径 | 所属一级项 |
| --- | --- | --- | --- |
| Usage 用量 | Overview → 查看用量明细 | 状态栏今日 Token → 用量页 | Overview |
| Sessions 会话 | Overview → 查看会话。现有按日期、执行环境查看会话的入口继续可用 | 状态栏执行环境子菜单 → 近期会话，现有已授权的会话跳转 | Overview |
| Findings 问题发现 | 设置 → 诊断与工具 → 问题发现 | Overview 在已有数据能指出可处理的问题时显示快捷入口。已有问题处理动作继续定位到对应设置 | 设置 |
| Test 测试 | 设置 → 诊断与工具 → 测试 | Studio 的作品试玩走 Studio → City 交接 | 设置 |
| Trust 信任 | 设置 → 诊断与工具 → 信任 | 已有授权与信任流程继续可用。后续 Market 可在下载、安装或授权时复用相关能力 | 设置 |
| Skills 技能 | 设置 → 诊断与工具 → Skill 体检 | 状态栏「Skill 体检」仍直接打开 Skills 页 | 设置 |

保留 `#usage`、`#sessions`、`#findings`、`#test`、`#trust`、`#skills` 路由及已支持的查询参数。设置锚点、预算通知、状态栏近期会话和现有插件跳转都要覆盖。实现时把「显示在一级导航」与「路由有效」拆开，避免下移入口时停用旧深链。

## 5. macOS 状态栏菜单

在「打开工作台…」下方依次加入：

1. **打开 City**（Open City）→ 唤起工作台并进入 City。
2. **打开 Studio**（Open Studio）→ 唤起工作台并进入 Studio。

原有 Token、预算、月度费用、执行环境和近期会话、订阅、同步状态、打开工作台、Skill 体检、立即同步、退出，沿用现有顺序、显示条件和点击行为。打开 City 或 Studio 在窗口关闭、隐藏、已打开三种状态下都应进入正确页面，复用同一个工作台窗口。

## 6. Market 演进

| 阶段 | 前台入口 | 前置条件与验收信号 |
| --- | --- | --- |
| M1 · 官方精选 | City 内增加「发现作品」。可从迈阿密和内置游戏中选择适合展示的体验 | 有可立即试玩的内容及明确的兼容状态。先用随应用提供或已获准的内容来源验证发现到试玩的路径 |
| M2 · 创作者投稿 | Studio 提交选定的发布版本并查看审核状态，City 展示可公开的精选作品 | 作品能对应明确发布版本，具备公开素材审阅、上下架及问题处理流程。下载、安装和数据授权分别确认 |
| M3 · 独立 Market | Web 可先承接独立发现和作品页。桌面是否新增第五项另行评审 | 有持续更新的供给，回访用户会主动浏览并试玩第二个不同作品。评审时同时看作品兼容性、试玩成功率和维护成本 |

**Studio 管创作和发布版本，Market 管发现和分发，City 管游玩。** 本期侧栏保留四项。导出体验包、邀请朋友加入受限远程会话、公开上架是三个独立操作。未来上架以创作者选定的发布版本和公开素材为范围。公开分发前另行评审内容范围、权限和数据政策。通用 Web 游玩按实际支持情况展示。

## 7. 实施顺序与验收

| 优先级 | 交付项 | 验收条件 | 主要负责 |
| --- | --- | --- | --- |
| P0 | 工作台四项导航、旧页面入口和路由 | 四个标签顺序正确。六个旧页面均可通过表中常驻入口打开。日期、执行环境、会话定位与已有设置深链正常 | 桌面前端 |
| P0 | 状态栏新增 City、Studio | 两个新增入口在窗口关闭、隐藏、已打开时均能进入对应页面。现有 Token、近期会话、Skill、同步和退出行为通过回归 | 桌面 Host / QA |
| P0 | 城市体验与创作试玩路径 | 无日志的用户仍能启动内置体验。有可试玩候选版本时，从 Studio 进入 City，结束后回到对应项目 | City / Studio / QA |
| P0 | 失败状态与交互可达性 | 缺数据、同步失败、载入失败、失效目标均有可识别的反馈和下一步。检查中英文、窄窗口、折叠侧栏、键盘和返回操作 | 设计 / 桌面前端 / QA |
| P1 | 场景入口优化 | 根据任务观察调整 Overview 中 City 入口的显著性。已有可靠状态时增加对应问题提示 | 产品 / 设计 |
| 后续 | Market | 先验证精选作品的发现到试玩，再评审投稿与独立入口 | 产品 / City / Studio |

## 8. 验证目标与评审风险

建议邀请至少 5 名现有用量用户、5 名首次接触产品的用户，用前后两个版本完成相同任务。以下数字是首轮验收建议值，需要用实际观察确认。

| 指标 | 建议门槛 | 验证方式 |
| --- | --- | --- |
| 查账路径 | 5/5 现有用户能从菜单找到今日 Token 并打开用量明细，操作步数不高于现版本 | 从菜单打开前开始计操作数，记录是否误入其他页面 |
| 首次游玩 | 至少 4/5 新用户在 60 秒内从工作台打开并开始操作一个内置体验 | 使用无本机会话数据的安装，观察是否找到 City 和试玩入口 |
| 创作到试玩 | 至少 4/5 参与者无需提示完成「已有候选版本 → City 试玩 → 返回原项目」 | 使用同一候选版本，记录卡在哪一步。该指标单独测导航与交接 |
| 旧入口可达率 | 六个二级页面、两条新增菜单入口和指定旧深链全部通过验收 | 按第 4、5、7 节逐项核对 |

用可用性任务、人工计时和本地验收脚本收集结果。本期依据数据政策执行，验证过程既不新增产品联网埋点，也不上传会话或用量记录。Market 的发现、试玩、回访指标在其隐私和数据方案审定后再确定收集方式。

| 风险 | 本期处理 |
| --- | --- |
| 老用户以为功能被删 | 用量和会话保留明确的常驻入口。诊断工具集中到一个可命名的分区，同时兼容旧跳转 |
| 新用户仍把产品认成用量工具 | Overview 首屏提供可见的 City 入口，让无数据的用户也能直接试玩 |
| 快捷入口进错页或吞掉旧深链 | 分离可见导航和可达路由，覆盖窗口生命周期、通知和试玩交接 |
| Market 提前占据主导航，作品供给和试玩链路跟不上 | 先在 City 内验证精选内容。按作品供给和玩家回访决定后续入口 |

需求组织采用 PM 熊叔《需求文档规范》的场景、功能、指标与风险框架。导航的固定顺序沿用已讨论的决定。二级入口归属、默认落点规则和验证门槛为本稿给出的评审建议。
