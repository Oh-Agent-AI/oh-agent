## 1. 目标与边界

把模型自身的几何事实声明为可复用数据，减少规划、落位、修复、渲染间的口径差异。
模型声明提供检查输入，共享谓词执行检查，最终守卫验证跨对象关系。

核心原则为：**结构进类型、自洽进工厂、关系留守卫**。
类型可强制 bridge 必带锚点，但不能证明锚点在图中存在或已连上地面道路；声明占地形状，
也不能直接证明建筑不落水、不压路、不悬空。道路裁剪、设施换位和地形变化后必须重新验证。

本设计不承诺守卫数量下降或性能提升。成本包含候选数、模型参数变体、路段数及空间索引，
不能把120岛的场景检查等价替换成15行模型表检查。首批目标是正确性与可追踪性。

## 2. 声明与验证职责

| 模型可声明的事实 | 必须在场景中验证的关系 |
| --- | --- |
| 局部占地、基础接触区域、静态实体包络 | 与地形、水域、道路及其他实体的净空和支撑 |
| 入口局部坐标、朝向、接入宽度与用途 | 入口路线存在、未穿建筑且能到主网 |
| 桥面、桥台/墩包络和结构连接端 | 跨距、两岸接入、纵坡、桥头连续及通航净空 |
| 高架实体包络、部件最大运动范围 | 与障碍物冲突、桥上桥下交叉与匝道连接 |
| 楼型尺寸域、可缩放范围 | 实际参数实例是否适配当前地块 |
| 批次容量及构件数量计算规则 | 实际写入数量、显示数量和更新后的实例范围 |

声明与实例分开：声明不含地形、当前道路、用户数据或“已经可达”这样的可变结果。
检查结果绑定实例与 network/terrain/visible 版本；版本变化后不得复用旧结论。

## 3. 物理声明契约

### 3.1 局部坐标与占地

统一局部坐标：+y 向上，+z 为默认正面；长度沿用现有世界单位，不擅自等同于米。
占地在局部 x/z 平面定义，实例位置、yaw、合法缩放通过共享变换转到世界坐标。
必须与渲染矩阵方向一致，用已知朝向测试校验；实例 yaw 只应用一次。

以下类型是目标示意，尚未创建对应生产接口：

```ts
type LocalRegion =
  | { shape: "circle"; center: Vec2; radius: number }
  | { shape: "rect"; center: Vec2; width: number; depth: number }
  | { shape: "convex"; vertices: readonly Vec2[] };
type LocalFootprint = { parts: readonly LocalRegion[] }; // 扁平并集，限制部件数
type PhysicalDeclaration = {
  modelId: string;
  schemaVersion: number;
  modelRevision: string; // 显式版本或规范化内容指纹，不依赖加载顺序
  footprint: LocalFootprint;
  foundation: FoundationSpec;
  entrances: readonly EntranceSpec[];
};
```

矩形不携带实例 yaw；斜置子部件可预转换为局部凸多边形。数值必须有限，尺寸为正，
多边形无自交、凸且统一绕序；限制顶点数。非均匀缩放把圆变为椭圆，首批不支持时拒绝，
或使用保守多边形，不能继续按圆判定。

包围圆用于粗筛；确为圆形的模型可用圆终筛。复杂占地使用实际并集，不能以整体凸包填满合法空隙。
贴岸模型分开声明陆侧基础、水侧码头及允许介质，不因部分允许入水就豁免整座建筑。
地面占地、各高度段实体包络和运动包络分别建模，上层悬挑不能无条件当作地面障碍。

### 3.2 基础、接地与高度

单一 groundOffset 只能表达抬升，不能证明找平或接地。目标接口：

```ts
type FoundationSpec =
  | { kind: "ground"; support: LocalFootprint; maxRelief: number;
      maxGap: number; maxEmbed: number; baseOffset: number }
  | { kind: "piles"; supports: readonly Vec2[]; maxLegLength: number;
      allowedMedium: "land" | "water" | "both" }
  | { kind: "floating"; waterlineOffset: number; requiredDepth: number };
```

声明不赋予地形改造权限。首批地面基础不合格则换位置/拒绝；桩基或浮体启用前，
模型与渲染必须生成对应支撑，禁止仅换 kind 标签放行。

基础高度按支撑区域与共享规则求得。检查区域内部及边界，明确分辨率、误差余量与细分预算，
未能证明可接受的区域保守拒绝。容差按尺度标定、版本化，不采用未经验证的全模型0.5容差。
道路、基础及未来碰撞消费者读取同一最终地形。

### 3.3 入口与联合落位

```ts
type EntranceSpec = {
  id: string;
  local: Vec2;
  outward: Vec2; // 非零、规范化的局部方向
  width: number;
  mode: "pedestrian" | "vehicle" | "service";
  required: boolean;
  approach: LocalFootprint; // 允许进入的入口通道，不是整个建筑占地
};
```

无入口装饰可声明空列表；车站、体育场声明必要入口，港口区分陆侧货运入口与水侧停靠区域。
入口与 footprint 同批接入，不等待完整道路分层。

候选事务同时试算建筑、基础、入口通道及到主网的连接。接受后保存 ownerId 和入口连接节点，
入口通道成为预留区；附近有路不能代替入口可达。换位联合更新入口与预留，共享道路按需求引用重验。

### 3.4 道路、桥梁与高架

首批保留地面 RoadEdge、显式桥和独立 highwayRuns，通过适配器验证。
完整多层图及消费契约另立实现批，不作为建筑物理声明的前置条件。

未来结构声明须分开水平半宽、路面高度、桥面厚度与垂直净空，不能用一个 clearance 混用这些量。
结构端引用实际节点 id，坐标是几何信息而非拓扑证明。

桥头连续由最终网络检查：节点存在、接合法引道或明确设施入口、高度/切向连续。
连续桥段与海上设施尽端按结构规则处理，不机械要求每个桥段都接非桥边。
高架投影与地面路交叉不自动建路口，匝道显式验证。桥台/桥墩与船舶航道净空仍是关系检查。
规划后改路、拆边和展示裁路后重验，字段齐全不能替代检查。

### 3.5 楼型适配与实例批次分别验证

楼型声明尺寸域和缩放规则；具体参数生成实例占地后，与旋转地块及道路退界验证，
不只比较宽深范围。不合格时换楼型/地块或按明确契约聚合，保留会话映射与容量统计。
尺寸过滤属于行为变更，不能预先宣称“无行为争议”。

crownFinMesh.count 等错误与地块适配是两类问题。实例批次独立检查：

- capacity 为缓冲容量，writtenCount 为本轮写入数，visibleCount 为显示数；
  满足 0 ≤ visibleCount ≤ writtenCount ≤ capacity，连续填充时 visibleCount = writtenCount。
- 更新、生长、筛选及楼型切换重新设置有效范围，不残留旧矩阵；非连续布局使用显式映射。
- 构件计划、容量计算和编译输出一致；保留已有实例数量事故的回归测试。

## 4. 共享来源与模型一致性

现有 BuildingModel.geometry(GeometryInput) 依赖 seed/radius/sizing/siting，并有父组、
烘焙变换、anchor、实例部件及动画。不能只检查一个默认模型或未变换顶点范围。

模型注册项提供物理声明生成器，与 geometry 消费同一规范化参数。SiteSpec 引用模型 id
和选址规则，不独立复制宽深事实。未声明化模型登记迁移适配器和豁免理由。
生成、修复和终筛调用共享谓词，最终关系检查继续保留。

工厂仅作轻量自洽验证：有效数值、形状、版本、入口引用、基础规则和参数域。
工厂复制并建立深只读数据；Object.freeze 是浅冻结，使用冻结需覆盖嵌套对象与数组。
版本不依赖自增计数、Date 或加载顺序（main 上并无 nextVersion 一类机制，该表述泛指此类做法）。

较昂贵的“声明 ↔ 渲染几何”比对在构建/测试期执行：

1. 与编译器相同顺序累积 parent/bake/preShift/anchor/rot/shift 与实例矩阵，检查编译后包络。
2. 覆盖尺寸上下限、条件部件、seed 变体、缩放及动画运动范围。有限样本是回归证据，
   不冒充连续参数域证明；不能提供保守包络的变体需在实例生成时验证。
3. 区分基础、阻挡实体、装饰/光束和运动包络。现有 PartRole 是视觉语义，
   不能未经审核当物理分类；光束不应扩大实体占地。
4. 并集按部件对应验证，不用全部顶点的凸包填满空隙；记录尺度相关容差和允许突出部件。

schemaVersion 表达字段协议；modelRevision/内容指纹与形态参数共同用于缓存失效。
不影响物理的颜色修改无需强制改变 footprint。几何与声明分别记录并验证兼容性，
不能用“两个 golden 同时变化”代替包含关系检查。

### 4.5 变换唯一实现（2026-10-09 修订，批 A 门禁）

“与编译器相同顺序累积变换”不允许以**第二份实现**满足：同序复刻仍是两份代码，必然漂移，
而 yaw 双重应用正是本 spec 要拦截的事故类。硬性规则：

- `render/buildingCompiler.ts` 导出件几何构造（preShift → bake → anchor → shift）与
  件位姿（at/rot/parent 链）的唯一实现，并提供编译回调（onPart）让检查方拿到
  part ↔ 编译产物 的对应关系。
- 检查器消费编译产物（世界矩阵/包围盒）或编译器导出的同一函数；
  **在守卫或规划器里自写变换累积视为门禁失败**。
- 编译器改为消费导出函数属等价重构，由场景图基线守卫（verify-city-landmark-baseline /
  verify-city-scene-baseline）证明零视觉变化。

### 4.6 与 planner v2 / SceneSpec 的对接（2026-10-09 修订）

三份文档两条流，对接点在此钉死，避免占地事实出现第二来源：

- **planner v2（已落地）**：constraints/solve 的 measure 共享谓词在 `planner/footprint.ts`
  （地形侧）与 `models/physical.ts`（模型侧）延续同一模式；批 B 的接入点是 siting 候选
  试算与 solve measure，不新建第三套谓词。
- **CITY_ARCHITECTURE 分层**：PhysicalDeclaration 属 L1 输入（模型注册项携带，纯数据无 three）；
  SceneSpec（L3）只引用 modelId + input，不复制宽深事实；L4 渲染不消费声明
  （编译器导出的位姿纯函数除外，见 §4.5）；L5 运行时读运动包络只用于镜头/拾取避让，不改声明。
- **守卫**：verify-city-physical 按注册表驱动（同 verify-city-models 模式），
  未声明模型登记待声明清单（PHYSICAL_PENDING），条数只减不增、每批复核。

## 5. 守卫职责调整

| 检查 | 迁移后职责 |
| --- | --- |
| siteInWater / roadThroughSite | 候选/补丁先检查，最终图继续按实际占地复核 |
| 地块终筛 | 实例占地与完整道路包络，重算容量，不静默丢弃容量损失 |
| suspensionBridgeClearOfHighways | 声明提供输入，最终3D包络关系检查保留 |
| stationDoorFacesRoad / archStraddlesRoad | 共享变换与入口/开口规则，验证真实连接、宽度及高度 |
| looseInlandRoadEnds | 核实 owner/demand 与尽端用途，不能靠改标签豁免 |
| disconnectedComponents / bridgeheadContinuity | 完整规划图与实际展示图分别检查，共享节点而非坐标邻近 |
| acuteJunctions / crowdedArterials / civicPlazaCentred | 相邻及全局关系继续检查 |
| 确定性 / 跨引擎 / 车流 | 生成、消费与动态行为继续检查 |
| 声明一致性 / 实例容量 | 注册模型、参数域、运动包络及实例批次，按实际范围报告覆盖 |

旧稀疏圆采样仅作迁移对照，不是最终真值；新算法纠正旧漏检时允许解释充分的差异。
使用独立几何已知答案、故障注入和端到端守卫防共模失效。
不得因“两季度无分歧”自动撤销最终守卫；仅在覆盖和性能证据充分时合并重复检查，
保留独立回归证据。

性能报告区分声明构建、候选搜索、终筛、最终验证和缓存命中；比较同 seed/tier/参数/活动集合。
空间粗筛减少候选对，几何缓存绑定参数与世界版本。未知或失败结果不能缓存成安全。

## 6. 分批实施与门禁

| 批 | 可验收交付 | 前置与边界 |
| --- | --- | --- |
| A | 局部形状、基础、入口协议，自洽检查及模型参数/变换测试 | 首选 **arch**（并集占地带合法空洞：两墩之间是路面，凸包会误判）、**sail-opera**（+z 台阶入口 + 地面基础）、**ferris-wheel**（旋转运动包络）。车站/体育场尚为 cityPlan PublicSite + 手写造型（不在 BUILDING_MODELS），待其模型声明化后随批 B 接入；纯新增未接线时基线不变 |
| B | 两类设施占地与入口联合落位接入生产，共享生成/修复检查 | 最小安全连接器和预留，不等待 A* 或完整立体图 |
| C | 地块/普通楼型适配、实例容量契约和统计 | 按真实失败样本实施，保留全部数据映射 |
| D | 岸边/多体/动态模型，完整规划图与展示图复核 | 介质、共享入口、裁路和回放验证 |
| E | 完整 EdgeStructure 与多层消费契约 | 单独设计桥梁、车流和渲染适配；关系检查保留 |

入口在 A/B 同批。已有几何工具仅为挂点，生产调用链与参数验证通过才算实现。

新检查按 diagnostic-only → 固定缺陷样本 gating → 普查 gating 迁移，保留旧门禁。
新生产成功结果要求安全条件满足、required 入口/连接满足及容量诚实；过渡残留单列诊断，
不得把“实测违例数”直接设为安全阈值。水上部件按用途检查，不要求全模型全干。
预算耗尽显式失败或安全降级，保留旧成功场景，不放宽物理条件。

行为变更逐项审查差异后更新 golden。按涉及范围运行类型/构建、模型、几何、选址、连接、
规划/场景基线、求解/普查、展示布局及跨引擎守卫，新增检查进入实际测试入口。
视觉完成须固定 seed/tier/commit/config 的俯视及近景验收，覆盖低密度和跨河活动区。

## 7. 必测反例

- 斜置长条与局部入口经90°实例旋转，渲染与检查一致，父组/烘焙/缩放不重复应用。
- 中心干但基础落水、边界干但内部有水、基础高差超限、仅抬升造成悬空，正确拒绝。
- 并集空隙、裙房突出、圆非均匀缩放、码头部分入水，按实际用途正确判定。
- 附近只有孤立道路、入口通道被占或展示裁路切断，最终需求检查失败。
- anchors 齐全但引用缺失、桥头道路被删、桥墩堵航道、高架净空不足，仍判非法。
- 更新写入少于上次、容量耗尽、条件冠饰增减，不显示旧实例或越界写入。
- 声明嵌套数据不能被实例修改；注册顺序反转、重复输入及跨引擎仍确定。
- 候选拒绝/取消不改变正式设施、入口、道路和缓存，版本变化使旧检查结论失效。

## 8. 非目标与完成定义

- 不实现完整物理引擎，不将静态净空检查称为“物理碰撞保障”。
- 不承诺零守卫、固定15个模型或未经测量的性能收益；覆盖从注册表与迁移白名单计算。
- 优先保留渲染接口；无法准确消费结构信息时单独升级契约，不丢信息强行兼容。
- 不改变地形权限、数据隐私和离线边界，声明只消费模型参数与规划配置。

完成意味着：生产消费共享物理声明，模型事实与几何一致，入口与落位联合接受，
完整规划图和展示图关系验证有效，实例批次/容量正确，错误有显式处理与可复现证据。
声明新增、工厂断言或测试通过中的任何一项，不能单独证明整套不变量已实现。
