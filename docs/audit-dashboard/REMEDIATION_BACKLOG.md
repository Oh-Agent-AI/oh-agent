# Agent Vitals Audit — 整改问题清单

> 状态：待排期  
> 整理日期：2026-08-22  
> 依据：V1.6 PRD、`http://127.0.0.1:3080/` 的视觉审查与 UX 交互验收。  
> 范围：仅记录已验证的问题与 PRD 中需要先决策的缺口；不包含功能扩张建议。

---

## 0. 建议处理顺序

1. **先修 P0**：移动端操作可达性、JSON 导出闭环、PRD 的“3 类 / 5 类”口径冲突。
2. **再修 P1**：四张核心 KPI 的钻取交互、固定输入框遮挡、筛选与可访问性细节。
3. **最后补齐验收治理**：页面状态、性能、导出脱敏等可复现验收项。

完成 P0 后，才能重新进行移动端和导出回归验收；完成 P1/P2 后，PRD 才适合作为 V2 的唯一验收规格。

## 1. P0：必须解决

### P0-01 — 小屏 Finding 操作被裁切，无法完成审计路径

- 类型：实现缺陷 / 响应式
- 证据：在 390px 宽度下，审计内容可用宽度约 242px，且从 x=148 开始；“复制证据 / JSON / 复制 / 展开”按钮落在视口右侧之外。页面没有横向滚动条，但操作不可达。
- 影响：用户无法在手机或窄窗口查看证据、导出单条 JSON、复制或展开详情；不满足 AC-06。
- 建议动作：
  1. 在 `<= 760px` 隐藏或抽屉化执行环境侧栏，审计主内容占满视口；
  2. Finding 改为两层卡片布局；
  3. 保留“展开证据 / 添加备注”，将复制和 JSON 收入“更多”菜单；
  4. 用 320px、390px、768px 逐项验证所有可操作控件的可见与可点状态。
- 完成标准：在 320px/390px，结论、筛选、搜索、展开、备注、导出均不被裁切且无需 hover。

### P0-02 — “导出 JSON”未形成可验证的完成或失败反馈

- 类型：实现缺陷 / 交互闭环
- 证据：在本地运行页面点击“导出 JSON”后，5 秒内未产生浏览器下载事件，也没有成功或失败提示。
- 影响：复盘与留痕用户无法判断导出是否完成；FR-12 缺少可信的用户反馈。
- 建议动作：
  1. 明确导出机制（Blob 下载或执行环境下载 API）并保证可观测；
  2. 成功提示文件名与成功状态；失败时显示“导出失败，请重试”及可诊断原因；
  3. 在导出 JSON 中加入 FR-12 所列字段、估算假设、缺失字段和脱敏状态。
- 完成标准：点击后可下载合法 JSON；下载失败有可见反馈；自动化测试断言导出字段完整。

### P0-03 — PRD 对上下文构成的类别数自相矛盾

- 类型：PRD 口径冲突
- 证据：FR-04a 明确 V2 只有 3 类常驻前缀；§8、§8.1 的 V2.1 描述和 §14 仍写“粗粒度 5 类”。
- 影响：前后端、原型和验收可能各自实现不同数据结构，导致“完成”无唯一标准。
- 建议动作：统一改为：
  - **V2：3 类**——系统提示词、工具定义、技能目录；
  - **V2.1：逐工具 / 逐技能的细粒度归因**；
  - 删除所有“V2 粗粒度 5 类”的遗留文案和原型示例。
- 完成标准：PRD、数据契约、原型、测试 fixture 与页面文案均只出现同一口径。

## 2. P1：重要整改

### P1-01 — 固定 Composer 在滚动中遮挡审计内容

- 类型：实现缺陷 / 布局
- 证据：桌面端滚动至 Finding 队列中部时，底部固定输入框覆盖首行 finding 与备注入口。
- 影响：审计阅读与备注操作被打断，用户需要额外滚动才能确认内容是否被遮住。
- 建议动作：为审计滚动容器预留 `composer 高度 + 24px` 以上的底部安全区；或在审计 Tab 将 Composer 缩为不遮挡内容的紧凑状态。
- 完成标准：任意 Finding 行和行内详情滚动至底部时，均可完整显示并操作。

### P1-02 — 四张核心 KPI 缺少到二级信息的明确钻取入口

- 类型：交互完整性 / 信息架构
- 背景：费用、Token、上下文峰值、异常正是用户进入审计页最先关心的四个核心问题，**应保留四张 KPI 卡**，不应因“报告定位”而删除。
- 证据：当前 KPI 卡主要承担静态摘要；用户无法从卡片明确进入对应的费用构成、Token 趋势、上下文归因或 Finding 队列。
- 影响：用户看见数字后还需要自行猜测下一步去哪里查看原因与证据，Dashboard 的“概览 → 定位 → 解释”链路中断。
- 建议动作：
  1. 每张卡提供低权重的 `查看详情 →` / Chevron，桌面端整卡亦可点击；
  2. 费用估算 → 展开费用构成（模型、缓存/未命中、价格版本、覆盖率、估算说明）；
  3. Token 用量 → 定位会话健康时间线并切换至 `[Token]`；
  4. 上下文峰值 → 定位时间线并切换至 `[上下文]`，同时展开常驻前缀构成与计算方法；
  5. 异常 → 定位 Finding 队列，并应用“严重 / 警告”筛选；
  6. 钻取后必须有明确状态反馈（选中 chip、曲线模式、区域标题或高亮），支持再次点击恢复概览。
- 可访问性：卡片或详情入口必须有可见 hover/focus/pressed 状态，支持 Enter/Space，且用唯一可访问名称表达目标，例如“查看 Token 用量时间线”。
- 完成标准：用户可从任一 KPI 在一次点击或键盘操作内到达其二级解释；回退后保留默认概览，且移动端整卡可操作。

### P1-03 — Finding 筛选未覆盖 PRD 的最小集合

- 类型：实现与 PRD 不一致
- 证据：当前页面可见“全部 / 警告 / 提示”，未见 critical 与“有备注”筛选入口。
- 影响：存在 critical 或大量备注时，用户无法按 PRD 定义的方式缩小范围。
- 建议动作：始终渲染 `全部 / 严重 / 警告 / 提示 / 有备注` 五个 chip；0 条时禁用或显示 0，不应消失。
- 完成标准：五类 chips 均为真实 button，具 `aria-pressed`，可清除并恢复筛选状态。

### P1-04 — Finding 行操作过密且缺少唯一可访问名称

- 类型：交互 / 可访问性
- 证据：单行同时展示“复制证据、JSON、复制、展开、添加备注”；多个“添加备注”按钮使用同名可访问标签。
- 影响：桌面视觉噪声高，移动端造成裁切；屏幕阅读器难以分辨操作对象。
- 建议动作：
  - 整行点击/Enter 展开；
  - 保留“添加备注”为低权重入口；
  - 复制和 JSON 收入更多菜单；
  - 使用例如“为 SV613 T31·s2 添加个人备注”的唯一 `aria-label`。
- 完成标准：每行主操作不超过 2 个可见入口；所有行操作能明确朗读对象、动作与状态。

### P1-05 — 关键发现层的交付边界未决

- 类型：PRD 范围不清
- 证据：§6 规定有独立“关键发现（异常摘要卡）”层；当前页面主要呈现时间线、结构性浪费、子代理和 Finding 队列，未形成独立关键发现卡。
- 影响：设计、开发与验收对是否需要摘要卡没有共同结论。
- 建议动作：产品二选一：
  1. V2 保留 1–3 张关键发现卡，并定义排序和点击目标；或
  2. 从 §6 删除该层，明确由结论行和队列承担摘要职责。
- 完成标准：信息架构、页面实现与验收标准一致。

### P1-06 — 页面区块分区与扫描层级不足

- 类型：视觉层级 / 信息架构
- 证据：费用、Token、时间线、常驻前缀构成、结构性浪费、子代理和 Finding 队列大多连续使用相近的白底、文字层级和留白；在滚动中，用户不容易判断自己正处于“概览、诊断还是证据队列”。
- 影响：Dashboard 的信息路径“概览 → 定位 → 解释 → 证据”不够可扫描；Finding 队列容易与前面的空状态或补充说明视觉连在一起。
- 设计原则：不为每个模块增加重卡片、阴影或高饱和色块，保持 DSH 原生的克制感；采用轻分区而不是卡片堆叠。
- 建议动作：
  1. 使用统一的一级 Section Header（标题、可选 `查看详情 →`、低对比 1px 分隔线）；
  2. 一级区块固定为“会话资源概览”“会话健康时间线”“上下文归因与优化线索”“Finding 队列”，区块间保留 24–32px 节奏；
  3. 将“常驻前缀构成 / 结构性浪费 / 子代理”归入“上下文归因与优化线索”，内部使用 `--dsw-alias-bg-layer2` 弱背景或 8px 圆角容器，不加阴影；
  4. Finding 队列使用独立标题、数量、筛选与搜索工具栏，和前一一级区块保持至少 32px 间距；
  5. 用户从 KPI 钻取时，平滑定位目标区块，短暂高亮该区标题，并显示当前模式/筛选状态。
- 完成标准：在不阅读正文的情况下，用户可以清楚辨认四个一级区块；从任一 KPI 钻取后，用户能立刻知道已进入哪个区块及当前筛选/曲线状态。

### P1-07 — 会话健康时间线缺少完整的事件级交互

- 类型：图表交互 / 可访问性 / 响应式
- 已通过：`[上下文] / [Token] / [费用]` 三种纵轴可切换；风险事件与模型切换图例可显隐；点击事件可定位并展开对应 Finding；图表有文本摘要，事件可获得键盘焦点并通过 Enter 触发。
- 问题 1（键盘）：按方向键后，live region 更新为另一个请求的明细，但焦点仍留在原事件，对应 Finding 详情也没有切换。它实现的是请求级游标移动，不是 FR-03 要求的“在事件间移动”。
- 问题 2（Hover）：悬停事件时没有出现包含规则、严重度、turn/seq 与“点击固定”说明的事件级 tooltip；当前只可观察到请求级数据说明。
- 问题 3（小屏）：390px 下时间线仍直接渲染为约 186 × 35px 的窄图，且没有“展开时间线”入口；不符合 `<760px` 默认摘要、按需展开的 PRD 规定。
- 问题 4（未覆盖）：当前会话无法验证 compaction 标记与超过 1,000 请求点时的曲线降采样、事件保留和键盘可达性。
- 建议动作：
  1. 定义事件 roving tabindex：`← / →` 将焦点、固定态、live region 和关联 Finding 同步移动到上/下一个可见事件；
  2. 为鼠标 hover 与键盘 focus 提供相同的事件级 tooltip / 信息浮层，内容包含规则、严重度、turn、request n/m、seq 和操作提示；
  3. 小屏默认仅显示“请求数、峰值、异常数”的时间线摘要，提供明确的“展开时间线”按钮；展开后保留纵轴切换与事件列表替代路径；
  4. 增加 compaction 与 >1,000 请求点 fixture，断言降采样不丢 finding、模型切换、compaction 事件及其键盘可达性。
- 完成标准：键盘可逐事件遍历并同步展开正确 Finding；hover/focus 呈现同等事件解释；320px/390px 图表先摘要后展开；大数据 fixture 通过事件保留和性能断言。

## 3. P2：验收与规格治理

### P2-01 — FR-12、页面状态、性能和脱敏没有闭环验收项

- 类型：PRD 验收缺口
- 问题：现有 AC-01 至 AC-08 未覆盖：JSON 导出结果、加载/空/Partial/Error、剪贴板失败、无价格、500 条 finding 性能、导出脱敏。
- 建议动作：新增：
  - **AC-09 导出与复制**：下载、字段、脱敏、成功/失败反馈；
  - **AC-10 页面状态**：第 10 节每种状态均有 UI 与重试/降级断言；
  - **AC-11 性能与规模**：500 findings、1,000 请求点、超过 1,000 请求点的降采样与事件可达性；
  - **AC-12 隐私与隔离**：session 级备注隔离、无跨会话豁免、导出脱敏状态。
- 完成标准：每个 FR 都能映射到至少一个可执行 AC 或明确的非功能测试。

### P2-02 — “开发前待确认事项”中仍有发布阻塞项

- 类型：PRD 发布治理
- 未决项：价格表唯一来源、客户端 sessionId、导出是否过 redact 管道、500 条 finding 的执行环境性能约束。
- 影响：分别阻塞费用可信度、备注隔离、导出隐私和性能承诺。
- 建议动作：将第 16 节拆为“发布阻塞项”和“后续演进项”；每项增加 owner、决定日期、未解决时的降级策略。
- 完成标准：V2 发布前所有阻塞项均为已确认，或相关能力被明确移出 V2。

### P2-03 — 国际化规则应排除执行环境既有 Chrome

- 类型：PRD 表述需澄清
- 问题：§12.3 禁止无解释中英文混排，但执行环境已有 `Session log`、`Workspace Write` 等既有术语。
- 建议动作：改为“插件新增的面向用户文案必须来自 i18n；执行环境既有 UI 遵循执行环境语言策略”。
- 完成标准：插件没有硬编码混排；不会为了满足 PRD 而破坏执行环境术语一致性。

### P2-04 — 示例数据与验收 fixture 需分离

- 类型：PRD 可维护性
- 问题：PRD 包含特定真实会话数字（如 12,233 token），运行会话可呈现不同合法数值（例如 19.6K）。
- 建议动作：所有真实会话数字标明 session、采样日期和“示例/验证记录”；验收使用独立、冻结的 fixture 断言，而不是把文档样例当作页面固定值。
- 完成标准：文档示例变化不会触发产品缺陷；自动化测试有稳定输入与期望输出。

## 4. 已通过或已具备的基础能力

- Finding 搜索与 warning/info 筛选在当前会话可用。
- `[上下文] / [Token] / [费用]` 三种纵轴可切换，事件标记保持在同一请求位置。
- 时间线事件可定位并展开对应 finding；键盘 Enter 可触发事件选择，且有 live region 状态说明。
- 个人备注支持保存、删除和撤销反馈；本次测试备注已清理。
- 上下文构成已显示“约”字样，且结构性浪费未命中时有明确空状态。
- 本次本地页面检查未发现控制台 error/warn。

## 5. 回归验收建议

完成整改后，按以下顺序回归：

1. 320px、390px、768px、1280px：检查所有核心操作是否可见、可点、可键盘访问；
2. 四张 KPI：验证费用、Token、上下文峰值、异常均可钻取至正确的二级信息，并能恢复概览；目标一级区块和当前筛选/曲线状态必须清晰可见；
3. 时间线：验证三种纵轴、图例显隐、点击联动、逐事件键盘导航、hover/focus 摘要，以及小屏摘要/展开；
4. 导出成功与失败 fixture：验证 JSON、提示、脱敏与缺失字段；
5. critical / warning / info / 有备注 fixture：验证五类筛选、计数、排序与 session 隔离；
6. 有/无结构性浪费、Partial、Error、无价格、剪贴板失败 fixture：验证诚实表达、一级区块边界与降级；
7. 500 findings 与 >1,000 请求点：验证性能、降采样、所有事件保留及键盘可达性。
