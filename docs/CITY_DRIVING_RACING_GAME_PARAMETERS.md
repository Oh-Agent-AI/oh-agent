## 2. 三个仓库的精确调参数值（提取为对照参考，非实施值）

### 2.1 web-racing（Ammo RaycastVehicle，MIT）

| 参数 | 值 | 与我们的差异（标"试验起点"） |
| --- | --- | --- |
| 转向角上限 | 0.4 rad（低速）→ 0.15 rad（150 km/h 线性） | 我们 0.48 rad。外部车辆尺度/速度单位/转向模型均不同——0.45/0.40 仅为试验档 |
| 转向打入速率 | 1.5 rad/s | 我们 `steeringResponse=8` 是**指数平滑系数（1/s）**，不是 rad/s；95% 到达约 0.375s |
| 转向回正速率 | 2.0 rad/s（= 施加速率 × 1.33） | **1.33× 是候选值而非已验证最佳比例**。外部车辆的底盘/速度/转向模型不可直接迁移 |
| 悬挂刚度/阻尼 | 50 / 10 | 我们不做悬挂；`bodyPivot` 视觉俯仰/侧倾可参考量级 |
| 相机距离/高度 | 10 / 5（车长 4 → 比例 2.5 / 1.25） | 等效比例 7 / 3.5 仅为**试验起点**；城市道路视野、车速和遮挡都会影响实际取值 |
| 相机 lerp | 0.1（每帧线性插值） | 不借鉴——帧率相关；我们用 `1-exp(-k·dt)` |
| 前视距离 | 2（车长 50%） | 等效 ~1.5，试验起点 |

### 2.2 HexGL（悬浮艇，MIT）

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 漂移 lerp | 0.35 | 漂移横向分量衰减率——远期"路肩降抓地"可参考此量级 |
| 视觉滚转 | 0.6 rad（满舵） | 悬空艇非汽车，只说明范围宽，不借鉴数值 |

### 2.3 Three.js-City（街机，Apache-2.0）

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 到极速时间 | ~5s（accel = maxSpeed/5） | 这是它的设计选择；我们当前 2.36s，可做手感对照 |

## 3. 尚未实现的改进项（按修订后实施顺序）

### 第一步：相机阻尼与速度响应（方向确定，数值实驾校准）

当前 `presentDrivingCamera` 每帧硬跟（`set position + lookAt`），无平滑、无速度响应、无遮挡处理。

- **修法方向确定**：`camera.position.lerp(target, 1-exp(-k·dt))`；注视点同样平滑；遮挡射线缩短（FlightCamera 已有模式可复用）。
- **数值不定**：距离/高度/前视的实际值须实驾校准——城市道路视野、车速和遮挡均影响取值。
- **与飞机相机分策略**：汽车路径追踪相机不应照搬飞机的平滑参数；高速转弯时需验证不产生视野滞后。

### 第二步：固定路线对照测试（转向回正与加速参数同批做）

在同一测试路段上，记录以下指标并对照：

| 指标 | 测法 |
| --- | --- |
| 0→极速时间 | 固定直线，全油门，计时到 95% maxSpeed |
| 制动距离 | 巡航速度 → 全刹，记录距离 |
| 低/高速转弯半径 | 10%/90% 极速，满舵稳态，测半径 |
| 连续行驶碰撞/卡停次数 | ≥5 分钟连续驾驶，计数 |
| 帧率一致性 | 30/60/120Hz，同固定输入步数，终态误差 <1e-9 |

**转向回正实验**：比较"对称响应"与"回正更快"（1.33× 施加速率档，同时测 1.2×/1.5×）三组实测，选实测最佳；不预设结论。

**加速手感实验**：当前 2.36s 到极速。候选档：
- `acceleration=4` → 3.25s（紧凑）
- `acceleration=3` → 4.33s（舒缓）
- `acceleration=2.6` → 5.00s（最接近 Three.js-City 的设计选择）

选择标准：SPEC"休闲可控"定位 + 试驾者反馈。不预设"哪个是对的"。

**版本纪律**：任何动力学参数变化 → `DRIVING_PHYSICS_VERSION` 递增（当前 =2）；不更新体验文档了事。

### 第三步：汽车引擎音效（独立音色，纳入共享生命周期）

现有基础设施盘点（已核实）：
- `GameAudio`：背景音乐（m4a 直播），不支持效果音或车辆遥测。
- `GameSfx`：飞行音效（Web Audio 程序化合成），`SfxTelemetry = { speed, minSpeed, maxSpeed, throttleUp, throttleDown, rainIntensity }`。

**实施方案**：新建 `DrivingSfx`（或扩展 GameSfx 为多载具），引擎音色按车速连续驱动：

```
pitch = idleFloor + (max - idleFloor) × |speed|/maxSpeed
idleFloor ≈ 0.4  // 防零速无声（Three.js-City 的缺陷不照搬）
```

纳入共享游戏音频生命周期（暂停/恢复/静音跟随 runtime 相位），不启动独立 AudioContext。

### 另列：检查点淡入（属于挑战模式工作，不排自由驾驶调参）

本轮调研原文把"检查点淡入"列在自由驾驶调参里——**这是排期错误**。汽车检查点挑战任务尚未确定实现（现有 `RaceMission` 是飞行任务链路）；淡入效果应由检查点视觉组件负责（而非车模 `CarVisuals`）。移至路线挑战任务计划，待 V3 挑战模式启动时实施。

## 4. 明确不借鉴清单

- HexGL 的帧率耦合积分（每帧固定增量，无 dt 乘法）；
- web-racing 的 `lerp(target, 0.1)` 每帧常数插值；
- Three.js-City 的 `|tilt|×30` 速度项（无 dt 乘法，量纲不正确）；
- 三个仓库的相机 lookAt 硬跟；
- Three.js-City 的零速 playbackRate=0 映射（无声缺陷）；
- **跨游戏参数数值直接迁移**——所有外部数值均为试验起点。

## 5. 修订后实施顺序

1. **相机阻尼 + 速度响应**（方向确定，数值实驾校准）
2. **固定路线对照测试**（转向回正三档 + 加速三档，同时记录验收指标）
3. **汽车引擎音效**（新建独立音色，纳入共享音频生命周期）
4. **检查点淡入**（移至 V3 挑战模式，不排自由驾驶批次）
