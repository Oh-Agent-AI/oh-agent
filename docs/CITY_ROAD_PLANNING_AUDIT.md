# City 道路与用地规划审计（2026-10-06）

真机反馈：「道路很混乱，没有有机生长和规划的感觉；地标和公共建筑胡乱摆放，门前没有道路，或者方向不对。」
本文取证（用户种子 `1703294958`，2 档岛）、定位根因，并给出参照开源算法的重写方案。

![审计图](images/city-road-audit-1703294958.png)

图例：紫灰 = 街区；深灰 = 主干道；浅灰 = 支路；红线 = 桥；橙虚线 = 环线高架；
绿圈 = 公共用地、粉圈 = 地标（圈 = 预留半径）；蓝线 = 到最近道路；紫线 = 朝向（yaw）；红圈 = 锐角路口（<40°）。

## 2. 根因（`cityPlan.ts` L2 骨架）

1. **街道不是被「规划」出来的，而是网格格子的边。** 每个扇区铺一张旋转网格（`cityPlan.ts:513` 起）；
   离主干道 10、离环线 9、碰到海滨带或预留地的格子整格丢弃，剩下格子的四条边就是街道。
   所以街区边缘是锯齿、街道不会一直通到主干道，主干道两侧是一圈空地。
2. **孤岛靠「连通补丁」接回去。** 并查集找出不含核心的连通分量，每个分量拉一条最近的连接路（`cityPlan.ts:600` 附近），
   海滨大道两端也各拉一条（≤260 的「最近合法节点」）。这些补丁路不看角度、不看已有道路——
   截图里的长斜线、X 形交叉和 8° 锐角路口都来自这里。
3. **主干道先画、用地后放，二者互不避让。** 主干道是从核心放射到海边的直线；公共用地与地标只要求
   「街区格子避开它们」，主干道本身穿过预留地不受任何约束（车站中心到路 = 0）。
4. **朝向与道路无关。** 公共用地和地标的 yaw 来自岸线方向或种子（如摩天轮 = 岸线法向 + 90°），
   不是「面向门前道路」；也没有任何「给它修一条入口路」的步骤。
5. **没有生长顺序。** 整张网在最大档一次铺满，档位变化只是缩放；没有「从核心沿主干道向外长」的过程，
   所以看不出有机生长。

## 4. 重写方案（建议分 4 步，每步有守卫）

**R1 · 局部约束（先止血，改动小）**：在现有骨架上加 Parish–Müller 式 `localConstraints`，作用于所有补丁路与海滨大道连接：
交叉处切成 T 路口；端点 15 内吸附到已有节点；拒绝 <60° 的路口和 <25 的近平行段；连接路改成「垂直接到最近道路」而不是「直连最近节点」。
守卫：锐角路口 = 0、近平行主干道对 = 0。

**R2 · 用地先于路网、路网绕开用地**：主干道生成时把公共用地/地标当障碍（绕行或切到边缘），
每个用地选一条门前道路：yaw = 面向该路，并生成一条入口支路（港口 → 进港路）。
守卫：用地中心到道路 ≥ 半径；门前道路距离 ≤ 半径 + 12；朝向误差 < 5°。

**R3 · 张量场街网替换「格子边」**：参照 MapGenerator：网格场（每个城区一个主方向）+ 核心径向场 + 岸线/河流边界场混合，
先积分主干流线（间距 ~120），再积分支路（间距 ~45）；街区 = 路网平面图的面（face extraction），地块由面内递归切分。
街道连续、一直通到主干道，扇区之间平滑过渡，岸边街道顺着海岸弯。守卫：无孤岛、街区面积分布、地块全部临街。

**R4 · 生长顺序**：路段带「出生时间」（优先队列按离核心的路网距离展开），按会话时间轴揭示——
回放时城市从核心沿主干道向外长；保留现有确定性与档位缩放稳定性守卫。

R1 与 R2 可以在现有代码上直接做，预计 1–2 轮；R3 是骨架替换，需要先出一版对比图再决定是否推进。

## 4b. 规划总纲：先「城市结构」后「细节绘制」（用户 2026-10-06 第二轮反馈）

用户：「真正的城市是根据环境生长的……需要有一个综合性的算法作为指引，然后再到具体的细节绘制。」
现有 `buildPlan` 是「各画各的」：主干道放射、环线画圈、扇区铺格子、海滨带只取一段 85° 弧、用地按地理点选址——
没有一层回答「这块地是什么、为什么在这里、和旁边是什么关系」。参照的理论与论文：

| 来源 | 给我们的规则 |
|---|---|
| Lynch《城市意象》[The Image of the City](https://www.cooldavis.org/wp-content/uploads/2022/03/THE_IMAGE_OF_THE_CITY_Kevin_Lynch.pdf)（路径/边界/区域/节点/地标） | **海岸线与河岸是「边界」**，边界要被路径看见：沿岸、沿河要有连续道路；地标要立在节点（路口、广场）上并可见 |
| Lechner, Watson, Wilensky [Procedural Modeling of Land Use in Cities](https://www.researchgate.net/publication/277289480_Procedural_Modeling_of_Land_Use_in_Cities)（agent 选址） | **用地由价值场决定**：商业/酒店追逐「临水 + 交通可达 + 靠近核心」的地价高点，住宅要「离商业近、离工业远」 |
| Weber, Müller, Wonka, Gross [Interactive Geometric Simulation of 4D Cities](https://www.peterwonka.net/Publications/pdfs/2009.EG.Weber.UrbanSimulation.FinalVersion.pdf) | **生长顺序**：路网从已开发区边缘按可达性扩展，街区由路网围合，随时间填充 |
| Vanegas et al. [Procedural Generation of Parcels](https://twak.org/project/parcels/)（OBB 递归切分） | **街区形状由大地块决定**：路网围出的面（三角、扇形、梯形）再按最小外接矩形递归切成临街地块，不是统一正方形 |
| [ProbableTrain/MapGenerator](https://github.com/probabletrain/mapgenerator) 张量场 | 街道方向场：岸线/河流附近顺着边界走，核心附近放射，其余网格 |

由此得到管线（每层只读上一层的结果）：

1. **地理层**：陆地、海岸、河流、山体 → 可建性、临水距离、坡度。
2. **结构层（Lynch）**：边界道路（环岛滨海路、河岸路）+ 放射主干道 + 环线 + 节点（核心广场、桥头、主干道与滨海路交点）。
3. **价值与用地层（Lechner）**：地价 = 临水 × 可达性 × 离核心距离；海滨景观带 = 「临海 + 住宅/商业密集」的岸段（不是固定一段弧）；
   酒店/商场/景点放在价值高点与节点上；住宅（会话楼）填其余。
4. **街区层（Vanegas）**：路网围合的面 → 按面形状（三角/扇形/梯形）递归切地块，全部临街。
5. **细节层**：建筑、景观、灯光（现有渲染）。

**用户补充的组织原则（分形城市）**：每个 harness 城区类比上海的行政区（Codex≈黄浦、Claude Code≈浦东，仅作类比）。

- **分形层级**：建筑 → 小区（一组临街地块，有共享绿地/配套）→ 城区（生活 + 工作，按 harness 划分）→ 城市；
  每一层用同一套规则「从上一层的地块里切出下一层」，城市地块不够用时向外扩展边界（现有档位扩岛）。
- **区内地价场**：同一城区内地块价值不同——离区中心、主干道、水岸、地标越近价值越高。
  建筑保持区的颜色与风格一致，但**形态随地价变化**：高价值地块 → 塔楼/裙楼、更高更细；低价值 → 板楼/低层、更宽更矮；
  会话数据仍决定「是否有楼、楼多大」，地价决定「长成什么样」。
- **每区一个地标**：除全城地标外，每个城区在自己的地价最高点（区中心节点）有一座本区地标，造型取区色。

据此 S3–S5 调整为：S3 区内地价场 + 海滨景观带随用地走；S4 街区 = 路网面（三角/扇形）+ 小区层；S5 地价驱动建筑形态 + 每区地标。

小步快跑的顺序（每步截图验收）：
- **S1** 地标/用地不得压水（双子塔进河）+ **环岛滨海路**：沿整条海岸可建处一条连续道路，与海滨大道衔接。
- **S2** **河岸路**：河两岸各一条沿河道路，桥头接入。
- **S3** **海滨景观带随用地走**：沙滩、步道、大道覆盖「临海且邻近住宅/商业」的所有岸段，而非一段固定弧。
- **S4** **街区 = 路网面**：用结构层道路围出的面替换扇区格子，面内按形状切地块（三角/扇形街区出现）。
- **S5** 价值场选址：酒店、商场、地标落在价值高点与节点上。

## 5. R1 + R2 结果（2026-10-06）

![R1+R2 之后](images/city-road-audit-1703294958-after-r1r2.png)

30 个岛（10 种子 × 1/2/5 档）对比，守卫 `scripts/verify-city-planning.mjs`（已进 `verify:city`）：

| 指标 | 重写前 | R1+R2 后 | 守卫上限 |
|---|---:|---:|---:|
| 锐角路口（三路以上、夹角 <30°） | 45 | 5 | 10 |
| 被道路穿过的用地 | 196 | 3 | 8 |
| 门前无路的用地 | 10 | 2–3 | 6 |

用户种子：近平行主干道对 53 → 0；塔、车站、公园、凯旋门贴主干道且朝向误差 0°；港口/摩天轮/歌剧院有入口路。

做了什么：
- `connectToNetwork`：所有补丁路（海滨大道两端、孤立街网）垂直接入最近路段并切成 T 路口；12 内吸附到端点；
  拒绝 <60° 的中段接入、两端 <35° 的夹角、与其它道路交叉、穿水/陡坡/预留地。逐级放宽，最后才退回旧直连，保证全网连通。
- 市政广场改成环岛：主干道从半径 52 的广场环路出发，不再穿过广场。
- 内陆用地/地标贴到最近主干道一侧（边缘离路 12）并与道路对齐；岸边对象保持海岸位置，主干道到其门口为止，
  仍离路远的补一条入口支路。压到预留地的街网格子整格不生成。
- 车流折线插入被切出的 T 路口节点，仍沿真实路段行驶。

仍未解决（R3/R4）：街区仍是「旋转格子的边」，扇区之间不连续、大片空地；没有生长顺序。断头路增多（117 → ~200），
主要是用地入口支路与停在岸边用地门口的主干道，属预期。
