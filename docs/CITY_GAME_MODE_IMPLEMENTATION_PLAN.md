# Agent City 飞机游戏模式：设计与实施方案

日期：2026-10-04。状态（2026-10-08 更新）：G1–G3 已在分支 `worktree-city-game-mode` 实现——状态机/FlightWorld/相机所有权（G1.1–G1.2）、飞行/输入/追尾相机/碰撞/练习 HUD/接入（G1.3–G1.5）、确定性路线与穿环任务闭环（G2）、plugin.state 端口与档案持久化（G3.1–G3.2）均已通过对应 verify 脚本（controller/world/flight/race/profile）与浏览器冒烟；Rust `cargo test --release`、`clippy -D warnings`、`cargo tauri build --bundles app` 通过。入口仍为开发开关（`?cityGame=1` 或 `localStorage.cityGameDev=1`，经城市设置进入）；**§12 的原生 bundle 全流程 UAT（练习→挑战→暂停→成功/失败→重试→退出→切 Overview→重启看成绩）尚未执行，验收前不得默认开放入口**。本文的参数是首轮调试起点，性能数字是验收目标，不是现有测试结果。

## 1. 交付目标

在 City 插件内加入可选的飞机游戏模式：进入城市、驾驶飞机练习、完成穿环挑战、查看成绩、退出后回到原来的数据视角。沿用现有海岛与本地渲染引擎，游戏 HUD 遵循 [CITY_UX_SPEC.md](CITY_UX_SPEC.md) 的场景优先原则。

首版必须包含一架飞机、自由练习、一个任务类型（穿环竞速）、明确的暂停/重试/退出、本地最佳成绩。路线按当前城市生成，不要求只有一条写死航线。默认仍进入数据模式，游戏模式需要用户主动进入。

第二阶段再做配送任务。多人、战斗、等级树、多载具、触控/手柄、游戏过程视频录制、球面世界均不进入首版。已有航拍视频导出仍保留在数据模式。

### 1.1 与真实数据的关系

- 城市是飞行场景；会话建筑、地形和公共地标提供空间，不承担任务奖励或完成判定。
- 游戏分数不表示 Agent 效率、任务完成率或账单价值。飞过某楼不修改会话、不消除 Findings，不产生新的分析事实。
- 游戏期间使用进入时的布局快照；数据更新延后应用，避免飞行中建筑移动或升高。
- 游戏 HUD 不展示提示词、异常原文、账户标识。存档只保存玩法记录，不保存真实会话列表或航行轨迹。
- 数据为空时可在正常生成的空岛练习。若场景或投影加载失败且没有可用布局，明确提示暂不可进入，不伪造本机真实城市。

## 3. 用户流程和界面

1. 在 City 通用工具菜单选择“驾驶飞机”。进入准备面板，可选“自由练习”或“穿环挑战”，显示简短控制说明。
2. 准备布局与路线后进入安全出生点，镜头平滑切换到机后；准备过程显示加载状态，失败可退出。
3. 练习模式直接起飞；挑战模式显示 3、2、1，倒计时期间飞机和任务计时都冻结。
4. 飞向下一个高亮环，HUD 显示 `4 / 12`、剩余时间和下一目标方向。错误顺序不累计进度。
5. 完成或超时后冻结输入，展示结果、重试和退出；成绩落盘失败仍可查看结果，并显示“本次成绩尚未保存”。
6. 退出游戏恢复进入前的城市相机、标签、选择和面板状态，再按 §8 处理待更新数据。

常驻 HUD：左上任务标题/进度；右上挑战计时或“自由练习”；右下简短按键提示（熟悉后可收起，帮助入口保留）；下一目标的世界标记。宿主提供通用命令入口“暂停”“退出游戏”，插件内也有暂停入口与 Esc。

暂停面板包含继续、重新开始、操作说明、退出游戏。用户主动切 Tab 后回来仍保持暂停，需主动继续。练习不显示失败倒计时、排名或升级提示。

概念图仅用于构图与 HUD 方向，见 [游戏模式意图图](assets/city-game-mode-concept.png)。图中城市细节、水面和光照不构成本期画质交付要求，实施沿用当前资产和渲染预算。

### 3.1 输入规则

| 输入 | 首版行为 |
| --- | --- |
| W / S | 按住加速 / 减速；松开趋向巡航速度 |
| A / D | 左右转向，带有限机翼倾斜 |
| ↑ / ↓ | 爬升 / 下降；下降是 City 新增，不假称沿用原版 |
| Esc | 运行中暂停；暂停面板打开时继续；结果面板不自动重开任务 |
| 鼠标 | 操作菜单，首版不接管鼠标飞行、不要求锁定指针 |

按 `KeyboardEvent.code` 映射位置按键；组合键、输入框、contenteditable、输入法组合期间不处理游戏动作。菜单出现或焦点转到宿主时，清空按键和一次性输入队列并暂停。只有插件画布获得焦点且处于运行状态才消费方向键默认行为。所有监听可成对释放；不能复制上游未移除 blur 监听的实现。

## 4. 模块结构与现有接入点

当前 `CityEngine` 已拥有 renderer、scene、相机、OrbitControls、统一绘制循环、布局与插件 suspend/resume 监听。`photoView/restorePhotoView` 可作为视角保存参考，但不足以完整保存面板和控制器状态。`CityApp`/`CityExperience` 管理投影、回放和工具发布。以下目录和 API 均为拟新增。

```text
apps/agent-city/ui/src/game/
  types.ts                 状态、输入、路线与结果类型
  GameModeController.ts    进入/暂停/重试/退出事务与状态机
  FlightInput.ts           DOM 输入适配与焦点管理
  FlightSimulation.ts      固定步长纯运动更新
  FlightCamera.ts          追尾、镜头遮挡和视角恢复
  FlightWorld.ts           从只读布局生成地形/障碍/边界接口
  FlightCollision.ts       运动扫掠与碰撞事件
  RaceCourse.ts            确定性生成、验证、安全降级路线
  RaceMission.ts           检查点、时限、结果，纯逻辑
  FlightVisuals.ts         飞机、圆环、反馈和资源释放
  GameProfile.ts           记录合并、版本与存档端口
  GameHud.tsx              菜单、任务 HUD、结果
  game.css / gameCopy.ts   局部样式与中英文文案
```

`FlightSimulation` 和 `RaceMission` 不依赖 React、DOM、Tauri 或 Rust。`FlightWorld` 是引擎内布局的只读适配，不是第二份 authority 投影。`GameHud` 不能直接操纵相机/renderer。

渲染保持一个 renderer 和一个 rAF。游戏控制器注册到现有引擎循环，不启动第二个绘制循环，不把每帧飞机位置写入 React。HUD 按事件更新；计时显示最多 10 Hz，方向提示可用专门轻量视图更新。

拟提供：`enterGame(options)`、`pauseGame(reason)`、`resumeGame()`、`restartGame()`、`exitGame()`。进入返回可识别失败原因，退出和清理幂等。新增 `cameraOwner = orbit | cinematic | game`，同帧只能有一个所有者更新相机；游戏时禁用 OrbitControls、吸附归位和普通拾取。

## 5. 状态机与互斥

```text
data → preparing → practice
                 → countdown → racing → result
practice/countdown/racing → paused → 原状态
preparing/practice/countdown/racing/paused/result → exiting → data
准备或运行错误 → 可恢复错误面板 → 重试准备 / 退出到 data
```

暂停记录来源（user/host-hidden/focus-lost/menu/lag/context-lost）与原状态。暂停不推进飞机、检查点、倒计时或任务随机序列。恢复需重新确认焦点、清空旧键值；锁屏回来不追赶经过的真实时间。

| 当前操作 | 游戏入口与结果 |
| --- | --- |
| 实时观看 | 保存状态并进入 |
| 回放 | 保存游标及原播放状态，暂停回放；使用该游标下稳定的建筑几何 |
| 航拍中 | 游戏入口禁用并说明先结束航拍 |
| 视频导出中 | 游戏入口禁用；导出进度与取消仍可达 |
| 游戏中改种子/时间范围 | 禁用，提示退出游戏后修改 |
| 游戏中拍照/导出 | 首版不提供；不会把游戏相机误送入原航拍导出 |
| 重复进入/退出命令 | 合并或无操作，不创建第二实例，不重复保存结果 |

## 6. 飞行与相机设计

### 6.1 空间与参数

使用城市右手坐标：Y 向上，XZ 为地面。状态为 position、heading、speed、verticalSpeed、bank；倾斜主要为视觉，不引入失速或升力仿真。

以布局包围盒对角线 `D` 为尺度参考，城市单位不标作真实米。首轮参数：巡航速度约 `D/35` 每秒，最小 `0.4×巡航`、最大 `1.8×巡航`；从巡航到最大约 1.5 秒，转向最大约 0.9 rad/s，转向平滑约 8/s，机翼倾斜上限 25°。飞机半径、圆环、镜头距离按 D 和建筑分布共同确定并限制极值，写入同一版本化配置。

参数必须用 0/1/90/500 会话与不同种子试飞。不能把上游球半径约 5 的速度直接搬入城市。难度首版固定“休闲”，不动态更改挑战中途速度。

### 6.2 时间步长

物理以 1/60 秒固定步长推进，画面按渲染帧插值。每帧最多处理 5 个物理步；超过可处理积压或单帧间隔超过 250 ms 时进入 `paused:lag`，清空积压，提示继续。物理和赛事计时共用同一模拟时钟，禁止一方丢步、一方仍按墙钟倒计时。

倒计时使用模拟时钟；浏览器刷新率变化不改变比赛规则。相机平滑使用 `1-exp(-k*dt)`；避免把插值系数写死为每帧常量。

### 6.3 碰撞与边界

从实际布局导出楼体、桥梁、重要地标的保守碰撞盒以及地形高度查询；使用空间网格加速。动态车、鸟和船首版为装饰，不参与碰撞。必须覆盖高楼，不能只用地形高度防穿地。

飞机用包围球/胶囊近似，对前后位置做扫掠检测，不只检测当前点。地形按段步进检查，步距由飞机半径与高度场采样精度约束。相机到飞机做遮挡检测，缩短距离或抬高以避免钻楼。

碰撞采用温和重置：返回最近安全点、减速、短反馈。挑战每次有效碰撞罚时 3 秒，并有 1 秒恢复保护防止同一接触连续扣罚；保护期仍保持不穿模，不跳过检查点。没有有效安全点则返回起点，任务进度按最近通过的检查点保持。

软边界提前提示返航，硬边界触发安全重置；水平范围由布局外扩，垂直范围由地形和建筑高度推导。出生点和每个重置点需有相机净空。任何路线无安全点时拒绝开始挑战，提供自由练习或重新生成路线。

## 7. 穿环任务

### 7.1 路线生成

输入：`layoutSnapshot、citySeed、courseVersion、physicsVersion、variant`。同样输入产生相同路线；重试复用原路线。显式“新路线”才更新 variant。

优先沿港口、海面和城市外围形成宽弧线，逐步加入桥上方/城区上方片段；首版不设计狭窄桥洞穿越。12 个检查点是默认目标，包含终点。

生成流程：候选路径→平滑曲线→按弧长放环→高度净空校正→转弯/爬升/障碍验证→完整安全走廊验证。转弯半径至少满足配置速度下 `r = v / ω` 的约束，环间距保证在最大速度下有可见反应时间；环面法线沿路径切线。

固定最多 8 次候选尝试，失败后使用海面上方的宽弧形降级路线。降级也必须通过同一验证，不能通过“忽略障碍”强行成功。空岛允许生成同样规则的练习路线。

限时按路线长度、参考速度及爬升/转弯预算计算，以参考飞行时间的 1.6 倍作为初始值。生成器把参考时长限制在适合约 45–90 秒挑战的范围；不保证不同尺寸城市都能固定 45 秒完成。边界参数在 G2 试飞后锁定版本。

### 7.2 判定与得分

对当前目标，检查前后位置是否按指定方向跨过环面，交点是否在扣除飞机安全半径的圆内；掠过外圈、反向进入和跳过顺序不算。一个步长跨越多个相邻环时按相交时间排序处理，避免帧率影响进度。暂停、重置产生的瞬移不参与穿环检测。

成绩字段：是否完成、模拟耗时、碰撞次数、罚时、最终用时（模拟耗时+罚时）。完成后只比较同一路线和相同物理版本的最佳最终用时；并列时碰撞更少者优先。超时按模拟耗时+罚时判定，失败不覆盖成功最佳成绩。

每次任务使用唯一 runId；成功/失败进入终态后只能结算一次。最后一环与超时发生在同一步时，以步内交点时间与截止时间比较，截止时刻及之前完成算成功。

### 7.3 反馈

仅下一目标明显发光，其后少量环渐弱显示。通过时短促碎光/轻音效、进度加一；首版不自动加速或翻滚，保证初学者可控。声音可关闭，失败/成功不能只依赖声音或颜色。默认轻反馈，reduced-motion 下禁镜头震动与大幅 FOV 变化。

## 8. 布局快照与退出恢复

进入保存 `ReturnState`：相机位置、up、target、FOV、OrbitControls 参数、回放游标/播放状态、选择的 opaque handle、标签和面板状态。取消未完成的相机 tween；快照冻结真实几何在进入时的显示高度，不复制整个 renderer 或纹理。

游戏运行时允许原有环境装饰更新，但地形、建筑碰撞体、任务目标位置不变。投影失效只保留最新 revision/待刷新标记，不无限缓存全部新 DTO。

退出顺序：停止输入与模拟→移除游戏对象/监听/资源→归还相机所有权→恢复 ReturnState→触发一次最新投影刷新。若旧建筑已不存在，清除其选择并说明；若种子/布局已经失效，回到总览并明确提示，不能恢复悬空详情。原来播放中的回放先恢复暂停游标，避免退出时立即跳动画面。

插件失败或 WebGL context lost：冻结任务和输入，不发放成绩；宿主重试后回到数据模式，不恢复半局。resize 仅更新视口和相机 aspect，不重新生成路线或实例。

## 9. 本地存档与协议

当前原生插件使用 `incognito(true)`，不能假定浏览器 localStorage 足以跨重启保存。首版应有明确的存档端口，而非直接照抄上游 localStorage。

拟增加通用、按插件隔离的 `plugin.state.read/write` 方法，通过现有 SDK 信封和原生实例检查；描述表声明允许的 `flight-profile:v1` key。方法名及字段需在实施期同步 SDK 契约；此处为待实现接口，不是现有 API。Rust 只提供有界本地 JSON 存储，不实现飞机/任务规则。

存储位于应用私有数据目录的 `plugins/<registered-id>/state/`，路径由宿主生成，插件不能传路径。单文档上限 32 KiB，读写带 revision 做乐观并发检查，写入临时文件后原子替换；文件操作不得阻塞原生 UI 线程。访问和返回都校验当前授权实例，游戏档案不写 authority DB。

拟定档案：

```ts
type FlightProfileV1 = {
  schemaVersion: 1;
  tutorialSeen: boolean;
  preferences: { muted: boolean; reducedCameraMotion: boolean };
  records: Array<{
    courseId: string; // 城市种子、无业务标识几何摘要、路线/物理版本的组合摘要
    bestTimeMs: number;
    collisions: number;
  }>;
};
```

最多保留 20 个路线成绩，超额淘汰最旧访问记录（顺序由数组表示）。不保存 session handle、提示词、工作路径或任务轨迹。读取时验证有限数值与版本；损坏保留可恢复副本并启用空档案，未知新版本只读降级，不能静默覆盖。

浏览器预览实现相同端口，可使用该预览 origin 的有界 localStorage，失败退到内存并显示“成绩仅本次保留”；只使用合成场景。保存发生在设置改变和比赛结算时，不逐帧写入。保存失败可重试，退出无需等待无限 I/O。

## 10. 性能与隔离预算

首轮目标：游戏新增 CPU 更新 P95 ≤2 ms/帧，新增 draw call ≤20，额外资源 ≤32 MiB；在同设备/种子/画质/视角的现有城市基线上，新增模式帧时间增量 P95 ≤4 ms。以上均须测量，失败后降低环/特效复杂度或画质，不能当作已兑现指标。

至少覆盖省电画质的 30 FPS 目标和正常画质的 60 FPS 目标，记录设备、分辨率、DPR、会话数及实际结果。追尾近景可能增加可见几何，不得把固定视角的低开销结果直接用于飞行。

隐藏 Tab 时停止模拟与游戏动画，保留轻量状态；切回需用户继续。20 次进入/退出后游戏 Mesh、监听、任务实例归零，renderer 保留；以对象计数和内存趋势检查泄漏，不能仅要求 GC 后字节完全相等。

游戏代码留在 City 插件，宿主只增加通用状态能力和通用命令呈现。游戏异常通过插件错误路径恢复，不拖住宿主 Overview。游戏内环境与结果均离线，不迁入上游服务。

## 11. 三个迭代与工作包

### G1：飞得起来，退得出去

- G1.1 定义相机所有权、ReturnState、模式互斥；接入 CityApp 与 CityExperience。
- G1.2 提取 FlightWorld 的地形/障碍/边界接口，生成安全出生点。
- G1.3 实现固定步长运动、输入、追尾与基础碰撞恢复。
- G1.4 加入程序化飞机、练习 HUD、暂停与退出。
- G1.5 验证原生/iframe 的焦点、Tab 隐藏、窗口 resize、重复进入退出。

交付：可在当前城市自由练习，键盘失焦不粘键，退出恢复视角；原 City 回放/航拍/导出可继续使用。阶段内入口保持开发开关，未验收不默认发布。

### G2：完整任务闭环

- G2.1 实现有界确定性路线生成、校验和降级。
- G2.2 实现倒计时、连续穿环检测、任务终态、碰撞罚时和重试。
- G2.3 完成最小任务 HUD、方向提示、中英文、结果页与无声反馈。
- G2.4 用固定种子和高低帧率测试可达性，再实际试飞校准难度。

交付：一个完整穿环挑战；相同路线可重试；失败可恢复；每局只结算一次。成绩此阶段可先驻内存，不标注跨重启保存。

### G3：存档与第一版发布验收

- G3.1 增加通用状态端口、描述表能力、原生持久化与预览适配。
- G3.2 接入版本化档案、最佳成绩、存储故障与冲突恢复。
- G3.3 完成资源清理、性能分析、布局更新冻结和退出后刷新。
- G3.4 打包安装真实 macOS bundle，执行完整 UAT，保留录像/截图、日志与二进制标识。

交付：重启 App 后成绩仍在，Overview 正常；首版游戏入口开放。各迭代独立提交、可回退；进度以验收证据为准，不承诺未经验证的人日估算。

依赖关系：G1 控制/空间契约先稳定，G2 使用其版本生成路线；G3 存档仅保存 G2 的稳定结果。极简 HUD 的完整重构可以继续独立推进，首版游戏不依赖全部 U1–U3 完成，但必须有通用模式入口、暂停和退出。

## 12. 测试与验收

| 类别 | 必测场景 | 通过条件 |
| --- | --- | --- |
| 运动 | 相同输入轨迹，30/60/120 Hz 渲染、固定物理步 | 模拟位置/方向在容差内一致；无 NaN、越界和粘键 |
| 路线 | 20 固定种子 × 0/1/90/500 会话布局 | 输出有效路线或明确不可用；无无限重试；安全走廊通过验证 |
| 穿环 | 高速跨越、反向、擦边、越序、同一步多环、重置瞬移 | 按规则判定，终态只触发一次 |
| 计时 | 暂停/锁屏/Tab 隐藏/长帧/最后一环临界时刻 | 不偷跑、不追赶墙钟，不产生双重结算 |
| 互斥 | 回放进入、航拍/导出中请求进入、重复命令 | 按 §5 一致处理；返回数据视角与功能正常 |
| 数据刷新 | 飞行时新增/删除会话、退出后刷新 | 局内布局不变，退出后最新数据恢复，过期选择清除 |
| 存档 | 重启、损坏、新版本、写失败、revision 冲突 | 可理解降级，已知成绩不被旧状态静默覆盖 |
| 容器 | iframe + 原生 WebView | 相同任务规则；焦点、事件、生命周期分别通过 |
| 布局 | 640×480、760×560、1100×760，侧栏开关，中英文 | 退出可见、任务 HUD 不重叠、不盖宿主导航 |
| 资源 | 连续练习 10 分钟、20 次进入退出 | 无增长性对象泄漏，CPU/GPU 达到已记录预算 |
| 绘制 | 侧栏切换、连续 resize、恢复窗口 | 动作期间帧证据；落点截图不能判定闪烁消失 |

测试位置建议：`game/` 旁的纯逻辑测试，以及现有 scripts 中增加一个游戏行为验证入口；测试应验证任务规则与状态转移，不靠匹配源代码字符串宣称功能通过。

原生 UAT 走 `.app` bundle，通过 Computer Use 完成练习→挑战→暂停→继续→成功/失败→重试→退出→切 Overview→重启看成绩。记录源码 commit（含未提交差异）、bundle SHA、配置、设备、帧率证据及未覆盖项。现有瞬时闪白为独立已知问题，游戏完成报告不得悄悄标记为已解决。

原生验收包可用 `AGENT_VITALS_CITY_GAME_UAT=1 cargo tauri build --bundles app` 显式开启城市设置中的开发游戏入口（构建环境变量由 City Vite 编译为常量）。普通构建默认为关闭；证据必须注明该构建开关。浏览器的 `?cityGame=1` / `localStorage.cityGameDev=1` 入口继续有效。

## 13. 第二阶段：配送与成长

首版通过后，基于相同 FlightWorld 增加 `DeliveryMission`：在公共地标领取虚拟包裹，携带飞往另一个公共地标，在交付范围内保持低速一段时间完成。地标不可达时重新生成；不使用真实任务文本生成 NPC 对话。

成长先考虑外观奖励、路线解锁和个人记录。若加入升级速度，路线成绩须按物理配置分组，否则不公平且难以比较。暂不迁入月球危机、彩弹敌怪、火焰收集、多载具解锁或联网排行。

## 14. 完成定义

用户能主动进入游戏、控制飞机、理解并完成一次任务、暂停与重试、重启后查看成绩，并可靠地回到原有 City/Overview 工作流程。上述功能、原生验收与存档都完成，才称“游戏模式第一版完成”；概念图、源码模块存在或仅浏览器通过均不充分。
