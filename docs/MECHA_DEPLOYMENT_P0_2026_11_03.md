# PvE 开局部署 P0：实施与验收（2026-11-03）

## 范围

实现本地城市 PvE 的「选战场 → 布阵 → 确认 → 第一回合」闭环。
依据主 checkout 的 `docs/MECHA_GAMEPLAY_UPGRADE_PLAN_2026_11_02.md` §5.6；该用户文档保持只读。
本轮不是 PvP 部署或远程部署协议实现，不能将本地/序列化测试称为远程重连验收。

## 权威规则

- `Phase` 增加 `deployment`，`MatchState.deployment` 保存声明的部署区和预留增援格。
- `DeployPlan` 携带 revision 和三台机甲的完整 placements。
- `validateDeployPlan` / `applyDeployPlan` 是纯规则边界，经 `pveRules.deploy` 暴露。
- 验证阶段、整数 revision、完整且唯一的三台机甲、整数棋盘坐标、部署区、安全地形及占位。
- 水面、山地、采样过陡格、建筑所有占格、掩体、障碍、活 Boss footprint、活 raider、预留增援格均不能部署；不同机甲不能共用一格。
- 安全格少于三格时明确拒绝，不临时扩大部署区。
- 拒绝不修改输入 state/plan；成功克隆 state、写入三台位置，再执行 `bossPrepare()`。
- 部署是一个原子指令：对外 revision 恰好 +1；确认前没有首回合敌意，普通行动/提交/自动战斗不能推进部署阶段。
- 保留既有确认后可编辑的开局行动建议。建议规划器失败时降级为空白草稿并提示，不阻塞已被权威接受的部署。

## 初始化与兼容

- 城市 `createMechaController({ site })` 默认进入 deployment，重新开局也回到 deployment。
- 普通城市生成器采用声明的后排区域：至少最后两行；若生成器原始出生点更靠前，初始化时纳入该行（正常生成器限定后四行）。这不是因可用格不足而扩区。
- 底层 `createMatch()` 默认保留旧 enemy_prepare 行为，已有直接规则 fixtures 和未开放部署的 PvP/远程入口不被静默改写。
- 显式 `createMatch({ deployment: true, deployZone, reservedDeployCells })` 可用于测试或未来权威地图声明。
- 部署期间权威机甲保留初始化位置占位字段以兼容 `Mech.pos` 类型，但不能参与战斗推进；显示和格子检查只使用已放置的部署草稿，不显示未放置机甲或占位位置。

## UI 与交互

- 左侧原有队伍区显示 0/3–3/3、当前机甲、未放置/坐标、确认、撤销和重置。当前机甲复用常态队伍的蓝色选中边框、背景及 inset 标记，并保留 aria-pressed。
- 棋盘绿色矩形表示合法部署格；部署图例只解释部署区，不显示虚假的「风险未知」或敌方攻击预告。
- 直接棋盘点击或坐标列表均可放置。已放置两台可交换位置，一次撤销恢复交换前状态；未放置机甲不能挤走已放置者。
- 重置部署可以撤销，不消耗正常回合的单次重置机会。
- 只有完整合法方案才能确认。非法位置有明确原因，保持已有草稿；错误文案随当前语言切换。
- 沿用左下设定稿大头像和单位信息；放置后对应格子检查从地面更新为该机甲。
- 首次放置直接显现于落点；修改已放置位置保留现有快速滑步和行走动画。
- 窄屏部署/正常行动面板固定于底部独立滚动区，避免盖住队伍选择和结束回合按钮。
- 不改动既有约 45° 相机、棋盘材质/图层分层或 Assault 快速路线播放策略。

## 2026-11-03 补充：主机单独离线时的恢复体验

- 手机到中继的 WebSocket 仍在线、但电脑主机断开时，远程页面不再把局面简单描述为「在线」。同步期间暂停棋盘操作，显示中继已连通、电脑端不可用及自动重试提示；顶栏提供「重新同步」。中英文均有提示。
- `host_offline`、`unavailable` 和网络异常触发快照重试，间隔从 1 秒倍增至最多 15 秒；中继连接离线时暂停，重连后恢复；成功快照、有效替换、关闭或销毁会取消待执行重试。其他协议/授权类错误不自动循环重试。部署遇到不确定结果时保留原命令以便幂等重试；普通回合和认输的异常也会触发权威快照同步。

## 2026-11-03 补充：远程行动提交不确定性的局部保护

- PvE 转 PvP 仍复用同一个 matchId，但新 session 的 revision 取切换前的 revision 加一；接近安全整数上限时拒绝切换，避免溢出及无可用后续版本。独立创建的 PvP 初始 revision 不变。这阻止旧 PvE `plan.submit` 延迟到达后在新 PvP session 中因版本重置而被执行。

## 2026-11-03 补充：同标签页刷新后的保守待确认锁
