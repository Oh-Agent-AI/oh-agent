# Agent City：数据可读性回归修复 SPEC（2026-10-05）

状态：批次 1–3 已实现（2026-10-05）；F6 的「提高上限/恢复分页」与 F7 的「稳定键重构」留作后续（见各节「实现注」）。基线：`main` @ `c035cf9d`（城市已拆为独立包 `apps/agent-city/ui/`，VICE 海滨批次、场景优先 HUD、后台导出 worker 均已合入）。
范围：规划层的「背景楼」策略、回放叙事、会话载入上限、视频导出兼容性、i18n 键。**不改** seed→地形、街网骨架、城区楔形、配套/花园/地标选址、VICE 海滨带与 Art Deco 造型。

## 1. 背景：两版设计的取舍

Agent City 的核心承诺（`CITY_MODULE.md`、`CITY_PLANNING_SPEC.md`）是 **城市即数据**：

- 每栋可见楼 = 一个会话；楼高 = token 规模；施工态 = 活跃会话；
- 空地 = 增长余量——回放时城市从规划空地上长出来；
- 城区 = 执行环境（host），四个色相楔形围绕核心，一眼可分。

VICE 批次（`CITY_VICE_THEME_SPEC.md`）的目标是「迈阿密是一座已建成的城市，即使会话很少也不该退化成空白规划图」。为此 `cityLayout.ts:254–318` 新增 **背景楼（contextBuildings）**：

```ts
// cityLayout.ts:258–280（摘要）
if (coastal?.profile === "miami-coastal") {           // CityEngine.ts:448 恒传 MIAMI_COASTAL —— 始终开启
  candidates = 所有未占用、可建、避开高架/海滨带的地块
    .rank(min(到最近会话楼距离, 到核心距离×0.85) + 抖动)   // 优先贴着会话城区填
  target = min(280, 224 + (tier-1)·24)                // 224–280 栋
}
```

`cityParts.ts:1846` 明确：背景楼「无会话 id、无标签、不可点、**无生长**、不计入 HUD」。

两个目标都合理，但现在的实现让第二个目标压过了第一个。

## 2. 问题（代码层可证实）

| # | 现象 | 代码依据 | 对核心承诺的影响 |
| --- | --- | --- | --- |
| P1 | 城区边界被填平 | 候选按「离会话楼最近」排序，224–280 栋优先塞进城区之间与城区边缘的空地块 | 四个 host 楔形之间的街道/花园/空地间隔被粉彩楼占满，host 分区读不出来 |
| P2 | 回放失去「从空地长出」的叙事 | 背景楼无生长（`cityParts.ts:1846`），回放第一帧即全部矗立 | 拖到窗口起点时城市仍「建成」，会话楼的生长淹没在背景里 |

## 3. 目标与非目标

**目标**
1. 恢复「城市即数据」的可读性：host 楔形可分、回放从空地长出、楼量随数据增减。
2. 保留 VICE 的「已建成都市」氛围，但把它放在**数据不说话的地方**（远景、城区外、海滨酒店带），而不是数据之间。
3. 视频导出在无 H.264 的环境仍可用。
4. 载入上限有唯一真相源，文案与代码一致。

**非目标**
- 不删除 VICE 海滨带、Ocean Drive 酒店排、Art Deco 造型与配色。
- 不改 seed→地形→街网→城区→地块的确定性契约（`verify-react-city-layout/geography` 守卫照旧）。
- 不改后台导出 worker 架构。

## 4. 方案

### F1 背景楼「让位」规则（解决 P1、P3）

在 `cityLayout.ts` 背景楼候选过滤中新增三条硬约束：

1. **城区保留带**：地块到任一会话楼的距离 < `DISTRICT_KEEP_OUT`（建议 = 该城区半径 × 0.35，最少 60）的不入选——城区之间的间隔与花园周边保持原样。
2. **楔形缝隙**：两个城区楔形之间的扇形缝隙（`cityLayout` 已有楔形角度）整体不入选。
3. **数量随数据缩放**：`target = clamp(round(sessions × 0.35), 0, 224 + (tier−1)·24)`。会话少 → 背景少；不再「至少 224」。保留一个下限开关（见 F4）给「空城不好看」的场景。

排序改为 **离核心/海滨带近优先、离会话楼远优先**（与现在相反）：背景楼承担「远景都市 / 海滨天际线」，不贴着数据。

### F2 背景楼参与回放（解决 P2）

背景楼获得一个确定性的「落成时刻」：按 `rank` 均匀映射到数据窗口 `[windowStart, windowEnd]`，与会话楼共用 `applyConstruction` 的生长插值（只需在 `buildUrbanContext` 里把实例矩阵写入改为按 `cursor` 更新，复用 `writeCivic` 的 y 缩放方式）。

效果：回放起点只有地形/街网/海滨带，城市随时间「填满」；现在（live）画面与当前一致。

### F3 视觉区分（解决 P4）

背景楼统一降饱和、略低明度（色板取各 zone 当前色 × 0.75 饱和度），夜间窗灯密度降为会话楼的 40%；会话楼保持 host 色相与屋顶霓虹。目标：远看仍是统一的迈阿密天际线，近看一眼分出「我的楼」。

### F4 设置开关

城市设置对话框新增「城市背景楼」：`自动（默认，F1 规则）` / `关闭（纯数据城市）` / `繁华（当前行为）`。导出 worker 通过 `FilmJob.backdrop` 使用同一档位，拍照取屏幕当前状态。

实现注：档位暂存本机浏览器存储（`localStorage["city.backdrop"]`），**不**经宿主 `city-settings` 投影——种子走那条路需要宿主（Rust）侧同步改动；换机/换浏览器档位回到「自动」。若要跨设备持久化，另开宿主侧任务。

### F5 视频导出回退（解决 P5）

`CityEngine.ts:931` 的候选列表在 H.264 之后追加 `vp09.00.10.08`、`vp8`，命中时走 WebM 封装（旧版 `webmMuxer.ts` 已在 git 历史 `8092fa79`，可直接恢复）。文件扩展名按实际封装决定；UI 文案「不会生成改名的 WebM 文件」改为「将导出 WebM」。worker 路径与主线程路径同一份编码器选择函数。

### F6 载入上限单一真相源（解决 P6）

- 查明实际截断点（`LOAD_CAP = 4_500` vs 文案 500，可能在宿主 IPC 侧另有限制）。
- 文案改为由常量插值生成，不再写死数字；`verify-react-city-data.mjs` 增加断言：文案数字 == 生效上限。
- 若生效上限确为 500：恢复旧版「366 天窗口、旧→新分页懒加载直到 `LOAD_CAP`」（`aa8643ab`）。

实现注（F5）：候选编码器在 H.264 之后追加 VP9 → VP8，命中时走 `webmMuxer.ts::WebmFilmWriter`（从 `8092fa79` 恢复的封装器 + 与 `Mp4Writer` 同接口的适配层）；文件名与 MIME 随实际容器（`.webm`/`video/webm`），界面写明「不支持时改为 WebM」——不改名、不伪装。错误码 `mp4_encoder_unavailable` → `video_encoder_unavailable`（三种编码器都不可用时）。

实现注（F6）：查明真相源是宿主 `crates/agent-vitals-query/src/query/app_local.rs::SESSION_CAP = 500`（按最近活动倒序 LIMIT）；UI 显示宿主回报的 `coverage.returned/total`，与真实截断一致。矛盾来自 `cityModel.ts` 里从未被引用的 `LOAD_CAP = 4_500` 和一条无人使用的「最多 500 条」目录文案——两者已删除。**提高 500 上限或恢复按时间窗口分页需要宿主（Rust）与 `city:v2` 协议改动**，不在本次范围，另开任务。

### F7 i18n 键（解决 P7）

`i18n.tsx` 改为稳定键（`city.backdrop.note` 等）→ `{ zh, en }`；新增守卫：所有 `t(...)` 调用的键在两种语言都存在（复用 `verify-react-i18n-billing.mjs` 的检查方式）。

实现注（F7）：先落守卫 `scripts/verify-city-i18n-catalog.mjs`——抽出 `.tsx` 里所有含中文的字面量与 JSX 文本，逐条要求英文目录有对应（或被 `cityText` 的替换链/就地三元覆盖）。它立刻抓到了本次 F5 修改导出说明时英文失配的真实回归。全量改成稳定键（`city.backdrop.note` → `{zh,en}`）牵涉全部 UI 文案，留作后续重构；守卫已消除「静默丢失」这一风险本身。

## 5. 不变契约

- 布局确定性、刷新不搬家、输入顺序无关（`verify-react-city-layout.mjs`）。
- 胶片导出可复现：F2 的背景楼生长只依赖 `cursor` 与哈希；F5 的编码器选择不影响渲染帧。
- 会话楼的选址、楼高、施工态逻辑不变。

## 6. 验收

1. **同 seed 对照照片**（拍照功能 `capturePhoto`，1280×720，正午/黄昏/夜，总览 + 城区边界 + 海滨三机位），`关闭 / 自动 / 繁华` 三档各一组，评审 P1/P3/P4。
2. **回放**：游标在窗口起点 15% / 55% / 100% 各一张总览，起点画面背景楼 ≤ 10%。
3. **楼量**：自动档背景楼数 ≤ round(会话数 × 0.35)，且离会话楼 ≥ 60。实测 3 / 50 / 700 会话 → 1 / 18 / 42（700 会话时空地块多在会话楼 60 以内，保留带生效，远低于上限 245——这是预期，不是缺陷）。「繁华」档 3 会话仍为 190（守卫钉住原行为）。
4. **导出**：强制禁用 H.264（测试钩子）时导出得到可播放 WebM；正常环境仍是 MP4。
5. **守卫**：tsc、`verify-react-city-*` 全绿；新增文案上限一致性、i18n 键完整性两条断言。
