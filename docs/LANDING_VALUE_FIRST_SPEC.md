## 0.5 v1.3 优化（2026-10-01，待评审；不改动 §1 不可变决策）

> 来源：对 `website/landing` 现状的复查 + 对外部概念稿
> （`agent-vitals-runtime.gold3bear.chatgpt.site`）的对标。概念稿的钩子更抓人，
> 但其「实时 / 干预 / 健康评分 / 进度百分比 / 上下文衰减」我们均不产出，
> **只借叙事结构，不借承诺**（与 §1.2、§5、§10 一致）。

### A. 先修的回归（P0，早于任何文案工作）

1. **`app.js` 被 i18n 提交误删**：`b1621514` 把 85 行演示脚本删成 2 行，周期切换、
   图表柱、会话弹窗、动效开关全部失效，而 `verify-landing` 未报警。
   处置：从 `HEAD~1` 恢复并改走 `window.__avLandingLang`。
2. **契约脚本补「行为断言」**：静态检查之外，用 jsdom（仅 dev，不入页面）
   断言 `#chart-bars` 渲染非空、`[data-period]` 点击改变数值、
   `#inspect-session` 能打开 dialog。防止「脚本绿、页面坏」。
3. **英文页残留中文清零**：`index.html:25`（brand aria-label）、`:129`
   （图表 aria-label）；校验脚本对 `lang="en"` 页的可见文本与 aria 属性
   扫 CJK，命中即失败（`data-i18n` 默认值除外，由 i18n.js 覆盖）。
4. **Release 链接核实**：`releases?q=app-v` 需对应真实 `app-v*` 标签与
   资产；仓库当前仅见 `skill-v*` / `v*`。无可下载资产则 CTA 文案改为
   「查看 Release / Star 关注」，不写「Download」。

### B. Hook 结构优化（替换 §4.2.1 的单一候选）

现状问题：首屏先给身份口号（「Keep the reins」），痛点在 lede 里才出现，
没有「这说的就是我」的瞬间；对标稿的强项是**反直觉失败 → 命名 → 证据**。

采用三段式，且每句绑定一个可复现来源（写入发布门记录）：

| 层 | 内容（英文候选，母语审校定稿） | 来源绑定 |
|---|---|---|
| H1（痛点，事后语态） | `Every tool call succeeded. So why did the run go nowhere?` | SV611 重复调用 / 连续失败规则 |
| 副句（能力+边界） | `Agent Vitals reads the logs your agents already leave on your Mac and shows repeated failures, usage, and cost basis — with the trace to verify it. Nothing is uploaded.` | 现有功能；不含评分/进度 |
| 证据位 | 一条真实、脱敏的重复失败 trace（节点 + 失败标记） | `b1-repeated-failure`（W2）；W1 用总览/用量真图 |

- W1 无 B1 真图时，H1 换用与所配截图一致的问句
  （`Where did your agent usage actually go?`），不得先写空转而无图可证。
- **禁用词表**（契约脚本扫描，命中失败）：`healthy`、`health score`、
  `real-time`、`intervene`、`auto-fix`、`wasted`、`burned`、`saves you`、
  `progress %`。`Is it healthy?` 式问句及「评分」类指标，在产品出现对应
  可复现指标之前不得使用。
- 品牌句 `Keep the reins` 降为副标/页脚，不再独占首屏。

### C. 差异化前置（我们比概念稿强的地方放到首屏第二屏）

1. 紧随 hero 的一条**信任带**：`On-device only · MIT · No API key` 已有，
   增加一句「三种金额不相加」的可视化小件（订阅 / 按量估算 / 账单，
   「未知 ≠ 0」）——这是竞品与概念稿都没有的差异，现埋在「工作方式」第二步。
2. 「体检 × 收据」隐喻连接：名称是 Vitals，下载区落点是 receipt；
   在 hero 与下载区各一句话串起来（「每次 agent 运行留下一张体检单和一张收据」），
   避免两个隐喻各自孤立。
3. 「五类信号」式速记框架可借鉴，但必须映射到真实规则族
   （重复/失败/危险命令/输入膨胀/缓存），不新增无规则支撑的维度。

### D. 转化与分享（不引入追踪）

1. `og:image` 用真机截图 + 品牌排版，绝对 URL；补 `og:url`、`og:type`、
   `og:locale`、`twitter:card=summary_large_image`、`canonical`。
2. 每个 CTA 区就近放「仅 macOS，Linux/Windows 暂无 → 提 issue」（§4.4）。
3. 增加「30 秒看懂」的单屏静态对照：`一次失败会话 → 你看到什么`，
   取代 ASCII 动画的信息承载职责（动画保留为品牌视觉）。

### E. 分期调整（替换 §6 中相应项的顺序）

1. **P0**：A.1–A.4（恢复脚本、行为断言、CJK 清零、Release 核实）。
2. **W1**：B 三段式 + 总览/用量/口径真图 + C.1 + D.1；英文根页与 `zh/`。
3. **W2**：B1 真图、Hero 换诊断图、C.3 信号框架。
4. **不做**：实时、干预、评分、进度百分比、上下文衰减、双 Hero 赛马。

### F. 验收增量（追加到 §7）

- 禁用词与 CJK 扫描在 `verify-landing` 绿。
- 行为断言绿（A.2）。
- H1 与副句的每个主张在发布门记录里有「规则 ID / 截图 / 动线」三选一的出处。
- 首发后 7/30 天除下载数与 stars 外，记录 hero 与 og 文案版本号，
  便于事后对照（方向信号，不作归因结论）。

## 0.6 增长闭环：landing 与产品同步推进（2026-10-01，待评审）

> 决策：**主路线 = 面向普通 agent 用户的 macOS 桌面应用**；CLI/GitHub 是第二入口，
> 不在首页同时讲两个故事。landing 与产品按同一条「引流 → 激活 → 留存」链路迭代，
> 每个 landing 承诺都必须有对应的产品能力与真截图，否则不发布（§1.3）。
> 对标稿（外部概念页 + 「Landing V1」设计稿）的取舍见本节末。

### 1. 闭环与各环节的唯一抓手

| 环节 | 用户要做的事 | landing 侧 | 产品侧 | 成功信号（无追踪） |
|---|---|---|---|---|
| **引流** | 点进来、理解、下载 | 痛点 hook + 真截图 + 下载 | — | Release 下载数、stars、来源类 issue |
| **激活** | 装完 30 秒内看到**自己的**真实发现 | 「你会看到什么」三步真图 | 首次启动价值路径（见 §2） | 首次启动后是否打开过一个会话详情（本机自查，不上报） |
| **留存** | 隔几天还回来 | 「每周回来看什么」一句话 | 状态 + 新增待复核会话；（S3 后）提醒 | 版本更新后回访、issue/讨论活跃 |

钩子与功能的分工：**钩子是「装完 30 秒看到你自己的真实发现」**（零配置、零上传，
读本机已有日志）；「复核状态」是激活与留存功能，不单独做获客标题。

### 2. 产品侧（同步推进，按依赖排序）

| # | 工作 | 依赖 | 对应 landing 用途 |
|---|---|---|---|
| P1 | **会话详情首屏重构**：结论卡（一句话 + ≤3 条原因 + 涉及量级），诊断图与审计表降到下钻层 | 无（复用现有 `insights.diagnostics` 与证据接口） | B1 真图（解 W1 缺 B1 的问题） |
| P2 | **会话状态三档**（需要先看 / 建议看看 / 未发现问题，「未发现」≠ 正确）+ 会话列表按状态排序、一句话原因 | P1 + 离线标定（人工标注真机会话，测误报） | Hero 状态总览真图 |
| P3 | **总览精简**：只留「状态汇总 / 最该看的 3–5 个会话 / 本月费用口径卡」，设置/价卡/数据源下沉 | P2 | Hero、B3 |
| P4 | **首次启动价值路径**：无配置、扫描本机已有日志，30 秒内落到一条真实发现；空态三分（无日志/无权限/未同步） | P1–P3 | 「装完 30 秒」的第 3 步真图 |
| P5 | **截图专用演示工作区**：人工构造但可真跑的会话日志，让真实界面产出可复现、无隐私的截图 | P1–P3 | 全部真图来源 |
| P6 | 新检测：**成功空转**（重复模式，不判「无进展」）、claude/codex 的 `context_tokens` 标准化、峰值占用 + 压缩次数 | 先在 `AGENT_EXECUTION_PROBLEM_TAXONOMY.md` 登记 | W2 hook 升级、「四个信号」屏 |
| P7 | 留存：S2 候选汇总、S3 重复失败通知（默认关、持久去重、点击直达证据） | P2 + S1 真机证据 | 「每周回来」屏 |

红线沿用：状态只排序不开释；不输出百分制/健康分；金额只走 S1 的「相关回合名义成本」
并带免责；缓存命中率与峰值占用是观察读数、不单独触发档位、不写成「漂移/衰减」；
缺失维度标「不可用」并注明「基于 N 项」，不按 0、不假装正常；无基线不告警（FR-05）。

### 3. landing 侧（随产品里程碑放行）

- **P0（已落地 2026-10-01）**：恢复被 `b1621514` 误删的 `app.js`；英文页 aria 中文残留清零；
  `verify-landing` 增加演示脚本行为守卫（语法可解析 / 交互接线在场 / 选择器均存在 /
  aria 无 CJK），并经「截断 app.js」负向注入验证确实会红。
- **W1（依赖 P1–P3、P5）**：§0.5 B 三段式 hook；Hero 与 B2/B3 换真图；B1 文字卡；
  「订阅/估算/账单三栏不相加」前置到第二屏；og 全套 meta（绝对 URL、真图）；
  核实 Release 与 `app-v*` 标签（无资产则 CTA 不写 Download）；仅 macOS 披露。
- **W2（依赖 P6）**：B1 真图、Hero 可换诊断图、「四个信号」屏（只列已实现且标覆盖范围）。
- 页面结构（9 屏）：Hero → 「看似全成功」的问题屏（示意） → 日志 vs Vitals 品类对比 →
  四个信号 → 聚焦证据演示 → **花费口径（我们独有）** → 本地与开源 → 支持的执行环境 → 终屏。

### 4. 截图设计标准（普通人一眼看懂）

1. 3 秒内能说出「这页告诉我什么」：一个结论 + 至多 3 条原因 + 一个量级。
2. 人话，不出现 SV 码、step、fingerprint；规则码只在下钻层。
3. 单一视觉焦点；整屏至多一种强调色表示「需要看」；不放表格与长列表。
4. 数据为真：来自真实界面 + P5 演示工作区；禁合成数字；发布前隐私人审。
5. 三张即可：总览状态、会话详情首屏、花费口径。

### 5. 对标稿取舍（记录，防止回潮）

- **吸收**：单一故事线；「全成功却走不通」反直觉开场；日志 vs 诊断的品类对照
  （改为 `Logs tell you what happened. Agent Vitals tells you where to look.`）；
  ECG 视觉隐喻；啄木鸟「听树干里面哪里空」品牌句；终屏 `Your agent has logs. Now give it vitals.`；
  10 屏以内的克制结构；深色 + 薄荷/琥珀配色（红色仅用于「需要先看」）。
- **禁用**（契约脚本词表，命中失败）：Health Score / 百分制；`waste`/`$ wasted`；
  progress delta、goal drift、confidence %、loop probability；context bloat %；
  Intervene / STOP / REPLAN / Policy 层；`MONITORING` / 实时；
  LangGraph/CrewAI/AutoGen/OpenAI Agents SDK 的 Logo 墙与「framework-agnostic」；
  不存在的命令 `agent-vitals audit|inspect` 与未核实的 `cargo install`；
  架构图里的 Health/Policy Engine；「The agent still failed」（我们不判成败，用 `went nowhere`）；
  「开发者注册」（无账号体系、不上传）。
- **保留我们独有、对标稿没有的**：三类金额不相加、未知≠0、本地不上传、MIT、
  执行环境覆盖差异诚实标注。

### 6. 验收与节奏

- 每个产品里程碑（P1–P5）合并后，才放行对应 landing 区块；`verify-landing --wave`
  按 §1.5 分组，并新增禁用词扫描。
- 首发观测沿用 §7.6：Release 下载数 / stars / 平台需求 issue 的 7/30 天对比，
  记录 hero 与 og 文案版本号；issue 模板加一条自愿的「你怎么找到我们的 / 最先看了什么」。
- 标定门：P2 上线前必须有人工标注的真机样本，给出「需要先看」的精确率与误报率；
  不达标只上排序、不上标签。

## 0.7 承诺兑现清单（2026-10-01 核对；每次发布前重跑）

> 状态为 ❌/❓ 的承诺，要么先补齐，要么从页面上撤下或降级措辞（§1.3、§1.4）。

## 1. 不可变决策（实施期间不重开）

1. **无客户端分析脚本与用户级追踪。**不引入分析脚本、字体 CDN、社交
   小组件或用户级分流。若后续做第一方渠道级归因，需说明服务器访问日志
   仍可能包含 IP/UA，定义保留期与脱敏方式；不能把它称为绝对「零追踪」。
2. **痛语言必须由实物回答。**hero 和价值清单先说具体问题，再用截图
   展示输出；不得用额度耗尽、任务进度或节省金额等当前诊断不能证明的因果
   问句。原有「工作交给 Agent，掌控留给你」可留作辅助品牌句，不再独占首屏。
3. **证据必须是真的。**hero 与价值清单的图只能是真机产品截图（带口径标签/
   失败标记的原样界面，允许裁剪与缩放，不允许合成数字）；截图位用显式
   占位机制，`verify-landing` 的发布门检查占位必须清零。mock 演示区保留
   但明确降级为「交互示意」，不承担证据职能。
4. **下载路径只展示已可用渠道。**首发沿用可验证的 macOS Release 与
   安装说明；新 CLI 命令、brew tap 或安装脚本均需分别开发与安全验收，
   不能作为本轮 landing 上线前置项。
5. **诚实边界同步翻译成痛语言。**FAQ 可补商业模式与竞品比较，但免费/
   付费边界未正式确定前不虚构承诺；竞品能力在发布时复核，只陈述可验证
   差异，不贬损。
6. **a11y 与既有工程纪律不动**：skip-link/aria/reduced-motion 模式延续；
   页面保持纯静态（HTML+CSS+原生 JS，无构建链）；资产变更走仓库提交。
   落地页本身获得与产品同级的**契约脚本**（`verify-landing.mjs`）。
7. **海外发布先有英文证据。**面向 Reddit/X 的英文页面、英文真机截图、
   英文安装说明与术语校对须同时就绪；中文页可以保留，不以中文唯一版本
   承接海外首发。

## 4. 设计

### 4.1 L0 · 工程底座（~0.5 天）

1. **`website/landing/tools/verify-landing.mjs` 契约脚本**（Node、无依赖；
   以实际仓库脚本位置为准）：
   - 检查本地资产与禁止的客户端追踪请求；允许的外部链接按明确用途维护，
     不把所有 `https?://` 文本都误判为网络请求。
   - **发布门**：首发证据位的真图、mock 示意标注、口径边界、隐私说明、
     下载链接、英文页与 a11y 关键属性均在场；对残留占位与外链脚本做
     负向自测。静态检查不能代替截图人审与动线手测。
   - 挂入仓库校验惯例（README 说明 + 可选 npm script）。
2. 页脚声明：`本页不使用客户端分析脚本，不上传 Session 数据。` 如后续
   采集第一方访问日志，公开其用途、字段与保留期。
3. FAQ 在商业边界确定、竞品事实复核后补充；未定事项明确写「尚未公布」。

### 4.2 L1 · Hero 痛语言 + 真截图位（工期待截图脱敏与动线确认）

1. Hero 备选：H1 `哪次 Agent 会话在反复失败？`（v1.1 的「Agent 还在运行」
   是实时语感，产品是事后离线分析，与撤回「实时止血」的原则冲突，已改）；
   W1 若 Hero 图是总览，H1 可用 `你的 Agent 用量花在了哪些会话上？`，
   问句须与所配截图一致。英文候选：`Where did your agent sessions actually
   go?` / `Which agent session kept failing — and what did it cost?`（后者
   仅 W2 可用），由母语审校定稿。副句：
   `在 Mac 上查看受支持 Agent 的用量、计费依据和失败区间，回到会话轨迹
   核对证据。Sessions 不上传云端。` 英文版需按目标用户语感重写，
   不是机械翻译。不得用「额度 40 分钟烧完」暗示尚不能证明的额度归因。
2. **截图占位机制**：`<figure data-shot="hero-diagnostics" data-required="true">`
   内放显式「待真截图」占位；发布前替换为真实且经隐私人审的产品图。
   截图应展示诊断与证据入口，不能只展示经修饰的数字卡。
3. og:image 可用真实界面裁剪与品牌排版，但画面中的数据与 UI 不合成；
   海外版分享卡与落地页语言一致，先做一个可验证的版本。

### 4.3 L2 · 「它替你抓什么」三组证据

每组都用「具体问题 → 产品原样输出 → 点击后到哪里 → 能力边界」四步，
避免五张同质卡堆砌：

| 组 | 问题标题 | 必须能在产品里复现的输出 | 边界 |
|---|---|---|---|
| B1 | 哪次会话在反复失败？ | 重复失败诊断、命中回合和证据检查入口 | 涉及 Token 不等于浪费或可节省 Token |
| B2 | 用量集中在哪些会话？ | 时间/执行环境用量 → 会话列表 → 所选会话详情 | 只称「一键到会话」当入口确实能直达该会话；否则展示真实的两步动线 |
| B3 | 这笔钱是账单还是估算？ | 订阅、按量估算、已知账单及未知项的原样口径 | 不同币种与 basis 不混加；估算不等于实付 |

原 B4 额度与 B5 输入膨胀可以放在后续专题或 FAQ；只有执行环境能力、
真实数据和截图都通过验收才升级为首页主价值卡。啄木鸟与收据动画保留
为品牌视觉，不承载未实现的数字承诺。

### 4.4 L3 · 英文承接与现有下载路径

海外版页面、截图、CTA、FAQ 与 Release 安装说明必须用一致的英文术语。
首版仅链接已发布且可验证的 macOS 安装渠道；下载前告知系统要求、
受支持执行环境、首次无数据/权限不足的处理方法。不要展示尚不存在的
`agent-vitals vitals`、brew tap 或 `install.sh`。

**URL 结构**：英文为根 `website/landing/index.html`（`lang="en"`，海外分享
链接落点），中文迁至 `website/landing/zh/index.html`；两页互设
`<link rel="alternate" hreflang="en|zh-CN|x-default">`，页头放显式语言切换
链接（纯静态，不做浏览器语言自动跳转）。资产共享 `assets/`，截图按语言分
目录。`og:image` / `og:locale` 各页各自设置。

**平台披露**：下载区与 FAQ 首条写明「目前仅 macOS（Apple Silicon/Intel 以
Release 实际为准）；Linux/Windows 暂无」，并给 GitHub issue 链接收集需求——
这也是不引入分析脚本时唯一的需求信号来源。

### 4.5 L4 · 后续可选项目：CLI、分发与渠道实验

CLI 摘要命令属于产品功能，需要另立只读语义、口径、空库降级与 Rust/Python
兼容测试；安装脚本属于供应链安全项目，不能以脚本内、同源提供的 checksum
视为独立可信校验。渠道 `ref` 只能说明入口来源；网站日志无法直接证明
GitHub Releases 的实际下载或安装。若要实验双 Hero，先定义基线、样本量、
渠道分层、隐私告知与可观测的转化事件，不以「两周/三个渠道/平局选费用」
作为预设胜负规则。

## 5. 明确不做

- 不做用户级 A/B 与任何客户端状态（ Cookie/localStorage 分流）。
- 不引入构建链/框架/客户端分析；英文版是海外发布条件，不做未经审校的机械翻译。
- 不在 landing 承诺额度正向余量、省钱比例、自动优化。
- 分享卡片生成（产品内导出即得分享图）是**产品侧**后续项，本 spec 只做
  静态 og 分享卡。

## 8. 风险与守卫

| 风险 | 守卫 |

## 10. 后续诊断内容位的发布条件（与成本暴露 spec 对齐）

`WASTE_ATTRIBUTION_SPEC.md` v1.1 已将原「疑似浪费金额」方案收紧为
**单会话失败区间成本暴露**。它并不证明可避免性，因此原 v1.0 的 Hero
浪费读数、月度「白烧金额」头条、浪费收据与数字 og 卡**全部撤回**，
不得作为已排期的内容位。即使 S1 实现，也只可在解释型专题中展示：
「这段重复失败涉及多少输入与名义成本」，紧邻证据、计费 basis、
正常工作混入说明和不可节省声明；不放入首屏省钱承诺。

通知专题须等该 spec 的 S3 独立验收：触发时效、默认关闭、持久去重、
点击到证据等都实测通过后，才可说「检测到新的重复失败后提醒」，
不能说「实时止血」或「正在白烧时提醒」。未来若建立事实级血缘、
可避免性证据和经审查的浪费指标，须另立口径与营销措辞评审，
不得自动恢复旧图或旧文案。
