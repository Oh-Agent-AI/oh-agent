# 价卡币种、结算证据与参考汇率 V2 SPEC

日期：2026-09-30  
状态：部分实施（2026-10-01）——参考汇率机制与报告币种已落地并通过两轮独立验收；价卡双币、补价卡表单 USD、历史估算冻结未做。见文末「实施状态与决策修订」。  
关联：[美区首发国际化与费用可信展示](US_LAUNCH_I18N_AND_BILLING_SPEC.md)、[统一成本视图](UNIFIED_COST_VIEW.md)、[计费三轴模型](v1.0.0/BETA_1_BILLING_AXIS_MODEL_SPEC.md)

发布前决策：产品尚未正式发布，本 SPEC 取代国际化 SPEC §2.1 中“未知结算币默认 CNY、估算按 `fx_estimate` 转结算币”的计价规则。**不为预发布版本的错误价格估算维持永久兼容路径**。允许在版本升级时废弃并重建派生费用、预算结果和 UI 缓存；但原始用量事实、来源锚点、用户录入的账单/订阅/价卡/预算、已有声明及其撤销链必须保留。无法安全重算的旧估算标为未定价，而不是保留错误数值或归零。未完成 M0–M5 前，本 Draft 不授权直接修改正在使用的本机数据。

## 1. 决策摘要

1. **币种不是模型国籍的属性。** 同一供应商/模型可以有多套官方报价；报价币种、用户结算币种、展示参考币种是三个独立字段。界面语言、系统地区、统计时区均不改变任何已记录金额。
2. 原始账单和用户声明按原币种保存；没有结算证据时 `settlement_currency = unknown`，不得默认 CNY/USD。公开价卡只能生成“按价卡估算”，不能证明用户在该币种付款。
3. 默认视图不换汇、不跨币相加。可选参考换算必须是独立的派生对象，显示 `≈`、原始币种金额、汇率值、来源、采集/适用日期与过期状态；不得进入实际支出、预算已用、MCP 权威金额或默认导出。
4. **不把 `7.15` 直接替换为 `6.8`。** `6.8` 可由用户手动设为参考情景（明确“手动假设，并非银行结算汇率”），不是官方价或默认实时汇率。预发布的旧 `7.15` 派生估算可清理并按 V2 重建；不得改变账单、用量或用户声明。
5. 美区首发不新增联网汇率服务。更新公开价卡沿用现有价格同步/发布审查机制；可验证生效日之后按新价估算，生效日不明时不能把新价倒灌到旧用量。
6. **正式发布后的已封账历史估算必须可复现。** 折算估算绑定价卡版本、汇率快照和算法版本；之后汇率变化不能在查询时改写旧金额。补录事实或纠错只能追加明确标记的修订版本，不能静默覆盖。

## 2. 当前问题与范围

| 现状 | 风险 | V2 处理 |
|---|---|---|
| `assets/pricing.json` 顶层 DeepSeek 卡无 `currency`；`domain/cost/claude.rs` 顶层卡固定返回 CNY | 有 USD 官方报价时无法表达；“中国模型=CNY”被编码为事实 | 报价变体带显式币种，删除国籍推断 |

| DeepSeek `deepseek-v4-flash` 旧卡仍是旧价，官方已说明旧名由 V4.1 Flash 服务并按新价收费 | 新事件估算偏差，改 FX 无法修复 | 单独发布价卡版本与生效日，评估历史事件对应模型版本 |

本 SPEC 涉及价格目录、计价/归因、预算与桌面展示；不授权改变执行环境日志、原始 token 事实、真实账单金额、用户既有结算声明或公共导出格式。用户本机虽是预发布数据，仍不能被自动删除或覆盖。当前网络政策仍生效：应用不得上传用户数据；新增汇率网络请求不在本范围。

## 3. 术语与不变量

| 概念 | 含义 | 来源优先级 |
|---|---|---|
| `quote_currency` | 某张价卡的报价币种 | 价卡原文，必填 |
| `settlement_currency` | 某账户/计费方实际收款或用户声明的币种 | 执行环境账单 > 用户明确声明 > 可验证账户结算证据 > unknown |
| `reference_currency` | 用户希望查看的参考换算目标 | 用户显式选择；首装地区只可建议，不反推结算 |
| `billing_basis` | 已记录账单、声明订阅、按量估算、API 等价估算等 | 沿用现有枚举与来源，不由币种决定 |
| `quote_variant` | 同一 provider/model 下的地区、渠道、账户方案、币种与有效期组合 | 官方/用户价卡及来源证据 |

同一币种且同一可加口径才汇总。`unknown` 不能归为零。订阅费用不是额外的逐 token 实付；API 等价估算不能与实付叠加。“官方报价为 USD”不等于“用户用 USD 结算”。不同语言、地区与参考汇率下，权威事实与已记录账单逐字节不变。

### 3.1 分层边界（实现约束）

- `agent-vitals-harnesses` 的 Claude/Codex/DSH adaptor 只解释各执行环境原始字段，产出规范化用量、模型原文、provider/route 证据及来源锚点；不能根据执行环境或模型国籍写入 CNY/USD 结算结论，也不能在摄入时换汇。
- `agent-vitals-domain` 的通用价卡策略按 `provider + model + scope + 有效期 + quote_currency` 选卡，验证显式报价币种并计算原币种估算；币种、结算证据、FX 快照和不可变修订是跨执行环境不变量，不应散落在 `domain/cost/claude.rs` 或 Codex 特化路径。执行环境特有的 token 桶映射可保留在 adaptor/harness 计算器。
- `agent-vitals-query` 只在规范化事实与价卡版本之间做聚合和替代，不从当前 `fx_estimate` 推断历史结算；`agent-vitals-billing` 按同币预算核算，异币标覆盖不完整。UI 仅消费后端投影，不另造换汇或账单逻辑。
- 迁移时可先删除旧自动 FX 调用点和缺币默认值，再抽取通用 `PriceQuote`/`QuoteSelection` 接口；每次移动必须保留 Python/Rust parity 与执行环境契约测试。不得把通用价格政策简单搬进每个 adaptor 复制一份。

## 4. 价卡 V2 数据契约

价卡**保留报价原值**，允许同模型多个币种/市场版本并列。示意如下；字段名在实现前与既有 `pricing_snapshots` schema 对齐，不直接以此片段改库：

```json
{
  "provider_id": "deepseek-official",
  "model_id": "deepseek-flash",
  "quote_variant_id": "deepseek-usd-example-version",
  "quote_currency": "USD",
  "market_or_account_scope": "global-usd",
  "source_kind": "official",
  "source_url": "https://api-docs.deepseek.com/quick_start/pricing/",
  "captured_at": "2026-09-30T00:00:00Z",
  "effective_from": null,
  "effective_to": null,
  "unit_tokens": 1000000,
  "price_dimensions": { "cache_hit": "0.003", "cache_miss": "0.15", "output": "0.6" },
  "tariff": "off_peak",
  "tariff_timezone": "Asia/Shanghai",
  "pricing_version": "sha256:..."
}
```

- 价格用十进制字符串或精确定点值；一张价卡内币种唯一。相同 provider/model 可并列 USD/CNY 变体，绝不把两套官方报价当作待实时换汇的同一张卡。
- `price_dimensions` 仅示意。缓存写入、不同缓存时长、长上下文、速度档、请求级阶梯及峰谷维度按模型实际报价单独建模；缺计算所必需的维度时该部分 `unpriced`，不能以 0 或其他模型费率补齐。
- 版本键至少包含 provider、规范化 model、scope、quote currency、tariff、有效期及来源版本。内置缺币种旧卡在发布前补上经来源核实的报价币种；用户自定义缺币种卡进入“需确认”，不得自动解释为 CNY。新价卡一律拒绝缺币种，价卡币种不得推断用户结算币种。
- 保留源模型 ID 和规范化 ID；别名映射有生效区间。DeepSeek 旧 Flash 名称的新请求按官方当前别名规则匹配新卡；无法证明旧事件当时对应模型和价格时，旧用量仍可见但费用未定价，不拿今日价回填。
- `effective_from` 无法核实时，只允许从 `captured_at` 起用于新估算；更早事实未定价，不用当前报价倒填历史。上面的 JSON 是结构示例，并非发布价卡或官方生效日声明。
- 峰谷价按价卡指定的供应商时区和日历规则计算，不随用户统计时区或 UI 语言改变；中国节假日例外需要版本化日历或明确的覆盖降级，不能把“周一到周五”当成完整规则。
- 对同步源的跨币价格，只在来源/市场与数字可验证时新增变体。第三方聚合站数字不同不自动覆盖官方卡；币种冲突、有效期重叠或数量级异常进入隔离报告。

## 5. 选卡与计费算法

**优先级（每个用量事实/调用独立执行）：**

1. 有执行环境已记录的真实金额：保留其原币种、来源和覆盖范围；不要再以价卡覆盖或换汇。若有用户手工账单，同样按现有账单匹配/替代规则处理。
2. 有明确计费方、账户/方案与结算币种声明：只在相应 scope 存在价卡时按该报价估算；若报价币种与结算币不同，**不自动变成结算金额**，保留原价卡币种的参考估算，并将结算金额标为未知，除非用户另外提供明确的合同换算规则/费率。
3. 有可靠路由证据但无结算币：从匹配的官方价卡生成 `catalog_estimate`。若仅有一张适用报价变体，可用该报价币种显示估算，但结算币仍 unknown；若 USD/CNY 两张均适用且无法辨别市场/账户，输出两个**互斥参考情景**或提示选择参考价卡，不生成一个含混合计。
4. 路由不明或价卡不足：保留 token，标 `unresolved/no-route-evidence` 或 `unpriced/no-price-card`。可另列原厂 API 等价估算，但不能冒充用户实际计费方。

同一事实不得同时累计 USD 与 CNY 两个互斥情景。费用结果携带 `price_snapshot_id`、`quote_variant_id`、`price_currency`、`settlement_currency?`、`evidence_basis`、`pricing_method`、覆盖和未定价原因。金额只在规定的后端统一舍入点转最小单位；极小非零结果不能显示为免费。

**产品默认参考报价选择**：用户可在设置里选“参考价卡币种/市场（USD、CNY、自动仅在唯一可判定时）”，其作用仅限尚无账单的估算视图。美区新装可以建议 USD；已有用户保持既有选择。UI 语言或所在时区本身不决定选卡。选择改变应视为重新计算估算的显式操作，提供变动预览，不触碰历史账单或用户声明。

## 6. FX 政策

### 6.1 默认与可选情景

- 默认不换汇。跨币概览按 `USD $X + CNY ¥Y` 分栏，不生成无口径的总额。
- 可选“参考折算”是**独立派生**：`source_amount/currency + target_amount/currency + fx_snapshot_id + rate + rate_pair + rate_source + rate_as_of + captured_at + policy_version + stale`。绝不覆盖原金额字段或作为账单证据。
- 首发无在线汇率服务。用户手动输入 `6.8` 等正数时，`rate_source=user_assumption`、`rate_as_of` 为用户声明日期或 unknown；界面写“按手动参考汇率约算”，不是“当前汇率”或“已支付”。没有用户日期时只能做即时 what-if，不能固化为某历史日期的折算成本，也不能用应用启动时间补日期。
- 自动、结算或历史日 FX 服务是后续独立功能，须先审查来源授权、历史日规则、离线缓存、隐私/网络政策与数据契约；失败时仅回退原币种，绝不回退到无日期硬编码常量。

### 6.2 历史成本冻结与汇率更新

- 此节是后续“历史参考币种报表”的实现契约，**首发不启用历史自动换汇**。首发保留原币种历史费用和不可变价卡来源；用户手动汇率只用于即时参考情景。
- **权威账单始终冻结原币种。** `USD 10` 的已记录账单永远是 `USD 10`；未来 `USD/CNY` 从 6.8 变成 7.5，不改变这条账单及原币种价卡估算。转换后的人民币数字不是“实际支付人民币”。
- 若用户明确启用“历史参考币种报表”，计价层为事件日期选可验证的历史日汇率；月报由各事件日/日桶的转换结果汇总，不能拿**查询当天**汇率乘整月旧金额。无相应历史日汇率时保留原币金额，标“参考折算不可用”。手动月均价只能作为单独的规划情景，不能冒充逐日历史价；大幅波动时尤其不得用月均价替代日价。此为产品报表口径，不宣称满足财务会计准则。
- `fx_rate_snapshots`（或等价版本化存储）每条包含 `pair, rate_decimal, rate_date, rate_source, captured_at, source_version, policy_version`，只追加、不原地更新。同一来源日期的修正生成新 snapshot ID。折算使用精确定点算术，并定义唯一舍入点。
- 历史折算投影保存 `source_amount/currency, target_amount/currency, fx_snapshot_id, pricing_snapshot_id, usage_revision, conversion_policy, calculated_at, report_status`。可按日期/币种/basis 聚合存储，不要求复制每条原始调用；但必须能重放出同一金额。查询**已封账**历史期不得从当前全局 `fx_estimate` 重新计算。
- 当期结果标“暂定”，可因晚到日志、价卡勘误或汇率更新而变化。账期首次成功封账后固定版本；晚到数据或错误修正创建 `revision N+1`，保留 `revision N` 和差异/原因，UI 明示“已修订”，不静默漂移。封账时机与晚到容忍窗口在实现前固定，并与用户统计时区一致；失败不得假装已封账。
- “按**今日汇率**重看历史”只能是另一个实时 what-if 视图，明确显示新汇率日期及“非历史账本”；不得替换封账金额、已导出报表或预算历史。用户切换语言、地区、参考币种也不改变已封账原值。

### 6.3 预发布 `7.15` 清理

- 升级时识别由旧 `fx_estimate` 生成的 `fair-market-fallback-fx`、预算规划折算、补卡预填及 UI 缓存。它们是可重算的派生结果，不是用户账单。完成本地备份和影响预览后，使旧派生版本失效并按 V2 重建；缺报价原值、路由或生效日的部分显示未定价/覆盖不完整。
- 不把旧换算后的 CNY 数字仅改币种符号“还原”为 USD，也不对已录入的用户价卡或预算做逆向 FX。若无法区分用户确认值与自动预填值，保留原值并要求用户确认，不能自动改写。
- 从所有新计价调用点移除 `fx_estimate`。展示参考折算若需要默认汇率，首发宁可不显示；用户手动输入无日期的 `6.8` 时只产生即时参考情景，不写回费用事实或封账历史。
- 数据重建必须是可中断、可回滚的本地升级步骤；失败时保留原始用量与账单，费用显示“重建未完成”，不得继续展示已知失真的旧数值。无需维护旧价卡兼容计算分支，也不承诺预发布估算的数值稳定。

## 7. 界面与交互

- 费用行必须同时说明“已记录/声明/估算”、币种和来源；“美元官方价”不写成“美元实付”。会话、用量、总览、菜单栏和导出使用同一后端金额投影。
- 价卡补录表单以原价卡币种预填；不再强制 USD 官方卡按 7.15 转 CNY。修改币种需重新输入金额或显示明确的参考换算预览并二次确认；用户保存的是其确认的价卡，不是假定官方报价。
- USD/CNY 双卡可在详情选择“报价来源/地区”，并展示价格版本与有效期。用户没有结算证据时允许跳过，不强迫做虚假的币种选择。
- 预算展示本币已记录/估算部分、跨币未纳入部分和 FX 假设；缺汇率或情景冲突时给 `coverage=incomplete`，不得报确定的“预算安全”。任何参考折算不触发支出警报；若需跨币规划预算，须另建明确假设的预算情景。

## 8. 迁移、兼容与实现顺序

| 阶段 | 工作 | 完成判据 |
|---|---|---|
| M0 证据盘点 | 列出每个 `CNY`/`USD` 默认、FX 调用点、派生表/缓存与用户输入表；核对官方 USD/CNY 价卡 | 明确“可重建”和“必须保留”的对象，升级前本地备份与影响预览 |
| M1 契约 | 在版本化价卡快照添加变体与显式币种；结果增加 provenance/FX 元数据；定义未来不可变汇率快照和折算修订契约 | 内置旧卡补显式币种，自定义缺币卡待确认；新快照拒绝缺币；历史换汇未启用时不产生伪快照 |
| M2 计价 | 后端统一选卡；移除新路径国籍/未知=CNY 推断；对双币不确定降级 | 同一事实不双计、跨币不合计，Python/Rust golden parity |
| M3 价卡同步 | 同 provider 多币种变体并存；DeepSeek Flash 旧名改用有证据的新价卡 | 官方来源和有效期可复核，异常 overlay 隔离 |
| M4 本地重建与 UI | 预发布派生费用失效/重算；原币显示、互斥情景、补卡表单与预算降级；手动汇率只提供即时 what-if | 不改用户输入和原始事实；失败可回滚；英中/离线/读屏验收；旧账不随汇率设置变化 |

预发布旧估算不作数值兼容承诺。SQLite schema 仍需向前迁移，避免已安装开发版丢失原始事实和用户录入；可重建的旧价格快照/投影可在备份后废弃，但不得盲删整库或 `harness_bills`。`MoneyMinor` 仍按币种与 basis 分桶；CLI/MCP/导出等机器契约若需改变，必须同步更新消费者、golden 和 Python/Rust parity，不能以快照更新掩盖回归。

## 10. 待评审问题与来源

1. 当前 `pricing_snapshots` 实际是逐事实还是窗口末选取，各消费面需实测列明；V2 要求按事实时点，但不得假定当前所有消费面均已做到。
2. DeepSeek 官方两套报价的适用范围是否由用户账户/地区决定，现有公开页面不足以证明；在取得结算证据前只把它们当两套报价，不宣称是同一价经汇率换算。
3. 中国节假日表及 DeepSeek 价卡生效时间需从官方资料核实并作为版本元数据；无法核实的部分不写精确历史账。

### 决策修订：预算已用可以包含「参考折算」部分（取代 §1 第 3 条与 P08 中对预算的限制）

用户 2026-10-01 批准：当月的异币订阅折算进预算已用与状态，**折算部分必须单独标注**（预算 JSON 的 `subscription_converted_minor` 与 `subscription_fx` 出处），界面标 `≈`；**支出警报只读不含折算部分的比例**（`alert_ratio_bp` / `daily_alert_ratio_bp`），折算是约数，只提示、不触发警报。
