# Creator Studio V2 原型功能对照与缺口

基线为 `dev@3335ff01`。本次逐项审查 ImageGen 的[项目库效果图](../artifacts/creator-studio-v2-imagegen/studio-project-library.png)和[编辑工作区效果图](../artifacts/creator-studio-v2-imagegen/studio-workspace.png)，对照[可点击原型](../artifacts/creator-studio-v2-prototype-2026-11-22/index.html)、[交互脚本](../artifacts/creator-studio-v2-prototype-2026-11-22/prototype.js)及应用源码。表中的「已有」表示找到用途相符的应用路径，「部分」表示已有底层或单独页面，尚未形成效果图中的体验，「缺」表示本轮未找到对应的正式交互。浏览器里的 Mock 动作单独说明。本轮是静态审查，实际运行表现和响应时间仍需验收。

## 1. 优先结论

1. **先把「看见变化」做成主路径。** 画布选中对象应进入本轮 Agent 请求，候选就绪后自动画出来，审阅时可接受到草稿或放弃。当前任务进度可订阅，有限的 City 补丁显示在请求提交之后。效果图中的聊天输入、对象关联和候选自动上画布仍要接通。
2. **先确定编辑对象和试玩对象。** 项目库的「继续编辑」与「打开预览」在原型里进入同一个静态编辑页，只替换标题。正式版要按作品类型分流，区别可编辑草稿、运行中的 City、候选和 Release。
3. **给所有状态绑定证据。** 「已保存」「待确认」「试玩中」「检查通过」各有独立来源。编辑稿同屏显示出租车还在检查与底部全绿，无法看出绿色结果属于哪个版本。静态场景稿可以举例，能点的原型应展示同一版本的状态约束和失败分支。
4. **缩减未定义控件，补足退出路径。** 首轮保留创建、继续编辑、查看候选、确认、取消和试运行。先去掉原型中没有需求支撑的账户头像、语音、无动作的加号和快捷键提示。修复窄窗隐藏进入工作区按钮、切面板后无法定位焦点的问题。

## 4. 点击原型与下一轮交付之间的验收项

| 优先级 | 工作 | 完成条件 |
|---|---|---|
| P0 | 项目库进入正确的编辑器 | 搜索、筛选、清空、窄窗、键盘均有可达的打开入口。Game、Story、可编辑 City 和只读 City 实例进入相符的界面。返回恢复选择和焦点。 |
| P0 | Agent 连续编辑产生可见效果 | 选中建筑或检查点，连续提交两条指令，当前画布显示最新候选。等待和失败都有反馈。拒绝恢复基线，接受后读到真实新版本，旧提案不能覆盖新画面。 |
| P0 | 实际试玩与调试交接 | 一条道路编辑先显示候选轮廓，准备好同一版本的路面和碰撞后可重新试玩。暂停／停止依赖实际运行能力。退出试玩可回到原工作区。 |
| P0 | 证据与发布一致 | 修改候选后旧测试标记为已失效或历史版本。通过状态可追到测试范围、来源和候选。真实发布需独立确认。无法试玩时明确原因和下一步。 |
| P1 | 补其余受支持入口 | 安装管理、截图、项目历史和浏览器真实服务按各自契约实现。继续保留桌面与浏览器能力差异，按宿主提供的能力显示控件。 |
