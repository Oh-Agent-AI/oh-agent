## §1 剩余核心：需求驱动增量规划（F1 主体）

分支现状仍是「几何生成 + 事后剪枝」；本文的核心主张不变——**让规划过程本身成为模拟**，
而本产品的独有优势是把会话数据当真实需求场：

```text
输入（现成）:
  成本场   = terrain.height/slope + coastDistance + river（L1 已输出）
  需求密度 = 小区 wedge × 会话分布（layout 已算）
  规则     = 桥单价×跨距、坡度惩罚、离岸惩罚、升格阈值

循环（种子化 PRNG、固定遍历序、逐步）:
  for 每个增长步（对应回放时间窗）:
    1. 按需求密度采样 ≤N 个需求点
    2. 需求点经最小成本路径（A*，粗网格 20–30m）接入最近路网
    3. 路段流量（介数中心性）超阈值的支路升格主干
    4. 街区在路网围合多边形内填充（F3；过渡期沿用分支的对齐网格）

两笔旧债的偿还机制（无需专门代码）:
  D-绕行 ← 成本含坡度 ⇒ 最小成本路径自然沿等高线
  D-桥址 ← 过河成本 = 单价×跨距 ⇒ A* 自动选最窄处
```

`growWithBuildings` 的活动剪枝与增量规划不冲突：过渡期共存（剪枝管「现在铺不铺」，
寻路管「怎么接」），F3 完成后剪枝自然退化为活动渲染的一部分。

## §2 参考库评估（v0.1 结论不变，摘录）

**symbios-tensor**（Rust/MIT，crates.io）：张量场 RK2 流线 + **主干沿等高线、次级沿梯度**、
街区面行走提取、`MathMode::Portable` 跨平台确定性——F1 SPEC 底稿；平地退化需微坡/网格兜底，
仓库年轻需代码评审。配角：josauder/procedural_city_generation（L 系统生长，MPL 署名）、
Grzybojad（Voronoi 划界）；工具箱：OSMnx（考卷）、networkx（A* 与介数中心性）、
shapely（F3 街区原型）。根文献：Chen 2008、Parish–Müller 2001。

## §3 不可动摇的三条约束（不变）

1. **确定性**：同 `(seed, tier)` 同城；算法迁就守卫（含分支新增的 City planning 四项指标——
   F1 起这些数字是回归基线，只许变好）。
2. **性能**：L1–L3 < 120ms（700 会话，M1）；粗网格 + 需求点上限 + `(seed,tier)` 缓存；
   超预算退回分支现行生成器（其已成为新的降级基线）。
3. **数据语义不变**：路网只影响形态不影响统计面；迈阿密只当考卷不当地图。

## §4 剩余分期（F 系，基线 = 分支合并后状态）

| 期 | 内容 | 验收 |
| --- | --- | --- |
| **F1** | 需求点 + A* 接入替换主干/连接生成；桥成本项启用 | 守卫全绿且 City planning 四项指标不劣于分支基线；桥均跨距下降（最窄处选址证据）；等高线段占比上升；回放可见骨架先于街区 |
| **F2** | 介数升格 + 与 `growWithBuildings` 的生长时序统一（骨架先行、支路随楼） | 回放片头路网密度单调增长；升格路段可视觉区分 |
| **F3** | 路网围合多边形填块（shapely 原型 → TS 移植，参考 symbios face-walk），替换扇区/对齐网格 | 地块数 ≥ 档位目标；临海街区斜切形不回归；守卫全绿 |

每期独立提交、独立可回退；F1 前先出算法 SPEC（成本函数、采样规则、升格阈值、降级条件、守卫增项）。

## §5 验证基准（迈阿密考卷——仍未实施）

1. city-roads 本地加载迈阿密，scene API 导出路网（开发期一次性，App 零新增出站点）；
2. OSMnx 算基准统计：长度加权朝向直方图、平行路间距分布、密度-离岸曲线、等级比例；
3. F1 起每期对 30 种子生成城市同口径打分，进守卫输出（先报告后硬门）。
   分支的 City planning 守卫是内部指标；考卷提供「像不像真实城市」的外部标尺，两者互补。
