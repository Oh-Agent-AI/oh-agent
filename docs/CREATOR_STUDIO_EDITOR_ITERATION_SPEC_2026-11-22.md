# Creator Studio 编辑器迭代规格

2026-11-22 · 依据项目库与编辑器验收截图，以及 [Studio V2 PRD](OH_AGENT_CREATOR_STUDIO_V2_PRD_RFC_2026-11-20.md#132-用户信息层级与布局决策)。

本文保留本轮交付与验收记录。后续编辑器入口、组件和阶段验收见 [Creator Studio 编辑器重构实施说明](CREATOR_STUDIO_EDITOR_REFACTOR_IMPLEMENTATION_2026-11-22.md)。

## 目标

进入 Studio 后，用户可以扫视作品、直接继续编辑，或者写一次目标并带到对应项目。打开编辑器后，当前作品、草稿状态、可执行的下一步和最新试玩结果都在首屏。仍需解释的版本、证据和日志通过详情展开。

## 本轮交付

| 编号 | 要求 | 实现边界与验收 |
| --- | --- | --- |
| ST-IT01 | 项目库保留轻量筛选、作品卡片和详情 | Host 顶栏保留搜索和新建，正文省略重复的「我的项目」。桌面最多三列，窄窗口重排。卡面采用 4:3，已有插画按类型和玩法区分。作品卡直接打开，详情入口单独可用。 |
| ST-IT02 | 待配置的 Game 直接到场地 | 项目详情与画布顶栏使用「配置场地」，进入已选择项目的「玩法」并聚焦场地表单。校验、保存继续调用现有场地事务。普通作品卡仍直达工作区。 |
| ST-IT03 | 画布区显示当前版本的下一步 | 依据已打开项目、保存状态、场地、候选与正式发布记录决定操作。新建候选、开始试玩、查看结果、试玩正式版分别映射现有操作。查看结果打开证据区，发布仍由用户显式确认。 |
| ST-IT04 | 试玩概况与诊断可分别访问 | 概况显示候选阶段、最近 Run 及证据来源。候选读取失败有重试动作。原始证据、修订及检查细节按需展开。浏览器标明合成数据，桌面执行依赖宿主。 |
| ST-IT05 | 编辑器保留项目目标与角色分工 | Agent 目标按项目交接，创建计划、批准、执行、确认修改沿用现有链路。切换到独立 City 预览时显示所选 City 及只读状态。 |

## 状态和动作

| 条件 | 首屏状态或动作 |
| --- | --- |
| 独立 City 或世界包 | 只读场景预览，操作属于正在查看的城市或世界包 |
| 缺少布局 | 查看项目设置 |
| 草稿有未保存修改 | 查看未保存修改 |
| 缺少玩法场地 | 配置场地，定位已有编辑表单 |
| 场地已保存，候选读取失败 | 重新读取试玩状态 |
| 场地已保存，尚无候选 | 创建试玩候选 |
| 候选待试玩或上次未完成 | 开始或重新试玩 |
| 候选试玩中 | 查看进度 |
| 候选已有结果 | 查看试玩结果，人工复核沿用既有证据门控 |
| 当前修订已发布 | 试玩正式版。存在新候选时仍可从详情找到正式版入口 |

## 后续契约与验收

- 作者简介与专属封面需要可编辑的持久元数据。封面来源可复用已保存修订的场景捕获，明确图片更新与项目修订的关系。
- 对象绑定、多轮 Agent 消息和连续渲染反馈需要可寻址的对象上下文与轮次事件。首条任务目标复用现有任务账本，完整对话以新的契约验收。
- 暂停、继续与退出属于实际运行会话，按 Runtime 声明的能力开放。主 City 标记来自 Host 已确认的运行对象。
- 浏览器用合成数据验收项目库、键盘与窄窗口、目标交接、场地校验和保存。原生桌面验收候选试玩交接、证据反馈与真实 Agent 执行。保存截图并记录测试命令和未验收条目。

## 本轮验收记录

- Studio 类型检查、80 项单元测试及浏览器构建通过。单元测试覆盖阶段动作的前置条件、试玩证据门控，以及驾车与飞行锚点的选择。
- 浏览器验收三列与 4:3 封面、项目详情直达场地、键盘焦点、校验与保存、试玩准备、场景诊断、窄窗口和 City 只读预览。保持合成数据标记。
- 桌面 Agent 执行、原生试玩和发布交接仍需在实际桌面应用中验收。
