How we set up a game 3D character asset pipeline (AI drafts, hard gates)

Published 27 October 2026Oh Agent

Agent Citymecha3D pipelineBlenderGLB

AI image-to-3D tools are good at first meshes. They are not a one-click path to a playable mecha on a tactics grid. This post is the pipeline we locked for Agent City mecha characters: concept views → AI draft → mesh cleanup with measure-first gates → rigid parts and pivots → GLB → runtime acceptance.

We do not treat “Claude / an agent ran Blender” as delivery. Agents are operators and batch accelerators. Topology, joint axes, rule-space coordinates, and runtime budgets still pass human stage gates.

The route in one line

Multi-view concept → AI draft mesh → (optional) generator remesh → Blender cleanup & retopo → rigid mechanical parts + pivots → bind / clips → GLB → Three.js acceptance.

Animation only presents moves the combat rules already accepted. It does not rewrite hit, damage, or win/loss.

Stage A–B: freeze the contract, then prototype two roles

Before any generator run:

  • Front, back, left/right, and 3/4 views as separate images — not a labeled moodboard pasted as “views.”
  • Main colors, faction mark placement, weapon side, height/depth, foot baseline, facing.
  • License, tool version, date, and permission to modify recorded up front.

First prototypes are Gunner (humanoid + long railgun + recoil) and Raider (low non-humanoid quadruped). Two or three cheap white-mesh candidates per role; pick silhouette accuracy before spending on materials. If the camera cannot read the role, fix reference / blockout — do not stack detail.

Stage C: the hard gate (measure before you change)

Cleanup happens before cutting rigid parts. Fail C and you do not enter D.

C.1 Import and report

  1. Keep a read-only *_ai_source backup. Destructive work is always on a copy.
  2. Apply transforms; check meters vs the usual cm/mm AI export mistake; foot origin.
  3. Report triangle count, loose islands, non-manifold, zero-area faces, self-intersections, and whether UVs are usable.
  4. Branch:

- Shell intact, mess controllable, UVs usable → Decimate path (keeps UVs).

- Multi-shell, shredding, self-intersect, QuadriFlow refuses → Voxel → quads path (destroys UVs; bake is mandatory).

Industry consensus we stole here (StraySpark, Unity AI-mesh-cleanup notes, Meshy docs): measure first, then pick the tool. Remesh (Voxel / QuadriFlow / Instant Meshes / Quad Remesher) kills UVs. Decimate keeps UVs but will not fix triangle soup.

C.2 Light cleanup (both branches)

Merge by Distance scaled to bbox (about 1e-5 × longest edge), consistent normals, drop degenerates. Delete floaters by relative volume/face share (e.g. &lt;1–2%) — never “keep only the largest component,” or eyes, claws, sensors, and scythe blades vanish.

C.3 Decimate path (keep UV)

Target runtime triangles in the trial budget: humanoid 8k–25k, Boss 20k–50k. Prefer planar prep then collapse; protect textures when UVs exist. If silhouette dies under pressure, switch to Remesh — do not hammer Decimate forever.

C.4 Remesh path (lose UV — common for mecha shred)

  1. Voxel Remesh to one manifold shell (Adaptivity 0; Remove Disconnected). Voxel size from target density; denser then reduce beats a melted shell.
  2. Protect thin parts. Scythe blades, antennas, barrels, claw tips thinner than the voxel fuse away. Separate them before Voxel, use a finer voxel, or rebuild those rigid pieces from design after.
  3. Then QuadriFlow (or Instant Meshes for background props). Preserve Sharp on hard surface. If QuadriFlow rejects non-manifold input, go back to Voxel — do not force quads on a bad shell.
  4. Re-UV (xatlas / Smart UV as a base) → bake Base Color / Normal / AO from *_ai_source or pre-Voxel high mesh. Cage extrude ~0.5–2% of bbox. Do not pretend old UVs still map.

C.5 Agents / Blender MCP (optional)

Batch measure, Voxel, Decimate, export if you want. The agent must print before/after face tables and open fails. Thin parts and silhouette still need a human signature on the stage gate. No generator API inside the desktop app; no user sessions, paths, or logs uploaded — only approved concept stills, as a separate asset decision.

Gate C: editable manifold mesh(es); triangles in budget; no fatal floaters/non-manifold; if Remesh was used, new UV + bake record exists; thin parts readable; source backup intact.

Stage D–F: pivots, clips, GLB, board check

On the cleaned low mesh, set local facing to project -Z with foot baseline at Y=0, then convert to glTF Y-Up on export and verify on re-import. Split by motion function. Each moving part’s origin sits on the mechanical hinge or rail start — not the mesh centroid. Stable names (root, limbs, railgun, scythe_l/r, …). Faction accent stays a runtime-controllable material region, not baked into albedo.

Clips follow the game state contract: idle, move, attack, repair, hit, defeat. Unsupported states map to deliberate substitutes, not silent wrong clips. Mecha prefer rigid parts driven by bones/object nodes, not soft whole-body auto-skin. Auto-rig APIs aimed at humans/animals are isolation experiments, not the default.

Export one .glb per role with embedded textures. Record version, clip list, size, face count, material count, texture size, file weight. Preview page first, then the real City tactics board (16×16 m cells; small roles 1×1, Boss 2×2). root placement and facing stay owned by board code; visuals do not drag grid position. Keep procedural placeholders until each GLB passes; load failure must not crash City.

Trial file budgets (targets to recalibrate after first browser/desktop runs): humanoid GLB ≤8 MB, Boss ≤15 MB; material slots ≤6 / ≤8.

What we are not claiming

  • AI / Claude / MCP is an operator + first draft, not a finished game mesh.
  • Generator remesh in the cloud is preferred when it hits face targets — less triangle soup dumped into Blender — but it still does not skip Gate C.
  • Nanite-style “ship the ultra-high mesh” does not apply: we need rigid animation and Three.js GLB.
  • One-shot replace of all five roles is out. Order: Gunner → Raider → Assault → Support → Boss. Each ships source .blend, runtime .glb, metadata, screenshots, and a written accept/fallback note.

Takeaway

If you are wiring AI meshes into a real game loop, lock immutable stage gates before you optimize prompts. Measure → choose Decimate (keep UV) or Voxel→quads (lose UV, bake) → protect thin parts → set real pivots → accept in the actual camera and rules space. That is the pipeline; the model files are outputs of the gates, not the other way around.
