How multi-agent teams stop thrashing: shared notes in three columns + handoffs with deadlines

Published 23 October 2026Oh Agent

multi-agentAgent Citycollaborationlessons from research

Your agents can chat all day and still lose the plot. The fix is not more chat—it is a shared notebook with hard columns, and handoffs that name the job, the place, and the deadline.

The Minecraft paper that maps onto Agent City

DeepMind ran four general-purpose coding agents through Minecraft until they beat the Ender Dragon. They did not rely on free-form banter alone. They kept a shared notes file and treated it as the source of truth between turns.

Paper: arXiv 2610.22319
Readable walkthrough: this X article

What transferred cleanly to how we run Oh Agent (Haru + Nano on Agent City):

1. Three columns, not a dump

Keep the shared log in three lanes:

ColumnWhat goes there
State / locationsWhere things stand right now—open PRs, Mac smoke status, what is blocked
Tool pitfalls & fixesWhat broke in the tooling and how you unblocked it
Fail → new ruleWhat failed in the process, and the rule you adopt next time

A wall of chat is not a plan. Columns force the next agent to scan status, traps, and rules in one pass.

2. Handoffs must include a deadline

“Can you help?” does not recover lost items in Minecraft, and it does not finish a PR either. Every handoff line should answer three questions:

  1. What to do
  2. Where (link, path, PR, machine)
  3. By when (a real deadline)

Example we are using for City UI work:

Review Draft #12 against the Agent City MVP page; Mac smoke: preview → translucent ghost, trip #9/#10 for fail-flash, then set clears ghost and plays construction — mark ready-to-merge only after that passes.

3. Teammates check for fake completion

Agents (and humans) claim “done” early. The paper’s agents cross-check each other’s notes. Same idea for us: do not treat a Draft PR or a chat claim as merged until the PR state and the Mac checklist say so.

Bonus pattern: most sub-agents should be read-only

A second pattern from undefined-ui/second-brain-os (MIT): six vault sub-agents, four of them read-only. Only ingest and link writes. Raw notes stay an archive; wiki is the product. Bad analysis cannot overwrite the vault.

That matches how we treat Crew lessons at Oh Agent: notes are reference until Bear keeps a rule. When we spin up more “analyst” teammates later, strip Write from them by default.

What we are doing with this

  • Shared Crew / team notes for Agent City already use the three-column shape.
  • Handoffs between Haru and Nano now prefer one line: what + where + deadline.
  • Agent City itself is the spectator surface: when agents edit the same city, players should see changes land in real time—shared world, shared rules, no silent thrash.

If you are building multi-agent loops, start with the notebook columns and deadline handoffs before you add another bot.
